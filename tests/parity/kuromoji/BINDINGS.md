# Persistent Kuromoji binding contract

`bindings.json` defines ordered SQL statements, parameters, expected rows, failures and close/reopen boundaries. It uses the same schema as the [Nori contract](../nori/BINDINGS.md), so each actual binding can execute the same language-specific observations through shared assertions. These authored SQL expectations supplement the pinned Docker morphology oracle; they are not reference outputs generated by Rust.

The 68 enabled steps cover both protected built-ins, six Japanese attributes, original source coordinates, user-dictionary segments, N-best compound paths, stopped position holes, reversed phrases and the pinned completion spelling `toukyou`. Diagnostics preserve HTML source coordinates; highlighting returns the original width, base-form, reading, number and iteration-mark source spans. Complete diagnostic JSONB is retained in the database and compared after failed replacement and reopening, avoiding another expanded token fixture.

Prepared parameters and statements, transactions, savepoints, rollback, independent index/search revisions, definition replacement, column/table rename, new writes after reopening, and final resource deletion share the existing SQL interfaces. Missing bundles and invalid user rules must preserve an existing definition and publish no failed new name. Nine disabled steps require both Japanese built-ins to be absent, reject tokenizer and filter tags explicitly, and preserve generic keyword analysis and reopening.

The Rust Engine harness executes both contracts on SQLite and redb. A second run closes every handle, copies the database, removes its original directory, and opens only the restored copy at each reopen boundary. Separate Engine adapter tests verify sibling-session visibility after commit/rollback and retained index revisions, plus `53200` memory failures during diagnostics/highlighting, `57014` cancellation, retained results and successful recovery on Memory, SQLite and redb. Analysis algorithms and their low-level control tests remain in `uqa-analysis`.

Native enabled/disabled and both-language runs pass. The CLI executes both built-ins from its actual `usql` binary with Japanese support enabled and rejects them in a build without dictionary features. Actual enabled/disabled Python wheels, native Node.js addons and Node-hosted WASM execute the same contracts. Real Chrome verifies enabled and disabled Nori/Kuromoji fixtures across fresh IndexedDB-backed page/WASM constructions.

```sh
cargo test -p uqa-engine --features kuromoji --test integration --locked kuromoji_
cargo test -p uqa-engine --no-default-features --test integration --locked kuromoji_
cargo test -p uqa-engine --features nori,kuromoji --test integration --locked binding_parity
cargo test -p uqa-cli --features kuromoji --test integration --locked builtin_
cargo test -p uqa-cli --no-default-features --test integration --locked builtin_
python3 scripts/check-analyzer-feature-isolation.py
```

The `kuromoji` feature forwards through `uqa`, `uqa-engine`, `uqa-cli`, `uqa-python`, `uqa-node` and `uqa-wasm`. Analysis, Engine and the Rust facade have no default dictionary feature; CLI, Python, Node.js and WASM development builds default to both languages. CI checks all four normal-dependency trees for each of these packages and `uqa-analysis`; disabled dictionaries must be absent from production dependencies.

JavaScript hosts share [`../bindings.mjs`](../bindings.mjs) and the browser-neutral [`../bindings.core.mjs`](../bindings.core.mjs); Python parametrizes the same fixture runner by language. Test environments require both languages by default. Set `UQA_TEST_NORI=disabled` and `UQA_TEST_KUROMOJI=disabled` when loading an artifact built without either feature, or disable only the omitted language for a single-language build. `UQA_TEST_PACKAGE` selects a separate Node/WASM artifact; Python tests use the wheel installed in their interpreter's environment.

`scripts/verify-morphology-browser.py --language kuromoji --output output/playwright/kuromoji-enabled/report.json` opens actual Chrome and runs all 68 steps across three fresh page/WASM constructions, awaiting IndexedDB synchronization before each reload. Its `--feature disabled --bundle PATH` form verifies the nine disabled steps across two pages. The default is one functional run with no host memory sampling. The existing Nori diagnostic corpus remains checked, and optional Nori memory observations require an explicit flag.

`tests/python/retained_analyzers.py` creates compact databases using the enabled wheel, requires a disabled wheel in a separate process to reject each retained tokenizer without changing the database bytes, and verifies identical diagnostics and search after restoring the enabled wheel. Release archive checks require both complete packed dictionaries in each native or WASM runtime and complete source resources in the sdist, including IPADIC attribution and both model/resource identities. WASM inventory restores active data segments and zero-filled gaps before comparing complete dictionary bytes; unsupported or malformed memory layouts fail explicitly.
