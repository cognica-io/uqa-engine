# Official PostgreSQL regression corpus

`source.json` pins the PostgreSQL 18.4 release archive by URL, size, SHA-256, and its `REL_18_4` source commit. `inventory.json` records every byte of the 791 files under `src/test/regress`, `src/test/isolation`, and the upstream `COPYRIGHT`. The importer retains the original SQL, psql commands, isolation session specifications, expected-output alternatives, data files, schedules, and test-driver sources. The [PostgreSQL license](COPYRIGHT) applies to those upstream files; the UQA harness has the repository's license.

The inventory contains 231 default core tests in 28 ordered parallel groups, 119 default isolation specs, and four tests outside the default schedules: `numeric_big`, `reindex_catalog`, `prepared-transactions`, and `prepared-transactions-cic`. The full run executes all 354. `numeric_big` follows the complete original core schedule, and the prepared-transaction specs follow the complete isolation schedule. The reference runs `reindex_catalog` in a separate fresh cluster because its upstream source documents interference from the cleanup of previously exited sessions. No upstream input or expected output is edited, and no test is excluded.

## Import and validate

Python 3.9 or later is required. Importing verifies the complete archive before extracting any file, checks the extracted corpus against every inventory hash, and refuses a modified cache. The archive and original sources remain under the ignored cache directory.

```sh
python3 tests/parity/pg18/upstream/harness.py validate
python3 tests/parity/pg18/upstream/harness.py fetch
python3 tests/parity/pg18/upstream/harness.py validate --source target/pg18-upstream/postgresql-18.4
```

`fetch --archive PATH` accepts an already downloaded archive after the same checksum verification. Changing the PostgreSQL pin requires regenerating the inventory from the authenticated release archive, preserving the license, reviewing every added or removed schedule entry and expected file, and updating the complete coverage ledger. Do not change expected files to accommodate UQA output.

## Execute the reference

The Docker image pins the same PostgreSQL 18.4 base image as the Apache AGE oracle. It installs matching development headers, builds the original `regress` C helper and verbose SPI helper modules through PGXS, and uses the shipped PostgreSQL 18.4 `pg_regress`, `pg_isolation_regress`, `isolationtester`, and `psql` executables. Each reference batch creates a disposable local PostgreSQL cluster. Prepared transactions are enabled for the optional upstream specs. Reference containers have no external network and publish no ports.

```sh
python3 tests/parity/pg18/upstream/harness.py build
python3 tests/parity/pg18/upstream/harness.py run --output target/pg18-upstream/reference
```

The output directory must be new. `--docker PATH` selects the Docker executable, and normal Docker environment settings such as `DOCKER_CONTEXT` select the daemon. `--suite core` runs all 233 core tests, and `--suite isolation` runs all 121 isolation tests. A focused run keeps the unexecuted suite visible as `not_run`; only an all-suite run can set `all_cases_passed`. The default timeout is 1,800 seconds per driver invocation; a timeout ends the disposable container and records every missing result.

`report.json` records the source pin, complete inventory and harness hashes, image ID, program hashes, actual PostgreSQL build, revision provenance, commands, test results, result-file hashes, timing, and infrastructure errors. Original driver TAP logs, per-test output, upstream diffs, and temporary-server logs remain alongside it. The original driver controls expected-file selection and comparison, including its platform alternatives and normal whitespace comparison rules. The harness rejects omitted, duplicate, unexpected, skipped, or malformed TAP results, incomplete plans, conflicting exit codes, missing result artifacts, and evidence generated by a stale image. It does not normalize SQL or replace psql and concurrent isolation execution with serial statement replay.

The pre-merge Rust workflow runs the complete reference and uploads its evidence. Reference success validates the corpus and its environment; it does not verify UQA execution or close the compatibility plan's regression item.

## UQA execution and remaining work

`coverage.json` assigns an owning crate or module to every upstream test. Each entry starts at `not_audited` with category `unclassified`; importing the corpus and passing its PostgreSQL reference do not change that status. Triage actual UQA failures into parser, binder, type-system, planner, executor, catalog, transaction, protocol, or administration ownership and attach the observed evidence. A verified entry requires `postgres` and `uqa` evidence paths relative to this directory, each naming a saved report that records a pass for that test against the pinned corpus. Every behavior difference remains a bug to fix.

The transport accepts a real disposable UQA SQL server through `run --backend uqa --host HOST --catalog-host CATALOG_HOST --network DOCKER_NETWORK --revision FULL_COMMIT --output DIRECTORY`, with optional `--port` and `--user`. It checks the target's UQA `server_version` before the drivers can change its databases. The revision is recorded as supplied by the caller. `PGPASSWORD`, when required, is passed by environment name and excluded from the report. The target must expose PostgreSQL SQL execution and the server-side files and libraries referenced by the upstream scripts at their original container paths. The official drivers create and drop test databases and roles. Use dedicated disposable servers; `--catalog-host` must name a separate fresh server for the standalone catalog-reindex batch and is unnecessary for `--suite isolation`. The harness never chooses an existing application server by default.

UQA currently provides network-independent PostgreSQL codecs and scripted client fixtures, but no general SQL server capable of running this corpus. Implementing that real server boundary, executing the complete corpus through UQA, classifying failures, and fixing them remain part of `regression.core-and-isolation` and the client/operations matrix. This change supplies no UQA pass result.


These tests exercise complete schedule and extra-test accounting, platform output variants, archive corruption and unsafe members, license retention, TAP failure detection, missing evidence, stale images, explicit target identity, and separation of reference evidence from UQA compatibility.
