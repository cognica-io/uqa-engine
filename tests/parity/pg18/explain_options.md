# EXPLAIN descriptions, option diagnostics and execution effects

`capture_explain_options.py` uses Python 3 and libpq to capture 343 operations from PostgreSQL 18.4 on aarch64 Alpine. The official `postgres:18.4-alpine` image used for capture has repository digest `sha256:9a8afca54e7861fd90fab5fdf4c42477a6b1cb7d293595148e674e0a3181de15`. Set `PG_EXPLAIN_CONNECTION` to an explicit disposable connection. The capture creates temporary objects and session-owned prepared definitions; permanent relation probes are rolled back or explicitly dropped after commit.

The fixture records preparation, description and execution separately, including parameter and result OIDs, column names, command tags, SQLSTATE, primary diagnostics, transaction status and nontransactional sequence effects. Ordered and duplicate options, quoted identifiers and format names, Boolean spellings, missing arguments, cross-option constraints, invalid options before execution and planning errors, and savepoint recovery are covered. Normal plan payloads and timing measurements are omitted after checking that PostgreSQL returned rows. Deterministic skipped-target output is retained exactly in all four formats.

PL/pgSQL record loops observe the text, JSON and XML result identities. Utility cases exercise DECLARE without a retained cursor, EXPLAIN EXECUTE parameter binding and effects, read-only CTAS commit and materialized-view destinations with subsequent write rejection, WITH NO DATA, existing targets before planning errors, and immutable-function planning effects occurring once. Materialized-view refresh reuses the retained definition rather than the initial optimized value. Temporary routines exercise explicit namespace lookup, search-path exclusion, replacement rollback and DISCARD TEMP rollback. Native owner tests replay the fixture independently on Memory, SQLite native, SQLite KV and redb; durable routine tests additionally check refresh and reopen.

The semantic references are PostgreSQL's [EXPLAIN contract](https://www.postgresql.org/docs/18/sql-explain.html), [result descriptions and utility execution](https://github.com/postgres/postgres/blob/REL_18_4/src/backend/commands/explain.c), and [ordered option interpretation](https://github.com/postgres/postgres/blob/REL_18_4/src/backend/commands/explain_state.c). UQA retains its native physical operators and measured execution data in the rendered plans. This fixture does not establish physical-plan equality, performance acceptance or complete instrumentation-option coverage.
