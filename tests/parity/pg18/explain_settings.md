# EXPLAIN effective settings and summaries

`capture_explain_settings.py` records eighteen operations from PostgreSQL 18.4 on aarch64 Debian using Python 3 and libpq. The disposable official-image container used image ID `sha256:bc8a94e4a938576533c0f0e8ad6f2e8c67d5c5facef05005a5e5cf9adce2fe25`. Set `PG_COMPLETION_CONNECTION` to an explicit disposable connection. The capture supplies the startup option `work_mem=64MB`, matching UQA's documented initial setting; PostgreSQL's built-in boot value remains 4 MiB, so EXPLAIN reports this initial override and RESET ALL restores it.

The observations retain effective SETTINGS objects and the presence of planning and execution summaries. They cover initial overrides, all four planning parameters implemented by UQA (`enable_indexonlyscan`, `plan_cache_mode`, `search_path`, `work_mem`), exclusion of `statement_timeout`, disabled SETTINGS and SUMMARY, ANALYZE with TIMING disabled, transaction-local changes, rollback and RESET ALL. Measurements, optimizer-specific plans and costs are omitted. The capture checks every command succeeded before extracting observations. Native tests replay the operations independently on Memory, SQLite native, SQLite KV and redb.

The semantic references are PostgreSQL 18's [EXPLAIN contract](https://www.postgresql.org/docs/18/sql-explain.html), [EXPLAIN renderer](https://github.com/postgres/postgres/blob/REL_18_4/src/backend/commands/explain.c), and [`GUC_EXPLAIN` parameter definitions](https://github.com/postgres/postgres/blob/REL_18_4/src/backend/utils/misc/guc_tables.c). PostgreSQL supplies the expected observations independently of UQA.
