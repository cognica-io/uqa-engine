# Prepared request admission reference

`capture_prepared_admission_oracle.py` captures forty-six ordered libpq operations from PostgreSQL 18.4 (Debian 18.4-1.pgdg13+1, aarch64). Run it against an explicit disposable `PG_PREPARED_CONNECTION`; it creates and drops `prepared_admission_positive`, and all prepared definitions and settings belong to the connection. Named parameter declarations resolve through each engine's own type catalog before preparation. The fixture records parameter and result metadata, rows, command tags, SQLSTATE, primary diagnostic and transaction status.

The reference covers host parameter-count errors before failed-state rejection, descriptions with and without row columns, empty preparation, preparation and execution of transaction exits, parameterized exits rejected in a failed block, savepoint restoration, COMMIT becoming ROLLBACK, syntax errors before failed-state rejection, removed definitions and unused parameter conversion before an idle ROLLBACK completes. The Engine replay maps each generated native handle name to the corresponding reference name only inside quoted diagnostic identifiers; every other observed field is compared unchanged on memory and native SQLite.

Capture SHA-256: `f80128dcdf3aeff7f50740abd85650e3663c741a34806e4fdf084a06a095e439`. Fixture SHA-256: `28f3317a59b65c25b93fed2dd9fc501fd87d57300b90d0996ddf321208bc02dc`. PostgreSQL's [Parse, Bind and Describe implementations](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/tcop/postgres.c) provide the independent admission and diagnostic-ordering reference. Before correction, both Engine providers returned `42601` and left the transaction active after the first wrong-count operation; the reference requires `08P01` and an aborted transaction.
