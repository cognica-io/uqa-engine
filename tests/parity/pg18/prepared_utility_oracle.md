# Prepared session utility reference

The reference is PostgreSQL 18.4 (`Debian 18.4-1.pgdg13+1`, aarch64), captured on 2026-10-24 through libpq's `PQprepare`, `PQdescribePrepared`, `PQexecPrepared` and `PQexec`. All definitions, cursors, settings and transactions belong to one disposable connection; no durable objects are created. PostgreSQL's [utility descriptors](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/tcop/utility.c), [parse-analysis classification](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/parser/analyze.c) and [plan-cache policy](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/utils/cache/plancache.c) define the behavior being compared.

Run `PG_PREPARED_CONNECTION='dbname=postgres user=postgres' python3 tests/parity/pg18/capture_prepared_utility_oracle.py > tests/parity/pg18/prepared_utility_oracle.expected.json` against an explicit disposable PostgreSQL 18 reference. The script checks the server version and captures sixty-one ordered operations, including column names and OIDs, parameter OIDs, rows, completion tags, SQLSTATE, primary messages and transaction status. Expected results come from PostgreSQL, independently of UQA.

The fixture covers canonical `SHOW` and `SHOW ALL` descriptions, unknown settings, unused declared parameters and forced-custom plan policy, snapshot-free preparation, `FETCH` after cursor replacement, `DISCARD PLANS`, `MOVE`, cursors created after preparation, SQL `EXECUTE` after referenced-definition replacement, and execution-time rejection of `$1` in SQL `EXECUTE` arguments with and without declared outer parameters. Literal arguments still execute with unused outer declarations. Engine's `tests::prepared::utility` replays every field on memory and native SQLite. The C11/C++17 prepared client exercises these descriptor and execution distinctions through the shared ABI. This fixture does not cover `CALL`, `EXPLAIN` or remaining prepared failure-ordering work.
