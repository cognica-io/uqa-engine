# Prepared EXPLAIN input reference

`capture_prepared_explain_inputs.py` captures twenty-eight prepared declarations from PostgreSQL 18.4 (Debian 18.4-1.pgdg13+1, aarch64). Set `PG_PREPARED_CONNECTION` to an explicit disposable connection and run the script with Python 3 and libpq. Its temporary relation and prepared definitions belong only to that connection. Each case begins a transaction, calls libpq Parse and then Describe on success, records status, parameter OIDs, SQLSTATE, primary diagnostic and transaction status, and rolls back.

The cases cover queries, INSERT, UPDATE, DELETE, MERGE, RETURNING, assignment subscripts, CTEs, scalar subqueries, ON CONFLICT, CREATE TABLE AS and DECLARE. Invalid literals and conflicting parameter occurrences exercise preparation order. Missing targets precede their expression inputs, while UPDATE expressions precede invalid assignment-column diagnostics. Preparation of EXPLAIN ANALYZE does not execute its body.

SQL owner tests compare the captured input types and diagnostics; Engine tests also compare transaction states on memory and native SQLite and verify that preparation leaves the table empty. C11/C++17 clients exercise inferred input metadata, prepared ANALYZE execution and savepoint recovery through the shared ABI. Plan rendering and EXPLAIN result descriptors have separate outstanding implementation requirements in [the C binding ledger](../../../docs/plans/0028-c-bindings.md).
