# Prepared CALL reference

`capture_prepared_call_oracle.py` captures sixty-three ordered libpq operations from PostgreSQL 18.4 (Debian 18.4-1.pgdg13+1, aarch64). Run it against an explicit disposable `PG_PREPARED_CONNECTION`; it creates and drops the `prepared_call_reference` schema. It records parameter and result metadata, rows, command tags, SQLSTATE, primary diagnostic and transaction status. The Engine replay compares every observed field on memory and native SQLite; SQL owner tests independently compare preparation diagnostics, parameter types and output columns from the same capture.

The cases cover IN/OUT/INOUT inference, named arguments, defaults, overloaded procedures, unknown literal conversion, missing procedures, forbidden subqueries and set-returning arguments, conflicting parameter contexts, body replacement, transaction abort/savepoint recovery and dropped procedures. After a date-order change and DISCARD PLANS, Describe reanalyzes the original input under the current session settings without increasing plan-use counters. A dropped procedure invalidates a row description, while a NoData description still succeeds and execution reports the missing procedure.

PostgreSQL's [CALL analysis](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/parser/analyze.c) and [prepared Describe implementation](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/tcop/postgres.c) supply the independent ownership and ordering reference. The initial Engine replay after connecting CALL input analysis still returned stale columns after the procedure was dropped on both providers; the reference requires `42883` from Describe.
