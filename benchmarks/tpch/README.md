# TPC-H compatibility benchmark

This directory contains a deterministic, checked-in TPC-H-derived compatibility workload: all 22 default queries and `dbgen` data at scale factor `0.001`. It is intended for correctness regression and local performance comparison. It is not a compliant, audited, or publishable TPC-H result.

The data was generated by `tpch-dbgen` 2.14.0 at commit `32f1c1b92d1664dba542e927d23d86ffa57aa253`. The parameterized queries came from DuckDB's `tpch` extension 1.5.3 with its default substitutions. Full provenance and row counts are recorded in `manifest.json`.

## Correctness test

The checked-in `expected/pg17.json` fixture is generated only after every UQA result matches a live PostgreSQL 17 result. The normal test is self-contained:

```sh
cargo test -p uqa-engine --test sql_tpch
```

This gate intentionally remains a separate test target because it loads the complete fixture once. The rest of the engine integration sources are modules of domain harnesses such as `engine_queries`, avoiding one independently linked test executable per source file.

## Release timing runner

Build the package-scoped release executable before measuring. Do not use a debug test binary or a workspace-wide feature-unified executable as a timing substitute.

```sh
cargo build --release -p uqa-engine --example tpch_runner --locked
target/release/examples/tpch_runner --iterations 201
```

The runner validates one result before timing, executes every selected query the requested number of times against one loaded engine, checks that every measured result remains identical, and writes JSON to stdout. A single query or its physical plan can be selected without changing the fixture:

```sh
target/release/examples/tpch_runner --iterations 501 --query 9
target/release/examples/tpch_runner --iterations 1 --query 22 --explain
```

For example, `jq` can extract the median and p90 from an odd-sized run:

```sh
target/release/examples/tpch_runner --iterations 201 --query 9 \
  | jq '.queries[0].elapsed_ms | sort | {median: .[100], p90: .[180]}'
```

The remaining local gaps are Q02, Q07, Q09, Q13, Q16, Q19, Q21, and Q22. This list is deliberately retained so optimization work does not hide behind the aggregate result.

## Live PostgreSQL differential run

To regenerate and differentially verify the fixture, start a dedicated PostgreSQL 17 container and database:

```sh
docker run --name uqa-tpch-pg17 \
  -e POSTGRES_PASSWORD=postgres \
  -p 15433:5432 \
  -d postgres:17
docker exec uqa-tpch-pg17 createdb -U postgres uqa_tpch
python3 scripts/run-tpch-pg17.py --iterations 3 --write-expected
```

The comparison script verifies that the server major version is 17, recreates the `public` schema in the dedicated `uqa_tpch` database, loads and analyzes the fixture, compares all result columns and ordered rows, and writes timing data to `target/benchmark-runs/tpch-pg17.json`. Numeric output is canonicalized only for columns PostgreSQL describes as numeric; text remains byte-for-byte exact.

Use `UQA_TPCH_PG_CONTAINER`, `UQA_TPCH_PG_DATABASE`, or the corresponding command-line flags when the container or database has a different name.

## Criterion benchmark

The benchmark validates all results against the checked-in PostgreSQL fixture before measuring any query:

```sh
cargo bench -p uqa-engine --bench tpch
```
