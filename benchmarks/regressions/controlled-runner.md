# Controlled EC2 performance checks

Use one reusable, on-demand EC2 instance in Seoul with dedicated tenancy, sixteen physical Graviton3 cores, 32 GiB of memory and encrypted gp3 storage. The operator uses the `appspand` AWS profile and its existing `seoul` SSH key. Instance identifiers, SSH addresses, private keys, controller evidence and generated reports remain outside source control. Stop the instance after each session; retain its encrypted volume and build caches for reuse. A restart invalidates the previous session's calibration because placement and the operating environment may change.

The operator owns the host and the controller. Build both immutable revisions before calibration, then run no compiler, package installer or unrelated workload during calibration or candidate measurement. Reserve CPUs 0–7 for administration and ordinary services and CPUs 8–15 for the workload's complete process tree. Record effective cgroup CPU sets, boot identity, kernel/toolchain, CPU topology, swap state, process inventory, binary hashes and CPU steal counters. An unexpected process in the measurement partition, overlapping controller lease, reboot, nonzero CPU steal or unsuccessful workload invalidates the session; do not retry it until it passes. The controller's signing key remains inaccessible to the account executing candidate binaries.

Keep the manifest's data, correctness assertions, warmup, twenty linear samples, measurement duration, four counterbalanced candidate/reference pairs and regression limits unchanged. Calibration and candidate invocations use exactly the same filter. This removes unrelated comparison time without changing any regression gate or query work.

Before executing a candidate, collect exactly 32 independent A/A pairs from the reference executable, alternating the order of the two named roles. Retain every observation, including outliers. For each workload let $a_i$ and $b_i$ be its paired positive slope estimates and define $E_i = \max(a_i/b_i, b_i/a_i)$ and $n = \max_{1\leq i\leq32} E_i$. Compute the bound from these reference observations only and sign it before the candidate starts. Do not replace this bound using candidate samples or increase the reviewed regression limit.

The explicit statistical assumption is exchangeability of the 32 reference-pair absolute multiplicative errors and the four subsequent candidate/reference-pair errors after accounting for the true performance ratio. Host isolation and environmental records support that assumption but do not prove it; workload-dependent noise or drift can violate it. Under this assumption, an arithmetic median of four paired ratios can leave the multiplicative interval $[1/n,n]$ only if at least two of the four future absolute errors exceed the maximum of the 32 calibration errors. By exchangeable ranks, that event has probability at most $4\cdot3/(36\cdot35)=1/105$. Ties make the bound conservative. Thus the interval has marginal prediction coverage at least $104/105 > 0.99$ for each workload's complete four-pair median estimator. This is not simultaneous engine-wide coverage or posterior certainty about a permanent host property. Record this assumption, exact sample count and coverage with the signed evidence; expire it at the end of the controlled boot/session.

Apply the existing qualification verifier to $[r/n,rn]$, where $r$ is the candidate's median paired ratio. Accept only when the entire interval satisfies the unchanged manifest limit, report regression only when its lower endpoint exceeds that limit, and report inconclusive otherwise. Arithmetic overflow, incomplete samples, missing control evidence or a changed sampling protocol must fail explicitly. Generated observations and signatures belong in ignored output directories or CI artifacts; retain only compact provenance and conclusions in reviewed documentation.
