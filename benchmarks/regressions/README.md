# Deterministic performance regressions

Search-read checks cover spilled HNSW topology validation without vector decoding, edge restoration without vector rewrites, distance/scoring vector reads, candidate-bounded residual filters, and cold native SQLite scalar/composite equality probes. They verify complete results together with coordinate, document-read, SQLite VM-instruction, hydration and original-allowance bounds. The Engine cases use synthetic SQL fixtures across session refresh, peer writes, undo and reopen.

The [inventory](manifest.json) selects existing tests in their owning crates. Ready-for-review PR batches and main pushes that change Rust, the inventory or its runner automatically execute it on Linux and macOS through [performance-checks.yml](../../.github/workflows/performance-checks.yml). It covers type OID occupancy without full type-row projection, retained catalog type resolution and scalar/view callbacks without per-row or per-view metadata capture, bounded missing row-type descriptor retention, indexed foreign-key reads, routine and ordinary-statement analysis reuse, bounded sorting, text occurrence and phrase memory, WAND output, HNSW/IVF spill and certified HNSW/IVF mutation retention, native IVF assignment deltas, scoped revision reads, bounded reconciliation/restaging copies and encrypted spill-path writes, one-publication bulk construction, pending HNSW identities and authenticated read reuse, maintenance-safe transaction-local counts, DiskANN resource and I/O accounting, native graph projection, durable allocation, batched key-claim arbitration across independent processes, exact row/key identity retention and transient-key reclamation and independent temporary dependency admission, predecessor storage-owner exclusion, SQLite commit-cache work, version-payload WAL page counts and read-free post-commit cache adoption. The 42 separately named temporal concurrency histories remain included.

Native parallel worker checks require the configured concurrency bound, ordered branch output, pool reuse by repeated and nested work, and complete worker/thread-local cleanup after the final owner or partial startup failure. They count actual worker identities and destructor observations without using elapsed time as an acceptance bound.

SQL collation checks retain PostgreSQL identifier normalization under explicit memory allowances, including multibyte clipping and escaped quotes. They require partial-allocation failures to release all reservations, common-type analysis to propagate resource errors and already selected collation identities to bind again with no free allowance.

Mutable scalar checks compare live allocator bytes with node and child reservations, transfer or discard children without copying payloads, preserve parent containers during replacement, and retire temporary ownership metadata when freezing. They also cover partial container construction, both cancellation scopes, callback failure and unwind, original shared-constant lifetimes and ancestor/sibling limits. These SQL owner checks are preparation for native mutable-plan integration; they do not complete the remaining admission work in #1292.

Native scalar rewrite checks require surviving boxes and CASE/COALESCE vectors to retain their original allocation identities while preserving lazy errors and unbound type arms. KNN threshold merging retains the first call's payload without a large copy and admits its field index and placement buffer before allocation. Exact ordering, NaN and signed-zero behavior, partial rejection, both cancellation scopes and sibling reservations are checked in Planner; the actual native catalog-scalar adapter verifies rejection, cancellation and recovery on all four providers. These tests exercise threshold IR through that adapter and do not claim that every ordinary SQL KNN call uses the threshold-merge eligibility rules.

The work and memory bounds live in the referenced Rust assertions, beside their input fixtures and output checks. For example, indexed referential lookup may enumerate no child rows and may load only matching documents; 32 generic routine calls fold one immutable expression; 32 warm managed allocations require two synchronized commits. Sixteen warmed direct synchronous sequence logs require seventeen FULL commits, including one allocation reserve, with no additional acknowledgement writes. Native SQLite WAL sequence consumers instead publish sixteen NORMAL logs with at most one FULL allocation reserve and one FULL transaction-completion barrier. Cross-session cached consumption, rollback, exact retry and expired publication leases preserve sequence durability; rollback-journal modes retain synchronous publication. Retained completion also verifies live-owner protection, durable SSI overlap and legacy-provider acknowledgement retry. Changing a limit requires reviewing that test's workload, correctness checks and reason for the new bound. The inventory does not maintain a second copy of numeric limits that could disagree with the executable assertion.

Rewrite-rule qualification follows the native query implementation introduced by `493056f7ee5a957b6dbdf6b662b030fff3df1222` and the VALUES correction in `c2ab00f0d`. The former eager rule-event relation, required-column runs, selection/suppression ordinal indexes, original-row index lookup and INSERT/view input staging were removed to preserve PostgreSQL query evaluation. Their 35 obsolete implementation-specific inventory entries are retired; the native query reference checks source effects, lazy failures, set cardinality, output and savepoint recovery on all four providers. SQL owns event collations and scope, Planner owns unused-output pruning, and Execution owns the retained mutation and RETURNING images.

Nine existing inventory entries follow their moved or replaced owner tests without relaxing the retained memory bounds: 32MiB of mutation images and 64MiB of RETURNING images each stay below 2MiB additional live allocation. Current VALUES query coverage additionally requires a 16MiB folded input and its copied plan to stay below 8MiB, and automatic-view binding counts overload analyses for 1, 8 and 32 inputs. The changed physical range reservation check observes reached datums and preserves predecessor addresses, including the approved `XX001` boundary for malformed owned values. Native event collation, pruning and four-provider reference entries replace the obsolete mechanism assumptions; they do not claim the separate planning-memory admission work tracked in [#1292](https://github.com/cognica-io/uqa-engine/issues/1292).

Each entry records the package, existing harness kind, exact test function, every expected parameter-case name and their count. The runner lists compiled tests before execution and fails if a required case disappeared, was ignored, was filtered out, moved to another crate or overlapped another entry. A same-count replacement of a provider or parameter case also fails. It also rejects unexpectedly selected tests. Nextest then runs the same selection with the existing `ci` profile: no retries, a 30-second slow-test notice and a five-minute termination limit. These timeouts detect a stuck test; they are not latency regression limits.

To validate the inventory without compiling:

```sh
python3 scripts/run-performance-checks.py --check
python3 -m unittest discover -s scripts/tests -p test_performance_checks.py
```

To run it with the repository toolchain and cargo-nextest installed:

```sh
CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 CARGO_PROFILE_DEV_OPT_LEVEL=2 CARGO_PROFILE_TEST_OPT_LEVEL=2 RUSTFLAGS='-D warnings' python3 scripts/run-performance-checks.py
```

The local runner builds the selected crates' existing library/integration targets once while listing tests. Its run command reuses those build artifacts. CI instead compiles a nextest archive and the independent-process claim fixture in a separate build job, using the workspace's 60-minute compilation bound. The fixture build uses the same inventory-selected packages and Cargo test profile, including dependency overrides, so it reuses the archive's feature-unified libraries instead of compiling a second dependency graph. The 25-minute execution job downloads only that workflow run's matching-platform artifact, verifies the complete manifest selection and runs the prebuilt binaries without invoking compilation. `--build-archive PATH` and `--archive-file PATH` expose those two runner modes; the archive must come from the same source checkout and platform. Test profiles remain optimized with debug assertions and overflow checks; 30-second SLOW reporting, the 300-second individual deadline and zero retries are unchanged. CI retains JUnit output and compact JSON/Markdown summaries for seven days. The summary records the revision, inventory hash, source hash of every selected test, compiler/nextest versions, platform and workflow attempt. Generated files live under ignored `target/`, never in the source inventory. A failing test retains nextest's assertion diagnostic; an inventory failure names the missing or skipped case before execution.

To extend coverage, add a test to the owner's current harness that asserts both output correctness and a deterministic resource bound, then add an inventory entry with the workload and invariant. Parameterize independent provider cases when useful and update the exact expected case count. Run the inventory validator and its unit tests; CI validates the compiled selection and executes it on both platforms. Existing Nori allocation limits and release workload fixtures retain their own contracts.

This inventory is the deterministic part of [#261](https://github.com/cognica-io/uqa-engine/issues/261). The [actual controlled EC2 results](ec2-results-2026-10-08.md) retain each session and its original decision. Run 37756360358 accepts Q6, cursor scans and all sixteen claim comparisons; Q1 and materialized scans remain inconclusive. The reviewed protocol preserves all calibration observations, existing limits and at-least-99% marginal coverage. The [coverage checklist](ec2-results-2026-10-08.md#ci-coverage-and-timing-decisions) maps the implemented CI to #261's original requirements, including explicit inconclusive results; completing that implementation does not grant timing acceptance to a measured revision. Shared-runner elapsed times, the stall timeout and successful output assertions cannot establish timing acceptance, and this deterministic runner explicitly records `timing_acceptance: false`.

Documentation-only updates to an existing product PR retain its earlier regression run without cancelling or rebuilding it. Input selection compares the preceding head and examines intervening base history, including reverted product changes; unavailable history conservatively selects a new build. Concurrency applies only after platform work is selected. A skipped update is not passing test evidence: delivery still requires the actual Linux/macOS reports for equivalent product and regression inputs.

The separate [controlled EC2 protocol](controlled-runner.md) defines the actual isolated runner, independent reference calibration, fixed analytical/claim workloads and automatic main-CI lifecycle. It preserves this pre-merge inventory and the original timing limits. Detailed timing results remain artifacts; only reviewed conclusions and compact provenance belong in this repository.

The analytical checker's separate [qualification contract](../../docs/design/performance-qualification.md) can verify independently authenticated calibration and controlled-run evidence. It preserves reviewed limits and reports uncertain results as inconclusive. Its synthetic tests do not establish an actual controlled runner or noise bound, and this deterministic inventory does not substitute its counts for that evidence.

The same Linux/macOS workflow also checks the [independent-process claim workload](claim-contention.md) in its clock-free verification mode. Its eight process/key-count combinations verify actual foreign conflicts and completed releases; measurement mode is separate and cannot run in a debug-profile executable.
