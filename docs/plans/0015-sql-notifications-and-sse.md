# SQL notification subscriptions and SSE implementation

Status: active. The [design](../design/sql-notifications-and-sse.md) is the full acceptance contract. Work starts from Engine `b82d8d146dd6bda7bfef7d1642b0ae285b0a3dc1`; end-to-end subscription and authenticated HTTP endpoint qualification remains incomplete.

## Ownership and delivery boundaries

Engine retains the original database, selected SQL authorization, notification hub and listener lifetime. Core owns transport-independent values. Storage and its providers own durable publication, recovery and bounded registry reads. Execution owns statement dispatch, including the stateless-session restriction; Engine supplies the session policy. The HTTP client owns framing, transport and reconnect state and cannot depend on Engine. Each language adapter owns its actual runtime cancellation and iterator behavior.

The authenticated HTTP server is `crates/cloud-node` in the sibling [UQA Cloud repository](https://github.com/cognica-io/uqa-cloud); this workspace's `uqa-api` owns fluent query construction. Current local Cloud commits `2551551c` and `9dc2009f` implement Node SSE and database-tunnel forwarding and pin Engine `0.4.0` source `009b7393`. The Cloud design records real Node/client and tunnel development tests, while complete quality/platform, resource/timing and ingress qualification remains open. That local Engine pin must be replaced with the reviewed merged successor after its required interfaces land. Existing Cloud work must be preserved and reviewed before integration; a mock client route cannot close the real server requirement. No deployment or manual package publication is requested.

## Invariants and proof obligations

The design's ordered-history projection is the mathematical contract. Implementations must establish the actual registration and closing boundaries, independent cursors, exact value encoding, and visible termination before any skipped suffix. No adapter republishes a notification or changes transaction-local duplicate suppression. A new epoch after transport loss cannot claim continuity or replay. Extend the proof alongside the implementation that establishes each precondition; finite tests exercise those obligations but do not replace the argument.

Resource acceptance includes the original hub and durable registry, listener/channel ownership, each queued value, parser and transport buffers, and admission waiters. A bounded queue placed after an unbounded `entries_from` or destructive session drain is insufficient. Defaults require evidence for idle listeners, bursts, maximum escaped payloads and slow consumers. Timing qualification requires independent host-control/noise evidence for the measured margin; deterministic functional/accounted-resource checks do not establish that margin or a performance claim. Do not invent deployment defaults, weaken limits, or rerun uncontrolled measurements until they pass.

Use the existing single integration harness per crate and reuse established build artifacts. Run focused owner tests, strict Clippy, formatting and repository ownership/dependency checks for the actual change. PostgreSQL-sensitive behavior requires independent PostgreSQL 18 evidence. JVM tools run in Docker. CI remains responsible for its own runs and release publication; no manual dispatch, rerun, cancellation or package publication is part of this work.

The shared attempt owner now also supplies Node and Fetch with one set of readiness/idle budgets, decode order and terminal handling; each runtime owns its actual request and cleanup. All forty-six Node HTTP/package regressions pass after the extraction. The public browser HTTP package passes sixteen actual Chrome 153.0.8010.53 cases, including cross-origin bearer preflight, ambient credential/referrer omission, readiness and receive cancellation, strict metadata/encoding/UTF-8 rejection, redirect refusal, epoch-separated reconnection, real Retry-After backoff cancellation, slow/healthy subscriber isolation, authorization discard and idle expiry. Review and the first Chrome run exposed a mismatched random-function interface in the new Fetch adapter; the same reconnection case passes after correction. The reproducible verifier additionally checks generated-source/declaration identity, records content hashes and closes its browser and peer; its two verifier unit tests reject partial or failed evidence. Custom output packaging includes every required notification module. The existing automatic browser workflow now invokes this verifier; no workflow was manually dispatched. The [browser proof](../design/browser-notification-fetch.md) covers module packaging, exact event histories, shared budgets and actual Fetch cleanup. Direct WASM, full resource/platform and integrated qualification remain open; these sixteen browser cases are not the fifteen complete serving-path design cases. The Cloud owner must expose X-Request-Id, Retry-After and Content-Encoding and qualify identity encoding through its actual serving path.
