# Default B-tree admission

This is the focused #299 correction prepared separately from PR #911. It supports subsequent user-defined range work without implementing the operator-class declarations and families required by original record 69. ## Contract and ownership

SQL's `catalog/index/operator_classes.rs` resolves the default B-tree capability of a selected `ColumnType`. Core's total carrier order does not establish PostgreSQL index support. Domains select their base class but preserve their declared visible name for errors; arrays and composite records have generic classes without requiring a scalar class for every element or field. Included attributes require no key operator class. Existing UQA vector and tensor admission is preserved.

Key constraints, direct/expression indexes and stored-index revalidation use the same SQL rule. Missing classes report PostgreSQL SQLSTATE `42704`, its message and hint. Attribute resolution order precedes the final virtual/system-column restriction. Non-immutable expression diagnostics retain their earlier position. Execution owns the ALTER scheduling: after all selected column types have changed inside the statement transaction, it validates affected B-tree declarations before row rewrites. Engine only replays public provider and reopen histories. No dependency edge, Cargo feature, integration executable or storage format changes.

## Preservation argument

Let $T$ be the resolved SQL type domain and $D \subseteq T$ the types with a default B-tree operator class, together with UQA's established native vector and tensor key types. Define $A(t)$ by the SQL owner's exhaustive type selection, with $A(\operatorname{domain}(t))=A(t)$ and with generic array/record classes selected independently of their component types. This is declaration admission, not a proof that every pair of component values can be compared without a runtime error.

For an admitted key $t \in D$, validation leaves its selected type, values, comparison functions, equality keys, hash functions, physical representation and multiplicities unchanged. Consequently every previously valid comparison, index probe and relational composition receives the same inputs and invokes the same operations; its values, errors and state effects are preserved. Included attributes are outside the key tuple, so admitting an unordered included value cannot change key equality or uniqueness. The correction adds no algebraic operation and does not replace a value-level comparison failure with declaration rejection for a generic array or record.

For a rejected key $t \notin D$, SQL reports the missing-class diagnostic before index publication. ALTER validation runs within the existing statement transaction, after selected column types are visible but before converted rows are published, so its error restores the original schema and values; enclosing transaction/savepoint rules remain unchanged. The independent reference checks rejected DDL, retained JSONB type, savepoint recovery and committed state after fresh connections. These finite checks exercise the boundaries of the argument; they do not replace it.
