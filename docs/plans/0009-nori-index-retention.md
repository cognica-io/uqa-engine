## Ownership and completion requirements

- `uqa-storage::mvcc::serializable::liveness` owns local participant and receipt lease lifetime. Releasing the final handle must return the empty registry allocation without a subsequent transaction or explicit reclamation. Failed admission must release all reservations without taking SSI/provider admission during destruction.
- Core owns failure-atomic persistent map insertion. MVCC single-record updates must reuse unique private paths, copy shared snapshot/savepoint paths and reserve all required nodes before changing a root. Local lease payloads share their admitted participant allocation.
- `uqa-storage::inverted_index` owns in-memory corpus representation, mutation staging and retained-reader accounting. Remove redundant retained structures while preserving ordered postings, graph identity, source metadata, atomic batches, snapshots, cancellation and exact quota admission. Existing native allocation ceilings remain unchanged.
- The Nori benchmark targets and Python verifiers must support allocation/output checks without timing samples. CI must run analysis, indexing, phrase and both persistent-provider checks independently so one failure does not hide subsequent results.
- Acceptance requires existing output fingerprints, commit/rollback and reopen results, final-reader cleanup and the existing allocation ceilings. Runtime evidence uses Linux Docker. Generated diagnostics remain under ignored output directories or CI artifacts.

## Implemented and verified

- #141: replace reverse-term AVL sets with admitted ordered vectors, remove duplicate cached position projections, combine document metadata/reverse terms and per-field counters, and transfer staged posting nodes through Core's allocation-preserving append. All five indexing workloads pass the unchanged allocation ceilings and complete graph/metadata outputs, resolving all 17 original violations. Populated-batch retained allocation counts are 912/927 and 932/947 (observed/limit).
- #142: final local lease destruction releases the registry entry and unused capacity; participant construction precedes the list lock so failed publication can release safely. Inline local lease payloads, failure-atomic reuse of private tree nodes, shared analysis scratch and moving staged term owners also resolve the 12 allocation violations exposed after fixing the original 48-byte leak. All four native redb workloads pass their unchanged reviewed Linux x86_64 ceilings, zero private retention, and live/reopened outputs. Peak allocation counts are 11,463 / 3,864 / 3,935 / 3,935; total counts are 1,942,760 / 156,163 / 181,775 / 173,821.
- Analysis, indexing and phrase benchmarks support `--allocation-only`. Native CI independently runs analysis, indexing, phrase, SQLite and redb; WASM CI independently runs analysis, indexing, SQLite and phrase. Verifiers reject timing observations and baselines in this mode. All nine latest-source gates pass and every artifact report records `timing_compared: false`.
- Linux Docker owner coverage passes: 256 Core unit tests, 505 Storage unit tests, 244 Storage integration tests, 54 redb unit tests and 47 redb contract tests across their affected changes. Coverage includes shared snapshots/savepoints, failed quota admission, private node reuse, scratch lifetime/cancellation, binary vocabulary encoding, commit/rollback, final-reader cleanup and reopen. The verifier changes pass 95 Python tests and independent native/WASM workflow contract checks. Strict Clippy with both morphology features, formatting, dependency/Engine ownership, one integration harness, Rust headers and file limits pass.
