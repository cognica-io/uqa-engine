# Declared range comparison and exact keys

This is the selected comparison and equality-key consumer boundary of original record 65, following [physical observation](0018-declared-range-observation.md). SQL range, multirange, scalar, record and array comparisons now consume the selected endpoint comparator. Execution's exact, hash, reservation and spill consumers use the corresponding admitted exact endpoint keys. Definition-derived support selection, custom declarations, constructors, canonical routines and final provider/binding acceptance remain required; this unit does not publish those SQL features or complete record 65.

## Ownership and operation contract

SQL owns the shared range comparison algorithm and physical decoding. The native adapter supplies its existing subtype comparator; a declared range supplies a captured range identity and catalog-selected endpoint comparator. A custom physical Datum retains its own range identity even inside a changed field descriptor. Ordinary text and native carriers retain their existing rules; a native range identity still comes from a selected field or array element. Reading bounds does not rerun input, domain constraints or canonical routines.

The existing statement value catalog carries two explicit operations: compare admitted endpoints and produce an exact endpoint equality key. The latter must satisfy equality under the same selected operator class and collation; a hash or arbitrary physical encoding cannot substitute for that contract. Execution owns the eventual definition-derived key implementation and routine invocation state. Missing support fails explicitly. Engine only forwards the borrowed catalog capability and contains no comparison or encoding algorithm. No crate dependency, Cargo feature, stored format or native key encoding changes.

The implementation uses the existing range ordering for both native and declared values: empty first, then lower bound with its infinity/inclusion rules, then upper bound with its infinity/inclusion rules. Multiranges compare their normalized members lexicographically. Selected support failures retain their SQLSTATE and evaluation order; an empty or already decided comparison does not invoke a later endpoint operation. The range and multirange classes and physical families remain distinct.

## Preservation argument

Fix one statement catalog generation and a range identity $r$. Let $B_r$ be its selected endpoint comparator, with equivalence $a\sim_r b$ exactly when $B_r(a,b)=0$, and let $K_r$ be an admitted exact endpoint key satisfying $K_r(a)=K_r(b)\iff a\sim_r b$. These are obligations of the support owner, not properties inferred from an available hash or byte layout. A publication implementation must establish them for every selectable operator class and collation before enabling these consumers.

PostgreSQL 18 uses the selected bound comparator for [range equality and B-tree order](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/utils/adt/rangetypes.c). The SQL range comparator is the lexicographic extension of $B_r$ over emptiness, bound presence, lower value/inclusion and upper value/inclusion. Its infinity and inclusion branches are shared with the native implementation. Thus a total preorder for $B_r$ induces the same total preorder for ranges; transitivity follows from lexicographic extension. Multiranges repeat that construction over their ordered member sequence and compare length only after an equal prefix. No endpoint is reinterpreted under a native integer canonicalizer.

Execution frames the class, immutable range identity, emptiness, bound presence/inclusion and each $K_r$ with unambiguous lengths. Two framed keys coincide exactly when every component observed by SQL equality coincides. Applying the same framing to each ordered multirange member preserves that equivalence. Therefore exact deduplication, equality hashes, reservation identities and spill membership agree for supported ranges; a hash collision alone never proves equality. Induction over typed record fields and array elements extends the result to their existing container encodings. Native tags and bytes are unchanged.

This transformation refines how existing admitted values are observed; it neither changes document support nor tuple multiplicities, payload composition or ranked scores. Equality-based relational consumers partition inputs by the same selected equivalence classes. Ordered consumers preserve the selected lexicographic relation. Support exceptions and cancellation remain effects of the invoking operation, not new values in the carrier.

Endpoint decoding, callback output and key framing reserve from the original invoking allowance before allocating. Decoded bounds remain owned through comparison; each temporary endpoint key is released after it is framed into the output. Failure or either comparison cancellation drops all temporary reservations. Physical input ownership and final key ownership are unchanged. This is bounded memory and output evidence, not a timing claim.

## Independent evidence and remaining acceptance

The compact [PostgreSQL reference](../../crates/uqa-sql/src/expr/datums/inline/tests/ranges/comparison.json) contains 109 observations captured from PostgreSQL 18.4 in Docker, retaining collector/input hashes and image identity. It supplies actual catalog constant bytes and twelve 7-by-7 comparison matrices for enum, domain, C-collated text, integer array, composite and reverse-integer-operator-class ranges and multiranges. The reverse operator class ensures the selected order differs from the underlying integer order. Its changed-domain observation preserves the input counter.

SQL checks the 588 independent order/equality pairs in scalar, typed record and typed array consumers, for 1,764 observations, checking both typed consumers and all six SQL comparison operators. NULL operands stay unknown without invoking bound support. Execution checks those same equality pairs against exact, hash and reservation keys, then performs actual in-memory and spill deduplication for every family. The fixture support's admitted key writer is deliberately limited to these canonical endpoint values; it is not a production key implementation for arbitrary operator classes. Exhaustion, lazy support errors, cancellation and reservation/file release have separate assertions. The automatic regression inventory includes these four checks.

Full publication still requires definition-derived comparator/key support, all four type identities and independent generated constructors, selected canonicalization, every public range operator, lifecycle/dependencies and all-provider/reopen/language acceptance. The reference CREATE TYPE statements prepare independent expected values; these tests do not demonstrate that UQA executes those declarations. Final local and automatic Linux/macOS acceptance must be recorded against the delivered source before merge.
