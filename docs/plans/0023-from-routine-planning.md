## Preservation argument

Let $R$ be the caller's bag of rows, $Q$ the analyzed SQL body, and $a_i(r)$ the selected, coerced argument expressions. The supported rewrite substitutes each parameter at its original use site. For every caller attribute referenced by a used argument, the rewriter allocates a fresh opaque identity $\kappa_j$ and captures that attribute from $r$ before entering the body's scope. For the resulting capture environment $C_r$, freshness gives $C_r(\kappa_j)=r_j$ and prevents any inner table, alias or CTE from changing that lookup. Substitution therefore preserves every used argument observation:

$$
\operatorname{eval}(a_i,r)=\operatorname{eval}(a_i[r_j\mapsto\kappa_j],C_r).
$$

The captures contain attributes, not argument computations. An unused parameter introduces no capture or evaluation, a conditional expression keeps its conditional argument demand, and volatile or subquery arguments fail the eligibility check. The body is analyzed without caller CTE bindings, and its selected relation references are qualified before substitution, so a same-named caller CTE cannot supply or replace a body relation. Selected argument/result types and collations are retained, including assignment casts after body distinctness, grouping, ordering and set operations.

For eligible definitions, the function has the caller's snapshot and no strict, security-definer or configuration boundary to reproduce. Applying the argument identity above to each leaf of $Q$ preserves the rows seen by its existing filters, projections, grouping, windows, CTEs and set operators. Those operators remain in their current owners; the rewrite introduces no alternative equality, multiplicity, ordering or scoring rule. Consequently the lateral bag result remains

$$
\biguplus_{r\in R} \{r\}\times Q[a_i\mapsto a_i(r)].
$$

A complete physical descriptor binds without executing the body. Closed public SQL columns alone do not describe execution-owned score sources: derived retrieval outputs, including nested queries, views and CTEs, retain their existing runtime descriptor-binding boundary before consumers bind score expressions. Open descriptors for schemaless documents and native table functions acquire their runtime columns before downstream name and wildcard binding; their runtime discovery is not a closed-schema promise. For complete descriptors, the common deferred operator initializes its physical input once at the first pull, preserving the existing blocking/spill boundaries while allowing a parent that requests no rows to close it without effects. Planner simplification still sees the substituted body and reports PostgreSQL's immutable constant errors before execution. Physical scope overlays retain outer values at nested query boundaries, and positional output shaping preserves declared columns and lock origins. No document support, payload merge, probability or ranking operation is added or changed.

For a declared derived output, let $p_i$ select the producer’s logical column for analyzed output column $i$, and let $s(p_i)$ be that column’s physical input slot. The output projection assigns slot $i$ the existing value at $s(p_i)$, or SQL NULL for an absent slot. Thus $\pi_b(r)_i=r_{s(p_i)}$ for every present slot, including repeated $p_i$, without reevaluating expressions or copying payloads. The analyzed descriptor supplies the same selected type, collation and record-field semantics used to bind the consuming query. Each retained score source keeps its opaque identity and qualifier, and its physical value is appended outside the public columns under that identity. Therefore score lookup observes the same value and ambiguity before and after projection, including when a source is rebound to a derived alias. Internal lookup aliases and score attributes do not become public columns; physical lock origins are retained independently. This projection preserves row order and multiplicity. Its per-row work depends on the public output width plus the selected score slots; one-time descriptor construction depends on schema width. Neither operation copies payloads.

Diagnostic decoration maps a primary error $e$ and its ordered frame sequence $c$ to $(e,c)$. Appending an enclosing frame is sequence concatenation: its identity is the empty sequence and its associativity preserves inner-to-outer call order. SQLSTATE, primary text, DETAIL, HINT, position and the typed cause project unchanged from $e$. Each procedural activation contributes its innermost failing statement once; a handler starts a fresh frame lifetime, while bare RAISE returns the saved pair. Cancellation matching uses the primary typed cause. This makes diagnostics observable without changing exception selection, rollback or cancellation handling.
