# Selected record image comparison and exact keys

This is one SQL-owned prerequisite for original #638 record 65's selected range support. PostgreSQL's `record_image_ops` observes field storage, including distinctions that ordinary value equality deliberately removes. The implementation is prepared after the separate #946, #948 and #949 corrections; it does not publish range declarations, an operator class, generated constructors or a public support routine.

## Ownership and behavior

SQL reuses the existing record walker for live attribute identities, NULL handling, reached-field diagnostics and delayed arity checks. Image comparison skips the ordinary field-operator availability check because PostgreSQL admits images of fields such as JSON without a value equality operator. Ordinary record comparisons still request and validate their existing field operators. The new operation uses the existing controlled SQL Datum codec, including physical-byte views, rather than introducing a second representation or performing input, domain checks or canonicalization.

Corresponding non-NULL fields of the same selected type compare as unsigned Datum words when passed by value and as storage bytes when passed by reference. Variable-width images exclude their outer storage header. The existing reader admits physical outer tuples and retains each field's image. Both cancellation scopes and all decoding/encoding allocations use the supplied production control; borrowed and inline images do not acquire an output buffer. SQL now exposes borrowed field images through a controlled visitor. Execution frames those images in its existing exact-key owner; selected range dispatch remains open.

## Preservation argument

For a fixed reached field type $T$, let $I_T(v)$ be the existing admitted Datum image of $v$. The by-value operation compares the unsigned fixed-width word; the by-reference operation compares its byte sequence lexicographically. Each is a total order on its admitted images, so $I_T(a)=I_T(b)$ exactly when the selected field comparison returns zero. Numeric scale, signed floating zero and other image distinctions are intentionally preserved even when ordinary SQL equality identifies the values. NULL adds one greatest element, matching PostgreSQL's record-image rule.

For records with corresponding field identities, the operation is the lexicographic product of these field orders. Thus antisymmetry and transitivity follow from the first unequal field, and equality requires equal images at every live position. The shared walker preserves PostgreSQL's partial diagnostic domain: a deciding earlier field suppresses later type, byte and arity errors, while a reached type disagreement precedes observing that field's bytes. This argument does not substitute image equality for ordinary value equality. Execution's corresponding key frames each field identity, NULL presence and byte length, then the live field count, reusing its existing length/byte writers. For one selected comparable field-identity domain, injectivity of the framing and the image order establish $K(a)=K(b)\iff\operatorname{imagecmp}(a,b)=0$. Consequently hashes of equal keys agree and exact membership preserves the same classes through spill. These bytes are not an order-preserving key or a change to existing durable encodings.

The production owner bounds each temporary image before allocation and retains its lease until that field has been compared. Decoded outer tuples retain their existing controlled owner until comparison exits. Success and every error path drop both fields' scratch and all decoded owners. Byte comparison checks cancellation between bounded chunks without copying borrowed payloads. Existing persistent encodings, default operator classes and dependency direction remain unchanged; this unit does not add a public SQL entry point.

The shared codec also corrects [#954](https://github.com/cognica-io/uqa-engine/issues/954), where reading a stored `int2vector` or `oidvector` composite field failed with `0A000`. Both vectors already use the existing array carrier and fixed integer element types. Their encoder delegates to the controlled array encoder; their reader validates the selected element OID and vector header before transferring the ordinary array decoder's owned result into the existing vector carrier. Let $E_T$ and $D_T$ be those existing array operations for the vector's fixed element type $T$. For an admitted vector $v$, the wrappers preserve its kind, dimensions, lower bounds and elements, so $D_T(E_T(v))=v$ without changing its ordinary comparison or output rules. A wrong element identity fails with PostgreSQL's `42804` diagnostic instead of being reinterpreted at the wrong width. Existing bounded-read errors and both cancellation scopes remain in force, and the decoded result retains the same memory lease through the wrapper.
