## Ownership and input contract

SQL's existing B-tree metadata owns class, input and support-function identities. The new borrowed binding validates the selected class's input using SQL's existing cast catalog. It removes domain wrappers for compatibility only, accepts the existing generic array/record/enum/range families and otherwise requires an implicit binary cast. A function cast, even an implicit one, is insufficient. The bound result retains references to the original declaration and actual selected class, including modifiers and domain identity. It performs no value conversion, input function, domain constraint or canonical call. Execution consumes this binding through the selected binary-key adapter; stored range support invocation remains separate; Engine remains the catalog/session adapter.

Independent PostgreSQL declarations establish that integer can select `oid_ops`, varchar can select `bpchar_ops`, and oidvector can select `array_ops`. These accepted alternatives have different observable order or equality from their default class. Invocation must consequently use the selected class's binary input interpretation, and exact-key generation must preserve that same selected equality. Merely accepting the declaration and then using its default comparator would be incorrect.

## Preservation argument

Let $T$ be the declared subtype, $b(T)$ its type after removing domain wrappers, and $I_C$ the input identity of selected class $C$. Binding succeeds precisely when $b(T)$ has identity $I_C$, belongs to the existing generic family represented by $I_C$, or the shared catalog records an implicit binary cast $b(T)\rightarrow I_C$. These are alternative identity-preserving admission rules; they neither execute a coercion function nor infer another class. The binding returns the original pair $(T,C)$, so projecting either component recovers the exact supplied reference. In particular, modifier removal for an identity check does not mutate the retained declaration, and domain unwrapping does not remove its later input obligations.

The input binding alone introduces no value operator, order, equality, stored representation or algebraic rewrite. Existing comparisons, grouping partitions, hashes and range construction therefore remain unchanged. The observation and binary-key argument below proves, within its stated domain, that its selected interpretation $J_C$ and exact key $K_C$ satisfy $K_C(x)=K_C(y)\iff\operatorname{cmp}_C(J_C(x),J_C(y))=0$ on the admitted comparable domain; this input binding does not assert that property for a class merely because metadata exists.

The result contains two borrowed references and allocates no retained state. Direct and generic identity checks allocate nothing. A cast lookup uses the existing controlled SQL name producer and releases both temporary names before returning. Each domain-unwrapping step checks both cancellation owners. Success, incompatibility, cancellation and allocation failure retain no scratch after returning. The operation invokes no callback and observes no values, so it introduces no state effects or repeated input behavior.

## Selected input observation and exact keys

SQL's `with_btree_input` interprets an already admitted value using the selected class, without rerunning type input, domain constraints or canonical support. A physical scalar is observed with the selected input OID at the original retained offset. Fixed-width logical scalars reuse the physical Datum bit reinterpretation owner. Character input uses the padded-character carrier under the caller's allowance. The generic array class borrows an ordinary array or the array inside a catalog vector; physical array observation follows the actual array header. A native vector class retains its atomic vector behavior. Record-image selection delegates to the independently verified image owner. A callback cannot retain borrowed decoding scratch beyond the call.

Let $D_{T,C}$ be the already admitted values of declared type $T$ accepted by selected native class $C$, with physical and logical representations of the same value identified. Let $J_C$ be the observation just described and let $\preceq_C$ be the selected support's preorder on its defined comparison domain. This change adds an adapter, not another relation: its observable comparison is exactly $x\preceq_C^T y\iff J_C(x)\preceq_C J_C(y)$. Reflexivity and transitivity on that domain follow by substitution from $\preceq_C$; equivalent representations have the same $J_C$ observation. The declared output/type identity remains $T$, so selected ordering does not substitute a type's input/output or rerun admission. A diagnostic or cancelled operation is outside the successful relation and retains its existing error contract.

Execution's binary-key entry point is restricted to one selected class, fixed field-type identities and collations whose equality is byte-preserving. It composes $J_C$ with the existing exact scalar, array or record-image encoder $E_C$: $K_C=E_C\circ J_C$. Scalar normalization is the existing typed-key normalization of the selected input, including unsigned OID bits and trailing ASCII-space removal for bpchar. Array framing retains dimension lower bounds and element count; each element uses the existing declared-range or native equality owner. Record-image fields retain the image encoder's NULL, identity and byte framing. These encoders distinguish the same equivalence classes as their corresponding comparison on the fixed domain, hence $K_C(x)=K_C(y)\iff J_C(x)\sim_C J_C(y)$. In-memory and spill sets compare complete key bytes, so they induce the same partition. This proof does not authorize these binary keys for a nondeterministic collation, or establish executable support merely from class metadata.

The existing array header sequence is extracted without changing any byte, so ordinary array equality keys and hashes remain unchanged. The fixed-character correction in #956 shares Core's normalization instead of scanning unchecked in Execution. For a string $s$, both implementations return its maximal prefix after removing the suffix consisting solely of U+0020; this preserves all successful comparison and encoded bytes. The shared helper adds an entry check, checks at most 4,096 scanned bytes apart and checks before returning, uses no allocation and borrows the original prefix. Cancellation after the key tag is therefore observed before a padding scan or subsequent output. No ranked score, document support, payload composition or optimizer rewrite changes.

Borrowed scalar/vector/record observations allocate no new carrier. A physical decode or varchar-to-bpchar carrier keeps its admitted lease until the callback completes; all errors release temporary ownership. Output-key capacity remains charged to its returned owner, and failure releases partial output and scratch. Independent PostgreSQL fixtures cover the selected input differences and existing exact-key tests cover adjacent numeric, range, array and record-image behavior. Full selected collation invocation, native class dispatch and user-defined range publication remain separate work.
