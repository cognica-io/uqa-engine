# Shared row layouts and owned value transfer

The maintainer requested all four follow-ups from the comparison of `jaepil/rapidjson` shaped rows (`fdbe7620342c30f528c5ccdcccc75de9aba48e26`) with UQA main `16533ee6d1aa7636075b97c43ae5a54badcfe1e4`. UQA already shares SQL schemas, physical value fragments and memory document layouts. This work removes repeated metadata and value copies at their owning boundaries while preserving UnifiedPlan, SQL semantics and persistent formats.

## RapidJSON comparison

The reviewed source is [jaepil/rapidjson at fdbe762](https://github.com/jaepil/rapidjson/tree/fdbe7620342c30f528c5ccdcccc75de9aba48e26), specifically [the design](https://github.com/jaepil/rapidjson/blob/fdbe7620342c30f528c5ccdcccc75de9aba48e26/doc/shapedrow.md), `shape.h`, `shapedvalue.h` and `shapeddocument.h`. Its shape owns ordered names and a collision-checked name index; each row owns positional values, a presence bitmap and optional ordinary-object overflow. Reusable parsing writes root fields into those slots, while nested values remain ordinary JSON values. The principal transferable idea is resolving metadata once for many values, rather than replacing one per-row name lookup with another.

| Concern | UQA before these changes | Application in this delivery |
| --- | --- | --- |
| Shared names and positional execution | SQL `RowSchema` and Execution `PhysicalRow`/fragments already separate schema from values; UnifiedPlan is unchanged. | Keep these owners and remove value-copy overhead at columnar output (#1254), including the shared-scan correction #1261. |
| Direct root-field decoding | Persistent projected reads could rebuild selected field-name maps; native SQLite already had eligible decoded-column cache hits. | Decode into positional values plus explicit presence under the existing legacy/V1/V2 validation and provider snapshot contracts (#1255). |
| Shape discovery and repeated projections | Memory documents already had layout IDs and shared value vectors, but layout search and projection construction repeated metadata work. | Index exact ordered layouts and retain only the current read projection, compiling mappings only for encountered layouts (#1256). |
| Composite metadata | Named records repeated field strings and anonymous rows repeated type descriptors. | Core descriptors share immutable metadata through real SQL/Execution producers and result conversion; values stay independently mutable (#1257). |

RapidJSON's shapes and optional interned strings are non-owning pointer relationships whose lifetime must be enforced by their caller. UQA's returned values, snapshots and retained tuples can outlive a catalog generation, so immutable reference-counted owners and explicit logical memory admission are required. A shape pointer is not SQL type identity, and field absence is not SQL NULL. Heterogeneous document fields and nested maps keep their existing semantics; SQL output must still preserve repeated labels and positional aliases. No C++ dependency, global string intern pool, new algebraic operator or persistent-format migration is introduced.

The fork's published timings concern its own C++ workloads and allocator conditions and do not establish a UQA speedup. UQA qualification separately checks output, work/allocation bounds, provider lifetimes and controlled timing. The #1261 regression is evidence that reducing payload copies alone does not establish lower cursor latency.

## Ownership and preservation

Execution owns materialization and cursor transfer; SQL owns names, ambiguity, types and slot mappings. Storage owns projection and decoding; providers supply snapshots, bytes and compound-value hydration. Core owns composite descriptors without a SQL/catalog dependency. Engine supplies session, transaction and retained-resource adapters.

Preserve output order, duplicate labels/slots, missing fields versus NULL, present all-NULL records versus absent outer-join rows, types/collations, diagnostics/evaluation order, cancellation, memory accounting and snapshot ownership. Storage changes retain existing bytes and reopen behavior. Composite changes retain descriptor identity across DDL, rollback and delayed reads, including the approved XX001 owned-tuple boundary.

## Owned columnar conversion argument

Let a batch contain ordered rows \(r_0,\ldots,r_{n-1}\), logical-to-physical mapping \(s\), and output-label occurrence resolution \(p_j\). Its transfer observation is \(C_j[i]=r_i[s(p_j)]\), or SQL NULL for an absent position. Consuming conversion must preserve every value and \(n\), including zero-column rows.

An immutable shared owner permits an observationally equal clone. An exclusive owner can move a value on its last selected occurrence; earlier occurrences receive clones. Count occurrences after schema and fragment projections so aliases cannot move a value prematurely. Unselected values are dropped without evaluation. Therefore every \(C_j[i]\), duplicate position, row order and cardinality is preserved. No expression is evaluated and no algebraic operation changes. Shared owners remain unchanged; moved allocations belong to their output columns. Tests cover identity/remapped layouts, shared/projected fragments, duplicate labels/slots, missing positions, empty batches and zero-column rows.

A single-fragment scan row with another live value owner cannot donate its payload. Its shared transfer emits each requested position directly through the existing fragment projection, including missing and duplicate positions, so it has the same observation as borrowed lookup without rebuilding a routing vector. Releasing that consumed row immediately preserves the opportunity for a later final owner to donate. The exclusive and joined-alias paths still use the consuming argument above.

## Positional decoding and layout preservation argument

Let \(D\) be the historical field decoder after its ordinary validation, duplicate-key normalization and typed-value conversion, and let \(S=(s_0,\ldots,s_{m-1})\) be the requested names. The positional representation retains one value for each selected distinct name and a mapping \(P_i\) to that value, or an absent sentinel when \(s_i\notin D\). Consequently reading position \(i\) returns exactly \(D[s_i]\) when present; an explicit NULL has a real slot and remains distinguishable from absence. Repeated names share a slot without changing positional observations. The legacy fallback retains the original complete validation and sorted surviving-member conversion order, even for unselected fields; the canonical primitive path retains its historical skipped-string and checked-number rules. Neither legacy path emits a root field-name map. Modern codecs use Core root field visitation in input order, including conversion of every overwritten or unselected value before later syntax is read; repeated stored names replace values and release their old leases. V2 envelope/metadata validation and legacy xmin migration retain their original order. Native compound hydration retains sorted field-name diagnostic order even for reversed projections, and resumed cache pages rebind requested positions before moving values. A failed decode publishes no row, and the producer's allowance remains attached to all selected buffers and payloads.

Memory layout lookup hashes the exact ordered names, then checks actual names and width in the selected bucket. Hash equality alone never establishes identity, so collisions cannot combine different layouts. Immutable field-name arrays can be shared across cloned indexes; each index keeps its own ID mapping and additions. Values remain ordered by the same BTreeMap iteration used by the prior implementation. Thus identity selection, field lookup and snapshot observations are unchanged while lookup examines only candidate layouts.

A memory read owner retains one requested projection; an active page independently retains its mapping through callback reentry. Layout IDs remain stable while the owner appends or replaces rows, and clear resets both the row/layout state and projection cache before IDs can be reused. Clones and snapshots start independent projection caches over their own immutable layout identities. For selected names \(S\) and encountered layouts \(L_{\mathrm{read}}\), retained mapping state is bounded by \(O(\sum_{s\in S}|s|+|S|\,|L_{\mathrm{read}}|)\), independent of row count. Each slot is compiled by the same exact field-name lookup as before; absent sentinels, duplicate positions and shared value owners are unchanged. Replaced cache metadata survives only in active pages, and returned shared rows retain their own slot/value owners. No cache lock spans a visitor.

## Composite descriptor implementation boundary

Core owns immutable named-field descriptors and anonymous field-type descriptors, plus positional values. SQL continues to choose the descriptor, type identity and validation point; Execution retains it with the existing prepared expression or row-schema owner. Retained descriptors must never borrow a live catalog or use an unbounded global intern table. Actual repeated constructors must share their metadata; changing only Clone without connecting producers does not complete #1257.

The predecessor named RecordValue exposes a mutable Vec of owned `(String, Value)` pairs through Deref. That representation cannot share field names while retaining direct mutable access to each String. Keep explicit owned constructors and consuming conversions, introduce explicit positional/borrowed field access, adapt internal callers, and document the necessary Rust source migration. Do not hide payload copies or unbudgeted allocations behind immutable access. SQL and serialized field names, order, duplicates, type identity and values remain unchanged.

Let a named record observation be \(R=((n_0,v_0),\ldots,(n_{m-1},v_{m-1});\tau)\). A descriptor \(D=(n_0,\ldots,n_{m-1};\tau)\) and value vector \(V=(v_0,\ldots,v_{m-1})\) encode it, with decoding \(E(D,V)=R\). Width equality is a construction precondition. Because \(E\) is pointwise and ordered, field reads, ordered serialization and every existing comparison/key operation composed with \(E\) preserve their observations. Duplicate field names remain separate positions. Descriptor allocation identity is never equality, ordering, hashing or catalog identity. An absent composite remains an outer Value::Null; a present all-NULL or zero-field record remains a record.

For anonymous rows, \(D\) additionally retains exactly the existing optional sequence of OIDs, typmods and collations. Sharing immutable \(D\) changes no metadata value. Replacing values must preserve width; changing a descriptor creates another immutable owner. Cloning a value retains \(D\), so DDL, rollback or catalog replacement cannot mutate an earlier descriptor. SQL's existing lazy tuple interpretation and approved XX001 owned-tuple bound remain the authority for field access. No algebraic operation, approximation or optimizer rewrite is introduced.

Anonymous `RowDescriptor` owns a compact immutable field-type slice. Cloning rows or making a controlled value copy shares that allocation; mutable value buffers stay independent. Every admitted row still charges its logical descriptor bytes, so physical sharing does not weaken existing quotas. Compacting a newly produced descriptor reserves its destination before allocation and keeps the source vector admitted until conversion ends. `into_parts` returns independently mutable owned metadata; `into_shared_parts` keeps the descriptor without copying.

Verification must cover allocation identity and repeated producer sharing, exact JSON/binary encoding, equality/hash/index keys, NULL and duplicate positions, cancellation and retained-memory admission, prepared/retained tuples across ALTER TYPE/drop/rollback, and provider reopening. Record and Row production, copying, retained-size traversal and language bindings must be reviewed together; sharing cannot leave an allocation uncharged or weaken existing admission limits.
