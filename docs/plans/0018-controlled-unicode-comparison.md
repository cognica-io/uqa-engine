# Controlled Unicode comparison

This unit implements the native SQL-owned comparison needed by original #638 record 65 after selected B-tree input binding and retained record-field collations. It does not publish user-defined range declarations or claim that every SQL comparison consumer already passes its selected collation. Those integrations remain recorded in the parent plan.

## Ownership and configuration

SQL owns `compare_unicode_with_control`, the pinned root collation data, decomposition and contraction interpretation, and deterministic byte tie-breaking. Core owns borrowed byte comparison and inline production scratch through the existing admitted buffer owner. Engine receives no new algorithm or dependency edge. Runtime workspace dependencies and their direction are unchanged; external ICU data dependencies and enabled compiled-data features are explicit in Cargo manifests and the lockfile.

UQA's database default is builtin `PG_UNICODE_FAST` with C locale names. That default remains a byte-order selection. The separate `unicode` identity selects deterministic ICU `und` at tertiary strength with normalization checking disabled, matching PostgreSQL. Per-scalar decomposition is required for compact data lookup, but the implementation must not globally reorder combining marks. PostgreSQL returns a different sign for `a` followed by U+0301/U+0323 versus `å` when normalization is explicitly enabled. This distinction is a tested compatibility requirement, not an optional approximation.

The owner adapts the pinned ICU4X element algorithm because its public comparator neither admits private scratch nor preserves PostgreSQL's normalization-off selection. Source and data identities, licenses and independent fixture provenance are [recorded beside the implementation](../../crates/uqa-sql/src/expr/collation/PROVENANCE.md). Tailored locales, nondeterministic equality, other strengths and numeric collation are outside this fixed built-in entry point; callers must not use it for another catalog selection.

## Ordering argument

For a finite valid UTF-8 string $s$, the pinned root mapping produces finite primary, secondary and tertiary weight sequences $P(s)$, $S(s)$ and $T(s)$. The input/decomposition and contraction walk depends only on $s$ and immutable selected data; it does not inspect the other operand. Each level omits its zero weights and retains the original order of the remaining weights. Canonical scalar decomposition uses the acyclic pinned Unicode tables; the input sequence of combining scalars remains unchanged by normalization checking.

The comparator is lexicographic order on $(P(s), S(s), T(s), B(s))$, where $B(s)$ is the original UTF-8 byte sequence. Lexicographic products of total orders are total and transitive. The final byte component makes equality equivalent to $B(a)=B(b)$, including canonically equivalent but byte-distinct inputs. Therefore consumers in this fixed deterministic domain can retain their existing byte equality keys. Blank-padded character trimming remains the selected SQL input owner's responsibility. This argument defines the implemented algebra; finite PostgreSQL comparisons verify compatibility examples and are not substituted for the argument.

## Resource argument

Every input-dependent buffer uses `ProductionSmallVec`, whose controlled mode delegates heap growth and old/replacement capacity accounting to Core's existing `BudgetedSmallVec`. Ordinary and controlled calls share the same mapping. Copy-only elements have no hidden owned payload. The fixed inline capacities bound stack storage; each spilled capacity remains charged until its complete buffer is dropped. Quota failures propagate before allocating an unadmitted replacement, and every temporary owner is released on success, cancellation and error.

Consuming a buffer prefix advances an offset instead of repeatedly moving its remaining suffix. Capacity is reused by a controlled compaction only when a subsequent append fills the physical buffer. Insertions into an existing consumed prefix also reuse that space. This eliminates repeated front-removal copies while retaining original element order. Cancellation during scratch movement can leave partial scratch contents; callers propagate the error and discard that scratch, whose capacity reservation remains attached throughout.

Both cancellation scopes are checked while reading input, walking decomposition/expansion and contraction branches, moving scratch, producing collation elements, comparing buffered levels and observing the byte tie. Borrowed byte comparison checks at bounded 4,096-byte intervals. Immutable provider lookup uses baked static data. No detached worker, host ICU library or uncontrolled complete-string comparator bypasses the caller's allowance.
