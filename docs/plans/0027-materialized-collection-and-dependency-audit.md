## Borrowed final result collection

The next #653 correction follows the retained owner profile and source trace: a native memory scan acquires shared ownership of values and projection metadata for each row, pure projection/selection only relabels the physical slots, and the complete public collector immediately copies selected values and releases those owners. Execution now exposes an opt-in complete native accumulator through its existing physical operator and row-source interfaces. The new Storage capability visits stable decoded shared fields without per-row ownership; an unsupported provider declines before visiting any row. Fallible decoding, command overlays and arbitrary host callbacks retain the ordinary path. No new UnifiedPlan variant, Engine algorithm, public result format or persistent representation is introduced.

Only an unranked sequential source with an identity base projection, no appended metadata, virtual value materialization, lock origins or pinned rechecks may accept. Computed-expression-free Project and noncompacting ColumnSelection may forward the same final accumulator; all other operators decline by default. The accumulator is a concrete Execution-owned value copier, not an arbitrary callback under a storage read guard. The original statement cancellation token is checked between bounded pages, including pages rejected entirely by a predicate. Exact encoded-row sizing reuses the existing codec instead of estimating sizes or allocating a temporary physical row. Final public SQLResult ownership remains its documented complete materialization; this does not turn it into a bounded-result API.

For ordered source rows $R=(r_1,\ldots,r_n)$, let $p$ be the existing pure projected predicate and $M_S$ the existing final schema's named/positional materialization. Both paths produce $[M_S(r_i)\mid p(r_i)=\mathrm{true}]$ in source order. Storage supplies the same requested fields, missing values become SQL NULL at the same slots, and the final immutable schema selects the same physical positions, retaining all duplicate positional values for the unchanged public compatibility-key conversion. The new path removes only intermediate shared ownership and PhysicalRow construction. Predicate and encoded-size errors occur before the row is appended; any failure discards the complete result and invokes the original close/error-combination boundary. Providers with fallible page preparation cannot opt in, so moving predicate evaluation inside a storage borrow does not reorder a provider error that the ordinary page would report first. The same physical plan, statement generation, serializable relation observation and transaction boundary remain in force.

## Ownership and preservation argument

Execution owns consumer demand and physical scheduling. Core values, SQL name/type analysis, Storage interfaces and Engine session/transaction adapters need no new algorithms. `QueryRowConsumer::input_demand` defaults to singleton demand; a complete consumer without per-row observable effects or failures may permit batching. `PhysicalOperator::supports_batched_consumption` independently defaults to false. Only a certified producer and an exhaustive effect-free consumer together allow ordinary native batches. Custom RowSource adapters have the same conservative default. Slot-only projections propagate their child's guarantee; computed projections do not. Ordered iterator sources invoke the same iterator sequentially. Ordinary stored-column table sources evaluate predicates in row order; the single-table scored-document adapter opts in only for an unpinned, unlocked All scan without generated fields or tuple-xmin projection; virtual-generated projections and command/candidate partition reads retain singleton scheduling. This avoids a second expression classification or binding pass. Directional and inner LIMIT/cardinality paths retain their existing demand.

Let T be the ordered observable trace of SQL evaluations, effects and the first reached error, and R the ordered rows before that error or exhaustion. Producer eligibility requires equality of T and R under native versus singleton output partitioning. This is stronger than equal row order: a filter over a later failing row can otherwise run before an earlier row's projection. A row-sensitive consumer keeps singleton demand, so the same prefix and first consumer error remain observable. An eligible complete consumer introduces no interleaved SQL effect or error, and folds rows by ordered concatenation. Given producer eligibility, changing the partition of R preserves values, types, duplicates, names, ordering, row count and T. No new algebraic operator, approximation or optimizer rewrite is introduced.
