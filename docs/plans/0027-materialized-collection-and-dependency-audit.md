## Ownership and preservation argument

Execution owns consumer demand and physical scheduling. Core values, SQL name/type analysis, Storage interfaces and Engine session/transaction adapters need no new algorithms. `QueryRowConsumer::input_demand` defaults to singleton demand; a complete consumer without per-row observable effects or failures may permit batching. `PhysicalOperator::supports_batched_consumption` independently defaults to false. Only a certified producer and an exhaustive effect-free consumer together allow ordinary native batches. Custom RowSource adapters have the same conservative default. Slot-only projections propagate their child's guarantee; computed projections do not. Ordered iterator sources invoke the same iterator sequentially. Ordinary stored-column table sources evaluate predicates in row order; the single-table scored-document adapter opts in only for an unpinned, unlocked All scan without generated fields or tuple-xmin projection; virtual-generated projections and command/candidate partition reads retain singleton scheduling. ExternalSort and its Sort wrapper retain their existing blocking evaluation boundary and declare the completed output eligible. Post-sort assembly uses the projection owner's already-prepared layout: a nonempty computed-expression vector retains the RowAtATime boundary, while a slot-only projection preserves the child's native batches. This avoids a second expression classification or binding pass. Directional and inner LIMIT/cardinality paths retain their existing demand.

Let T be the ordered observable trace of SQL evaluations, effects and the first reached error, and R the ordered rows before that error or exhaustion. Producer eligibility requires equality of T and R under native versus singleton output partitioning. This is stronger than equal row order: a filter over a later failing row can otherwise run before an earlier row's projection. A row-sensitive consumer keeps singleton demand, so the same prefix and first consumer error remain observable. An eligible complete consumer introduces no interleaved SQL effect or error, and folds rows by ordered concatenation. Given producer eligibility, changing the partition of R preserves values, types, duplicates, names, ordering, row count and T. Each physical batch is consumed and released before the next pull; the final API still owns O(N) result rows. Native workspace/cancellation boundaries and existing cleanup paths remain. No new algebraic operator, approximation or optimizer rewrite is introduced.

## Public-output observation follow-up

This correction applies to callers that explicitly render public SQL output, including `sql_batch_with_labels` and the host query API. The canonical analytical `uqa_scan` benchmark instead calls raw `Engine::sql`; that entry point does not invoke this output renderer. The deterministic improvement below therefore establishes less work at the host-output boundary, not a correction of the remaining canonical materialized timing. Direct collection and the historical #653 cause remain separate investigation requirements.

Draft [PR #1268](https://github.com/cognica-io/uqa-engine/pull/1268) preserves the completed #1267 evidence and continues with SQL-owned carrier inspection. The existing public-output boundary separately walks every value to find deferred Datums and enum carriers. Two pre-correction local cases fail: 16,384 ordinary scalar values receive 32,768 inspections, while one 4,096-element list receives 8,194 inspections instead of 4,097. Output remains exact, the list retains its original allocation and the output call allocates nothing; the reproduced defect is repeated traversal. Test-only counters record actual recursive visits in both existing inspectors. No timing experiment is used to establish this work amplification.

The correction uses one SQL-owned traversal for the existing Datum and enum inspectors and the combined public-output observation. The combined observation records encountered enums and stops at the first Datum, retaining the old presence check's lazy boundary. It then completes the original Datum-reading phase before any enum-label rendering; if no enum was previously seen, decoded output is inspected because a Datum may introduce one. Ordinary output has one visit per scalar or native container node, while no output payload is copied or allocated by inspection. Six owner regressions cover work counts, retained buffers, repeated-label named/positional output, nested descriptors and array bounds, decoded enum OIDs, first-error order and partial-result state. Final local verification and source review are complete: all 2,240 SQL unit and 72 integration cases pass without failures or ignored cases, and strict SQL library/integration Clippy passes. The scalar and nested work bounds are now 16,384 and 4,097 visits, respectively; the early failing Datum inspects only its two reached nodes. Formatting, workspace dependencies (110 runtime edges / 34 crates), Engine capabilities (3,207 files / 124 adapters), integration registration (230 sources / 23 targets), the Rust file ceiling and the 1,746-check / 2,451-case regression inventory pass. Automatic final-source and controlled qualification remain required.

Preservation follows the original ordered value traversal. Without a Datum, the single walk visits exactly the same native child values as the old Datum check; its recorded enum flag is the result of the old subsequent enum-presence check. With a Datum, it stops at exactly the old Datum check's first match and performs the unchanged complete decoding phase, so a malformed first Datum does not inspect later values first. Any already observed enum survives decoding unchanged; otherwise the decoded value receives the original enum check. The same rendering function runs only after successful decoding, and assignment still occurs at each original phase boundary. Named/positional row order, values, metadata, first errors and retained state after failure are therefore preserved. No SQL expression, type input, permission check or algebraic operator is added, removed or reordered; timing improvement remains subject to the original controlled comparison.
