## Ownership and dependency decisions

The current manifests, dependency policy, public manual, native result/parameter/transaction contracts, existing binding manifests, and callback interfaces are the implementation baseline. `uqa-ffi` owns C layouts, pointer validation, diagnostics, lifetime/admission adapters, and callback trampolines. Engine owns sessions, transactions, retained resources, prepared identities, and shared registration lifetime adapters. SQL owns type interpretation and value observation; Execution owns query scheduling, prepared execution, and callback finalization. Core supplies existing memory reservations and value producers; SQLite owns encryption/compression options. Shared Arrow conversion belongs to `uqa-api`. No owner depends back on FFI.

The Cargo target is `uqa` and emits native shared/static libraries directly with that name. FFI does not emit a Rust `rlib`, so the public Rust facade keeps its existing `uqa` target without an output collision. Owner tests use the single FFI library harness; native C/C++ fixtures execute against the separately built C artifact. Default dictionary features and independent FDW/export features follow the design. Existing unrelated work in `tests/parity/pg18/README.md` is outside this implementation.
