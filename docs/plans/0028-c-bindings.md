# Embedded C binding implementation

Status: implementation in progress on `feature/c-bindings`, based on `5e9863beac6ce0bb72e7de60844e1f29546a86b8`. The [C binding design](../design/c-bindings.md) defines the requested interface. No C runtime release, completed qualification, or delivery is claimed by this ledger.

## Scope and accepted requirements

Implement the full embedded C interface: configuration and sessions, SQL messages and atomic request batches, typed positional results and exact values, native prepared statements, bounded cursors, transactions, cancellation, COPY, independent notifications and SQL notices, scalar/table/aggregate UDFs, host logging, optional Arrow export, packaging, and the five public C examples. Preserve the documented native transaction, catalog, resource, callback, and error contracts.

All functions return `uqa_status`; pointer typedefs represent opaque handles; ordinary string inputs are `const char *` with length-bearing alternatives. Diagnostics remain library-owned and require no caller destruction. Resource-first names, matching lifecycle operations, matching getter/setter properties, and explicit scalar/table/aggregate registration names are required. Every public declaration includes the actual `UQA_API` and `UQA_CALL` definitions. The design document contains no external product comparison. Preservation proofs are omitted at the maintainer's request.

SQL execution accepts the native SQL message, including multiple statements and empty input, and returns the native final result. Batch entries can also contain multiple statements. C must not add parsing restrictions, split text, replay statements, or change implicit/explicit transaction boundaries. Prepared and cursor entry points retain their own native contracts.

## Ownership and dependency decisions

The current manifests, dependency policy, public manual, native result/parameter/transaction contracts, existing binding manifests, and callback interfaces are the implementation baseline. `uqa-ffi` owns C layouts, pointer validation, diagnostics, lifetime/admission adapters, and callback trampolines. Engine owns sessions, transactions, retained resources, prepared identities, and shared registration lifetime adapters. SQL owns type interpretation and value observation; Execution owns query scheduling, prepared execution, and callback finalization. Core supplies existing memory reservations and value producers; SQLite owns encryption/compression options. Shared Arrow conversion belongs to `uqa-api`. No owner depends back on FFI.

The Cargo target is `uqa_ffi` because the workspace already contains the Rust facade target `uqa`; packaging supplies the native `uqa` library name. Default dictionary features and independent FDW/export features follow the design. Existing unrelated work in `tests/parity/pg18/README.md` is outside this implementation.
