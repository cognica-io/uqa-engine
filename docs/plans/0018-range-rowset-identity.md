This correction addresses [#949](https://github.com/cognica-io/uqa-engine/issues/949), found while auditing the remaining consumers after #946 and #948. ## Reproduction and ownership

The initial eight independent PostgreSQL 18.4 queries all fail through Engine SQL: recursive UNION retains two equivalent numeric range spellings instead of one, while scalar IN, WHERE IN and decorrelated EXISTS all miss the equal value. Both `numrange` and `nummultirange` reproduce the same failures. Correcting the reusable sets makes these eight cases pass; six further finite SEARCH/CYCLE cases expose generated records that still discard field types. PostgreSQL detects the numeric-range cycle one iteration earlier and sorts the range starting at 2 before the range starting at 10. The compact fixture records all fourteen queries, expected results, server version and Docker image; no timing measurement is used.

Execution's reusable hash and exact sets now retain selected scalar types across building and probing. Streaming hashes, exact spill bytes and collision verification use the existing SQL selected-type boundary. Physical recursive rows pass their logical selected field types; decorrelated EXISTS resolves its projections with the existing evaluator rather than suppressing inference errors. Cached IN captures the retained output type once, and streamed IN reads the same field type from its owned schema. Generated SEARCH/CYCLE records retain their selected field identities through the existing typed row carrier, with SQL's metadata mapping and a bigint breadth-first depth field. Engine only adds the public SQL acceptance check.

## Preservation argument

For supported exact-key types $T=(T_1,\ldots,T_n)$, the existing selected encoder produces $K_T(v)$, and collision verification uses the same component equalities $E_{T_i}$. Its congruence established by the scalar-key correction therefore applies to every insertion and probe: $E_T(a,b)\Leftrightarrow K_T(a)=K_T(b)$, with complete equality verification for hash collisions. Retaining $T$ makes recursive duplicate elimination operate on the same SQL equivalence classes throughout the fixed point. IN/EXISTS membership preserves these classes independently of memory-to-disk migration; NULL and empty-set control flow is unchanged. Raw exact-set methods and unselected/TEXT keys keep their previous representation domains.

SEARCH/CYCLE already construct positional records. Attaching the source fields' admitted SQL identities makes record comparison use their existing selected operators, including nested range observation; it introduces neither input effects nor canonicalization. The breadth-first depth remains the leading bigint field. Keys retain their input values and existing row/path multiplicities, while the cycle boundary and ordering are corrected to PostgreSQL. Type metadata is retained once per reusable set and borrowed during probes; generated record metadata is proportional to its key width and uses the existing spill format. No new algebraic operator, persistent format or dependency direction is introduced.
