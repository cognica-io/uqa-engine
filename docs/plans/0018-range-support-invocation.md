# Definition-derived range support invocation

This unit connects the retained definitions of original #638 record 65 to the selected SQL comparison and Execution exact-key owners. It fixes the reproduced physical-domain invocation defect [#961](https://github.com/cognica-io/uqa-engine/issues/961) and follows the frozen selected-comparison unit; it does not publish range declarations, generated constructors or arbitrary custom operator classes.

## Ownership and selection

Execution resolves range and multirange value OIDs through one index attached to the immutable catalog generation. Both identities borrow the same stored definition; array OIDs are not range value identities. The index is built once, retains only OID-to-name metadata and does not clone definitions or scan unrelated tables during repeated bound calls. An empty range registry creates no index. SQL validates the selected class's input and invokes its existing admitted-input interpretation, comparison, physical decoding and collation owners. Physical domain inputs expose their captured base-type view before polymorphic support observes them; this corrects a reproduced XX001 failure for domain-wrapped enum bytes without executing domain input or checks. Execution invokes the existing exact-key encoder with that same binding. Engine only supplies its pinned catalog view, value catalog and session state.

A range's direct enum subtype comparison has its own session-retained function state. This follows PostgreSQL 18's [range type cache](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/utils/cache/typcache.c), which initializes a comparison function per range and points multiranges to the corresponding range entry. PostgreSQL's [enum comparator](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/utils/adt/enum.c) leaves the private type unset on equal/even-OID fast paths and records the actual left label's type on the first slow call. The SQL owner retains those existing rules; nested array/record fields continue using their separate type support state. Read-only catalog metadata does not retain invocation state, and transaction rollback does not reset the session's support call.

## Preservation argument

Fix one valid immutable catalog generation $g$ and an admitted range identity $r$. Its definition determines endpoint type $T_r$, selected class $C_r$, collation $L_r$ and counterpart multirange identity $m_r$. Structural registry validation makes both value identities unique. Building the lookup index inserts exactly $(r,n_r)$ and $(m_r,n_r)$ for the definition's registry name $n_r$ and rejects duplicates. Hence lookup through either identity returns the same borrowed definition in $g$; lookup through an array or absent identity returns none. Cloning the view preserves the same snapshot and index, while a replacement generation owns a separate index. This establishes identity and generation preservation independently of later namespace changes.

Let $I_{C_r}$ be SQL's previously verified admitted-input interpretation. Define the connected comparison by $Q_r(a,b)=\operatorname{cmp}_{C_r,L_r}(I_{C_r}(a),I_{C_r}(b))$ and its key by $K_r(a)=K_{C_r}(I_{C_r}(a))$. The adapter uses precisely these existing owners with the same binding, catalog and production control. Within the successful comparable domain of the implemented classes and fixed deterministic collations, the [selected-input proof](0018-selected-btree-inputs.md) and [selected-comparison proof](0018-selected-btree-comparison.md) give $K_r(a)=K_r(b)\iff Q_r(a,b)=0$. The connection introduces neither a new normalization nor a new equality relation. Unknown definitions/classes fail instead of falling back to a default; unknown nonzero collation identities cannot silently produce binary equality keys. Arbitrary nondeterministic collations remain outside this fixed selector and require their own exact normalization.

The existing range and multirange algorithms consume endpoint comparison and key callbacks without changing their inclusivity, infinity, empty-value or identity framing. Substituting $Q_r$ and $K_r$ for those callbacks therefore preserves their established lexicographic order and exact equality partitions. SQL input, domain constraints, canonical functions and subtype-distance functions are not invoked while observing admitted values. This unit adds no optimizer rewrite and makes no purity or idempotence claim for future user callbacks.

For stateful enum support, let $S_r$ be the private state selected by the canonical range OID. Equal/even-OID calls leave its cached type unchanged; the first slow call records the type obtained from the admitted left label; subsequent calls reuse that type and preserve the SQL owner's diagnostics. Range and multirange calls share $S_r$, while another range uses a distinct state and nested container support retains its existing catalog-owned type state. This preserves the operation's state transitions, including failures, rather than proving order laws for malformed foreign label bytes outside the valid comparison domain.
