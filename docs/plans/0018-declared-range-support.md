# Declared range support and admitted equality keys

This work follows the catalog-generation unit in merged [PR #944](https://github.com/cognica-io/uqa-engine/pull/944) (`90b4c1ebe`) and preserves original record 65. The completed source changes provide caller-controlled SQL equality keys and shared built-in B-tree class metadata. Binding stored operator classes and collations, invoking selected support, SQL declarations and generated constructors remain active requirements; these shared interfaces alone do not complete them.

## Ownership and implementation

Execution's `distinct/encoding` remains the single exact-key owner for grouping, hashing, reservations and spill. The new admitted SQL entry point shares its existing scalar and container traversal rather than serializing a range endpoint into another key format. Both existing uncontrolled and storage-read-controlled entry points use the same implementation. SQL's existing physical reader observes datums; Core's existing numerical and JSONB producers normalize their equality representations. No input, domain check, canonical function or enum output is introduced.

The caller supplies a `ProductionControl`. Traversal frames, datum decoding, numeric and JSONB scratch and the final output retain that same allowance. Core's copy-only `ProductionVec::extend_from_slice` admits capacity before each bounded chunk and checks both cancellation scopes. It carries no SQL semantics. The successfully returned `Produced<Vec<u8>>` retains only its output capacity; scratch is dropped before return. Failures release the unfinished output and scratch while preserving borrowed input owners.

SQL owns the built-in B-tree class identities, families, input types, comparison-function identities and default selection. The existing default-index capability check now consumes this metadata. Domains select through their base type; aliases select the corresponding base class; arrays, records, enums and ranges retain their generic classes. UQA vectors and tensors retain their existing native capability without invented PostgreSQL OIDs. Class metadata is not an executable comparator or a proof that an arbitrary class has an exact equality key. Execution's RANGE/LIST partition catalog projection also consumes the shared selection. Its incomplete duplicate table returned zero for ten valid input types; #945 records that independently reproduced correction. Hash partition selection keeps its existing mapping.

## Preservation argument

Let $K_C(v_1,\ldots,v_n)$ be the existing exact SQL key under catalog generation $C$, after the selected SQL coercions have produced its inputs. The encoder writes the same row count, type tags, length framing, scalar equality representations and recursively framed container contents in the same order. The refactor changes the control parameter passed to each producer, without changing any emitted component. Induction on the encoder's explicit traversal stack therefore gives $K'_C(v_1,\ldots,v_n)=K_C(v_1,\ldots,v_n)$ whenever production succeeds. Enum OIDs retain identity lookup; physical datums pass through the same input-free reader; range fields retain their declared identity and selected endpoint-key callback. Native opaque reservation aliases keep their original non-observing path.

For any selected endpoint equality relation for which the existing key is exact, equality of the produced byte sequences is unchanged. Consequently the partitions used by DISTINCT, grouping and equality joins, the hashes of those sequences and spill/reservation membership remain unchanged. This argument does not establish a key for an arbitrary user comparator: the selected operator class must supply or justify its equality representation before it can use this encoder. In particular, a non-default collation cannot be replaced by byte order merely because a byte encoder exists.

For the resource obligation, each allocating producer receives the same control and admits its capacity before allocation. A container's frame stack owns its own lease until traversal exits. Each normalized leaf or decoded datum owns its lease until its bytes and children have been consumed. The output owns its accumulated capacity independently. On error, stack unwinding releases all of these owners; on success, only the output owner is transferred. Induction over appended copy-only chunks shows that capacity is admitted before each copy, element order is unchanged and both cancellation scopes are checked at each bounded step. No numeric approximation, new algebraic operator, persistent key format or storage-version change is introduced.

For class selection, let $B(T)$ be the previous default-index capability predicate on a resolved SQL type. The metadata selection applies the same domain recursion and unsupported-type exclusions; each remaining PostgreSQL type selects a default class with its base, alias or generic input identity. Its result is therefore present exactly when $B(T)$ was true for PostgreSQL types. The two UQA-only vector carriers retain their explicit true result. The refactor preserves the capability predicate and its diagnostics, while exposing the selected identity as additional metadata. It does not change any comparison, key, index row, catalog generation or persistent encoding. The partition projection deliberately corrects the former zero class identity for valid B-tree keys while preserving every previously correct identity; domain recursion selects the same base class. The hash branch retains the same match arms and OIDs. The selection scans a fixed 44-entry borrowed table and allocates no per-value state.

## Verification and remaining work

The 21 focused Execution key tests pass, including the existing independent PostgreSQL native/declared range and temporal equality matrices, exact/hash/reservation/spill agreement and three new admitted-key tests. The new tests compare logical and physical values with existing key bytes, exercise large text and nested numeric/JSONB values, verify quota cleanup and exact output retention, and interrupt both cancellation scopes during catalog lookup. The initial interrupt fixture used a built-in type that intentionally bypasses catalog lookup; the corrected fixture uses a declared OID and exercises the intended callback.

The four focused SQL operator-class tests pass. Independent PostgreSQL 18.4 catalog queries verify all 44 built-in B-tree classes, and 38 actual `CREATE INDEX` cases verify default selection through the real SQL compiler. Both reference fixtures retain the source SQL, server version and Docker image identity beside the SQL owner tests. Existing rejection diagnostics and domain identities remain covered.

The partition correction reproduces #945 against 76 actual PostgreSQL RANGE/LIST declarations. Its owner test now verifies both direct selection and the complete `pg_partitioned_table` projection for every reference type and corresponding domain wrapper. All 152 projected rows carry the expected class identity. The corrected Execution test, strict library/test Clippy and final ownership/dependency/harness/header/file-size checks pass. This is catalog projection evidence, not end-to-end execution of every declaration through Engine.

The automatic manifest adds six checks and contains 814 checks / 1,208 cases. Strict Core/SQL/Execution library/test Clippy, formatting, the 109-edge dependency policy, Engine ownership, the single-harness inventory, Rust headers and file ceilings pass. Actual Linux/macOS bounded-work, memory and output reports remain required before delivery. Independent-process correctness histories must also pass on both platforms. No timing measurement or release operation is part of this unit.

The declaration reference separately confirms PostgreSQL's ordered subtype/option validation, ignored subtype typmods, non-canonical custom integer bounds, strict multirange NULL handling and shell completion through an internal canonical function. Those observations are preparation for the following implementation, not UQA acceptance. Selected operator-class/collation invocation and generated routines remain unchecked obligations in record 65.
