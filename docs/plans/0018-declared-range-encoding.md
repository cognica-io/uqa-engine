# Declared range physical production

This is the physical production boundary of original record 65, following [selected construction](0018-declared-range-construction.md). A completed, admitted range or normalized multirange now becomes an immutable physical `DatumValue` with its selected type identity. Custom SQL declarations, definition-derived support and generated routines remain required; these internal producers do not publish `CREATE TYPE AS RANGE` or complete record 65.

## Ownership

SQL's `expr/range/datum/encoding.rs` owns range flags, endpoint layout, multirange offsets and the output carrier. `expr/datums/encoding.rs` shares existing scalar, array, tuple, numeric and JSONB codecs; the tuple owner still owns physical attribute positions and the array owner retains dimensions, lower bounds, element OIDs and NULL bitmaps. Core only retains already admitted bytes and their shared allocation header. Engine acquires no value algorithm, crate dependency or Cargo feature. SQL continues to depend only on Core and the parser inside the workspace.

Production borrows completed endpoints and selected composite descriptors. It never executes a declared endpoint's input, domain checks, comparison or canonical function. Native range text retains its existing native parsing adapter. Already physical fields preserve their bytes; compressed fields use the existing admitted decompressor. Newly materialized arrays, records and JSONB use the caller's original allowance and both cancellation scopes. Immutable text and fixed-width endpoints avoid additional heap buffers: text borrows its original payload and fixed-width scratch stays inline.

The output retains the actual range or multirange OID. Catalog constants accept those declared physical values without converting them back to input text. No new persistent record format, `Value` variant or untyped-text interpretation is introduced.

## Physical preservation

For a selected endpoint type $T$, let $E_T(v)$ be its existing physical encoding and $D_T$ the corresponding admitted reader. Encoding preserves its stored representation, including enum label OIDs, domain base layout, array dimensions and element identity, record type identity, numeric display scale and JSONB container order. The shared writer changes ownership of construction buffers, not the scalar coding rule. Fixed-width bytes are copied with the selected width. Variable-width bytes receive PostgreSQL's short header when permitted or the ordinary aligned four-byte header otherwise.

For a completed range $R$, the producer writes its immutable identity, existing bound values and inclusion/infinity flags without another construction operation. Thus reading the produced value preserves the admitted interval and its physical endpoint spelling: $D_r(E_r(R)) = R$ under the selected metadata. No purity assumption is made about user input or canonical functions, because serialization invokes neither. For a normalized multirange, the producer writes members in their existing order; relative offsets and each fourth absolute offset locate precisely the same member boundaries. Induction over those offsets establishes the same sequence of intervals. The represented set and selected comparison/equality classes are unchanged, so existing exact-key, grouping and spill consumers keep the same equivalence relation. This unit changes no document support, tuple multiplicity, payload merge, retrieval score or ranked algebra.

Issue [#941](https://github.com/cognica-io/uqa-engine/issues/941) records a reproduced error in the existing shared alignment helper: it treated every non-eight-byte endpoint as four-byte aligned. PostgreSQL UUID multiranges instead use one-byte boundary alignment and smallint uses two bytes. Both reader and producer now honor `c`, `s`, `i` and `d` from the endpoint metadata. The containing range's alignment and the inner endpoint alignment remain distinct. Native four/eight-byte layouts are preserved.

## Resource preservation

Each dynamic buffer reserves capacity before construction. A nested child stays owned while its bytes are copied into the parent's admitted buffer, then drops immediately; a completed parent retains only its own output allocation. Temporary JSONB parse, numeric and field-order buffers use the same allowance and are released before output handoff. Tuple position scratch has its own lease and is dropped when only physical bytes are requested. Array and tuple headers are removed in place when producing a containing field's payload, without an unadmitted replacement allocation.

The final varlena header is inserted within admitted capacity. Core's existing `DatumValue::with_control` reserves its shared header before taking ownership. Every fallible production entry and traversal checks the original and invoking cancellation scopes. Quota, malformed-field, catalog and cancellation failures drop output and temporary allocations without consuming a borrowed input owner. A successful result's retained charge equals the physical carrier's retained bytes. Work is proportional to encoded payload and the existing field lookup/sort work of its owning codec; no timing improvement is claimed.
