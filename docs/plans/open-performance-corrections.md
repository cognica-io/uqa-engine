## Regex lifetime correction

The original SQL call compiled through a wrapper that mutably borrowed that call's resource hooks until destruction. Retaining that object directly would retain borrowed cancellation and allocation state beyond its valid lifetime. Separate the compiled allocation owner from each invocation's scratch/cancellation hooks, then retain a bounded SQL cache in the session execution context. Pattern text, compile flags and input collation all participate in lookup. A hit must still check current cancellation, and temporary matching allocations must use the current invocation's allowance. Eviction and session destruction release the original compiled reservation. Nested statements and dispatched workers must enter the correct session cache and restore their caller's context.

This is an implementation correction of existing SQL operations, with no new algebraic operator or result carrier. Reusing compiled state is valid only for identical compilation inputs; the matcher and SQL result construction continue to run for every invocation. Cache state cannot affect row multiplicity, selected spans, collation, NULL/argument validation order or diagnostic precedence.
