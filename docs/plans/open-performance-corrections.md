## Regex lifetime correction

The current SQL call compiles through a wrapper that mutably borrows that call's resource hooks until destruction. Retaining that object directly would retain borrowed cancellation and allocation state beyond its valid lifetime. Separate the compiled allocation owner from each invocation's scratch/cancellation hooks, then retain a bounded SQL cache in the session execution context. Pattern text, compile flags and input collation all participate in lookup. A hit must still check current cancellation, and temporary matching allocations must use the current invocation's allowance. Eviction and session destruction release the original compiled reservation. Nested statements and dispatched workers must enter the correct session cache and restore their caller's context.

This is an implementation correction of existing SQL operations, with no new algebraic operator or result carrier. Reusing compiled state is valid only for identical compilation inputs; the matcher and SQL result construction continue to run for every invocation. Cache state cannot affect row multiplicity, selected spans, collation, NULL/argument validation order or diagnostic precedence.

Local verification passes 40 wrapper tests, 37 SQL regex tests, 20 Engine regex/provider cases, 62 Execution statement cases and three Engine thread-context cases. The Emscripten artifact passes 13 unit and 22 integration tests under both baseline and optimizing V8, plus its doctest. Docker PostgreSQL 18.4 independently confirms the new collation/case/NULL expectations. Review caught and corrected constructor return-type inference compatibility and native-provider retention initialization; the cache now binds to the actual initialized session allowance, including the explicit transaction's separately accounted snapshot.

The [regex predicate fixture](../../crates/uqa-engine/benches/regex_predicates.rs) validates 10,000 matching rows out of 20,000 stored rows for equality, a literal pattern and a character-class pattern. Its local correctness mode passes without recording timings. The [comparison manifest](../../benchmarks/regressions/regex-predicates.json) fixes the reference, identical fixture overlay, ten linear samples, independent 32-pair reference calibration and eight counterbalanced comparisons before measurement. The regex intervals must be wholly below 1.00; the non-regex control retains a 1.10 limit. Reuse the existing controlled host and observer, build both artifacts before isolation/calibration, preserve all observations, and stop the instance after collection. This planned experiment is not timing acceptance.

Review additionally found avoidable eviction before a new pattern had compiled. The cache now removes idle entries only for actual byte pressure or when admitting a successful completed entry. All eleven cache owner tests pass locally, including a full 32-pattern cache that survives invalid compilation without changing retained bytes or recompiling any existing pattern. The controlled fixture uses one resident pattern per session, so this capacity-only correction does not execute in that already-running fixed comparison; its recorded candidate remains `1652d3dd9`, and no later revision is represented as measured.

The first operator experiment, `regex1063-20261020-1`, is invalid and was stopped during reference calibration: two pre-existing worktrees shared one Cargo target, and the candidate's older timestamps made Cargo reuse the reference executable. Both build records have the same binary hash, so none of this attempt is evidence for a candidate comparison. Preserve its signed invalid result, diagnostics and partial observations. The corrected procedure builds revisions sequentially in one canonical checkout and validates artifact source paths and distinct executable hashes before calibration. Before any valid comparison, the protocol was reduced from twenty to ten linear samples because the unchanged 20,000-row reference needs approximately 24 and 56 seconds per regex case with twenty samples; ten samples use 55 rather than 210 iterations at the minimum. Workload size, expected output, 32 calibration pairs, eight comparison pairs, estimators and acceptance limits remain unchanged. No observed candidate result informed this adjustment.

The Linux deterministic job on `a7022cf0a` found a real diagnostic regression: compiling an excessively complex pattern against the session cache allowance exhausted its 64 MiB retention limit before PostgreSQL reached its complexity error. Compilation now uses the invocation's original scratch allowance; only successfully compiled live state is offered to the bounded cache. A refused cache admission leaves the ordinary invocation usable, while an exhausted invocation allowance still reports its existing memory error. Shared owners transfer their existing reservation; distinct owners admit the completed state before releasing its original lease. The new zero-retention regression fails before the correction and passes after it; forty SQL regex tests pass locally. The public Engine adapter and four-provider PostgreSQL/reopen checks also pass (two session ownership cases and 28 SQL integration cases), together with strict SQL Clippy, formatting and ownership checks; automatic qualification remains pending. The ongoing controlled experiment still names `a7022cf0a`; it will not be represented as a measurement of this later correction.
