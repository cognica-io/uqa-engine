## Regex lifetime correction

The original SQL call compiled through a wrapper that mutably borrowed that call's resource hooks until destruction. Retaining that object directly would retain borrowed cancellation and allocation state beyond its valid lifetime. Separate the compiled allocation owner from each invocation's scratch/cancellation hooks, then retain a bounded SQL cache in the session execution context. Pattern text, compile flags and input collation all participate in lookup. A hit must still check current cancellation, and temporary matching allocations must use the current invocation's allowance. Eviction and session destruction release the original compiled reservation. Nested statements and dispatched workers must enter the correct session cache and restore their caller's context.

This is an implementation correction of existing SQL operations, with no new algebraic operator or result carrier. Reusing compiled state is valid only for identical compilation inputs; the matcher and SQL result construction continue to run for every invocation. Cache state cannot affect row multiplicity, selected spans, collation, NULL/argument validation order or diagnostic precedence.

Local verification passes 40 wrapper tests, 37 SQL regex tests, 20 Engine regex/provider cases, 62 Execution statement cases and three Engine thread-context cases. The wrapper Emscripten artifact at `1534575450d3321c25bf6940633768a02679be68` passes 13 unit and 22 integration tests under both baseline and optimizing V8, plus its doctest, in run 39309648835. This is earlier-source wrapper evidence, not a test of later SQL changes. Docker PostgreSQL 18.4 independently confirms the new collation/case/NULL expectations. Review caught and corrected constructor return-type inference compatibility and native-provider retention initialization; the cache now binds to the actual initialized session allowance, including the explicit transaction's separately accounted snapshot.

The [regex predicate fixture](../../crates/uqa-engine/benches/regex_predicates.rs) validates 10,000 matching rows out of 20,000 stored rows for equality, a literal pattern and a character-class pattern. Its local correctness mode passes without recording timings. The [comparison manifest](../../benchmarks/regressions/regex-predicates.json) fixes the reference, identical fixture overlay, ten linear samples, independent 32-pair reference calibration and eight counterbalanced comparisons before measurement. The regex intervals must be wholly below 1.00; the non-regex control retains a 1.10 limit. Reuse the existing controlled host and observer, build both artifacts before isolation/calibration, preserve all observations, and stop the instance after collection. The controlled fixture uses one resident pattern per session, so this capacity-only correction does not execute in that already-running fixed comparison; its recorded candidate remains `1652d3dd9`, and no later revision is represented as measured.
