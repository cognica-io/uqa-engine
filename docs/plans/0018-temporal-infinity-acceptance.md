# Infinite temporal value acceptance

This audit preserves original record 33 of the [extension task ledger](0018-extension-progress.md): infinite `date`, `timestamp`, `timestamptz` and `interval` input/output, arithmetic including multiplication by infinite floating values, `sum`, `avg`, justification, comparison and `in_range`. The implementation is merged in PR #770. This follow-up makes its complete acceptance discoverable in the automatic regression inventory, adds controlled producer checks and corrects the unnecessary interval-input scratch allocation reproduced in #926. Original record 34, full finite calendar/input coverage, and the broader #289/#317 requirements remain open.

## Ownership and preservation

Core owns the reserved endpoints, ordinary and admitted input/output, comparison/equality keys and durable numeric fields in `types/temporal`. SQL owns selected casts, operators, functions, physical Datums, range canonicalization and `in_range`. Execution owns aggregate transitions, finalization and partial-state spill. Engine's existing tests exercise public sessions, transactions and provider reopen; this audit introduces no Engine algorithm. The owning manifests, enabled features and workspace dependency policy require no dependency or feature change.

For each supported finite temporal carrier $T$, the existing implementation embeds it in $T^*=\{-\infty\}\cup T\cup\{+\infty\}$. Each reserved representation lies outside the valid finite domain. Date endpoints use reserved day extrema; an interval is infinite only when its complete field triple is reserved. Timestamp endpoints use two otherwise invalid low Unix-microsecond values, so Unix `i64::MAX` remains finite. PostgreSQL's distinct 2000-epoch sentinel representation is translated at the Datum boundary. The existing finite encoding and its interpretation are unchanged.

The order extension places $-\infty$ before every finite element and $+\infty$ after every finite element. Its comparison keys encode that same rank, while equality keys preserve endpoint identity. Therefore transitivity and equality/order agreement restrict to their original relations on $T$ and extend across both endpoints. Input/output and serialization round trips preserve each endpoint and the existing finite values. Grouping, joins, extrema, uniqueness and ordered indexes consequently observe the same equivalence classes and order as their selected scalar operations.

Arithmetic remains a partial operation with PostgreSQL's defined values and ordered errors. The audit does not assume that adding opposite infinities is defined or that checked finite overflow can be removed by reassociation. Interval aggregation retains finite transitions separately from each infinity count, completes those transitions before selecting the final result, and preserves input/finite-overflow failures even when infinity has been seen. Partial-state serialization retains the finite state and both counts; decoded and merged states pass the same finalization. The existing spill test checks that representation through a real spill file and verifies its removal.

Admitted scalar production reserves the output buffer before allocation and retains the charge until the owner is dropped. The strengthened producer test reproduced an unnecessary normalized-string allocation before interval infinity recognition: an empty allowance failed with a one-byte reservation request. Core now applies the existing borrowed, case-insensitive token recognizer to trimmed input before constructing finite-interval scratch. For every input, ASCII case-insensitive token recognition is unchanged by the previous ASCII lowercasing, so the selected endpoint and invalid-token fallback are preserved. Finite input still takes the same normalized parser path, and cancellation is checked before either path. Parsing a reserved endpoint needs no variable-width allocation. Either cancellation owner remains effective. The added Core test covers all eight endpoint/family combinations, zero-byte successful input and rejected output without allocation, retained output capacity, released ownership and both cancellation sources. No durable format, expression rewrite or relational operator changes in this follow-up.
