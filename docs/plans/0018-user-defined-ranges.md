## Ownership and representation

Inspect the owning manifests, enabled features, dependency policy and existing consumers before each implementation boundary. SQL owns declared range identity, syntax, selected endpoint semantics, input/output, validation order and admitted operations. Core owns any shared value carrier and its structural storage primitives without depending on SQL catalogs. Execution owns definition transactions, support-function invocation, permissions, dependency publication and catalog restoration. Engine supplies existing state, session, transaction and retained-resource adapters. Provider codecs retain opaque value state through their existing controlled read/write contracts.

Keep immutable range identity separate from the endpoint type, selected collation/operator family and optional canonical routine. Two ranges over the same integer subtype are distinct types. A user-defined integer range does not automatically select the built-in integer canonicalizer. Generated arrays, the associated multirange and constructor routines have their own catalog identities and dependencies; current spelling cannot substitute for those identities.

Custom values must retain typed endpoints once. Re-reading stored endpoint text would repeat domain input and lose enum identity after a label rename. `SQLValueCatalog` observes already admitted values; it must not gain a callback that executes arbitrary type input. Selected operations borrow retained metadata, and callable support routines execute only at the boundary that owns their effects. Output may resolve current enum labels without changing stored equality or ordering.

Exact/hash keys must use the selected endpoint equality contract, including collation and nested types. An available byte encoding is not evidence that it agrees with a selected comparator. Preserve the existing built-in representation and keys unless a separately reviewed migration is necessary; any new durable carrier requires provider format/version checks, old-owner rejection, bounded decoding and failure-atomic restoration.

## Native adapter preservation

### Native physical-value prerequisite

The next boundary reproduced [#929](https://github.com/cognica-io/uqa-engine/issues/929): a valid native range DEFAULT makes `pg_attrdef.adbin` fail because the shared SQL catalog/retained-tuple codecs omit range payloads. Its focused correction belongs to SQL's `expr/range/datum.rs`, with the existing catalog, composite and array producers and deferred physical reader consuming that one implementation. Review also reproduced [#930](https://github.com/cognica-io/uqa-engine/issues/930): replacing a retained nested record's descriptor loses range-bound equality when the field is read as a physical Datum. SQL now supplies admitted physical bounds directly to its selected comparator, and Execution consumes the same bounds for exact/hash/spill keys. No Core carrier, dependency, persistent format or user-defined declaration is added. The source retains 66 independently captured PostgreSQL 18.4 constants and 97 public consumer statements, including nested arrays, DEFAULT/CHECK catalog output, constraint rejection, prepared values, descriptor changes, comparison/group/join consumers, exact diagnostics, rollback and twelve actual provider-reopen observations; source-matched automatic platform acceptance remains required before delivery.

For a native admitted range value $v$, encoding writes its existing type OID, scalar endpoint bytes and bound flags. Scalar codecs preserve each native endpoint, including decimal display scale and temporal infinity; empty and unbounded endpoints have no scalar payload. Decoding reconstructs these same components without applying input or canonicalization again, so every existing bound observation is preserved. Multirange encoding retains the normalized member sequence and writes checked length/offset entries for the aligned bound blocks. One checked cursor visits this sequence: text output formats one member at a time, while typed comparison retains the admitted member sequence under the original allowance. Hence $D(E(v))$ preserves native type, bound values, flags and member order. Tuple and array containers reuse this codec while retaining their own identity, null bitmap and shape. The original physical owner remains immutable; output, member scratch and retained comparison bounds are all admitted before allocation, and unsuccessful reads release their reservations.

Let $r$ be the native identity recorded in an owned payload and $t$ the currently selected field type. Within the same range or multirange class, PostgreSQL observes the payload using $r$ even when an attribute change gives the field a different $t$. The reader therefore selects $r$'s endpoint decoder rather than reinterpreting its bytes as $t$'s endpoints. A missing physical type OID reports PostgreSQL's `42704` diagnostic through the current statement catalog. An existing type in the wrong range/multirange class reports PostgreSQL's `XX000` diagnostic; comparing two different physical families also reports its exact mismatch diagnostic. For comparable values of one family, the decoded bounds and flags equal those produced by admitted native input, so the unchanged comparator and exact/hash encoder observe identical components. Equal physical and admitted values consequently share grouping, join and spill equality classes, including numeric bounds whose display scales differ. No text-input round trip is inserted into a deferred physical read. The independent byte fixtures, descriptor-change histories and actual spill tests exercise these obligations rather than substituting generated UQA output for a reference.

### Native selected operations

For a built-in range identity $r$, let $S(r)=(r,T_r,C_r,B_r,O_r)$ contain its selected endpoint type, optional canonical operation, comparison and output. `RangeSubtype` remains the existing public tag for the native family; it is not a newly introduced user-defined identity or durable format. The six static definitions in SQL's `expr/range/semantics.rs` retain that identity separately from `ColumnType` endpoint input and the optional canonicalizer. Native adapters borrow these definitions; no pointer or function address is stored in a value, plan or database record.

For every native $r$, $T_r$ is exactly the former `RangeSubtype::scalar_type()` result. Input calls the same scalar cast with the same admitted decoded input, target spelling and control. Complete syntax validation, lower-before-upper input, memory ownership and error propagation are unchanged. Therefore the resulting endpoint values and ordered diagnostics are identical. `int4range`, `int8range` and `daterange` select their original successor canonicalizers explicitly; the other families select no canonicalizer. No rule derives canonicalization from an arbitrary integer endpoint type.

Each selected $C_r$ performs the original lower-bound adjustment followed by the original upper-bound adjustment, skipping temporal infinities and using the same checked successor and diagnostics. The production owner retains both emptiness/order checks before and after that call. Thus its output and failure trace equal the original canonicalization for all native inputs. Native $B_r$ and $O_r$ are the original comparison and formatting functions, including admitted decimal scratch, generic native carrier output, temporal session formatting and exact error text.

All consumers retain their original branch structure and replace each endpoint comparison by the identical selected $B_r$. Induction over those branches establishes equal range ordering, containment, adjacency and cover results. Multirange sorting retains its original ordinal tie key, and the merge loop retains the same member sequence and endpoint ownership; induction over that sequence establishes identical normalization and lexical endpoint retention. Equality and exact-key consumers still receive the same canonical fields through `RangeComparisonValue`; their byte encoder is unchanged. Consequently the equality classes, exact keys and hashes used by grouping, joins, uniqueness and spill retain their original agreement.

The static definitions introduce no per-value allocation or retained field. `CanonicalRange`, `CanonicalMultirange`, Core `Value`, physical codecs and stored native text remain unchanged. Every input/output allocation, bound copy, reservation transfer, drop order and cancellation check remains at its original operation boundary. This establishes preservation of the existing resource contract; it is not a timing improvement claim. The independent input, 1,264-comparison and infinity references, controlled producer tests, exact/hash consumers, actual spill and provider reopen exercise these preserved boundaries.

This argument covers the native adapters only. Custom typed endpoints, installed identity, selected collation/operator families and effectful canonical routines require their own catalog/value implementation and proof. SQL's read-only value observation interface is unchanged and gains no callback that executes arbitrary type input or user routines. None of the remaining original record-65 or extension completion conditions is removed.
