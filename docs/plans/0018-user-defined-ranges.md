## Ownership and representation

Inspect the owning manifests, enabled features, dependency policy and existing consumers before each implementation boundary. SQL owns declared range identity, syntax, selected endpoint semantics, input/output, validation order and admitted operations. Core owns any shared value carrier and its structural storage primitives without depending on SQL catalogs. Execution owns definition transactions, support-function invocation, permissions, dependency publication and catalog restoration. Engine supplies existing state, session, transaction and retained-resource adapters. Provider codecs retain opaque value state through their existing controlled read/write contracts.

Keep immutable range identity separate from the endpoint type, selected collation/operator family and optional canonical routine. Two ranges over the same integer subtype are distinct types. A user-defined integer range does not automatically select the built-in integer canonicalizer. Generated arrays, the associated multirange and constructor routines have their own catalog identities and dependencies; current spelling cannot substitute for those identities.

Custom values must retain typed endpoints once. Re-reading stored endpoint text would repeat domain input and lose enum identity after a label rename. `SQLValueCatalog` observes already admitted values; it must not gain a callback that executes arbitrary type input. Selected operations borrow retained metadata, and callable support routines execute only at the boundary that owns their effects. Output may resolve current enum labels without changing stored equality or ordering.

The existing Core `DatumValue` already retains an owned byte allocation, physical type OID and deferred address, including independent memory charges and serialization. A range's physical payload also records its own range OID and typed endpoints. Reuse that carrier for custom range values instead of adding another Core enum variant or serializing endpoint text. SQL must supply the missing catalog-selected physical layout and observing operations; an opaque byte carrier alone does not establish SQL equality or complete custom type support. Existing native text carriers and their keys remain unchanged. This decision does not waive format negotiation for the new durable catalog records or imply that the later general extension envelope is implemented.

Exact/hash keys must use the selected endpoint equality contract, including collation and nested types. An available byte encoding is not evidence that it agrees with a selected comparator. Preserve the existing built-in representation and keys unless a separately reviewed migration is necessary; any new durable carrier requires provider format/version checks, old-owner rejection, bounded decoding and failure-atomic restoration.

### Typed physical endpoint observation

SQL now shares one inline physical reader between the actual native range and array consumers. It selects the endpoint storage width and alignment, unwraps domain layout without invoking constraints, reads short or ordinary varlena values, and delegates fixed, numeric, text, nested array and composite decoding to their existing SQL owners. Enum bounds retain their physical label OID as an owned Datum; label lookup remains deferred until output or comparison selects that observation. Core's `DatumValue::with_control` transfers the admitted backing buffer and reserves its shared header before allocation. The composite reader uses that same constructor for its retained tuple backing. No new Core value variant, range catalog entry or durable layout is introduced.

For an endpoint type $T$, let $b(T)$ remove only domain wrappers and let $L(T)$ be its PostgreSQL physical width and alignment. Domain layout satisfies $L(T)=L(b(T))$; decoding the same bytes with the existing base decoder preserves the admitted value without executing input effects. Fixed-width endpoints use the same scalar bit decoder, and variable-width endpoints use the same payload decoder after checking their short or ordinary length header. The cursor advances by exactly the decoded physical length after the containing value's alignment adjustment. Induction over array elements or range bounds therefore preserves the consumed prefix and each value. Enum decoding copies the original four-byte label OID without resolving its name; subsequent output uses the current label for that immutable identity. Composite decoding preserves its physical tuple identity and deferred fields. Thus the refactor preserves every existing native observation and does not introduce repeated domain input, canonicalization or stale enum spellings.

The owned Datum constructor moves the existing admitted byte allocation, so its pointer, capacity, identity and deferred offset are unchanged. The additional reservation is exactly the existing shared-header accounting; the constructor reserves it before allocating the `Arc`. Both the produced wrapper and all error paths retain allocation ownership until the matching lease is released. Element results transfer their original leases to the container; failed or cancelled reads release all scratch and output reservations. Zero-heap scalar endpoints remain readable under a zero-byte allowance, while enum, text and nested endpoints require admission. These properties preserve the resource boundary independently of endpoint display text.

### Native physical production allowance

The physical-value correction merged in [PR #931](https://github.com/cognica-io/uqa-engine/pull/931) as `e337ac6de`, qualifying corrected source `039f5844d5872e88d6c36d31b560bded6354c7d7`. Range encoding remains in SQL; Core only exposes fixed-length mutation of already admitted `Copy` slots. No Core value tag, native value layout, stored format or dependency changes. Custom endpoint descriptors, their operators and declaration publication remain unimplemented by this producer unit.

For numeric input with integer digits $I$ and fractional digits $F$, the former encoder formed $S=0^p I F 0^q$, where $p$ and $q$ align decimal groups of four. The new borrowed group cursor computes each $g_i=\sum_{j=0}^{3}10^{3-j}(S_{4i+j}-\mathtt{0})$ from the same digits and virtual zeroes. Therefore every base-10000 group, first/last nonzero position, weight, scale, sign and short/long header is identical, including all-zero and special values. It allocates neither the padded string nor the digit vector. The controlled scalar formatter owns its scratch and text, and the encoded byte buffer owns its separately admitted capacity; completed output retains only that byte-buffer lease.

The range writer emits the same type OID, flags, endpoint encodings, alignment and member offsets as its predecessor. Induction over members preserves the output prefix and current offset after each member; the equal numeric encoding establishes the variable-width case. Offset and flag updates borrow a fixed-length mutable slice of admitted `Copy` elements. Such a slice cannot grow the allocation or introduce an allocation-owning element, so it preserves the producer's existing capacity and memory ownership. Every growth and scalar scratch allocation is admitted before allocation, cancellation propagates from both owners, and a failed producer publishes no result and drops all its allocations before their leases. Ordinary wrappers invoke this same implementation with explicit uncontrolled production; no second encoder bypasses the new owner contract.

The static definitions introduce no per-value allocation or retained field. `CanonicalRange`, `CanonicalMultirange`, Core `Value`, physical codecs and stored native text remain unchanged.
