## Original ownership and allocation inventory

Core owns reservations and containers. SQL owns executable-plan and scalar storage, copying, binding and typed result contracts. Planner owns rewrites, cardinality/cost calculations, join enumeration and EXPLAIN rendering. Execution owns statement preparation and diagnostics sequencing; Engine supplies request/session adapters. The existing Cargo features and dependency policy allow these directions without adding a dependency or moving algorithms into Engine.

## Join search representation and preservation

For a valid join graph with at most 64 relations, let a subset be its existing `u64` relation mask. A retained decision consists of that mask, estimated rows, cost, child subset masks, selected edge and physical operator kind. These fields contain no separately allocated payload. Memo storage admits its exact nodes, temporary layers admit vector capacity, and the selected output admits each boxed node before construction. Removed scratch releases its own reservations; output reservations survive until the produced tree is dropped.

The representation change introduces no algebraic operator. Define expansion of a leaf decision as its relation scan, and expansion of a binary decision as the existing join applied to the expansions of its children. Every child is a strict subset of its parent, so expansion terminates. In exact enumeration, all smaller subsets are settled before a larger subset is visited. In greedy search, a consumed child subset is never rewritten. In the star search, selected prefixes are reconstructed from the completed predecessor table. Thus each retained child reference denotes the same settled child that the earlier implementation copied.

Induction on subset cardinality proves representation preservation: leaf rows/costs and relation masks are identical; a binary candidate uses the same ordered operands, ordered edge selectivities, physical cost function and floating-point operation order, so its rows and cost are identical. Preserving candidate visitation order and strict cost comparison preserves ties and the selected decision. Expanding that decision therefore yields the same ordered tree, including disconnected-component cross joins and their stable cardinality order. This claim does not assume join commutativity for volatile SQL expressions: eligibility and predicate attachment remain in their existing SQL/Planner owners and are unchanged by decision storage.

Successful admission preserves this observation exactly. A failed reservation or either cancellation token terminates before constructing the rejected allocation; RAII drops all local containers and output nodes with their leases. Failure publishes no plan. This proof obligation must be checked against the completed implementation and its exact/greedy/star/disconnected tests before the corresponding task is marked complete.

The join-order adapter now constructs graph labels, row/access estimates and ordered edges through the same production control as enumeration. Its alias index borrows names in a sorted fixed array whose capacity is the graph's established 64-relation domain. Each alias maps to the original declaration index; sorting the index changes neither relation masks nor edge order. Relation count, cardinality, access cost and duplicate-alias validation retain their original order, followed by left/right predicate resolution. Singleton input retains its existing predicate handling. The graph's buffers and label leases remain alive during enumeration and are released before the selected tree escapes; borrowed statistics remain with the input owner.

The ordinary consuming adapter moves each relation into its selected leaf instead of cloning its statistics. Every selected binary node partitions its relation mask into disjoint child masks, and the root covers all input relations. Induction therefore gives exactly one leaf for each relation, making the move total and unique. A relation pair crosses the children of exactly one node, its lowest common ancestor, so a selected condition's strings can also move out of the existing last-predicate-per-pair lookup. Enumeration retains the first crossing edge in original edge order, the same edge the previous materializer found. These ownership transfers preserve the original tree, relation metadata, primary alias and condition orientation while avoiding a second metadata allocation. They do not yet admit the ordinary adapter's final descriptor tree or the native SQL rewrite's remaining copies.

Scalar costing now reads the same immutable column map through a borrowed row-count/statistics observation, and literal extraction borrows existing values while retaining owned results of actual casts. A borrowed value has the same comparison inputs as its previous clone; column lookup, MCV/null fractions, histogram inputs and ordered floating-point operations are unchanged. Induction over the scalar expression therefore preserves every estimate, including the existing fallback when a constant cast cannot produce a value. Local filter costing borrows a single predicate and reconstructs multiple conjuncts in their original order; the preferred provider is still called once before fallback costing, with the same expression value. The row count is captured with the same rounding before updating the relation. This changes storage ownership only, without evaluating the query, widening literal interpretation or changing lazy diagnostics. Controlled cast production and predicate-reference grouping are covered below; relation/column metadata, inferred predicates and attachment storage remain in the open native inventory.

For multiple local predicates, Planner admits the conjunction vector before filling it, and each child enters through SQL's controlled scalar copier. The vector and child leases move together into the immutable conjunction without another allocation. Component-wise scalar-copy preservation and unchanged child order establish equality with the previous `And` expression; no new evaluation or boolean transformation occurs. The conjunction remains alive through the provider estimate and fallback formula, and its storage is freed before its lease on ordinary return, invalid estimates or unwind. A partial copy never reaches the provider. Insufficient ancestor allowance or either cancellation token releases all constructed children, leaving the source predicates and sibling reservations intact. This owner accounts for the actual temporary expression. Reference grouping and cast destinations have their own production boundaries below; relation/column metadata, inferred predicates and attachment storage remain open.

Native optimization now captures the invoking request's existing memory allowance and cancellation token after SQL analysis succeeds. Cloning those handles preserves allowance identity rather than establishing a new limit. Every recursive join walk forwards that control unchanged through query, CTE, scalar-subquery, DML and cursor boundaries. Standalone planning retains its ordinary uncontrolled mode; Engine always supplies the native owner. The admitted graph and selected tree remain alive through SQL source materialization, and all exits release their leases. This connects graph/search admission; it does not yet admit metadata gathering, predicate attachment buffers or other rewrite storage.

The native materializer consumes the selected tree directly without constructing an unused intermediate join descriptor. A leaf mask's bit index is its original relation index, which equals the source atom's index by construction. For each binary node, the previous descriptor maps an absent edge to the automatic strategy and a selected inner-hash edge to the hash strategy. Direct materialization makes those same choices and recursively retains child order; induction on the selected tree therefore proves equality with the previous composed materializers. Predicate attachment runs unchanged after materialization. Allocation rejection publishes no replacement source. The existing transaction owner continues to apply failure and savepoint recovery; the planner introduces no admission guard or transaction reset.

Selected SQL materialization now transfers the original source boxes and values instead of copying them. An eligible binary source with n leaves has n leaf boxes and n-2 boxed internal nodes, because its root is held by value. Here 2 <= n <= 64, so fixed arrays of 64 and 62 box slots retain the original allocations without heap scratch. Collection preserves the original left-to-right leaf indices. The selected tree partitions its root mask into disjoint child masks and covers every input leaf exactly once; consequently, materialization consumes each leaf box once and exactly n-2 internal boxes. It preserves the selected child order and physical strategy while moving each entire leaf, including executable query bodies, scalar arguments and retained bindings. No new source-node or leaf-payload allocation occurs.

Original ON predicates remain borrowed during graph selection. After successful selection, collection moves their scalar values into the corresponding prepared metadata slots. Both borrowed discovery and owned collection visit left child, right child and then the node's recursively flattened AND items in order, establishing a one-to-one order-preserving correspondence. Inferred WHERE predicates retain their separate existing construction. The unchanged attachment rule therefore receives the same ordered expressions and qualifiers as before, preserving values, selected identities and evaluation placement without cloning the original payloads. Unavailable estimates, memory rejection and either cancellation scope exit before ownership transfer, leaving the original source intact. Remaining inferred-predicate, qualifier and attachment-buffer allocations are still part of the open native admission work.

Statistics catalog operations now retain typed SQL errors instead of erasing the provider cause into text. The adapter uses Execution's existing storage-to-SQL mapping, and the statistics owner keeps its original first-error order. Memory and cancellation failures therefore retain `53200` and `57014` through redb as through the other providers. Successful metadata and estimate observations are unchanged; the corrected diagnostic remains inside the same statement failure boundary.

## Join input workspace and preservation

Let L(S) be the ordered leaf sequence of a reorderable source S and C(e) the ordered non-AND descendants of expression e, visiting each AND child from left to right. Source discovery retains the previous recursive order: left input, right input, then the source's ON conjuncts. It stores at most 64 source references inline, matching the existing relation-mask domain. Encountering a 65th atom declines the same search that previously rejected the completed longer list; it never publishes a partial source. WHERE and ON reference lists use Core's admitted vector owner, with cancellation checked during traversal. A block with no source or a non-join source does not collect external WHERE references, because no eligible root rewrite consumes them; nested source and scalar queries still receive their original recursive processing.

For a scalar e, define R(e) as the set of resolved relation aliases when every referenced expression belongs to the existing allowed forms; otherwise R(e) is invalid. The previous local classifier selected e exactly when R(e) was a singleton. The new classifier retains either no alias, one borrowed alias a, or failure. Induction over the same expression variants shows that repeated a leaves the singleton unchanged, a different alias makes it ineligible, and an unresolved or disallowed reference also makes it ineligible. Literal-only expressions leave the state empty. Stopping after ineligibility only skips pure reference inspection; it evaluates no SQL expression and changes neither diagnostics nor row demand. Qualified and unique-unqualified resolution preserve the original alias and column-owner semantics; demanded unqualified names use the borrowed lookup described below.

The eligible source has at most 64 unique relation aliases. A fixed array pairs each borrowed alias with its original relation index, and sorting that lookup changes no relation or predicate order. Each eligible predicate enters its indexed reference buffer in original input order. Thus every buffer is exactly the old per-alias sequence, including duplicate predicates. Costing consumes buffers in original relation order and keeps the same single-predicate borrowing, controlled conjunction construction, provider preference and fallback formulas. The ordered callback inputs, floating-point operations and chosen graph therefore remain unchanged whenever admission succeeds. No algebraic query operation, predicate relocation or numerical approximation is introduced.

Only the reference buffers grow on the heap in these discovery/grouping owners. Their actual capacity is admitted before allocation through ProductionVec; aliases and predicate payloads remain borrowed. Each group releases its buffer after its estimate, and original ON discovery references release before selected-source materialization. Partial growth, ancestor exhaustion, either cancellation scope and provider unwind drop the same owners before returning. Allocation rejection publishes no source replacement and retains the original input identities. The native request adapter and transaction boundary remain unchanged. Borrowed column resolution is covered below. Relation/statistics production, inferred predicate/graph descriptors and attachment storage retain their separate unfinished ownership requirements; this correction does not claim their admission or controlled-host latency.

## Borrowed column resolution and preservation

For an eligible join, let its distinct relation aliases be a_i and its immutable column maps be C_i, with at most 64 relations. Define U(c) as the set of relation positions i whose C_i contains the exact column name c. The previous copied map resolved c to (a_i, c) exactly when U(c) contained one position; it marked repeated names ambiguous and left missing names unresolved. The borrowed view performs the same existing BTreeMap lookup in each C_i, retains its first matching alias/key references and rejects a second match. Induction over the relation sequence proves that its result is the same unique pair precisely when |U(c)| = 1. Stopping at a second match is valid because later observations cannot restore uniqueness. String comparisons remain exact, and the returned references identify the original immutable names.

Construction of this view retains only a slice reference and inspects no columns. A demanded lookup performs at most 64 map lookups, with constant extra space and no copied string or new index; a qualified reference continues to use its existing alias check. This replaces eager copying of every column, including unused names, with bounded relation traversal over the maps already owned by the statistics provider. It changes neither the provider call sequence nor the interpretation of its statistics. Statistics production itself, relation alias copies and later owned graph descriptors remain separate unfinished owners.

Local estimation now reads these immutable relation descriptors and returns up to 64 optional scalar cost results in an inline array. Each relation's calculation uses only its original row count, column map, local predicate sequence and provider response; it does not read another relation's updated cost. Calls, first-error handling, validation, rounding, clamping and floating-point operation order therefore match the previous loop. Predicate inference and descriptor construction between estimation and applying the results read aliases and column maps only. Applying the completed scalar results immediately before graph selection consequently presents the identical descriptor values to the same search. Errors or unwind publish neither a source replacement nor a partial descriptor update; the source tree remains with its original owner. Compound-expression and reference-buffer leases retain their existing callback lifetimes.

Since unique resolution, predicate eligibility, ordered estimates and selected graph inputs are preserved, this ownership change preserves the existing join rewrite and its composition with filtering and projection. It introduces no SQL evaluation, volatile effect, approximate cost formula or algebraic operator. Allocation regressions verify this boundary without claiming controlled-host latency or admission for the remaining metadata producers.

Let S_g be the complete ordered column map captured from catalog generation g, including each name, row/distinct/null count, bound, histogram, MCV value and frequency. The old observation is clone(S_g); the new observation dereferences a retained S_g. Relate them when every corresponding key and value is equal. Capture establishes this relation because cloning preserves all fields and moving or retaining the original allocation leaves them unchanged. Estimator attachment and cloning preserve the relation without changing the map. Induction over the existing lookup and arithmetic sequence therefore yields identical scalar estimates, costs and join-selection inputs, including floating-point operation order and fallback decisions. This representation introduces no SQL operator, reordering, evaluation, approximation or volatile effect; every existing relational or retrieval composition receives the same planning observations.

Capture takes the same catalog read lock and selects one generation before releasing it. A standalone `RelationStats::with_column` builder also detaches before changing a shared generation. Commit, rollback, statistics refresh and catalog restoration retain their existing transitions and publication order; new planning calls observe the generation selected by those transitions, while an earlier reader continues to observe its captured map. Sharing does not pin a mutable table guard or substitute current statistics during an operation. Owned public results remain independently mutable because their existing copy is retained.

The Engine snapshot helper preserves synchronization, name resolution, lazy-refresh decisions, ANALYZE calls and refreshed table lookup in their original order. Persistent planning still observes the last collected estimate without triggering a synchronous full-table analysis. Errors keep their original type and conversion boundary. Each successful capture retains one strong reference, released by ordinary destruction on return, error or unwind; the map is freed exactly when its last catalog or reader owner disappears. Empty defaults contain no reference-counted allocation. These already-owned catalog generations remain outside EXPLAIN's executable-storage measurement boundary and are not charged again to a reader. Initial statistics collection/refresh, aliases, index/graph metadata and other planning producers remain separate admission requirements.

## Costing constant production and preservation

Planner's scalar estimator reads literals, computes constant casts and combines selectivities; it does not execute a row, call a SQL routine or publish a plan. Its input is a scalar expression e, borrowed statistics S and an optional production control C; its output is either the existing bounded selectivity or a typed resource failure. SQL retains ownership of cast semantics and destination construction. A borrowed constant contributes no new allocation, while an allocating cast returns `Produced<Value>` and keeps its reservation alive until comparison is complete. Nested casts retain the input while constructing the output; membership releases each item's result before producing the next. Native plan, node, local join and parameterized access costing forward the same request control, and prepared selection obtains that owner through Planner's executable service. Engine only supplies its existing resource and statistics adapters.

Define the interpretation of an ordinary, typed or resident retained literal as its existing immutable Value. SQL's retained membership view exposes the same array elements and original order without reading or decoding a stored constant. Opaque or spilled values remain unknown to this observation. The scalar-array operator identity, dimension restriction and empty-ALL exclusion are unchanged, so recognizing a resident array preserves the same equality-set or three-valued negation input previously exposed by an ordinary array. Retrieval still excludes temporal carriers from physical set lowering, removes NULL from positive equality sets and rejects a negated set containing NULL; identity candidate extraction keeps its original admissible key domain. Sharing changes neither the represented SQL value nor those consumers' safety checks.

For an eligible constant cast, SQL's controlled and ordinary constructors have the same source, target and conversion order. On success they therefore yield equal Values; a reservation changes ownership, not interpretation. By induction over nested casts, the scalar estimator receives the same literal or the same best-effort unknown result from a non-resource conversion failure. RHS-first literal selection is unchanged, so an unused LHS cast is neither evaluated nor admitted. Equal/NotEqual now share one computed equality estimate: with non-NULL fraction n and equality estimate q, their estimates remain q and clamp(n-q), respectively. This removes the former second conversion for NotEqual without changing either formula. Boolean products, complements and membership/fusion sums preserve traversal, floating-point operation order, clamping and the sum identity's signed zero. Column lookup, MCV frequencies, null fractions, histograms and access-cost coefficients are unchanged. Induction over scalar composition establishes identical estimates for ordinary values; resident representations now receive their corresponding ordinary-value estimates instead of an unrelated fallback.

With a controlled request, failed admission and cancellation propagate as `53200` and `57014` instead of becoming heuristic selectivities. The existing first-catalog-error recorder retains its ordering when a callback has already failed. No candidate is published on costing failure. Every produced cast owns its lease, and Rust destruction frees its Value before its reservation on success, conversion failure, cancellation or unwind. Ancestor and sibling allowances are unchanged after release. This correction admits cast destinations and preserves resident observations; catalog/index metadata and the remaining plan/rewrite producers still require their separate owners; predicate-reference groups use the owner described above. It introduces no new SQL operation or approximation and establishes allocation bounds rather than controlled latency evidence.

## Prepared executable sharing and preservation

A prepared entry retains a logical-definition identity L, an optional generic executable G, its dependency observations and usage history U. Selection takes the existing ordered inputs (entry, current catalog, parameter values, cache mode), checks freshness and result shape, chooses custom or generic work and publishes against L only after success. SQL now represents the cached executable and selected execution by strong references to one immutable plan. A new generic result moves into that owner after optimization and costing; reuse retains another reference without copying its tree. Custom plans and descriptor-projected generic plans receive separate owners. Engine lookup, SQL effect inspection, named execution, SQL routine execution and PL/pgSQL statement/cursor selection carry these references to their existing borrowed consumers.

Let contents(H) be the complete plan stored by a handle H, including scalar values, relation/routine identities, source order and existing shared descriptors. Relate the old and new prepared states when L, dependencies and U are equal and every old owned generic or selected plan equals contents of its corresponding new handle. Generic creation preserves this relation because moving an optimized value into an owner preserves every field. Reuse preserves it because the old deep copy has the same contents as the shared source. Custom specialization and composite projection preserve it because they still operate on separate owned plans with the same inputs and traversal order; neither mutates G. Borrowed execution observes the same plan and invoking parameters, so rows, order, diagnostics, lazy scalar demand and volatile effects are identical. This representation change introduces no query operation, reordering or numerical approximation, and consequently preserves composition with every existing query operator under the same validity preconditions.

Publication uses the same original logical identity L, not executable ownership, and retains the original metadata/cost/count updates. Replacement or deallocation during a callback therefore rejects stale publication exactly as before. On analysis, optimization, projection or costing failure there is no publication; temporary references and independently owned candidates drop during return or unwind. Invalidation and deallocation remove only the cache's reference, leaving an already selected execution alive. The executable is freed when its last actual owner releases it. This is storage sharing, not cross-definition or cross-parameter execution reuse: parameter binding, catalog validation, generic/custom policy and composite interpretation retain their existing boundaries. Initial tree construction, mutable copies, plan-owner allocation and metadata admission remain explicit unfinished requirements; sharing does not establish full native planning accounting.

## Scalar translation workspace and preservation

For a selected `substring(text, text, text)` call with a nonconstant input and constant pattern p and escape e, PostgreSQL planning observes the translation T(p, e) before any input row exists. T maps the two immutable SQL values to a translated string, strict NULL or the existing escape/separator diagnostic. The call itself remains executable. Planner retains the existing eligibility order: selected builtin identity, constant operands, strict-NULL or fully constant handling, and permission to inline the SQL wrapper. Unreachable conditional arms remain outside this observation. Only an eligible translation receives the invoking production control; Engine still supplies the request's existing allowance and cancellation handles through the statement-planning adapter.

The old check passed copies p' and e' with the same value representation as p and e to SQL's escape kernel. The new check lends p and e directly to that same kernel. Neither input is mutated, and all conversions, character traversal, escaping, separator validation and result construction remain in their original order. Therefore T(p', e') = T(p, e), including the first SQL diagnostic, whenever resource admission succeeds and the request is not cancelled. The translation result is discarded in both representations without executing the substring call. Replacing this check in any existing plan consequently preserves its query operations, row demand, NULL behavior, result values and volatile effects; there is no new algebraic operator, numerical approximation or change to prepared-plan selection.

SQL's existing conversion and string producers acquire each buffer reservation before construction. Their `Produced` owners retain those reservations until the corresponding input or translated output is dropped, including partial construction, errors and unwinding. The check returns no retained output, so its reservations are all released before planning continues and must not appear in a later live-memory snapshot. A failed reservation or cancellation exits through the existing typed error and transaction-completion boundary. Parent/sibling allowances are unchanged except for the temporary live reservations. This correction covers the translation workspace and avoids its redundant ordinary-operand copies; it does not establish admission for general scalar folding, retained/spilled value reads, catalog-expression configuration or the complete plan owner.

A source owner consists of a value v and its constructor lease M, and a metadata owner consists of its immutable fields and their constructor leases plus the shared header. Cloning creates only another strong reference. For any positive number of references, the owners and M remain live; the final drop frees the payloads and releases each reservation exactly once. No mutable dereference permits new allocations beneath an old lease. An enclosing expression consumes intermediate owners in its existing evaluation order; once replaced or rejected, their leases disappear with the corresponding values. Header-admission failure drops the candidate and its existing leases. Read-only inference, comparison and copying cannot mutate a stored constant or introduce another evaluation of its original SQL expression. This is a representation change, not a query operator or new numerical approximation, so substitution into existing relational, retrieval, graph and ranked compositions preserves their operations and ordered effects whenever admission succeeds.

VALUES retains its existing bounded constant-storage owner and encrypted spill policy. A produced value stays leased until that owner has accepted its encoded representation. Decoding transfers the value's leases to its returned owner and releases the temporary encoded buffer independently. It does not dereference lazy physical-datum offsets. Map entries retain Core's existing logical key/value payload admission; opaque standard-library node bookkeeping remains outside the exposed payload boundary. Failures retain SQLSTATE 53200 or 57014 and use the existing statement and transaction completion paths.

Schema, rule, domain-check and ALTER USING optimization obtain the same request resources through the existing expression-planning service. Engine only supplies that service and request handles; it contains no new scalar or allocation algorithm. This correction does not complete all native allocation admission: initial and mutable IR copies, type-analysis and inline-literal metadata production, composite-specific folding, assignment coercion, identity materialization, retained-storage encoding and the remaining join/rewrite scratch remain in the open producer inventory. The measurement boundary below remains independent of these unfinished admission paths.

## Owned query optimization and preservation

Source preparation owns a private query P after restoring its binding layouts and applying the invoking source's output demand. The previous Execution callback lent P to Planner, which cloned its complete tree before applying the optimizer O and returned O(copy(P)); the caller then discarded P. The callback now consumes P, and Planner receives an owned Cow that moves directly into the same optimizer boundary. Borrowed CTAS and materialized-view inputs use the borrowed alternative and still receive a separate mutable destination. Engine only forwards the existing context and explicit ownership alternative; the optimizer remains in Planner.

Define contents(P) as all executable fields, ordered children, scalar values, selected identities, analysis descriptors and shared retained owners in P. Moving P preserves contents(P) and every allocation identity. A structural clone previously preserved those contents as well, so O receives the same complete input and invokes the same passes, metadata providers and scalar evaluators in the same order. Resource acquisition, layout restoration, privilege scopes and source publication retain their existing relative order. Therefore the returned plan has the same meaning, lazy diagnostic demand, volatile effects and subsequent streaming/materialization behavior. This argument uses the established preservation obligations of O and introduces no additional rewrite, approximate cost or algebraic operator.

The consumed input already belongs exclusively to this invocation: stored view and cached definition trees remain with their original immutable owners. On ordinary failure or unwind, the optimizer destroys its input; the caller cannot publish or retain a second copy. On success, the returned query becomes the sole owner of the transformed mutable tree. Shared descriptors and constants keep their existing lifetimes. The borrowed utility alternative continues to isolate its source, so mutating one optimization result cannot affect a later invocation. No caller-side reset or recovery path is added.

This correction removes the redundant full copy between two existing owners. It does not admit the initial catalog/source copy, ordinary borrowed optimization destinations, enclosing plan boxes or later source attachments; those remain in the native producer inventory. Exact pointer and allocation regressions verify ownership transfer, while independent native SQL references verify the existing source behaviors. ## EXPLAIN executable selection and preparation

Let L be an analyzed logical query or mutation, O its native optimizer, P the executable returned by prepared selection, and S the invocation's named-source preparation. Direct EXPLAIN must interpret its options and check an existing relation destination before optimizing L. EXPLAIN EXECUTE must describe the executable selected for its bound arguments, cache mode and current dependencies. SQL's borrowed `PlanRef` exposes the same query or command fields as its containing statement without allocating a second wrapper tree. Utility dispatch now borrows its relational child until the optimizer constructs its one mutable destination. Plain query and mutation dispatch retain that same preparation order.

For ordinary EXPLAIN, the previous path optimized copy(copy(L)) for a utility and copy(L) for a direct executable. A structural copy preserves every scalar value, node order, relation identity and shared descriptor, so O(copy(copy(L))) and O(copy(L)) have identical inputs and behavior. Removing the first copy changes allocation ownership only. The utility destination continues to retain its original command and stored query, including materialized-view publication; it is not replaced by the optimized query. The ordinary mutable optimizer copy remains an unfinished admission requirement.

Prepared selection already completes analysis, constant folding, optimization, costing and identity-checked publication before returning P. Execution now borrows P instead of invoking the optimizer on another deep copy. The chosen P remains the object described and executed. This does not assume that physical optimizer passes are structurally idempotent: the contract is to describe the selected executable. Query meaning is preserved because each applicable optimizer rewrite preserves the denotation of its input; both P and any former second optimization of P therefore denote the same query under the rewrite's established preconditions. Parameter binding, cache selection, freshness checks and publication counters remain in their original selector. Deferred utility bodies retain their own existing preparation boundary. No new algebraic operation or numerical approximation is introduced.

Named-source preparation still follows relation locking and precedes routine authorization, memory capture and optional execution. An exclusively owned ordinary EXPLAIN destination lends S its mutable query directly. A selected immutable executable lends S a shared query; S returns that same query when no attachment is required and constructs a private destination otherwise. Therefore no preparation can modify a cached executable or another active invocation. The new enclosing query box is admitted before allocation and destroyed before its reservation on success, SQL error or unwind. Source-preparation payload copies and new attachments retain their existing owners and remain part of the unfinished producer inventory; the box lease is not a claim that those payloads are already admitted.

Independent PostgreSQL EXPLAIN references and native provider tests verify the observable ordering and effects. Allocation regressions distinguish selected-plan borrowing from a second tree copy and compare utility extraction with the same direct query. The large mutation renderer legitimately exposes input-dependent diagnostic text, so its output size is outside the constant-workspace query-copy assertion; its prepared execution, recovery and cache invalidation are verified separately.

## EXPLAIN measurement boundary

The independent contract is [PostgreSQL 18 EXPLAIN](https://www.postgresql.org/docs/18/sql-explain.html) and its [planner measurement boundary](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/commands/explain.c). Execution captures the selected executable after optimization, source preparation and routine privilege initialization, before constructing diagnostic plan/cost/settings output or executing the statement. SQL owns the exhaustive executable-storage traversal; Core observes actual exposed layouts and retains its diagnostic workspace under the invoking request's allowance and both cancellation scopes. Engine supplies its existing request/session adapters. The observation does not establish admission for earlier plan construction; the remaining producer-admission requirements below are unchanged.

Define the observation domain A(P) as the live allocation layouts reached from the selected executable P through its exclusively owned boxes, strings, vectors, owned map/set nodes, scalar and type metadata, query/source/mutation children and retained constant owners. Value arrays, rows, records and tuple views expose their actual backing layouts; shared tuple, field-descriptor and constant-source identities enter the observation once. Each container contributes its live element layouts to used bytes and its actual capacity to allocated bytes; a fixed-size box or owned tree node contributes its complete layout to both. Inline members are part of the enclosing layout and are never separately charged. Vacated vector slots contribute only allocated capacity. Released optimizer scratch contributes neither. Constants stored in the bounded spill owner contribute their resident encoded buffers without reading, decoding or copying a value; spilled payload contributes no resident bytes.

The boundary excludes separately owned immutable SQL analysis/catalog descriptors, executor row sources and spill-file service owners, along with parsing, unrelated session caches, output buffers and observation workspace. Rust allocator/refcount bookkeeping, private BigInt capacity and standard B-tree node layouts are unavailable through their existing public interfaces and are excluded, while exposed key/value payloads remain observable. These are explicitly unmeasured allocations, not zero-sized estimates. No dependency is modified and no conservative admission bound, serialized plan size, process allocator count or request-wide peak is reported as measured capacity. Consequently these fields describe the exposed live executable and constant storage, not total process memory or all dependency-private allocations.

For every allocation a in A(P), its observed live layout u(a) and capacity c(a) satisfy 0 <= u(a) <= c(a). The traversal invariant is that completed allocations have contributed exactly once, and every remaining directly owned child is queued once while every registered shared identity is visited once. Exhaustive field/variant matches establish this invariant inductively: inline nodes contribute no second layout; boxes contribute their layout then their payload children; vectors contribute their contiguous layout and visit each initialized element; shared owners register identity before visiting payloads. The finite acyclic owned IR and deduplicated shared resources terminate with U(P) = sum u(a) and C(P) = sum c(a), so U(P) <= C(P). Checked arithmetic rejects overflow. The iterative vector and document-map cursors retain one frame regardless of width; its admitted stack and shared-identity index are dropped on success, memory rejection or cancellation. Their reservations affect the existing request allowance but never enter U(P) or C(P).

Let E(P) be the existing execution observation, including rows, order, diagnostics and effects. The observation borrows P immutably, never invokes scalar evaluation, constant readers, catalog callbacks or spill-file I/O, and does not replace its plan. Therefore E(P) before and after successful observation is identical. This introduces no query operator, so every existing relational, retrieval, graph and ranked composition retains its original operands and meaning. On failure, execution has not begun and the existing statement/transaction owner handles the typed diagnostic and rollback; no caller repairs its state. MEMORY FALSE skips observation entirely. Conversion of each nonnegative byte count b to ceil(b/1024) is monotone and preserves used <= allocated, with quotient/remainder arithmetic avoiding overflow.

The same capture follows selected direct, generic/custom prepared, reused and invalidated plans. DECLARE observes its query; CTAS and materialized-view paths observe their source after the existing target check. A skipped destination has no planning-memory observation. ANALYZE executes the selected body once after capture, retaining ordinary mutation and rollback behavior. The independent fixture `tests/parity/pg18/explain_memory.expected.json` contains 429 ordered PostgreSQL 18.4 SQL cases, including 188 format/option observations and exact sequence/state checks. Provenance retains the Docker image and both collector hashes. PostgreSQL byte totals and timing are intentionally not compared. The native replay covers TEXT/JSON/XML/YAML, MEMORY true/false, SUMMARY, TIMING and BUFFERS, forced generic/custom/automatic selection, reuse/invalidation, DECLARE, CTAS, materialized views, WITH NO DATA and existing destinations on all four providers.
