## Join search representation and preservation

For a valid join graph with at most 64 relations, let a subset be its existing `u64` relation mask. A retained decision consists of that mask, estimated rows, cost, child subset masks, selected edge and physical operator kind. These fields contain no separately allocated payload. Memo storage admits its exact nodes, temporary layers admit vector capacity, and the selected output admits each boxed node before construction. Removed scratch releases its own reservations; output reservations survive until the produced tree is dropped.

The representation change introduces no algebraic operator. Define expansion of a leaf decision as its relation scan, and expansion of a binary decision as the existing join applied to the expansions of its children. Every child is a strict subset of its parent, so expansion terminates. In exact enumeration, all smaller subsets are settled before a larger subset is visited. In greedy search, a consumed child subset is never rewritten. In the star search, selected prefixes are reconstructed from the completed predecessor table. Thus each retained child reference denotes the same settled child that the earlier implementation copied.

Induction on subset cardinality proves representation preservation: leaf rows/costs and relation masks are identical; a binary candidate uses the same ordered operands, ordered edge selectivities, physical cost function and floating-point operation order, so its rows and cost are identical. Preserving candidate visitation order and strict cost comparison preserves ties and the selected decision. Expanding that decision therefore yields the same ordered tree, including disconnected-component cross joins and their stable cardinality order. This claim does not assume join commutativity for volatile SQL expressions: eligibility and predicate attachment remain in their existing SQL/Planner owners and are unchanged by decision storage.

Successful admission preserves this observation exactly. A failed reservation or either cancellation token terminates before constructing the rejected allocation; RAII drops all local containers and output nodes with their leases. Failure publishes no plan. This proof obligation must be checked against the completed implementation and its exact/greedy/star/disconnected tests before the corresponding task is marked complete.

The join-order adapter now constructs graph labels, row/access estimates and ordered edges through the same production control as enumeration. Its alias index borrows names in a sorted fixed array whose capacity is the graph's established 64-relation domain. Each alias maps to the original declaration index; sorting the index changes neither relation masks nor edge order. Relation count, cardinality, access cost and duplicate-alias validation retain their original order, followed by left/right predicate resolution. Singleton input retains its existing predicate handling. The graph's buffers and label leases remain alive during enumeration and are released before the selected tree escapes; borrowed statistics remain with the input owner.

The ordinary consuming adapter moves each relation into its selected leaf instead of cloning its statistics. Every selected binary node partitions its relation mask into disjoint child masks, and the root covers all input relations. Induction therefore gives exactly one leaf for each relation, making the move total and unique. A relation pair crosses the children of exactly one node, its lowest common ancestor, so a selected condition's strings can also move out of the existing last-predicate-per-pair lookup. Enumeration retains the first crossing edge in original edge order, the same edge the previous materializer found. These ownership transfers preserve the original tree, relation metadata, primary alias and condition orientation while avoiding a second metadata allocation. The standalone adapter retains its ordinary allocation mode; the native SQL rewrite's remaining copies still require admission.

Scalar costing now reads the same immutable column map through a borrowed row-count/statistics observation, and literal extraction borrows existing values while retaining owned results of actual casts. A borrowed value has the same comparison inputs as its previous clone; column lookup, MCV/null fractions, histogram inputs and ordered floating-point operations are unchanged. Induction over the scalar expression therefore preserves every estimate, including the existing fallback when a constant cast cannot produce a value. Local filter costing borrows a single predicate and reconstructs multiple conjuncts in their original order; the preferred provider is still called once before fallback costing, with the same expression value. The row count is captured with the same rounding before updating the relation. This changes storage ownership only, without evaluating the query, widening literal interpretation or changing lazy diagnostics. Controlled cast production, predicate-reference grouping and selected output ownership are covered below; other source attachments, catalog/index and mutable-plan production remain in the open native inventory.

For multiple local predicates, Planner admits the conjunction vector before filling it, and each child enters through SQL's controlled scalar copier. The vector and child leases move together into the immutable conjunction without another allocation. Component-wise scalar-copy preservation and unchanged child order establish equality with the previous `And` expression; no new evaluation or boolean transformation occurs. The conjunction remains alive through the provider estimate and fallback formula, and its storage is freed before its lease on ordinary return, invalid estimates or unwind. A partial copy never reaches the provider. Insufficient ancestor allowance or either cancellation token releases all constructed children, leaving the source predicates and sibling reservations intact. This owner accounts for the actual temporary expression. Reference grouping, cast destinations and selected output have their own production boundaries below; other source attachments, catalog/index and mutable-plan production remain open.

Native optimization now captures the invoking request's existing memory allowance and cancellation token after SQL analysis succeeds. Cloning those handles preserves allowance identity rather than establishing a new limit. Every recursive join walk forwards that control unchanged through query, CTE, scalar-subquery, DML and cursor boundaries. Standalone planning retains its ordinary uncontrolled mode; Engine always supplies the native owner. The admitted graph and selected tree remain alive through SQL source materialization, and all exits release their leases. This connects graph/search admission; selected predicate output is covered below, while statistics collection and other mutable-plan storage remain open.

The native materializer consumes the selected tree directly without constructing an unused intermediate join descriptor. A leaf mask's bit index is its original relation index, which equals the source atom's index by construction. For each binary node, the previous descriptor maps an absent edge to the automatic strategy and a selected inner-hash edge to the hash strategy. Direct materialization makes those same choices and recursively retains child order; induction on the selected tree therefore proves equality with the previous composed materializers. Predicate attachment runs unchanged after materialization. Allocation rejection publishes no replacement source. The existing transaction owner continues to apply failure and savepoint recovery; the planner introduces no admission guard or transaction reset.

Selected SQL materialization now transfers the original source boxes and values instead of copying them. An eligible binary source with n leaves has n leaf boxes and n-2 boxed internal nodes, because its root is held by value. Here 2 <= n <= 64, so fixed arrays of 64 and 62 box slots retain the original allocations without heap scratch. Collection preserves the original left-to-right leaf indices. The selected tree partitions its root mask into disjoint child masks and covers every input leaf exactly once; consequently, materialization consumes each leaf box once and exactly n-2 internal boxes. It preserves the selected child order and physical strategy while moving each entire leaf, including executable query bodies, scalar arguments and retained bindings. No new source-node or leaf-payload allocation occurs.

Original ON predicates remain borrowed during graph selection. After successful selection, collection moves their scalar values into the corresponding prepared metadata slots. Both borrowed discovery and owned collection visit left child, right child and then the node's recursively flattened AND items in order, establishing a one-to-one order-preserving correspondence. Inferred WHERE predicates retain separate output storage and are copied only after successful selection. The unchanged attachment rule therefore receives the same ordered expressions and qualifiers as before, preserving values, selected identities and evaluation placement without cloning the original payloads. Unavailable estimates, memory rejection and either cancellation scope exit before ownership transfer, leaving the original source intact. The inference and executable-output sections below cover borrowed keys, admitted slot buffers, selected scalar copies and output conjunctions.

Statistics catalog operations now retain typed SQL errors instead of erasing the provider cause into text. The adapter uses Execution's existing storage-to-SQL mapping, and the statistics owner keeps its original first-error order. Memory and cancellation failures therefore retain `53200` and `57014` through redb as through the other providers. Successful metadata and estimate observations are unchanged; the corrected diagnostic remains inside the same statement failure boundary.

## Borrowed column resolution and preservation

## Join predicate inference and preservation

Inference now retains references to the original simple column equalities and their canonical endpoint keys. Core's copy-only `ProductionMap` reserves each complete ordered-map node before insertion and frees a removed node before releasing its lease. AND union, OR intersection and their removal-key buffers use the invoking production control. The accumulated inferred references and graph-predicate views also use admitted buffers. Predicate slots admit their private fixed-capacity buffer before filling it; their scalar payloads retain separate source or output ownership. No operation exposes growth of that buffer after admission.

Let K(e) be the existing canonical pair of resolved (relation alias, column name) endpoints for an eligible equality e. Let I(e) map each inferred key to its first representative expression: an equality contributes its singleton, an AND contributes the ordered union of its children with first insertion retained, an OR contributes the intersection of all child key sets with representatives from its first child, and other forms contribute nothing. This definition is unchanged. Borrowed strings compare identically to their earlier owned copies. Induction over e therefore establishes identical key sets, canonical iteration order, first representatives and operand orientation. Union and intersection inspect expression structure only; they invoke no SQL evaluation, constant read or provider callback. The existing empty-intersection stopping order is retained.

For the eligible pure column equalities, these rules preserve the existing implication argument under SQL's three-valued Boolean logic: a true conjunction has every conjunct true, and a true disjunction has a true branch; a key required by every branch is therefore true whenever the disjunction is true. A NULL equality is never true and cannot cause an additional matching row. The original WHERE expression remains as its semantic guard. This representation change adds no inferred predicate, changes no equality orientation and introduces no new optimizer transformation; every prior graph edge and attached scalar remains the same expression value.

An eligible join has distinct aliases indexed from 0 through n-1, where n <= 64. The map from alias subsets to relation masks is a bijection and preserves union and subset inclusion. A pushable predicate's previous qualifier set consists exactly of its two resolved aliases, so testing that its mask is contained in a selected node's relation mask is equivalent to the previous qualifier-subset test. Non-pushable predicates retain a zero mask and attach only at the root. Materialization follows the selected tree, so each node's mask denotes exactly its available source aliases. ## Owned query optimization and preservation

Source preparation owns a private query P after restoring its binding layouts and applying the invoking source's output demand. The previous Execution callback lent P to Planner, which cloned its complete tree before applying the optimizer O and returned O(copy(P)); the caller then discarded P. The callback now consumes P, and Planner receives an owned Cow that moves directly into the same optimizer boundary. Borrowed CTAS and materialized-view inputs use the borrowed alternative and still receive a separate mutable destination. Engine only forwards the existing context and explicit ownership alternative; the optimizer remains in Planner.

Define contents(P) as all executable fields, ordered children, scalar values, selected identities, analysis descriptors and shared retained owners in P. Moving P preserves contents(P) and every allocation identity. A structural clone previously preserved those contents as well, so O receives the same complete input and invokes the same passes, metadata providers and scalar evaluators in the same order. Resource acquisition, layout restoration, privilege scopes and source publication retain their existing relative order. Therefore the returned plan has the same meaning, lazy diagnostic demand, volatile effects and subsequent streaming/materialization behavior. This argument uses the established preservation obligations of O and introduces no additional rewrite, approximate cost or algebraic operator.

The consumed input already belongs exclusively to this invocation: stored view and cached definition trees remain with their original immutable owners. On ordinary failure or unwind, the optimizer destroys its input; the caller cannot publish or retain a second copy. On success, the returned query becomes the sole owner of the transformed mutable tree. Shared descriptors and constants keep their existing lifetimes. The borrowed utility alternative continues to isolate its source, so mutating one optimization result cannot affect a later invocation. No caller-side reset or recovery path is added.

This correction removes the redundant full copy between two existing owners. It does not admit the initial catalog/source copy, ordinary borrowed optimization destinations, enclosing plan boxes or later source attachments; those remain in the native producer inventory. Exact pointer and allocation regressions verify ownership transfer, while independent native SQL references verify the existing source behaviors. These checks are not controlled-host latency acceptance.

## EXPLAIN measurement boundary

The independent contract is [PostgreSQL 18 EXPLAIN](https://www.postgresql.org/docs/18/sql-explain.html) and its [planner measurement boundary](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/commands/explain.c). Execution captures the selected executable after optimization, source preparation and routine privilege initialization, before constructing diagnostic plan/cost/settings output or executing the statement. SQL owns the exhaustive executable-storage traversal; Core observes actual exposed layouts and retains its diagnostic workspace under the invoking request's allowance and both cancellation scopes. Engine supplies its existing request/session adapters. The observation does not establish admission for earlier plan construction; the remaining producer-admission requirements below are unchanged.

Define the observation domain A(P) as the live allocation layouts reached from the selected executable P through its exclusively owned boxes, strings, vectors, owned map/set nodes, scalar and type metadata, query/source/mutation children and retained constant owners. Value arrays, rows, records and tuple views expose their actual backing layouts; shared tuple, field-descriptor and constant-source identities enter the observation once. Each container contributes its live element layouts to used bytes and its actual capacity to allocated bytes; a fixed-size box or owned tree node contributes its complete layout to both. Inline members are part of the enclosing layout and are never separately charged. Vacated vector slots contribute only allocated capacity. Released optimizer scratch contributes neither. Constants stored in the bounded spill owner contribute their resident encoded buffers without reading, decoding or copying a value; spilled payload contributes no resident bytes.

The boundary excludes separately owned immutable SQL analysis/catalog descriptors, executor row sources and spill-file service owners, along with parsing, unrelated session caches, output buffers and observation workspace. Rust allocator/refcount bookkeeping, private BigInt capacity and standard B-tree node layouts are unavailable through their existing public interfaces and are excluded, while exposed key/value payloads remain observable. These are explicitly unmeasured allocations, not zero-sized estimates. No dependency is modified and no conservative admission bound, serialized plan size, process allocator count or request-wide peak is reported as measured capacity. Consequently these fields describe the exposed live executable and constant storage, not total process memory or all dependency-private allocations.

For every allocation a in A(P), its observed live layout u(a) and capacity c(a) satisfy 0 <= u(a) <= c(a). The traversal invariant is that completed allocations have contributed exactly once, and every remaining directly owned child is queued once while every registered shared identity is visited once. Exhaustive field/variant matches establish this invariant inductively: inline nodes contribute no second layout; boxes contribute their layout then their payload children; vectors contribute their contiguous layout and visit each initialized element; shared owners register identity before visiting payloads. The finite acyclic owned IR and deduplicated shared resources terminate with U(P) = sum u(a) and C(P) = sum c(a), so U(P) <= C(P). Checked arithmetic rejects overflow. The iterative vector and document-map cursors retain one frame regardless of width; its admitted stack and shared-identity index are dropped on success, memory rejection or cancellation. Their reservations affect the existing request allowance but never enter U(P) or C(P).

Let E(P) be the existing execution observation, including rows, order, diagnostics and effects. The observation borrows P immutably, never invokes scalar evaluation, constant readers, catalog callbacks or spill-file I/O, and does not replace its plan. Therefore E(P) before and after successful observation is identical. This introduces no query operator, so every existing relational, retrieval, graph and ranked composition retains its original operands and meaning. On failure, execution has not begun and the existing statement/transaction owner handles the typed diagnostic and rollback; no caller repairs its state. MEMORY FALSE skips observation entirely. Conversion of each nonnegative byte count b to ceil(b/1024) is monotone and preserves used <= allocated, with quotient/remainder arithmetic avoiding overflow.

The same capture follows selected direct, generic/custom prepared, reused and invalidated plans. DECLARE observes its query; CTAS and materialized-view paths observe their source after the existing target check. A skipped destination has no planning-memory observation. ANALYZE executes the selected body once after capture, retaining ordinary mutation and rollback behavior. The independent fixture `tests/parity/pg18/explain_memory.expected.json` contains 429 ordered PostgreSQL 18.4 SQL cases, including 188 format/option observations and exact sequence/state checks. Provenance retains the Docker image and both collector hashes. PostgreSQL byte totals and timing are intentionally not compared. The native replay covers TEXT/JSON/XML/YAML, MEMORY true/false, SUMMARY, TIMING and BUFFERS, forced generic/custom/automatic selection, reuse/invalidation, DECLARE, CTAS, materialized views, WITH NO DATA and existing destinations on all four providers.
