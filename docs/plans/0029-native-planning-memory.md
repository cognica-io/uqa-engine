## Ownership and allocation inventory

Core owns reservations and containers. SQL owns executable-plan and scalar storage, copying, binding and typed result contracts. Planner owns rewrites, cardinality/cost calculations, join enumeration and EXPLAIN rendering. Execution owns statement preparation and diagnostics sequencing; Engine supplies request/session adapters. The existing Cargo features and dependency policy allow these directions without adding a dependency or moving algorithms into Engine.

| Owner and path | Escaping allocation or lifetime | Required correction |
| --- | --- | --- |
| SQL `plan/copy`, `scalar` copy interfaces | Existing controlled copies return immutable produced values; ordinary `Clone` callers bypass them | Preserve exact pre-admission and immutable shared descriptors; introduce only owner operations that retain the destination leases through subsequent transformations |
| Planner `statement_planning/executable` | Cached analysis uses `cloned()`; query optimization clones and boxes the whole query | Borrow or consume existing plans where possible; otherwise copy through SQL's admitted owner operation |
| Planner `optimizer` traversal and transformations | Derived/CTE projection, pull-up, predicate rewrite, scalar folding, routine inlining and join rewriting allocate replacement plans and scratch | Admit each destination before construction; free discarded storage before releasing its lease; preserve lazy constants, selected routine identities, diagnostics and traversal order |
| Planner `join_enumerator` | Candidate costing recursively clones complete subtrees, allocates edge lists, connected sets, layers and star-state buffers | Retain copy-only decisions keyed by relation subsets, cost borrowed edges, admit memo/layer/state buffers and materialize only the selected tree; preserve the existing search order and cost rules |
| Planner `join_order`, `optimizer/join_reorder` | Graphs, aliases, statistics, atoms and predicates are copied; final trees copy their selected children again | Borrow metadata, move selected owned subtrees and admit unavoidable graph/output storage under the same request |
| Planner `cardinality/relational`, local join-filter costing | Literal/membership payloads and full column statistics were cloned for read-only estimates; compound local predicates and constant casts can produce owned storage | Literal/statistics observations now borrow their owners, and compound predicates retain admitted copies through costing; cast outputs and predicate-group scratch remain required |
| Engine `capabilities/statements` | EXPLAIN passes `body.clone()` into Planner | Pass the request context and borrowed input to the owning planning operation |
| Execution `statement/plan_executor/explain` | Cursor, CTAS and materialized-view paths clone query bodies; prepared EXPLAIN has an additional selection boundary | Preserve utility/prepared scheduling while retaining the selected plan and its admission through observation and execution |
| SQL `result/explain`, Planner `explain/planning` | Planning metrics carry I/O only; MEMORY is parsed without output | Add typed owner measurements and TEXT/JSON/XML/YAML rendering independent of buffer and timing visibility |

This inventory is an implementation checklist, not permission to account after allocation. Process allocator totals, guessed sizes, request-wide peaks and disabled optimizer passes cannot substitute for ownership. Shared immutable metadata remains with its existing owner; copied destinations require independent leases. Dependency sources, logging and the C API are outside this group.

## Join search representation and preservation

For a valid join graph with at most 64 relations, let a subset be its existing `u64` relation mask. A retained decision consists of that mask, estimated rows, cost, child subset masks, selected edge and physical operator kind. These fields contain no separately allocated payload. Memo storage admits its exact nodes, temporary layers admit vector capacity, and the selected output admits each boxed node before construction. Removed scratch releases its own reservations; output reservations survive until the produced tree is dropped.

The representation change introduces no algebraic operator. Define expansion of a leaf decision as its relation scan, and expansion of a binary decision as the existing join applied to the expansions of its children. Every child is a strict subset of its parent, so expansion terminates. In exact enumeration, all smaller subsets are settled before a larger subset is visited. In greedy search, a consumed child subset is never rewritten. In the star search, selected prefixes are reconstructed from the completed predecessor table. Thus each retained child reference denotes the same settled child that the earlier implementation copied.

Induction on subset cardinality proves representation preservation: leaf rows/costs and relation masks are identical; a binary candidate uses the same ordered operands, ordered edge selectivities, physical cost function and floating-point operation order, so its rows and cost are identical. Preserving candidate visitation order and strict cost comparison preserves ties and the selected decision. Expanding that decision therefore yields the same ordered tree, including disconnected-component cross joins and their stable cardinality order. This claim does not assume join commutativity for volatile SQL expressions: eligibility and predicate attachment remain in their existing SQL/Planner owners and are unchanged by decision storage.

Successful admission preserves this observation exactly. A failed reservation or either cancellation token terminates before constructing the rejected allocation; RAII drops all local containers and output nodes with their leases. Failure publishes no plan. This proof obligation must be checked against the completed implementation and its exact/greedy/star/disconnected tests before the corresponding task is marked complete.

The join-order adapter now constructs graph labels, row/access estimates and ordered edges through the same production control as enumeration. Its alias index borrows names in a sorted fixed array whose capacity is the graph's established 64-relation domain. Each alias maps to the original declaration index; sorting the index changes neither relation masks nor edge order. Relation count, cardinality, access cost and duplicate-alias validation retain their original order, followed by left/right predicate resolution. Singleton input retains its existing predicate handling. The graph's buffers and label leases remain alive during enumeration and are released before the selected tree escapes; borrowed statistics remain with the input owner.

The ordinary consuming adapter moves each relation into its selected leaf instead of cloning its statistics. Every selected binary node partitions its relation mask into disjoint child masks, and the root covers all input relations. Induction therefore gives exactly one leaf for each relation, making the move total and unique. A relation pair crosses the children of exactly one node, its lowest common ancestor, so a selected condition's strings can also move out of the existing last-predicate-per-pair lookup. Enumeration retains the first crossing edge in original edge order, the same edge the previous materializer found. These ownership transfers preserve the original tree, relation metadata, primary alias and condition orientation while avoiding a second metadata allocation. They do not yet admit the ordinary adapter's final descriptor tree or the native SQL rewrite's remaining copies.

Scalar costing now reads the same immutable column map through a borrowed row-count/statistics observation, and literal extraction borrows existing values while retaining owned results of actual casts. A borrowed value has the same comparison inputs as its previous clone; column lookup, MCV/null fractions, histogram inputs and ordered floating-point operations are unchanged. Induction over the scalar expression therefore preserves every estimate, including the existing fallback when a constant cast cannot produce a value. Local filter costing borrows a single predicate and reconstructs multiple conjuncts in their original order; the preferred provider is still called once before fallback costing, with the same expression value. The row count is captured with the same rounding before updating the relation. This changes storage ownership only, without evaluating the query, widening literal interpretation or changing lazy diagnostics. Owned cast outputs and predicate-group scratch still require admission in the complete native path.

For multiple local predicates, Planner admits the conjunction vector before filling it, and each child enters through SQL's controlled scalar copier. The vector and child leases move together into the immutable conjunction without another allocation. Component-wise scalar-copy preservation and unchanged child order establish equality with the previous `And` expression; no new evaluation or boolean transformation occurs. The conjunction remains alive through the provider estimate and fallback formula, and its storage is freed before its lease on ordinary return, invalid estimates or unwind. A partial copy never reaches the provider. Insufficient ancestor allowance or either cancellation token releases all constructed children, leaving the source predicates and sibling reservations intact. This owner accounts for the actual temporary expression only; it does not claim the remaining grouping maps or constant-cast destinations.

Native optimization now captures the invoking request's existing memory allowance and cancellation token after SQL analysis succeeds. Cloning those handles preserves allowance identity rather than establishing a new limit. Every recursive join walk forwards that control unchanged through query, CTE, scalar-subquery, DML and cursor boundaries. Standalone planning retains its ordinary uncontrolled mode; Engine always supplies the native owner. The admitted graph and selected tree remain alive through SQL source materialization, and all exits release their leases. This connects graph/search admission; it does not yet admit metadata gathering, final SQL source copies or other rewrite storage.

The native materializer consumes the selected tree directly without constructing an unused intermediate join descriptor. A leaf mask's bit index is its original relation index, which equals the source atom's index by construction. For each binary node, the previous descriptor maps an absent edge to the automatic strategy and a selected inner-hash edge to the hash strategy. Direct materialization makes those same choices and recursively retains child order; induction on the selected tree therefore proves equality with the previous composed materializers. Predicate attachment runs unchanged after materialization. Allocation rejection publishes no replacement source. The existing transaction owner continues to apply failure and savepoint recovery; the planner introduces no admission guard or transaction reset.

Statistics catalog operations now retain typed SQL errors instead of erasing the provider cause into text. The adapter uses Execution's existing storage-to-SQL mapping, and the statistics owner keeps its original first-error order. Memory and cancellation failures therefore retain `53200` and `57014` through redb as through the other providers. Successful metadata and estimate observations are unchanged; the corrected diagnostic remains inside the same statement failure boundary.

## EXPLAIN measurement boundary

The independent contract is [PostgreSQL 18 EXPLAIN](https://www.postgresql.org/docs/18/sql-explain.html) and its [planner measurement boundary](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/commands/explain.c). Capture UQA-owned live used bytes and allocated capacity after the selected plan has been produced and before executing it. Released scratch is not live memory; retained capacity and separately owned plan payloads must remain attributable. Parsing, unrelated session caches and execution output are not a substitute measurement. Compare field visibility, units and option behavior against independent PostgreSQL captures, never allocator-dependent byte equality. Prepared cache reuse and supported utility paths need explicit observations without a second execution.

The independent fixture `tests/parity/pg18/explain_memory.expected.json` contains 429 PostgreSQL 18.4 observations from `capture_explain_memory.py`, reusing the existing libpq capture helper. It checks direct option combinations, volatile sequence effects, forced generic/custom and automatic cache selection, cache reuse and invalidation, DECLARE, CTAS, materialized views, WITH NO DATA and existing destinations. Provenance retains the Docker image and both collector hashes. Actual allocator totals and timing are omitted; the collector verifies positive integer kilobytes and used space no greater than allocated space. Cache reuse still reports memory, while skipped creation has no planning-memory observation. The renderer owner tests replay the 96 direct format/option combinations; native replay of the complete transcript remains unfinished.

For a selected plan P, let E(P) be its existing execution observation, including rows, order, diagnostics and effects, and let M(P) be the planning owner's before-execution storage snapshot. Rendering adds M(P) only to the EXPLAIN observation when MEMORY is enabled. Its projection onto existing fields equals the original renderer, and it neither applies a query operator nor calls E. Thus adding the optional diagnostic preserves every existing query composition and execution observation; disabling MEMORY preserves the original output fields. Converting each nonnegative byte count b to ceil(b/1024) is monotone and preserves used <= allocated without overflow through quotient/remainder division. This argument depends on capturing M from the same selected owner without reexecution; that native integration remains a required implementation and test obligation, not an assumption of completion.
