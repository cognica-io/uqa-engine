## Preservation argument for output removal

Let \(D\) be the positional outputs demanded by a consumer. Replacing a pure unobserved output at \(i\notin D\) by a NULL with its analyzed type and collation preserves the positional descriptor and every observed value. The rewrite changes neither source rows nor filtering, grouping, slicing or duplicate counts. Original column reads remain in the authorization set. An output needed by ordering, DISTINCT, a set-producing expression or a volatile effect is not removed. Constant-error timing additionally follows PostgreSQL's member-pull-up and set-coercion boundaries, which are tested independently rather than inferred from value equivalence.

For bag union, \(m_{A\uplus B}(r)=m_A(r)+m_B(r)\). Applying the same positional demand independently to eligible members preserves both terms and therefore the observed bag, including duplicates; aliases map positions without changing member labels. Aggregate value elimination retains the aggregate compute phase, so an implicit group still emits one row for empty input. These arguments apply only to the guarded rewrites described above; they do not establish completion of joined/lateral propagation, predicate movement or consumer-driven execution.

For a join, required inputs are the union of consumer observations, ON/USING keys and the remaining right input's correlated references. Preserving those values preserves each matching decision and unmatched outer row, hence the observed bag multiplicities. An unused right-side LATERAL output is removed before collecting its producer demands, so it cannot keep an otherwise unobserved failing producer expression alive. SQL's analyzed physical slots distinguish duplicate labels, merged USING columns and alias hiding. Folded CTE consumers contribute positional demand before their producers are simplified, following SQL's dependency order and definition visibility; materialized and data-modifying boundaries retain their original value requirements. These arguments depend on the existing volatile, set-producing, ordering and typing guards; the independent PostgreSQL cases verify the observable error boundaries as well as rows.

For an ordinary definition at position \(i\), let \(E_i\) be its enclosing bindings extended by preceding local definitions and \(R_i\) the external names its body reads. Retaining \(E_i\vert_{R_i}\) preserves the identity of every input lookup when a later declaration shadows a name. Shared immutable plans and spill readers preserve the same row carrier without copying row payloads; invoking statement resources and transaction controls remain current. Recursive self references use their original recursive visibility instead. Restored output descriptors are derived in \(E_i\) before later names are installed, so both value execution and type observation use the same definition inputs. Owner tests verify shared handles and scope restoration, while the independent provider reference checks values, types, errors, sequence effects and stored-definition reopening.

For a pure predicate on input-derived outputs \(D\), selection is constant over every set-producing expansion of one input row: \(\sigma_p(\operatorname{flatmap}_F(R))=\operatorname{flatmap}_F(\sigma_{p\circ D}(R))\) at the bag level. Execution evaluates the predicate before the remaining outputs only at PostgreSQL's permitted boundary, so excluded rows do not invoke those outputs' errors or effects. Referenced volatile and set-returning expressions cannot be substituted into an ordinary scalar predicate. A predicate constant on each complete group or every affected window partition removes whole partitions without changing retained aggregates, selected DISTINCT ON rows or window ranks. Slicing and conversion barriers remain outside this argument: filtering before a set-member coercion can change a value, so differing observed type OIDs prevent that move. These guards supplement, rather than replace, independent error/effect observations.

For a simple pure projection with input filter \(q\), let \(I\) be a fresh internal relation identity and \(\gamma_I\) bind each demanded raw attribute to its physical position. The consumer evaluates \(\pi_{f[e[I]]}(\sigma_{p[e[I]]}(\gamma_I(\sigma_q(R))))\). Every substituted input still denotes the original value, including its type, collation and record descriptor, while unrelated SQL aliases cannot capture \(I\). The source bag and multiplicities are unchanged. Keeping the producer filter in its original query rejects FALSE and NULL before volatile consumer evaluation; no scalar AND approximation is needed. Pure single-producer conjuncts move to the original scan exactly once, preserving index planning and avoiding duplicated stable evaluations. Consumer scalar-subquery slots keep their original arena, and transient captures never enter stored view or prepared definitions. The subsequent correction below supports scalar-correlated consumer references; whole-row substitutions and observable producer boundaries remain guarded; this argument does not establish completion of those remaining implementations.

## Preservation argument for outer-join row identity

A relation's whole-row datum has identity beyond its field values. For its fields \(v=(v_1,\ldots,v_n)\), retain a hidden presence attribute \(p\in\{\mathrm{true},\mathrm{NULL}\}\), with \(W(v,p)=\operatorname{Record}(v)\) when \(p=\mathrm{true}\) and \(W(v,p)=\mathrm{NULL}\) otherwise. In particular \(W((\mathrm{NULL},\ldots,\mathrm{NULL}),\mathrm{true})\ne\mathrm{NULL}\). SQL RowSchema owns the namespace-to-internal-attribute binding; Execution owns the physical marker and interprets it through the existing scalar context. UnifiedPlan and the SQL → Planner → Execution path remain unchanged.

Only an outer join's nullable inputs acquire markers. Every produced unmarked input row receives TRUE, while an existing inner marker retains its original value. A matched join concatenates those rows without changing their markers; unmatched NULL extension clears the entire absent side, including its markers. Thus every carried scope's marker is TRUE exactly when that scope contributes a row. The visible bag multiplicity, logical column positions, join predicates, ordering and expression effects are unchanged. A new derived or join-alias scope denotes its newly produced row and acquires its own marker if a later outer join makes it nullable. Namespace-preserving projection and correlation keep existing bindings; hiding a namespace removes that binding from SQL lookup. Retiring internal attributes removes their dependent bindings rather than leaving dangling metadata.

Physical relayout resolves rebuilt marker identities through the same relation namespace. Spill encodes the marker bindings and values with explicit byte accounting; decoding bounds counts and validates Boolean internal attributes and duplicate qualifiers before exposing a schema. Consequently whole-row evaluation and COUNT observe the same \(W\) before and after spill: \(\operatorname{COUNT}(W)=\sum_r\mathbf{1}[p_r=\mathrm{true}]\), including present all-NULL rows. Each nullable input shares one immutable TRUE fragment, without copying row payloads; the existing row and spill retention rules include the additional slots and metadata. Owner regressions force spill for LEFT/RIGHT/FULL hash and nested-loop joins and verify zero allocation while marking a 256 KiB payload.

The independent 33-observation PostgreSQL reference covers LEFT/RIGHT/FULL/LATERAL, USING, correlated and nested joins, aliases, materialization, counts, NULL predicates, named zero-column relations, stored views and prepared inputs. The additional 29-observation anonymous-empty reference passes all four providers and 27 persistent-reopen observations, including whole-row versus ROW-star expansion, empty UNION ALL, scalar shadowing, missing fields and excess aliases. The original independent expectations remain unchanged.

For an empty anonymous relation, namespace membership is independent of an optional named composite type. SQL retains the qualifier in the same cold, shared relation metadata while its named-type lookup remains absent, so scalar inference uses `record`. This introduces no logical column or physical value slot: the present whole-row value is \(W((),\mathrm{true})=\operatorname{Record}(())\), while outer-join absence still gives \(W((),\mathrm{NULL})=\mathrm{NULL}\). Requalification establishes the new source name even when no column can carry it; a join keeps independent names, lexical nesting shadows the corresponding outer name, and a projection hides input namespaces. Execution uses that same SQL transformation for empty source selections and join aliases, and spill readers retain the original owned schema. Nonempty anonymous sources continue to infer their qualifier from existing columns without allocating a relation-type map. Alias-count validation runs only once the descriptor's width is known, preserving UQA's runtime-discovered table-function columns.

## Physical consumer demand checkpoint

Execution propagates finite row demand through scans, filters, projections, LIMIT/OFFSET/WITH TIES, join output, schema coercion, ROWS FROM, UNION ALL and ordinary/set-returning projections. Nested-loop joins retain and replay only the consumed right prefix; hash joins retain their real build barrier and resume a probe's duplicate candidates without evaluating later predicates. Reusable duplicate cursors share the memory index or retain one sequential disk reader. Ordinary unrestricted joins retain input batching. LATERAL producers now retain one physical cursor, and EXISTS stops through the existing query consumer instead of completing its input. No alternative UnifiedPlan or Engine execution algorithm is introduced.

For a finite consumer allowance n, a nonblocking operator evaluates at most the next n accepted outputs and the input candidates needed to produce them. A filter forwards one candidate until a survivor is found; a join resumes its current candidate before fetching another probe. Already-produced rows from a genuine materialization boundary remain retained without invoking parent expressions. Stopping therefore preserves the prefix's rows, errors and effects; resumption continues the same state rather than replaying SQL. Normal complete consumption traverses the same ordered bag and maintains the existing type, row identity, spill and cleanup contracts. Hash build, sort and aggregate barriers retain their required complete inputs. A read-only MATERIALIZED CTE is separately a shared prefix producer and is not covered by this completed operator unit.

## Shared materialized prefix

Read-only materialization now retains one existing physical pipeline on the caller's thread. Execution owns construction, finite pulls, independent reader positions, error retention and the budgeted indexed spill; Engine only retains its selected session, snapshot and transaction overlay. The zero-dependency `self_cell` 1.3.0 owner safely keeps the borrowed pipeline alive without an unsafe lifetime conversion, producer thread or alternate plan. Complete command and recursive buffers retain their existing representation. Folded CTE definitions remain available across recursive working-table iterations instead of being consumed by the first scan.

Let a producer's ordered observation trace be \(T=((r_0,e_0),\ldots)\), where each \(e_i\) contains the effects or reached error of producing the next row. The shared state retains exactly one consumed prefix \(T[0:k]\), and each reader stores a position \(p_j\le k\). A read with \(p_j<k\) returns the stored row and advances only \(p_j\); a read at \(p_j=k\) extends the single producer and then advances that reader. Induction on reads therefore preserves each consumer's ordered rows while evaluating every producer position at most once. A stored reached error remains at the same boundary, and preceding rows stay replayable. Encoding or spilling changes neither row values nor their order; the memory allowance bounds retained in-memory bytes independently of prefix length. Blocking physical operators still consume their required inputs before returning an output. Scope ownership releases the producer and spill when the last reader is gone.
