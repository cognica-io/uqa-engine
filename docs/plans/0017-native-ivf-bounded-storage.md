# Native IVF bounded storage

Status: implemented and locally verified; exact-head pre-merge CI is required before merge. This fixes native SQLite IVF mutation/reconstruction and shared MVCC commit-time IVF resolution under the original retention allowance. The standalone in-memory IVF and common Key/Value IVF cache remain resident representations; this change does not claim that those caches spill.

## Required result and ownership

Native IVF construction, reopening, document replacement/deletion, threshold-triggered retraining and top-K search must handle a canonical corpus larger than the caller's retained-byte allowance without admitting a complete resident corpus copy. The allowance stays unchanged, defaults to 64 MiB and is independent of SQL `work_mem`. An individual record, requested result, centroid matrix or minimum operation workspace must still fit. Storage owns the spilling maps, IVF preparation, deterministic numeric iteration and tensor score reduction; the SQLite provider owns ordered row decoding and atomic record publication. Engine supplies the existing session and transaction boundaries only. No dependency, persisted format, index parameter or catalog migration is added.

The existing IVF restoration envelope included canonical inputs and temporary assignment/seen maps, but its entire reservation survived after those allocations were destroyed. A restored 2,338-vector, 1,024-dimensional generation could therefore retain about 41 MiB and reject the next preparation at about 72 MiB under a 64 MiB allowance. Resident `IVFIndex::restore_controlled` now splits out only actual raw/normalized capacities, logical tree entries and the maximum current/retrained centroid/list capacity bound. Native preparation and shared commit resolution additionally use streamed spilling roots, so cardinality can exceed the allowance instead of only fixing the original over-retention.

## Carrier and representation invariant

Let a valid IVF generation be `(D, P, H, V)`, where `D` is the configured dimension, `P` contains the existing list/probe/training parameters, `H` contains state, ordered centroids and training/deletion counters, and `V` is the finite ordered map from `(DocId, u32 ordinal)` to raw coordinates, normalized coordinates, raw norm and optional centroid identity. Each document's ordinals are exactly `0..m-1`, raw and centroid values satisfy the existing vector validation, and a trained/stale generation has one in-range assignment per canonical vector. Document support alone is not the observable result: cosine scores, tensor maxima, ranked top-K selection and posting payloads are included.

The packed temporary key is `(u128(document) << 32) | ordinal`. It is injective and order preserving for the full `u64` document and `u32` ordinal domains, so lexicographic tensor traversal has exactly the resident map's order. For either a resident or authenticated temporary-page root `R`, define `alpha(R)` by ordered live-key traversal and record decoding. The invariant is `alpha(R) = V`, including every floating-point bit and assignment. Ordered lookup/successor preserve the same least key and value. The existing encrypted immutable map performs path-copy insertion/deletion and publishes a candidate root only after all writes, compaction and cancellation checks succeed. Thus insertion implements exactly `V[k -> value]`, deletion removes exactly that binding, and retained roots continue to abstract to their original maps. Moving all live bindings in order to a temporary file preserves `alpha`; final-handle destruction removes the temporary file. This is the same map implementation already used by HNSW, extracted into its owning common Storage module.

Reconstruction admits the small centroid directory under the original allowance, streams and validates assignments into a spilling map, then visits ordered canonical vectors one at a time. The successor invariant detects duplicate, unordered and incomplete tensor ordinals without a seen-key directory. Every trained vector must find its assignment; equality of assignment count and canonical count, together with unique assignment keys and coverage of every canonical key, implies that no extra or missing assignment exists. Untrained state rejects all trained metadata. Only successful `finish` yields a publishable owner, so no partial reconstruction can escape to publication.

## Numerical and mutation preservation

Normalization calls the existing `l2_normalize` with the same raw coordinate order. Temporary encoding stores IEEE-754 bits, not decimal text or lower precision. For deterministic k-means, the streaming source visits normalized vectors in the exact existing ordered-map order, seeds positions `i * max(1, count / clusters)`, and calls the same centroid comparison, tie rule, sum/division/normalization operations for the same ten iterations. Induction over seeding and each ordered addition yields bitwise identical centroid matrices: no floating-point addition is reassociated. The implementation refactors the existing resident `kmeans` to call that same source routine, so it does not introduce a competing numeric algorithm. The subsequent ordered assignment pass calls the same nearest-centroid routine and produces the same vector-to-list binding. Existing approximate IVF probe selection is unchanged; no new numeric or recall approximation is introduced.

For replacement, validate every input vector and ordinal bound before altering the private candidate; remove exactly the document's old contiguous keys and insert its new ordinals in order with the existing normalization and nearest-centroid rule. Replacement, including an empty replacement, does not increment trained deletion counters. Deletion removes exactly the selected document's bindings, increments the trained counter by the number removed, and marks stale exactly when the counter exceeds `trained_size / 5`. Preparation retrains stale candidates at the same point after each evaluated mutation. Untrained replacement crosses the same vector-count threshold after the complete document replacement, explicit training uses the complete current generation, and clear returns the same empty untrained header. Induction over the ordered evaluated input sequence therefore preserves `H` and `alpha(R)` after every successful operation. This is representation replacement, not a new query-algebra operator, and authorizes no optimizer rewrite or new law for payload collision merge.

## Ranked results and composition

Native queries score one validated canonical vector at a time using the existing raw-vector `cosine_similarity`; using normalized dot products instead would change rounding and is intentionally avoided. Let the score map contain each document's first score followed by the existing `f32::max` folds in original tensor order. Temporary encoding preserves score bits, including signed zero and overflow-generated NaNs, so moving this map to disk preserves the complete folded scores. The top-K comparator is descending `total_cmp(score)` followed by ascending document identity. A worst-first heap contains exactly the best `min(K, processed documents)` scores after each unique-document step: until full it inserts the next entry, and when full it replaces its worst element exactly when the next entry precedes that element. Induction establishes identical final selection to the existing full-score sort. Sorting selected entries by document identity and constructing the same `Payload::with_score(f64::from(score))` preserves the decorated posting list, stable ties and subsequent threshold/hybrid consumers. Zero-K and oversized-K use the same definition; any final result exceeding the original allowance retains the existing typed quota failure.

## Resources, cancellation and publication

Resident vector maps each use at most one third of the original parent allowance, leaving room for simultaneous source/new-assignment roots, provider pages, centroid work and one decoded/encoded record. The reconstruction-only assignment map has its own smaller child allowance. Parent admission remains authoritative even when other retained session resources exist. Every vector copy, map payload/path, centroid capacity, two-matrix training workspace, disk directory/cache, encoded record, decoded record and top-K/result buffer has a reservation before allocation. The same parent budget measures overlapping lifetimes; no independent unlimited or enlarged budget is introduced. Corpus-sized vector, normalized-training, seen-key, assignment-output and candidate-score arrays are absent from the native and shared-resolver paths. Required centroid workspace depends on configured list count and dimension; bounded per-record reads and temporary roots make corpus cardinality independent of required resident storage.

Provider loaders observe one retained committed/private boundary. Preparation owns a detached candidate; a failure or cancellation destroys it and its leases without altering canonical rows or an earlier reader. Native publication stages the prepared scalar header, centroid rows and streamed assignments with canonical replacements in the existing evaluated batch. Shared commit resolution rebuilds the current generation and applies the original input journal before staging the same existing record encodings and revisions. Existing atomic command undo and commit publication make these changes all-or-nothing. Retained native snapshots keep their original versioned view through later mutation, savepoint rollback, transaction rollback, source closure and reopening; temporary files belong only to preparation/query owners and are never persisted as canonical index data. Cancellation is checked during reconstruction, every numeric pass, mutation, score reduction and publication, and existing authenticated page failures retain their typed failure boundary.

## Transaction spill readers

Native HNSW rebuild publication exposed a separate shared MVCC pressure failure: merging four immutable private runs kept complete entry blocks and optional value chunks while the original batch and replacement writer remained charged. A 256 KiB native SQL lifecycle failed when a further 16,455-byte entry block required 273,432 bytes. Entry blocks are a read optimization rather than an indivisible semantic record. Point, predecessor and ordered run reads now retain an already admitted block when available and otherwise read through a 1 KiB buffered temporary-file handle, reserving its owned layout and buffer before allocation and reconciling the reported capacity. The streamed key moves directly into its original-allowance `RecordKey`; no whole-block allowance or uncharged replacement is introduced.

For a run's ordered encoded entries `E`, the cursor invariant is that its remaining byte count starts at the selected indexed block and advances by exactly each decoded entry's encoded length. Cached and streamed readers share one metadata decoder for flags, committed preconditions, write kind, private revision and value location. Induction on successive entries therefore preserves every selected key and associated change. Selection tests the same inclusive/exclusive starting bound, exact-key equality and predecessor cutoff; memory-tier and newest-run precedence in `TieredCursor` and the merge writer are unchanged. Cancellation or decoding/admission failure returns before private candidate publication, and the immutable source run remains available to earlier readers and undo roots. Cached lookups still borrow nonmatching keys and allocate only the selected key. The optional streaming owner is boxed only under pressure so ordinary merge cursors do not embed the buffered-reader layout. Each active streamed cursor retains its small buffer and current key under the invoking allowance instead of requiring a complete block; individual keys and the minimum reader workspace still must fit. This changes neither temporary record encoding nor persistent data formats.

The owning run regressions force all complete blocks to exceed available space while verifying point/predecessor results, bound-respecting ordered traversal, committed/private metadata, value reads, cancellation, final-owner file cleanup and identical corruption diagnostics for both decoders. The existing native HNSW SQL regression retains its 80 vectors, 1,024 dimensions, 256 KiB session allowance, 64 KiB `work_mem`, savepoint history, replacement, deletion/rebuild and cold reopen assertions.

Correctness and resource assertions are required; these fixtures establish no throughput or uncontrolled timing claim.
