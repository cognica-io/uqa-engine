# Selected range construction

This is the construction boundary of original record 65, following [declared observation](0018-declared-range-observation.md) and [selected comparison](0018-declared-range-comparison.md). SQL's actual native text, scalar-constructor and multirange paths now use the same admitted construction owner that accepts a selected declared range identity. Custom catalog publication, physical production of arbitrary typed endpoints, generated routines and the remaining public operators are still required; this unit does not expose `CREATE TYPE AS RANGE` or complete record 65.

## Ownership and observable effects

`RangeConstruction` selects identity, endpoint input, comparison and optional canonical invocation independently. It is a production interface, separate from the read-only `SQLValueCatalog`. Execution will supply definition-derived invocation state; Engine does not acquire an input, sorting or canonicalization algorithm. Core's existing `Produced`, reservation and cancellation contracts remain unchanged. No dependency, Cargo feature or durable format changes.

Text input validates the complete syntax before executing lower-then-upper endpoint input. The typed constructor instead consumes already coerced, admitted endpoints; its caller owns coercion and domain validation, including NULL-domain rules. An absent bound is unbounded and cannot remain inclusive. Reversed finite bounds fail before canonical invocation, and an already empty range skips that invocation. A selected canonical result is returned once without repeating input, canonicalization or post-canonical validation. Native discrete canonicalization retains its own existing successor and empty-result checks. A custom integer subtype does not inherit the native integer canonicalizer.

The canonical callback borrows a live admitted range. It can retain that input unchanged or return a fully admitted replacement; it cannot transfer the borrowed allocation with an empty reservation. SQL NULL is an invocation error, not the unchanged-input marker. Successful callbacks are checked under the original budget and both cancellation scopes. An earlier callback error keeps precedence over a simultaneous cancellation. Reading a completed carrier never invokes this interface.

Multirange normalization sorts complete ranges, skips empty members after sorting, and joins members in order. Text input already omits empty members, while a typed constructor's existing empty members participate in sorting, matching PostgreSQL's distinct paths. A canonical function can be called both for a union and to test whether a gap is empty. Already constructed individual members are not canonicalized again merely because they enter a multirange. These effects are not assumed pure or freely reorderable.

## Reproduced native corrections

[#939](https://github.com/cognica-io/uqa-engine/issues/939) records native constructor and normalization differences. Explicit NULL flags now raise PostgreSQL's `22000`; invalid flags raise `42601` with its exact primary message and HINT. Typed native scalar construction no longer formats both endpoints into a temporary range string before parsing them again.

Equal numeric bounds can have different display scales. PostgreSQL sorts by full range order and chooses the right operand when union bounds compare equal. Its equal-element permutation also affects the final spelling when many equal ranges are interleaved. The SQL range owner therefore preserves PostgreSQL 18's partition, pivot and insertion-sort behavior rather than imposing a stable ordinal tie key. This specialized sort is confined to range normalization; Core's general ordering is unchanged. The source adaptation retains its upstream attribution in `crates/uqa-sql/THIRD-PARTY/POSTGRESQL-SORT-NOTICE.txt`; all binding notice inventories and the Rust archive verifier include it. Quoted range endpoints now double quote characters, as PostgreSQL does, while retaining doubled backslashes.

## Preservation argument

Fix a range identity $r$ and its admitted endpoint domain $T_r$. The selected comparator $B_r$ defines a total preorder on valid endpoints; let $a\sim_r b$ mean $B_r(a,b)=0$. A range is empty or an interval of the quotient $T_r/{\sim_r}$, with independent unbounded ends and inclusion flags. Before the optional canonical call, the constructor rejects a reversed finite pair, maps an equal pair to empty unless both ends are included, and otherwise retains the interval. Each branch is the corresponding PostgreSQL serialization branch, so it preserves the interval denotation and the ordered input/diagnostic observations.

For extensional set laws, assume a selected canonical operation $C_r$ terminates successfully, preserves interval denotation and returns a canonical representative. These are the additional hypotheses needed for algebraic reasoning, not properties inferred from an arbitrary SQL routine. Under them, construction is closed over the range carrier and preserves the represented set. If $C_r$ is also idempotent, applying it to an already canonical representative leaves that representative fixed. No optimization in this change assumes idempotence or eliminates an observable call: arbitrary callable support still follows the operational invocation boundary, including failures and effects.

Let $S(R)$ denote an interval's represented endpoint classes. Full range ordering places lower bounds in increasing order. For two successive nonempty ranges, a shared included boundary or overlap permits a union; for separated bounds, the selected canonical function, when present, decides whether the complementary gap is empty. A union keeps the minimum lower and maximum upper bound, selecting the right physical endpoint for a comparison tie. Thus $S(\operatorname{union}(A,B))=S(A)\cup S(B)$ whenever the selected operation satisfies the hypotheses above. Induction over the sorted members proves that normalization represents exactly the union of all inputs, with disjoint nonadjacent output members. Empty input is the identity. The resulting extensional union is associative, commutative and idempotent because set union is; physical spelling and callback traces are not asserted to obey those laws.

The sorting adaptation performs the same pivot selections, comparisons and element swaps as PostgreSQL 18's [sort template](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/include/lib/sort_template.h), with indices replacing pointer offsets. The initial ordered check and insertion threshold are unchanged. Partition swaps preserve the input multiset and group elements by comparison with the pivot; induction over the smaller recursive and larger iterative partitions establishes the same ordered permutation, including equivalent endpoints. Recursing only into the smaller partition bounds stack depth by $O(\log n)$, and sorting allocates no scratch. Comparison work follows that PostgreSQL quicksort, including its possible $O(n^2)$ worst case; no general linear-time or timing improvement is claimed.

The construction and merge branches correspond to PostgreSQL's [range producers](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/utils/adt/rangetypes.c) and [multirange normalization](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/utils/adt/multirangetypes.c). Native adapters select the same endpoint casts and discrete canonicalizers. Apart from the independently demonstrated diagnostic, numeric-spelling and quoting corrections, existing native values, empty/infinite rules and representations are preserved. No document support, tuple multiplicity, payload merge, retrieval score or ranked algebra is changed. Exact-key consumers continue to observe the same selected equality classes; different numeric display scale does not change numeric equality.

Input payloads, ordered members, merge output and callback replacements remain under the same reservation owner. Every allocating copy is admitted before allocation. Workspaces place the complete value before its lease, including during error propagation and unwinding. A borrowed canonical input remains live until its admitted replacement exists; merge leases retain all moved bounds through the final output handoff. A replaced canonical result releases its superseded lease; only completed members and the current replacement stay retained. Sorting only swaps owned members. Every loop and selected comparison observes cancellation. Therefore successful handoff retains its allocations, and quota, comparison, canonical or cancellation failure releases temporary ownership without invalidating a prior result. Callback-owned allocations are bounded by the same allowance, not a separate unchecked workspace.
