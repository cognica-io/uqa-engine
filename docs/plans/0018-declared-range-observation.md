# Declared range value observation

This is the physical-value observation boundary of original record 65, following [typed endpoints](0018-user-defined-ranges.md#typed-endpoint-implementation-boundary) and [shell publication](0018-shell-type-acceptance.md). It does not publish user-defined range DDL, constructors or selected comparison operations. Those requirements, lifecycle and full provider/binding acceptance remain open in the [original task ledger](0018-extension-progress.md).

## Ownership and behavior

SQL owns separate range/multirange OID references, array identities, display names and physical alignment. `SQLValueCatalog::value_range_type` returns immutable metadata from the invoking statement generation; its descriptor supplies endpoint layout and both physical family identities. The existing Core `DatumValue` retains admitted bytes. Execution adapts foreign-column metadata and continues to reject unpublished type identities. No dependency, Cargo feature, Engine algorithm, storage format or native range carrier changes.

The shared physical reader selects the range family recorded in the payload, validates its class against the selected output operation, and reads each bound through the existing SQL inline codec. Domain endpoints use their physical base without executing domain checks; enum endpoints retain label identity. Nested declared ranges remain owned Datums rather than being flattened to text. The selected output operation retains its range/multirange class when the payload type is missing, preserving the PostgreSQL missing-type diagnostic. Invalid lengths, offsets, flags and descriptor identities fail before exposing a result.

Typed output now has an admitted entry point. Scalars reuse their existing output owners; arrays and records stream quoting and delimiters into the invoking output allowance. Enum output reads current labels from the same borrowed catalog. Legacy containers retain their established output shape, with transformed buffers admitted before allocation. Multirange output retains at most one decoded member at a time in addition to the accumulated output. Arbitrary input and canonical routines are deliberately absent from this read-only catalog contract; they belong to the still-required selected-operation boundary.

The actual nested enum consumer reproduced [#936](https://github.com/cognica-io/uqa-engine/issues/936), an existing Core panic when anonymous row production combined admitted values with an uncontrolled absent field descriptor. Core now represents that absence with its invoking owner's empty reservation. It preserves the existing ownership assertion and allocation accounting; it does not broaden which owners may be combined.

## Preservation argument

Fix a statement catalog generation $C$. An admitted range payload is $B=(r,f,b_l,b_u)$, with physical identity $r$, bound flags $f$ and zero, one or two finite endpoint encodings. Metadata $M_C(r)$ selects endpoint layout $T_r$ and the independently identified associated multirange. The reader $D_C$ first validates the payload class, then delegates each finite endpoint to the existing admitted decoder for $T_r$. It preserves $r$ and $f$ and neither invokes input nor canonicalization. Consequently it cannot change inclusive bounds, apply a native integer canonicalizer to a custom range, or introduce domain/callback effects during observation. Its error domain is the existing malformed/missing/wrong-class boundary rather than a partially exposed value.

Let $O_{C,T}$ be the existing typed PostgreSQL output of an endpoint. The range writer applies $O_{C,T_r}$ to each finite bound, quotes its result using the existing range escaping rule and emits exactly the delimiters selected by $f$. Thus output composition is $O_C(B)=Q_f(O_{C,T_r}(D_{T_r}(b_l)),O_{C,T_r}(D_{T_r}(b_u)))$, omitting infinite bounds and using the established empty token. Native adapters select their original endpoint types and output rules, so this composition preserves native observations. For enums, $D$ retains the label identity while $O$ selects its current label in $C$; renaming changes only the visible label, without reparsing or changing the retained bytes. Domain output applies the same base observation without introducing a new constraint-check transition.

For nested arrays and records, induction on the finite owned carrier establishes the same result: scalar leaves satisfy the preceding rule; each container visits the same ordered elements or fields, retains NULL positions and physical identities, and applies its established delimiter and escaping function. Multiranges apply the range observation to the same ordered member sequence. Streaming changes allocation order, not member order or output. No new equality, ordering, hash or relational operator is claimed here: existing native comparison adapters and exact keys remain unchanged, and custom selected operators remain unpublished. The transformation is a value observation at the same result boundary, so document support, tuple multiplicities, payload composition and ranked scores are unchanged.

For each admitted allocation, the producer reserves from the original owner before allocating and transfers that reservation with its buffer. Combining independently produced components is permitted only for that owner. The absent row descriptor contributes the same owner's zero-byte identity; this preserves reservation addition without weakening the ownership precondition. Successful output retains exactly its returned storage, and an error or either cancellation drops all local owned buffers and reservations. With a maximum decoded member size $m$ and emitted prefix length $s$, multirange observation retains $O(m+s)$ storage rather than all decoded members; type metadata is borrowed from the pinned catalog. Exhaustion returns no partial output.
