[#917](https://github.com/cognica-io/uqa-engine/issues/917) corrects built-in range input discovered while preparing original record 65. It is a separate correction from #299 default B-tree admission. User-defined range declarations, selected subtype identities, support functions and their complete lifecycle remain required by [the extension task ledger](0018-extension-progress.md).

## Contract and ownership

SQL's `expr/range/input.rs` validates a complete range's structure before reading either bound. Its private borrowed bound spans retain the original quoted and escaped input without allocating endpoint copies during structural validation. Lower-bound input precedes upper-bound input. Multirange input yields one member at a time: that member's range and subtype errors precede errors in a later separator or member. PostgreSQL's ASCII input whitespace, quoted segments, doubled quotes, backslash escapes and empty members retain their distinct roles.

`expr/range/production.rs` decodes each present bound under the existing production allowance and calls SQL's common selected scalar conversion. Integer prefixes, separators and overflow, numeric input and structured temporal errors therefore use their owning input functions. Temporal conversion retains its existing session DateStyle and transaction-clock context. The existing canonicalization, comparison, normalization and output owners remain in place. Engine adds only public provider and reopen coverage. No dependency, feature, test executable, index encoding or persistent format changes.

## Preservation argument

Let $S$ be range text, $T$ the selected built-in subtype, $P(S)$ the structural parser, $I_T$ its existing scalar input function and $C_T$ the existing range canonicalizer. For well-formed nonempty input, define $R_T(S)=C_T(I_T(l),I_T(u),b_l,b_u)$, where $(l,u,b_l,b_u)=P(S)$ and an absent bound remains unbounded rather than invoking $I_T$. Empty input maps directly to the existing empty carrier. Evaluation is ordered: $P$, then lower $I_T$, then upper $I_T$, then $C_T$. A failed step returns its diagnostic without executing a later step. The new private bound constructor is reachable only after structural validation, so decoding cannot encounter an unterminated quote or escape.

For a multirange, the cursor produces $S_1,\ldots,S_n$ in source order and evaluates each $R_T(S_i)$ before validating the following separator. Each empty member is discarded immediately after its ordered input completes. Once the entire input succeeds, the unchanged normalization function sorts the retained nonempty members and merges overlapping or adjacent members. This preserves the existing normalized carrier and order for every previously correct input, while correcting PostgreSQL mismatches in accepted spelling, diagnostics and validation order. The structural cursor stores only the input slice, byte position and finite state; it does not materialize a member list.

The correction introduces no new algebraic operation. For an input whose scalar values and structural interpretation were already correct, the selected subtype, canonical bounds, inclusivity and member sequence are unchanged. All existing range comparisons, equality keys, hashes, index consumers and relational compositions therefore receive the same carrier and preserve their observations and multiplicities. Newly corrected integer spellings denote the same scalar values as ordinary integer input. Errors publish no value; the surrounding statement transaction retains its existing rollback semantics. Memory leases cover decoded text while scalar input runs and cover admitted endpoints through canonicalization; partial failures release both values and leases. Structural parsing and bound decoding poll the existing cancellation control.

All eight focused public range tests pass on memory, native SQLite, SQLite K/V and redb, including the complete input corpus and existing element-containment reference; persistent providers close and reopen between initial and retained observations.
