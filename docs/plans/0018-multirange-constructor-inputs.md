# Multirange constructor input diagnostics

Issue [#973](https://github.com/cognica-io/uqa-engine/issues/973) was reproduced while preparing generated constructors for original #638 record 65. All four providers disagree with 21 of 25 independent PostgreSQL 18.4 observations: NULL array members and multidimensional arrays produce a generic `42804`, and a NULL among several individual ranges incorrectly produces SQL NULL. PostgreSQL reports `22004` for NULL members and `21000` for multiple dimensions. A single NULL range or a NULL variadic array still has the strict SQL NULL result.

## Ownership and preservation

SQL's existing `expr/scalar_range.rs` constructor owns argument shape, member traversal and normalization. It now rejects an array's multiple dimensions before visiting members, distinguishes the single strict NULL input from a NULL member, and preserves the independent PostgreSQL error fields. Core's array representation, Engine's provider adapters, Cargo features, dependencies and persisted formats are unchanged.

For every admitted zero- or one-dimensional non-NULL member sequence, the same existing parser and normalized union operation receives the same ordered members. Empty inputs, nondefault lower bounds, endpoint spellings and successful result bytes therefore remain unchanged. The new predicates affect only inputs that PostgreSQL rejects. Singleton SQL NULL still returns NULL before normalization. This scalar correction introduces no relation operator or change to row support, multiplicity, equality keys or ordering.

The owner keeps the original production control and both cancellation tokens. Array rank is read from existing metadata; no replacement member array is materialized. Member failure releases the already admitted earlier ranges through the existing ownership boundary. Inputs remain immutable, and exhausted allowance or cancellation cannot leave a retained partial result.
