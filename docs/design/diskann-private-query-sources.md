# DiskANN private query sources

A fixed query snapshot can contain evaluated private replacements and deletions without replacing its selected DiskANN generation with an exact in-memory corpus. Storage's [selection owner](../../crates/uqa-storage/src/diskann_index/query/selection.rs) retains actual canonical sources for the changed document identities and reuses the existing [document search](diskann-document-search.md). Execution supplies the evaluated identity selection and retains logical read observation; Engine supplies table and transaction handles. This boundary introduces no dependency, Cargo feature, persistent format or numerical transform.

## Actual source ownership

`VectorIndex::diskann_read_snapshot` returns an opaque `DiskANNReadSnapshot` only for an actual retained DiskANN owner. Its canonical roots, physical lineage and controls come from that owner, not from caller-supplied generation labels. `DiskANNReadChanges::capture` admits a strictly increasing sparse directory of document identities and source capabilities under the original capture allowance. Each entry selects the already evaluated version of that document; entries can retain different source snapshots. `None` is an evaluated deletion and removes the document even if a retained source still contains its old vector. Absence in a selected source also means deletion, while a present origin with zero ordinals means an explicit empty replacement. Neither case falls through to the base document.

`VectorIndex::snapshot_with_diskann_changes` verifies the database, table and index lineage and canonical width, then shares the receiver's prepared physical reader and complete-origin directory. Different generations within that lineage are allowed: the receiver keeps its selected generation and effective configuration, while replacements contribute only canonical data. This operation never selects the replacement source's graph or interprets matching dimensions as authorization to combine unrelated indexes. An incompatible source returns an error without changing the receiver.

The original and private sources can contain unrelated later changes. Only selected document identities read through private sources; every other document stays on the fixed base. Callers must therefore retain the source that supplied each evaluated private row, including tombstones, instead of resolving all private identities against a later live table. Column-incarnation mapping and catalog selection belong to Execution; this storage interface does not infer them from field names.

## Preservation argument

Let $D$ be the document identity domain and let $B$ be the receiver's fixed canonical source. For every $d \in D$, a source supplies either absence or an actual origin and its complete ordered tensor, written $(v_d, X_d)$. An explicit empty tensor has an origin and cardinality zero. The source invariants guarantee a non-reused actual origin for each canonical mutation, complete ordinal coverage, fixed dimensions and unchanged coordinate bits. Let $G$ be the receiver's prepared physical generation and complete build-origin map. Let $S$ be a finite partial map from document identities to retained source observations: an entry is either an actual source capability, validated against the same canonical lineage and width, or the constant absent observation for an evaluated deletion. Write $S(d)(d)=\bot$ for that constant absent observation. Define the selected canonical source by

$$
C_S(d) = \begin{cases} S(d)(d), & d \in \operatorname{dom}(S), \\ B(d), & d \notin \operatorname{dom}(S). \end{cases}
$$

This is a total selection over source observations, including absence, and thus closes over the existing canonical-source carrier. It neither unions tensors nor chooses versions by writer allocation order. The empty selection is the identity. For two ordered overlays $S$ and $T$, applying $T$ after $S$ equals applying their right-biased finite-map composition to $B$: a document in $T$ selects $T(d)$, otherwise a document in $S$ selects $S(d)$, and every remaining document selects $B(d)$. The three exhaustive cases prove both this equation and associativity of overlay composition. This law concerns selected canonical observations, not commutativity of payload merges.

The document cursor merges the base cursor with the ordered selected identities. It emits each identity once, omits evaluated deletions and selected absent replacements, and retains explicit empty origins. Original base validation still rejects unstamped values. Consequently the existing canonical metadata count equals $\sum_{d \in D,\ C_S(d)\ne\bot}|X_d|$, an ordinal count rather than a document count. Membership is equivalent to a nonempty selected tensor. A strictly advancing cursor also handles the terminal document identity without incrementing it.

For a fixed query vector $q$, each visible nonempty tensor keeps the existing raw score $s_q(d)=\max_{x\in X_d}\operatorname{cosine}(q,x)$, with the established finite-width floating-point and numeric-edge rules. The adapter reads the complete tensor from exactly one selected source and performs no coordinate conversion. Exact threshold search therefore emits exactly the existing decorated postings for documents with $s_q(d)\ge t$, preserving their identity, raw score and payload rather than only their support.

Approximate KNN remains the existing operation $\operatorname{DiskANNQuery}(G,C_S,q,k)$. The receiver's generation, PQ values, traversal, beam completion, numeric-side handling, canonical reranking, document deduplication and tie ordering are unchanged. The merged change cursor emits untouched base changes and the actual current origin for every selected present replacement, including replacements whose own source has already compacted its journal. If that origin matches $G$'s complete build-origin map, the original graph/side coverage already applies. If it differs, the existing candidate merge scores the selected tensor as an uncovered replacement; stale graph candidates fail the same origin comparison. A selected absent document cannot be scored. These cases are exhaustive, so no private replacement disappears because a later source pruned its journal, and no old graph node restores a deleted or replaced tensor. No synthetic origin is introduced.

The result is equality with the existing DiskANN query over the defined canonical source, not equality with global exact top-$k$. The extension adds no approximation or probability mapping beyond that existing candidate selection. Downstream filters, joins, unions, calibration and fusion consume the same decorated postings and retain their current order of operations; in particular a relational filter does not request replacement candidates. Any downstream equivalence claim still requires identical decorated inputs and its own existing preconditions.

## Row and snapshot integration

[Execution's private row capture](../../crates/uqa-execution/src/query/document_changes/vectors.rs) retains the immutable document source and its actual DiskANN canonical sources at the same selected table boundary. Each evaluated replacement keeps that capture, while a missing selected row becomes an explicit tombstone. Extending a selection preserves the sources of earlier rows and replaces only the newly evaluated identities. Column object identities match retained sources through a rename; a different column incarnation cannot reuse an old source merely because its name matches. The existing name match remains available for definitions without object identities.

[Physical query-table selection](../../crates/uqa-execution/src/query/table_snapshot/vectors.rs) uses the existing row layout to map the selected column to its fixed base column. It requires unchanged column type and dimensions and actual matching database/table/index lineage before retaining the base reader. Let $R_B(d)$ be the fixed base row and $R_S(d)$ its selected evaluated replacement or absence. Capture consistency gives the canonical tensor of each present $R_S(d)$ from that same row's retained source; a tombstone gives absence on both paths. For a compatible column $c$, let $\pi_c$ be the existing row-layout projection followed by canonical tensor extraction. Unselected identities satisfy $C_S(d)=\pi_c(R_B(d))$ and selected identities satisfy $C_S(d)=\pi_c(R_S(d))$. These two cases cover every identity, so the projected row view and the selected canonical view agree. Applying the preceding document-score and candidate-selection argument therefore preserves row/vector composition without reading a newer private source.

The snapshot builder omits retained physical vector fields from reconstruction; a field also needed by text indexing remains in that separate projection. It shares the prepared reader and source directory without materializing a second complete vector corpus. Document counts and layout metadata retain their existing controlled reads. Missing physical capabilities, changed types, different lineages and unsupported methods still use the preexisting reconstruction path; physical retention for changed index definitions remains a separate acceptance gate, not a claimed property of this compatibility check.

[Engine's capture adapter](../../crates/uqa-engine/src/session/portals.rs) supplies fixed table handles and evaluated row changes to Execution. When the source is already a query snapshot, a further capture starts from its captured tables and catalog, including retained graph handles, instead of resolving them again against live storage or durable metadata. Only row changes belonging to that query origin are overlaid. Thus a nested capture with no new changes is the identity on the selected row, vector and catalog observations, even after the original session rolls back, changes rows or drops the live index. With new evaluated changes, the right-biased overlay law above applies. Capturing fresh query-origin bookkeeping does not change those observations or acquire a new storage transaction.

## Controls and failure

Clones and nested snapshots share the original canonical roots, prepared readers, sparse directory and reservations. The directory charges only selected identities and source handles; it copies no vector coordinates or corpus directory. Query workspace remains on the receiver's original allowance. Sources retain their original allowances and cancellation controls, and read-only wrappers retain their enclosing leases and controls when exposing a source or wrapping a projected index. Invocation cancellation remains an additional check. Construction and read failure return no partial index or posting list and do not mutate either source; dropping the final owner releases its reservations.

The serializable observation wrapper forwards metadata capture without registering a query and wraps a projected index with the same original logical relation participant. Executing a nonzero KNN or threshold search therefore observes the original candidate corpus; zero-$k$ and unused captures retain their existing nonobserving behavior. Physical source composition neither creates a new transaction nor completes the original one.

## Verification and integration gate

The [Storage regressions](../../crates/uqa-storage/src/diskann_index/memory/tests/selection.rs) use actual writable forks and prepared DiskANN generations. They check fixed rows against unrelated later mutations, private insertion/deletion and whole-tensor replacement, journal compaction, literal cosine scores, exact thresholds, ordinal counts, absent terminal identities, separate evaluated versions, nested overlays, source destruction, unrelated-lineage rejection, explicit deletion despite retained old membership, ordered-selection validation, quota failure, cancellation and final lease release. Existing retained-reader regressions also cover graph read failure and shared preparation.

The [Execution regressions](../../crates/uqa-execution/src/query/table_snapshot/tests/physical_vectors.rs) verify fixed rows against unrelated later changes, explicit deletions, different evaluated versions, column-identity matching, no capture-time coordinate projection, nested retention and quota/cancellation release. The [public consumer regressions](../../crates/uqa-engine/src/tests/catalog/index_registry/diskann/consumers.rs) run through memory, native SQLite, SQLite Key/Value and redb. They check literal raw/tensor scores, thresholds, tie ordering, candidate filtering without refill, hybrid/calibrated/robust consumers, relational composition, API cursors, holdable SQL portals and nested statement copies. A REPEATABLE READ capture includes update, deletion, NULL replacement and tensor insertion, retains `diskann` through source rollback and close, and supplies the same literal results to another captured query.

These checks close the reproduced compatible-column private-copy reconstruction and nested-copy visibility defects. Different index definitions, remaining planning/model provenance, binding artifacts and integrated resource acceptance keep their original plan gates. No timing, RSS or throughput result is claimed.
