# DiskANN private query sources

A fixed query snapshot can contain evaluated private replacements and deletions without replacing its selected DiskANN generation with an exact in-memory corpus. Storage's [selection owner](../../crates/uqa-storage/src/diskann_index/query/selection.rs) retains actual canonical sources for the changed document identities and reuses the existing [document search](diskann-document-search.md). Execution supplies the evaluated identity selection and retains logical read observation; Engine supplies table and transaction handles. This boundary introduces no dependency, Cargo feature, persistent format or numerical transform.

## Actual source ownership

`VectorIndex::diskann_read_snapshot` returns an opaque `DiskANNReadSnapshot` only for an actual retained DiskANN owner. Its canonical roots, physical lineage and controls come from that owner, not from caller-supplied generation labels. `DiskANNReadChanges::capture` admits a strictly increasing sparse directory of document identities and source capabilities under the original capture allowance. Each entry selects the already evaluated version of that document; entries can retain different source snapshots. `None` is an evaluated deletion and removes the document even if a retained source still contains its old vector. Absence in a selected source also means deletion, while a present origin with zero ordinals means an explicit empty replacement. Neither case falls through to the base document.

`VectorIndex::snapshot_with_diskann_changes` verifies the database, table and index lineage and canonical width, then shares the receiver's prepared physical reader and complete-origin directory. Different generations within that lineage are allowed: the receiver keeps its selected generation and effective configuration, while replacements contribute only canonical data. This operation never selects the replacement source's graph or interprets matching dimensions as authorization to combine unrelated indexes. An incompatible source returns an error without changing the receiver.

The original and private sources can contain unrelated later changes. Only selected document identities read through private sources; every other document stays on the fixed base. Callers must therefore retain the source that supplied each evaluated private row, including tombstones, instead of resolving all private identities against a later live table. Column-incarnation mapping and catalog selection belong to Execution; this storage interface does not infer them from field names.

## Preservation argument

Let $D$ be the document identity domain and let $B$ be the receiver's fixed canonical source. For every $d \in D$, a source supplies either absence or an actual origin and its complete ordered tensor, written $(v_d, X_d)$. An explicit empty tensor has an origin and cardinality zero. The source invariants guarantee a non-reused actual origin for each canonical mutation, complete ordinal coverage, fixed dimensions and unchanged coordinate bits. Let $G$ be the receiver's prepared physical generation and complete build-origin map. Let $S$ be a finite partial map from document identities to retained source observations: an entry is either an actual source capability, validated against the same canonical lineage and width, or the constant absent observation for an evaluated deletion. Write $S(d)(d)=\bot$ for that constant absent observation. Define the selected canonical source by

$$
C_S(d) = \begin{cases} S(d)(d), & d \in \operatorname{dom}(S), \\ B(d), & d \notin \operatorname{dom}(S). \end{cases}
$$

This is a total selection over source observations, including absence, and thus closes over the existing canonical-source carrier. It neither unions tensors nor chooses versions by writer allocation order. The empty selection is the identity. For two ordered overlays $S$ and $T$, applying $T$ after $S$ equals applying their right-biased finite-map composition to $B$: a document in $T$ selects $T(d)$, otherwise a document in $S$ selects $S(d)$, and every remaining document selects $B(d)$. The three exhaustive cases prove both this equation and associativity of overlay composition. This law concerns selected canonical observations, not commutativity of payload merges.

The document cursor merges the base cursor with the ordered selected identities. It emits each identity once, omits evaluated deletions and selected absent replacements, and retains explicit empty origins. Original base validation still rejects unstamped values. Consequently the existing canonical metadata count equals $\sum_{d \in D,\ C_S(d)\ne\bot}|X_d|$, an ordinal count rather than a document count. Membership is equivalent to a nonempty selected tensor. A strictly advancing cursor also handles the terminal document identity without incrementing it.

For a fixed query vector $q$, each visible nonempty tensor keeps the existing raw score $s_q(d)=\max_{x\in X_d}\operatorname{cosine}(q,x)$, with the established finite-width floating-point and numeric-edge rules. The adapter reads the complete tensor from exactly one selected source and performs no coordinate conversion. Exact threshold search therefore emits exactly the existing decorated postings for documents with $s_q(d)\ge t$, preserving their identity, raw score and payload rather than only their support.

Approximate KNN remains the existing operation $\operatorname{DiskANNQuery}(G,C_S,q,k)$. The receiver's generation, PQ values, traversal, beam completion, numeric-side handling, canonical reranking, document deduplication and tie ordering are unchanged. The merged change cursor emits untouched base changes and the actual current origin for every selected present replacement, including replacements whose own source has already compacted its journal. If that origin matches $G$'s complete build-origin map, the original graph/side coverage already applies. If it differs, the existing candidate merge scores the selected tensor as an uncovered replacement; stale graph candidates fail the same origin comparison. A selected absent document cannot be scored. These cases are exhaustive, so no private replacement disappears because a later source pruned its journal, and no old graph node restores a deleted or replaced tensor. No synthetic origin is introduced.

The result is equality with the existing DiskANN query over the defined canonical source, not equality with global exact top-$k$. The extension adds no approximation or probability mapping beyond that existing candidate selection. Downstream filters, joins, unions, calibration and fusion consume the same decorated postings and retain their current order of operations; in particular a relational filter does not request replacement candidates. Any downstream equivalence claim still requires identical decorated inputs and its own existing preconditions.

## Row and snapshot integration

[Execution's private row capture](../../crates/uqa-execution/src/query/document_changes/vectors.rs) retains the immutable document source and its actual DiskANN canonical sources at the same selected table boundary. Each evaluated replacement keeps that capture, while a missing selected row becomes an explicit tombstone. Extending a selection preserves the sources of earlier rows and replaces only the newly evaluated identities. Column object identities match retained sources through a rename; a different column incarnation cannot reuse an old source merely because its name matches. The existing name match remains available for definitions without object identities.

[Physical query-table selection](../../crates/uqa-execution/src/query/table_snapshot/vectors.rs) uses the existing row layout to map the selected column to its fixed base column. It requires unchanged column type and dimensions and actual matching database/table/index lineage before retaining the base reader. Let $R_B(d)$ be the fixed base row and $R_S(d)$ its selected evaluated replacement or absence. Capture consistency gives the canonical tensor of each present $R_S(d)$ from that same row's retained source; a tombstone gives absence on both paths. For a compatible column $c$, let $\pi_c$ be the existing row-layout projection followed by canonical tensor extraction. Unselected identities satisfy $C_S(d)=\pi_c(R_B(d))$ and selected identities satisfy $C_S(d)=\pi_c(R_S(d))$. These two cases cover every identity, so the projected row view and the selected canonical view agree. Applying the preceding document-score and candidate-selection argument therefore preserves row/vector composition without reading a newer private source.

The snapshot builder omits retained physical vector fields from reconstruction; a field also needed by text indexing remains in that separate projection. It shares the prepared reader and source directory without materializing a second complete vector corpus. Document counts and layout metadata retain their existing controlled reads. Partial selections with missing canonical capabilities, changed types or unsupported methods still use the preexisting reconstruction path. Unchanged column incarnations and widths across different index lineages use the independent raw-source rule below.

[Engine's capture adapter](../../crates/uqa-engine/src/session/portals.rs) supplies fixed table handles and evaluated row changes to Execution. When the source is already a query snapshot, a further capture starts from its captured tables and catalog, including retained graph handles, instead of resolving them again against live storage or durable metadata. Only row changes belonging to that query origin are overlaid. Thus a nested capture with no new changes is the identity on the selected row, vector and catalog observations, even after the original session rolls back, changes rows or drops the live index. With new evaluated changes, the right-biased overlay law above applies. Capturing fresh query-origin bookkeeping does not change those observations or acquire a new storage transaction.

## Complete evaluated row selections

A column rewrite can replace every fixed base row while selecting a new physical index definition. [Execution's retained row owner](../../crates/uqa-execution/src/query/table_snapshot/documents.rs) establishes completeness during its existing document-count calculation: it starts with the fixed source's cardinality and subtracts one for each unique selected identity present in that source. Zero remaining identities proves $D_B\subseteq\operatorname{dom}(S)$, where $D_B$ is the fixed base row support and $S$ is the evaluated replacement/deletion map. This calculation reads only the existing count and membership metadata; it adds no corpus traversal, vector projection or coordinate copy. Private insertions do not decrement the fixed support, and deletions do.

Under that premise every visible row comes from $S$. [Storage's complete selection](../../crates/uqa-storage/src/diskann_index/query/selection.rs) therefore uses $C_S^{\mathrm{all}}(d)=S(d)(d)$ for selected identities and absence otherwise, retaining the selected definition's physical generation $G$ instead of the incompatible old base reader. Every present selected source must still match $G$'s actual database, table and index lineage and width; no origin is copied from an unrelated definition. Row capture establishes $C_S^{\mathrm{all}}(d)=\pi_c(R_S(d))$. Outside $S$, both the fixed base support and the evaluated row support are absent, so the same equality holds there. Thus the row/vector preservation argument covers the entire domain even when the old column type or index definition differs.

Complete selection suppresses unselected receiver documents in point reads, document enumeration and the change cursor. The receiver may include unrelated later rows or later versions of selected rows, but none supplies canonical values to the captured view. The existing graph/side/change algorithm uses actual selected origins: covered versions use $G$, uncovered selected versions enter the existing change merge, and stale or unselected candidates are masked. Empty selections produce an empty canonical support while retaining the physical reader and its controls. A later ordinary overlay composes with this complete selected source using the same right-biased replacement law. Original source controls, physical read errors, tensor maxima, exact thresholds, candidate quotas and score/probability rules remain unchanged.

This rule does not establish completeness merely because a new index exists or the counts of two independent stores happen to match. When any fixed row is unselected, Execution retains either the compatible base above or the independently selected raw view below; simply taking the new live index would expose unrelated commits.

## Canonical values across index definitions

An exact index snapshot predating DiskANN has no DiskANN writer or revision. A recreated index has a different physical lineage even when its vector values are unchanged. Storage's [raw vector boundary](../../crates/uqa-storage/src/vector_index/canonical.rs) therefore retains immutable values independently of mutation provenance. It reads existing retained vector buffers or bounded native records; it neither assigns synthetic origins nor turns opaque provider read identities into mutation revisions. [Raw document selection](../../crates/uqa-storage/src/vector_index/canonical/selection.rs) uses the same evaluated replacement/deletion and column-incarnation premises as row selection. The runtime memory and versioned provider paths share sources and copy only the sparse selection directory. The generic Key/Value adapter preserves its existing `KeyValueRead::retain` contract: versioned providers share visibility owners, while an unversioned provider can use the already controlled prefix-copy implementation. Bounded point reads on that retained copy check value size before lending its bytes. Each point read ends before another source is read, so comparing two snapshots never nests callbacks holding the same provider lock.

Let $C(d)$ be the complete fixed tensor selected with the query rows, $A(d)$ the actual canonical tensor retained with the newly selected physical definition, and $G$ its prepared generation. Define $M=\{d\in\operatorname{supp}(C):\operatorname{origin}_A(d)\text{ exists}\land C(d)=_{\mathrm{bits}}A(d)\}$, where equality requires the same ordinal count, dimensions and every coordinate bit in ordinal order. Let $D=\operatorname{supp}(C)\setminus M$. This equality includes the sign of zero and is stronger than equality of norms, scores or a hash. The [matching owner](../../crates/uqa-storage/src/diskann_index/query/matching.rs) exposes $A$ restricted to matching tensors to the existing versioned query pipeline. The versions returned there remain the actual versions of $A$; no version is attributed to the independently retained $C$.

For $d\in M$, sequential cosine evaluation and total-order tensor reduction receive identical input bits from $A(d)$ and $C(d)$, so their raw score bits agree for every validated query, including the existing numeric edge cases. Existing graph, numeric-side and actual change coverage rules operate on these real origins. Candidates outside $M$ are masked on this versioned path. Every $d\in D$ is scored once from the complete $C(d)$ and offered to the same bounded document top-$k$ selection before exhausted-graph completion. Since $M\cap D=\varnothing$ and $M\cup D=\operatorname{supp}(C)$, no stale tensor or later-only document is admitted and no genuinely uncovered fixed tensor is lost. Absent and empty raw tensors both have zero vector cardinality. An actual empty origin may remain available to a metadata probe, but it produces no score or vector membership. The existing document-ID tie rule, tensor maxima and candidate-quota completion apply to the union. With $D=\varnothing$, this is exactly the existing physical candidate computation on $A$ restricted to $M$, including its approximation; the query does not promote all matching documents into global exact top-$k$.

Thresholds and the existing non-navigable query routes scan $C$ directly, because those routes already specify exact evaluation. A normal ANN page or record failure propagates and never selects this exact route. Decorations remain the existing raw f32 cosine promoted to the posting score; calibration, probabilities, relational filters and downstream composition are unchanged. The preceding row/vector projection argument establishes that $C$ agrees with the retained rows. Right-biased raw selection also preserves nested captures, explicit deletion and independently evaluated replacements without asserting physical lineage equality.

This cross-definition path can compare all fixed tensors during a query. It uses bounded point-read buffers and the existing candidate workspace instead of copying the corpus at capture; it makes no sublinear-work or performance claim. Ordinary compatible-lineage reads keep their existing origin-based path. A derived source containing unversioned tensors does not expose a complete `DiskANNReadSnapshot`; it exposes its actual raw source for subsequent selection. This distinction prevents later consumers from mistaking raw equality evidence for a historical mutation origin.

## Metadata selection during execution and mutation

[Execution's retrieval validation](../../crates/uqa-execution/src/operator_tree/driver/relation_context.rs) obtains the declared column type and registered vector dimensions from the same selected query-table handle. If a captured query contains a private dimension rewrite and its source subsequently rolls back, validation still checks the captured dimension. It preserves the existing error order: declared non-vector type, missing registration, inconsistent schema/index dimensions, query width, then non-finite coordinates. Schema-less embedded tables continue to use their physical registration's width. Attention query-feature extraction likewise uses the captured text index, column definitions and original serializable observer, including after live table removal.

Let $T$ be the selected table observation, with columns $M_T$, vector registration $I_T$, text statistics $A_T$ and rows $R_T$. Runtime validation is the unchanged predicate $V(M_T,I_T,q)$, and attention features are the unchanged function $F(A_T,q)$. A later live table $L$ contributes no input to either expression. Therefore changing, rolling back or removing $L$ cannot change validation or attention features for the same $T$ and $q$. Scoring and candidate selection remain their existing functions of the selected index and rows; this correction changes neither their numerical rules nor physical index construction. It does not establish physical DiskANN retention for incompatible index definitions.

[Engine's mutation hierarchy adapter](../../crates/uqa-engine/src/hierarchy.rs) has a different input: statistics invalidation and referential actions require the current mutation relation and its current ancestors. They read those hierarchy handles directly, without constructing a retained query view. Column publication can therefore invalidate statistics while holding its existing column write guard without attempting to reacquire that guard through query metadata fingerprinting. Ancestor order, visited-identity handling, persistence order and publication locking remain unchanged.

[Query relation locking](../../crates/uqa-engine/src/capabilities/query_locking.rs) uses the existing captured hierarchy traversal. A retained query that opens a transaction for calibration obtains the same hierarchy names and descendant set as its row source, even after live relation removal. Ordinary sessions without captured table handles continue to use the existing current-hierarchy traversal; current-object lock modes, binding rechecks and transaction ownership are unchanged.

## Controls and failure

Clones and nested snapshots share the original canonical roots, prepared readers, sparse directory and reservations. The directory charges only selected identities and source handles; it copies no vector coordinates or corpus directory. Query workspace remains on the receiver's original allowance. Sources retain their original allowances and cancellation controls, and read-only wrappers retain their enclosing leases and controls when exposing a source or wrapping a projected index. Invocation cancellation remains an additional check. Construction and read failure return no partial index or posting list and do not mutate either source; dropping the final owner releases its reservations.

The serializable observation wrapper forwards metadata capture without registering a query and wraps a projected index with the same original logical relation participant. Executing a nonzero KNN or threshold search therefore observes the original candidate corpus; zero-$k$ and unused captures retain their existing nonobserving behavior. Physical source composition neither creates a new transaction nor completes the original one.

## Verification and integration gate

The [Storage regressions](../../crates/uqa-storage/src/diskann_index/memory/tests/selection.rs) use actual writable forks and prepared DiskANN generations. They check fixed rows against unrelated later mutations, private insertion/deletion and whole-tensor replacement, journal compaction, literal cosine scores, exact thresholds, ordinal counts, absent terminal identities, separate evaluated versions, nested overlays, source destruction, unrelated-lineage rejection, explicit deletion despite retained old membership, ordered-selection validation, quota failure, cancellation and final lease release. Existing retained-reader regressions also cover graph read failure and shared preparation.

The [Execution regressions](../../crates/uqa-execution/src/query/table_snapshot/tests/physical_vectors.rs) verify fixed rows against unrelated later changes, explicit deletions, different evaluated versions, column-identity matching, no capture-time coordinate projection, nested retention and quota/cancellation release. The [public consumer regressions](../../crates/uqa-engine/src/tests/catalog/index_registry/diskann/consumers.rs) run through memory, native SQLite, SQLite Key/Value and redb. They check literal raw/tensor scores, thresholds, tie ordering, candidate filtering without refill, hybrid/calibrated/robust consumers, relational composition, API cursors, holdable SQL portals and nested statement copies. A REPEATABLE READ capture includes update, deletion, NULL replacement and tensor insertion, retains `diskann` through source rollback and close, and supplies the same literal results to another captured query.

The [metadata regressions](../../crates/uqa-engine/src/tests/catalog/index_registry/diskann/metadata.rs) exercise all four owners: a captured three-dimensional rewrite retains literal scores and rejects a two-dimensional query after source rollback, while the source regains its original two-dimensional results. A deadline detects recursive column-lock acquisition. Captured attention retrieval keeps the same rows and scores after live table deletion. [Execution-owned validation tests](../../crates/uqa-execution/src/operator_tree/driver/relation_context/tests.rs) cover declared vector/tensor and schema-less widths, finite inputs, missing registrations and diagnostic precedence. Independent PostgreSQL 18.4 Docker execution confirms the shared transaction premise: rewriting two `real[]` rows to `{0,1,0}` inside REPEATABLE READ and rolling back restores `{1,0}` and `{0,1}`. It does not serve as an oracle for DiskANN or the internal captured-query API.

The complete-selection owner regressions additionally exercise selected tensors against unselected physical and journal documents, an empty selection, nested overlays, final resource release and no capture-time vector projection. Execution checks an otherwise identical partial selection to ensure the unselected fixed row keeps its original value. The [definition regressions](../../crates/uqa-engine/src/tests/catalog/index_registry/diskann/definitions.rs) check new/recreated indexes after complete row replacement and three-dimensional rewrite/rollback with nested capture on all four owners. A three-provider concurrent-write case establishes that the actual new index contains newer rows while the captured fixed query preserves its older rows; selecting the whole new live index would violate that fixture.

The unchanged-row definition regressions now require `diskann` through new/recreated definitions, nested capture and rollback on all four owners. The concurrent-write fixture also requires physical retention while preserving its literal older rows and scores. The [raw-source query tests](../../crates/uqa-storage/src/diskann_index/query/tests/retained/definitions.rs) include a deterministic fixture whose approximate result differs from global exact top-$k$; reselecting identical raw values must preserve the physical candidate results. They also check whole-tensor differences, later-row masking, numeric routes, thresholds, quotas, cancellation and final-owner release.

These checks close the original compatible-column, nested-copy and three changed-definition physical-retention reproductions. Selected-generation calibration metadata, remaining planning/model provenance, binding artifacts and integrated resource acceptance keep their original plan gates. No timing, RSS or throughput result is claimed.
