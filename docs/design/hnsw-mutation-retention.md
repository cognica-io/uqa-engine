# HNSW mutation retention

Native SQLite and common Key/Value HNSW mutations previously retained their input graph but discarded the immutable graph they had just evaluated and persisted. Each following mutation therefore decoded and validated the complete previous generation. Common Storage now transfers the evaluated graph from its persistence delta; SQLite translates native record identities, while the versioned session certifies the exact staging or publication boundary. Engine, graph construction, scoring, persistent formats and dependency directions are unchanged.

## Identity and state preservation

Let $V$ be the selected canonical records and graph generation, $I(V)$ its provider-issued visibility identity, $M$ an evaluated mutation and $G'=M(G(V))$ its resulting immutable graph. Ordinary persistence writes the canonical replacement and the corresponding graph delta atomically. Retaining $G'$ is sound exactly when a later read establishes $I(V')=I(M(V))$. This includes every canonical-vector prefix and graph metadata/node family; native identity also includes the physical owner incarnation. Equal identities certify the same source records, not merely an equal numeric graph revision.

Memory captures its resulting non-reusable revision while holding the same state mutex that applies the batch. Versioned Key/Value captures the resulting private prefix revision while exclusively borrowing the transaction. Native SQLite retains that staged snapshot before releasing the session gate. The candidate never acquires an identity by opening a later read: that view could already contain another mutation. Savepoint undo restores the matching old private root, and a replacement branch receives a distinct revision. A later cache comparison consequently either selects the exact graph or uses ordinary restoration and validation. Existing retained readers continue to own their earlier immutable roots.

For autocommit, let $s$ be the evaluated committed sequence and $r$ the exact successful receipt captured before releasing session serialization. A candidate may use committed identity $r$ only when $r=s+1$. Commit sequences are strictly increasing for record publications, so no peer record commit occurred between $s$ and this receipt; reconciliation has the same committed inputs and ordered mutation as evaluation. The published graph is therefore $G'$. If the receipt is absent, completion fails or $r\ne s+1$, the implementation retains only its private certificate, which cannot match the newly committed view. A peer commit after $r$ likewise produces a different committed identity. No failed or uncertain publication installs a candidate.

## Observable results and resources

The transferred candidate uses the same graph nodes, active tensor ordinals, tombstones, random construction state and floating-point coordinates as the persisted delta. Only the already staged dirty-node set is discarded. For each query $q$ and result limit $k$, the existing search algorithm therefore receives the same graph and evaluates the same scores, tie order and tensor reduction: $\operatorname{search}(G',q,k)=\operatorname{search}(\operatorname{restore}(\operatorname{persist}(G')),q,k)$. This equality concerns complete ranked postings, not only their document support. Subsequent mutations receive the same graph state, so induction preserves every finite mutation/query composition; no new UQA operator or algebraic law is introduced.

The candidate transfers its original construction reservation into the immutable cache owner. It does not copy the graph or obtain another memory allowance. Reader controls retain their original cancellation and allowance rules. Optional identity capture or cache-header admission may fail after successful staging; that drops the candidate and leaves the successful mutation result and ordinary validated restoration intact. Errors during evaluation, staging or commit follow the existing cleanup path without replaying application code.

## Verification and limits

The deterministic Key/Value fixture checks complete persisted topology against the serial in-memory owner after each of 32 inserts, followed by replacement, deletion, search and clear. Whole-graph restoration is zero, compared with 32 restorations for the original insertion fixture. A provider omitting certification still restores all 32 generations and returns the same count. Native SQLite checks zero restores in explicit transactions and uncontended autocommit, exact ranked results, retained readers and restoration after rollback. Shared conformance cases exercise memory, SQLite Key/Value and redb certificates through autocommit, failed evaluation, savepoint branches and outer rollback. Native tests inject an intervening independent commit and a graph recreation; the original mutation is evaluated once, and readers see either the correct merged graph or the original publication conflict.

This removes avoidable whole-graph reconstruction after own writes. It does not remove intrinsic HNSW neighbor search, commit reconciliation after competing publications or the private-key metadata work needed to establish existing visibility identities. Operation counts are deterministic regression evidence, not controlled latency or throughput acceptance.
