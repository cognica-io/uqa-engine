# SQL text-prefix comparison

SQL owns the binary `^@` operator and the shared `starts_with` kernel. PostgreSQL 18 selects the immutable, strict `text ^@ text` operator (OID 3877, function OID 3696); ordinary routine lookup must not replace that operator. The independently captured catalog and public transcript are in `crates/uqa-sql/src/type_resolution/pattern/tests/overloads.json` and `crates/uqa-engine/tests/pg18_semantics/prefix_operator.json`.

Let $T$ be the finite UTF-8 strings admitted as SQL text, and let $\bot$ represent SQL NULL. For $s,p\in T$, define $P(s,p)$ to be true exactly when there is a finite byte suffix $r$ such that $s=p\mathbin{\Vert}r$. The empty prefix is an identity for this predicate: $P(s,\epsilon)=\mathrm{true}$. If $|p|>|s|$, the predicate is false. Otherwise, comparing the first $|p|$ bytes of $s$ with $p$ is equivalent to this definition. Because $p$ is valid UTF-8, equality also establishes a complete character prefix. Case folding, normalization and wildcard interpretation are not part of this operation.

The SQL lifting has domain $(T\cup\{\bot\})^2$ and codomain $\{\mathrm{true},\mathrm{false},\bot\}$. Either NULL argument yields $\bot$ before the kernel observes a collation. For non-NULL arguments, PostgreSQL's collation validation precedes length shortcuts and comparison; an indeterminate collation is an error. Every currently admitted built-in collation is deterministic, so successful comparison uses the same byte predicate. PostgreSQL rejects nondeterministic collations for this operation; introducing such a collation requires preserving that rejection in its provider contract.

For a relation $R$, evaluating this scalar predicate in selection retains exactly the rows whose predicate is true, preserving their multiplicity, identities, payloads and ordering observations. Therefore selection remains closed over the same relation carrier, and applying the same successful predicate twice retains the same rows as applying it once. This does not assert commutation of error-producing expressions or new laws for scored payloads. No planner rewrite, score conversion or physical hash equality is introduced. Prepared operands retain the selected text conversion, and stored definitions retain the operator and input collation, so reopening preserves this same lifted predicate.

The implementation compares borrowed text bytes with Core's existing bounded-chunk cancellation checks. It produces a fixed-size boolean without copying the input strings. Cancellation and failed collation validation produce no database mutation and retain no workspace. Owner tests exercise zero memory allowance, both cancellation scopes and collation error ordering; the independent PostgreSQL transcript covers public values, types, diagnostics, prepared parameters and stored definitions across memory, native SQLite, SQLite Key/Value and redb.
