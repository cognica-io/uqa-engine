# Owned JavaScript HTTP notifications

The addon-free Node package implements `HttpEngine.subscribeNotifications(channels, options)` over its original authenticated origin. This document extends the [JavaScript protocol proof](javascript-notification-protocol.md) to the actual HTTP owner required by [SQL notifications and SSE](sql-notifications-and-sse.md). It does not establish embedded addon delivery, browser behavior, an authenticated Cloud endpoint or deployment resource defaults; their evidence remains assigned in the [fixed implementation ledger](../plans/0015-sql-notifications-and-sse.md).

## Values, admission and FIFO observations

Let $E$ and $J:E\to E_{JS}$ be the original event carrier and injective JavaScript representation from the protocol proof. Define the internal queue encoding $Q$ to store the variant tag, the canonical epoch's sixteen bytes and the ASCII request identity with its length. A notification adds its unsigned 64-bit sequence, signed 32-bit process identifier, channel byte length, payload byte length and exact UTF-8 strings. A gap adds the closed failure code; reconnection has no message fields. All admitted string lengths fit their encoded lengths; sequence and sender conversions use the matching full-width DataView operations. Canonical UUID formatting, exact integer reads and scalar-valid UTF-8 decoding give $Q^{-1}(Q(J(e)))=J(e)$ for every admitted $e$. No floating-point conversion, Unicode normalization, channel rewriting or payload interpretation occurs.

The bounded ring stores one separate byte allocation per queued event. Enqueue writes only at the current tail and advances the count after a successful capacity reservation; dequeue clears only the head, advances it modulo capacity and returns the inverse decoding. Induction on these operations proves that dequeue observations equal the FIFO prefix of enqueued values, including arbitrary ring wrap. If an enqueue exceeds either bound, that value is not accepted and the worker terminates with `NOTIFICATION_BACKPRESSURE`. Previously accepted events remain readable before the retained failure. Observed authentication rejection, authority revocation and cancellation discard the unsent prefix as required by the authority and cancellation contract. Explicit close ends iteration after local cleanup.

One pending consumer owns the wait slot until its operation completes. Another concurrent receive fails without changing the queue or stealing the first consumer's ownership. Every enqueue wakes that single waiter, and terminal completion wakes it after transport cleanup. JavaScript execution serializes the empty-queue check and waiter installation without an intervening await; publication therefore cannot be lost between those two operations. This establishes FIFO observation under event-loop progress and serialized application consumption, not exactly-once application processing.

## Epoch and retry ownership

Registration resolves only after the existing strict decoder admits ready for the original channel set and response identity. Initial HTTP or readiness failure is returned directly, even when retry is configured. After a retryable post-ready loss, the worker appends a gap carrying the lost identity and original cause before starting a replacement. A replacement must present a different canonical epoch; it appends reconnection before any new notification. The public identity changes only when the consumer dequeues that reconnection. These transitions preserve the concatenation of within-epoch FIFO histories with explicit gap and reconnection separators; they do not assert continuity, replay or a common sequence counter across epochs.

Each reconnect episode retains its original failure, absolute monotonic deadline and replacement count. A failed replacement keeps that episode and its last failure. The count increments before starting each replacement and is checked against the explicit maximum. Jitter is bounded by the explicit exponential cap, and validated Retry-After guidance can only increase the selected delay within its own cap and the unchanged episode deadline. A new admitted ready ends the old episode. Exhaustion preserves the original and last causes and makes the final error nonretryable. Authentication, authority rejection, corruption, unsupported endpoints and local overflow cannot obtain retry authority through server text or an unknown error code.

An attempt owns its ClientRequest, IncomingMessage and socket. Destruction is followed by awaiting their actual close events; the worker cannot start the next attempt until that barrier completes. The same barrier precedes terminal notification of a waiting consumer. AbortSignal stops pending connection, readiness, receive or backoff; explicit close signals the same controller and joins the worker, including concurrent close calls. A finalizer signals an abandoned idle facade as a best effort, but finalizer scheduling has no deadline and does not replace explicit close, AbortSignal or iterator return. A pending receive retains its facade owner. Continued event-loop progress is an explicit precondition of asynchronous cleanup; this proof does not impose an operating-system DNS, provider or whole-process teardown deadline.

External abort clears unread queue storage and sets the monotonic cancellation signal before its observer returns. Later enqueue checks that same signal, and a receive observes cancellation before taking a queued value. It joins the original worker before exposing the retained terminal failure; completed explicit close still ends iteration normally. Thus no receive that starts after observed cancellation can return the previously queued prefix, even when transport cleanup has not yet completed. A gated-cleanup regression failed against the earlier implementation and now verifies cancellation, immediate ended-delivery state, joined cleanup, repeated receive failure and explicit close.

## HTTP, timing and resource boundaries

Each attempt sends one POST to the retained original origin with the original request and credential. Node's native HTTP/HTTPS path has no application proxy, redirect following, decompression or automatic retry; idle connection reuse is disabled. TLS validation remains enabled. Credentials are added to the request after creating the connection options, avoiding an additional copy in the agent's options. The closed HTTP header contract, bounded strict JSON error envelope and existing SSE decoder validate all observable wire state before it can become a subscription event. SDK error formatting exposes closed categories only; explicit private-diagnostic access does not add retry authority. This establishes the SDK's diagnostic behavior, not a confidentiality boundary against host instrumentation that can inspect its own sockets or objects.

Connection establishment has its own timer. The absolute readiness deadline includes response headers, error-body parsing and the complete ready event, so pre-ready comments cannot extend it. Admitted ready replaces that deadline with the advertised idle budget, bounded by the caller's local limit. Subsequent nonempty chunks refresh liveness; complete-frame processing also checks the current monotonic deadline and yields the event loop between frames. Reconnect readiness is clipped to the unchanged episode deadline. These transitions introduce no SQL request lifetime timeout. The server's blocked-write budget remains a separate required owner. Timer relationships are validated exactly by the decoder; no measured scheduling margin is inferred from these functional checks.

For requested queue count $C$ and encoded-byte allowance $B$, the queue reserves a logical charge of $8C$ for its reference slots before opening HTTP and requires $8C\le B$. With retained records $r_i$, enqueue requires both $n<C$ and $|r|\le B-(8C+\sum_i|r_i|)$. Therefore $n\le C$ and $8C+\sum_i|r_i|\le B$ are inductive invariants. Each record owns one exactly sized `Uint8Array` allocation; text is encoded directly into its admitted storage without another encoded payload buffer. The [portable byte proof](javascript-notification-protocol.md#portable-byte-representation) establishes the unchanged record lengths and value inverse. Dequeue releases its slot and encoded-byte charge; terminal cleanup releases the slot array. JavaScript object, array and allocator overhead are additionally bounded by the event count and belong to whole-process qualification rather than being represented as an invented byte-exact RSS limit.

The request body and parser frame are each bounded by the protocol's 65,536-byte limit; the owner retains at most one application transport chunk bounded by the explicit chunk allowance. Error parsing uses one fixed 65,536-byte buffer and bounds total error bytes before copying. Response headers have a 65,536-byte parser ceiling. Within that byte ceiling the request disables Node's default header-count truncation, ensuring that a later duplicate cannot disappear before validation; protocol upgrades terminate explicitly. Runtime readable buffering, socket/kernel buffers, temporary decoded values, runtime task storage and shared process state remain additional components of the required complete resource profile. No deployment capacity or timing margin is claimed from these data-structure invariants.

## Preservation and evidence

The subscription state machine receives its transport attempt, bounded random-integer sampler and monotonic clock from an internal runtime adapter. The Node entry point supplies the same native attempt, cryptographic sampler and clock as before. For any fixed attempt-event trace, sampled delays and clock observations, substitution of this adapter leaves every branch condition, queue operation and completion barrier unchanged. Induction over state-machine transitions therefore gives identical readiness, event, retry and cleanup observations. Header/error validation now consumes standard byte arrays and the same strict UTF-8 decoder; copying the identical input octets into the identical fixed-size buffer preserves its validation result. This boundary permits sharing code but does not establish that an unimplemented browser transport satisfies the attempt contract.

The HTTP adapter executes no SQL, publishes no notification and changes no Engine transaction. Committed histories, rollback, transaction-local duplicate suppression and selected-channel projection remain upstream preconditions. Since $J$ and $Q$ preserve individual values, the FIFO and epoch arguments preserve the ordered observations of those histories without introducing a query operator, scoring rule, optimizer rewrite or alteration of UQA's existing algebraic compositions.

The Node HTTP harness exercises actual loopback TCP/HTTP connections through the manifest-copied addon-free package, including bytewise UTF-8 readiness/data, exact request snapshots, single-consumer waits, aborted TLS/readiness/receive/backoff, joined close and iterator return, explicit replacement identities, retry exhaustion, server guidance, queue bounds, authority discard, corrupt headers/frames, strict error envelopes, silent peers and cumulative streams. Queue fixtures independently include the full unsigned 64-bit maximum and signed process minimum. An offline packed-and-installed npm artifact executes SQL and an actual notification iterator without a native addon. These checks establish local client behavior; authenticated server, embedded runtime, supported-platform, process-resource and timing qualification remain required.
