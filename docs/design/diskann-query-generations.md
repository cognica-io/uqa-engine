# DiskANN query generation selection

Storage selects the physical generation on the same retained catalog and canonical view used by the query. Both `RetainedDiskANNCanonical::selected_source` and `RetainedSQLiteDiskANNCanonical::selected_source` use the shared selection owner; SQLite translates native keys and rows. The [document search owner](diskann-document-search.md) consumes this selection to merge paged candidates, numeric-side entries and changed documents. Public index dispatch, SQL and runtime acceptance remain in the [implementation plan](../plans/0014-diskann-vector-index.md).

## Selection and visibility

A bound canonical capture retains the actual table/index definitions, canonical tensor/origin/journal view and logical DiskANN namespace. Selection resolves the captured incarnations, reads that view's head and Published state, and verifies the physical history, data identity, durable handles, dimensions, complete-origin manifest and full catalog parameters. An absent head stays absent. A changed catalog configuration cannot reuse an incompatible generation merely because its index identity is unchanged.

A committed head retains the physical read view already selected by the query. It does not open another session after reading the head. A later publication or physical record replacement therefore cannot pair the old head with newer pages or a newer Retired state. Opening reads fixed metadata; graph pages, codebooks, PQ codes and origin batches remain lazy. The provider's existing retained MVCC lease preserves their physical history.

A private head may select staging artifacts committed after the SQL data snapshot, including the initial physical data marker and mappings. [Atomic publication](diskann-generation-publication.md) retains the actual verified sealed read source with the private head replacement through `KeyValueBatch::put_with_retained_source`. Query selection requires that attachment, the original seal owner and a private Published transition on the selecting view. The attachment validates the independent physical namespace while canonical rows keep the original SQL view. Missing resources, an ordinary equal-byte head replacement or inconsistent metadata fail closed; opening a fresh physical session cannot repair that missing provenance.

## Transaction ownership

Common MVCC owns a separate charged persistent map for metadata read sources. Ordinary row payloads and their change entries acquire no resource field. Metadata bytes and their source enter one evaluated private change atomically. Savepoints and retained snapshots share both immutable roots; failed operations and savepoint undo restore both. An ordinary overwrite or deletion clears the attachment from the new view even when the selecting bytes compare equal. Existing snapshots retain their original source until their last owner closes. Empty attachment entries remain bounded by the transaction's changed metadata keys and retain no physical reader.

Command refresh carries an attachment forward only when its selecting bytes survive the resolved write set unchanged. A savepoint restores its original committed boundary and source root after that refresh. Superseding a private generation gives the new head its own source while an older retained query continues using the previous selection. Native adapters translate only the selecting metadata key/value; the retained physical reader keeps its original logical key space and controls.

Only selecting bytes are durable; the attachment does not alter the record format, commit fingerprint or receipt. An evaluated transaction retains its private sources while an original commit outcome is unresolved. Receipt recovery uses the existing evaluated attempt without replaying publication or borrowing a newer source. After commit or cold reopen, a new query obtains the selected graph from its committed snapshot and requires no process-local attachment. A previously retained private query keeps its independent roots even after the transaction completes.

## Correctness and resource boundary

Let a query view consist of its committed snapshot, immutable private roots and captured catalog definitions. Its selected head is a function of that fixed view. For a committed head, the physical reader is retained from the same view, so every immutable page remains visible under the selected generation identity. For a private head, the selecting write and its verified sealed source share one atomic root publication and undo boundary; later commands cannot replace one without producing a different view. Exact manifest and incarnation checks prevent an unrelated source from satisfying the selection. These cases preserve head/page correspondence without changing canonical row visibility or inferring snapshot order from writer identities.

This correspondence authorizes physical candidate reads, not canonical document visibility or final scores. A graph can precede later canonical changes; the document query merge checks actual origin versions, includes uncovered current replacements and scores complete visible tensors through the existing canonical scorer. No probability conversion, relational filter movement or ranking change occurs at source selection.

Source wrappers, immutable map entries and retained views keep their original memory reservations. The existing standalone physical opener retains its independent read lifetime; cancelling a completed opening operation does not cancel later reads made with a fresh invoking control. Each read checks the selected query's original cancellation, the physical reader's control and the invoking control; bounded decode and page buffers use the invoking allowance. Scope resolution retains the existing catalog decode reservations, separately from the origin record-size limit. Retaining a snapshot does not copy the graph, but it can delay physical history collection; final generation reclamation must respect these actual owners. This contract makes no timing or RSS acceptance claim.

## Verification

Provider fixtures construct physical generations after the caller's data snapshot, select private pages without advancing canonical visibility, explicitly refresh commands, undo nested savepoints and retain old private and committed generations after supersession. SQLite native and Key/Value exercise plain, encrypted, compressed and combined files; redb releases all owners before cold reopen. Real page and complete-origin reads verify the selected generation, alongside incompatible configuration, missing attachment, original cancellation and quota rejection. Common MVCC tests check last-reader release, equal-byte replacement, delete/prefix deletion, failed batch atomicity, savepoint restoration, durable bytes without durable attachments and lost publication replies. Source-scoped results and review evidence belong to the implementation plan and PR.
