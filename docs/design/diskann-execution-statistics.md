# DiskANN query execution statistics

Status: Storage returns successful work from the original invocation; Execution collects retained invocation records and Planner renders them in SQL `EXPLAIN ANALYZE`. Source-scoped verification belongs to the existing [SQL integration unit](../plans/0014-diskann-vector-index.md#sql-lifecycle-and-planning). Static [physical EXPLAIN](diskann-explain.md) estimates remain separate from execution measurements.

## Observations and ownership

`DiskANNQueryResult` retains its postings, numeric exact-route reason and `DiskANNTraversalStats`, and adds `DiskANNQueryWork`. Traversal retains its cache-independent approximate/completion node expansions, PQ estimates and beams. `DiskANNTraversal::page_stats` and query work separately report graph-page/cache/provider outcomes, which can change when the cache is warm without changing navigation. Query work attributes successful complete-tensor cosine scoring to graph/side reranking, uncovered changes, independent raw tensors or an exact scan. Numeric-side entries count the references actually visited, including references rejected by canonical visibility. Empty tensors have no cosine evaluation and contribute zero scored documents and vectors. Repeated scoring is repeated work, not a distinct-document census.

`DiskANNReader::read_pages_with_stats` returns the actual leases and `DiskANNPageReadStats` from one call. Node decoding deduplicates packed/fragment page requests using its existing directory before collecting these counts. Each batch records its real cache probes, missing pages and completed provider call; it does not sample global cache counters before and after a search. A page fetched concurrently by another query can affect this query's actual cache outcome but cannot add that query's work to these counters. Existing `read_pages` and `read_nodes` delegate to the same implementation and return their original results.

Provider pages and batches describe the `read_graph_pages` interface. They do not measure SQLite/redb cache behavior, compressed or encrypted file sizes, operating-system reads, SSD operations or elapsed time. Origin, side-record and other metadata I/O is not part of graph-page counters. Scoring counts describe actual cosine evaluations and exclude provenance/equality checks; they are not an estimate of every CPU operation or coordinate read.

Exact KNN and threshold scoring expose invocation statistics through their existing owner algorithms. `search_threshold_with_stats` returns the threshold result and its work; `search_threshold` preserves its original posting-only API. Both numeric exact KNN routes and threshold evaluation count every scored tensor before candidate or threshold filtering. A valid zero-k invocation returns zero search work while retaining its existing input validation.

## Common vector-index boundary

`VectorIndex::search_knn_with_statistics` and `search_threshold_with_statistics` return `VectorQueryResult`: the actual postings and optional `DiskANNExecutionStats`. The report includes the selected immutable generation, actual route, navigation counters and query work. Routes distinguish approximate search, zero-norm/nonfinite-norm exact search, exact threshold evaluation and validated zero-k calls. Providers without reporting support execute their existing ordinary or controlled method exactly once and return `None`; absence is not zero measured work.

Memory, persistent and retained DiskANN indexes forward this result from the same prepared query. A live persistent handle captures one provider snapshot; it does not obtain report identity through a later live metadata lookup. Read-only snapshots preserve their selected allowance and original cancellation scope, check any independent invoking control before and after the call, and forward the original report. Execution's serializable wrapper performs the same validation and logical candidate-range observation before forwarding; zero-k and invalid queries retain their existing nonobserving behavior. Selected-source and nested snapshots preserve that participant.

The shared counter and route carriers live in Core. Storage retains their production and checked accumulation; the existing Storage exports preserve their public types. SQL carries admitted invocation records without importing Storage, and Planner owns their formatting.

## SQL invocation collection

Execution enters an admitted diagnostics scope around the existing nested executor in `execute_explain`. It executes the body once on the original statement context, including DML. Engine supplies the existing runtime identity and retention control; it does not clone a read facade to execute writes. Ordinary queries continue through their original posting-only methods when there is no active scope.

Each successful reported primitive appends its actual relation, field, requested K or threshold, returned document count, immutable generation, route and work. `Vector Searches` is separate from JSON `Physical Plans`; TEXT labels each record `Vector Search:`. Records identify actual calls, not speculative plan-node matches. Repeated calls remain separate, and parallel records may appear in completion order. An unsupported index contributes no record. An optimized SQL branch that invokes no index also contributes no record. SQL KNN requires a positive K; a zero-k primitive invoked through a supporting API retains its real empty-k report. Neither absence means a measured zero.

Nested ANALYZE has its own report; successful supported primitives also belong to each enclosing ANALYZE in the same logical session. Session identities isolate unrelated Engines and public sibling sessions. An admitted per-thread binding holds the session identity, captured collector and previous binding; its guard restores that binding on success, SQL error or unwind. Read-worker runtimes preserve the same logical session identity. Streaming portal and directional workers receive the requesting invocation on every step and rewind, including explicit absence; a cursor opened earlier can therefore report work performed by a later FETCH inside ANALYZE. A request binding changes only while the worker is suspended waiting for its caller. Query entry does not pin that binding across FETCH requests. Each parallel branch installs the driver's already-captured collector before invoking callbacks, so a child scope on one worker cannot capture another worker's work. Raw public snapshot contexts never acquire a diagnostics observer merely by being retained.

Records, relation/field strings, collector payloads, thread bindings and record-vector capacity retain the original allowance; nested reports share immutable record payloads. The collector never retains query vectors or rescans a corpus. A failure to append a successful primitive marks every affected enclosing collector incomplete. Even if SQL catches that error, finishing ANALYZE fails with the original failure class instead of publishing a partial successful report. Cancellation remains cancellation. Completed collectors reject late explicit appends; later runtime captures ignore completed inherited scopes.

## Preservation argument

Fix the retained canonical/physical view, query inputs and actual provider/cache completion schedule. Let $\sigma$ be the successful execution trace of the existing search. Its posting observation $R(\sigma)$ includes document support, complete tensor scores, payloads and ordering. The extension returns $(R(\sigma),W(\sigma))$ and changes no navigation choice, visibility predicate, score reduction, candidate admission, threshold comparison or posting construction. Erasing the second component therefore recovers the original result, including its established binary32 arithmetic and tie behavior. No extra search, tensor scan or graph read is used to obtain $W$.

Define $W$ as the componentwise sum of the actual successful work events. Each vector-bearing complete tensor score contributes $(1,n)$ to exactly its scoring category, where $n$ is the number of cosine evaluations already performed by the scoring owner. Each visited side reference contributes one independently of whether it produces a score. These are additive observations of the execution trace: $W(\epsilon)=0$ and $W(\sigma_1\mathbin{\|}\sigma_2)=W(\sigma_1)+W(\sigma_2)$. Associativity follows from integer addition on the representable count domain. It does not assert associativity of floating-point scores or a new law for ranked payloads.

For graph pages, each admitted requested page has exactly one retained cache lease or one completed provider slot. Consequently $R_p=H_p+P_p$, where $R_p$ is page requests, $H_p$ is cache hits and $P_p$ is provider pages. A nonempty missing-page batch contributes one provider batch; an all-hit batch contributes zero. Summing these partitions over node-read calls gives the traversal's counts. Packed nodes share the same request within a call, fragments remain separate pages, and a later request for the same page is new logical work. The statistics are local return values, so simultaneous queries cannot contribute to one another's sums.

All additions are checked; overflow fails without publishing a partially updated aggregate, as with the existing traversal counters. No resource allowance is replaced, no read is admitted outside the original controls, and no new corpus-sized diagnostic structure is retained. A provider, visibility, decoding, budget or cancellation error returns the existing error path without exposing a successful query report. For successful representable traces, erasing the observations preserves every existing posting, relational and ranked composition because their operands and operation order are unchanged.

The interface extension is a projection-preserving lift: for every successful invocation with live controls, $\pi_P(P,D)=P$. An unsupported implementation returns $(P,\mathrm{None})$ after one original dispatch; a DiskANN implementation returns $(P,\mathrm{Some}(g,r,W))$ from that same prepared reader. Here $g$ is its immutable generation and $r$ is its executed route, including the empty-k branch. Wrappers forward the pair without querying either component again. Consequently result erasure commutes with wrapper composition and preserves the established posting and ranked operations. Serializable observation remains the same pre-search effect and is not repeated to obtain diagnostics; a cancelled or failed call exposes no successful pair.

## SQL collection preservation

Let $P$ denote the established primitive posting carrier, including decorations and scores, and let $D$ denote finite multisets of admitted invocation records. Diagnostics composition is multiset union $\uplus$ with empty identity $\varnothing$. Closure follows because each completed scope has finitely many admitted records; associativity and identity follow from addition of record multiplicities. This is an observation algebra, not a new score or posting operation, and does not claim commutativity of UQA payload merging.

For a successful supported primitive trace $\sigma$, collection lifts its existing result to $(P(\sigma),\{d(\sigma)\})$. An unsupported primitive lifts to $(P(\sigma),\varnothing)$. Every execution and wrapper consumes exactly the original $P(\sigma)$, so erasure $\pi_P$ commutes with the existing posting, probability, ranking and relational compositions. No diagnostic code changes score arithmetic, support selection, candidate K, filtering, branch order or mutation dispatch. Additional admission can fail; preservation is asserted for executions whose original work and added diagnostics are both admitted, not as a promise of identical memory requirements.

For a scope $s$, let $L_s$ be the multiset of successful supported primitive invocations executed in $s$ or its nested scopes in the same logical session. A fixed collector parent chain has exactly one node per enclosing scope. Recording visits that chain once, appending the same immutable record exactly once to each node. Therefore the completed report is $D_s=\biguplus_{\sigma\in L_s}\{d(\sigma)\}$. Parallel interleavings may change presentation order, not this multiplicity. Explicitly captured worker bindings and distinct session identities prevent a simultaneous scope from becoming an accidental ancestor. Any append failure marks the entire affected chain incomplete, so no successful finish can falsify this equality by omitting a completed supported primitive.

The explained body's original nested executor, privilege subject and Engine state are unchanged. Consequently the diagnostic projection introduces no additional DML execution, transaction, epoch publication or sequence/host callback evaluation. Guard restoration changes only the diagnostics binding and does not commit or undo product state. Existing SQL transaction machinery retains responsibility for the effects of successful commands and command failure. SQL/provider regression cases and independent PostgreSQL DML reference results exercise this state-preservation obligation separately from the multiset proof.

## Verification

Owner fixtures use literal counts for packed pages, multi-page node fragments, actual provider batch limits, warm shared caches, concurrent invocations, invalid requests and original resource/cancellation failures. Query fixtures independently enumerate covered tensors, stale graph candidates, side entries, changed tensors, empty tensors and unversioned replacements. They compare literal scores and counts, check that existing tensor visitors run once, and repeat searches to reject accumulated shared totals. Numeric exact routes and threshold filtering count work before result reduction. Executed source-scoped evidence belongs in the implementation plan; these owner obligations do not alone establish SQL collection or language artifacts.

Interface regressions independently count canonical visits, require literal covered/change/exact work, retain older physical generations across mutation and rebuild, and distinguish unsupported reporting from zero-k work. Persistent acceptance runs against actual native SQLite, SQLite Key/Value and redb handles. Original allowance exhaustion and independent cancellation return errors; actual serializable histories exercise report searches and nonobserving zero-k/invalid controls.

The independent PostgreSQL state reference uses Docker image `postgres:18.4`, reporting server `18.4 (Debian 18.4-1.pgdg13+1)`. After creating a temporary `id int` table, `BEGIN; EXPLAIN (ANALYZE, COSTS OFF, TIMING OFF, SUMMARY OFF) INSERT INTO ... SELECT id FROM (VALUES (1),(2)) AS source(id)` leaves two rows visible inside the transaction; `ROLLBACK` restores zero. This is a state/row-count oracle, not a timing measurement or a PostgreSQL implementation of the DiskANN extension.
