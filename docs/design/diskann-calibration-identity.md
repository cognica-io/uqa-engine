# DiskANN calibration identity

The fixed-model boundary preserves the existing cosine-to-probability transform and binds it to the actual retained retrieval surface. Scoring owns the numeric transform, Execution validates runtime provenance, Storage supplies physical and canonical metadata, and Engine retains the table, statement, index and serializable observer. No Cargo dependency direction or feature changes are required.

## Selected inputs and version encoding

Let $C$ map document IDs to complete ordered canonical tensors, and let $G$ be the selected validated DiskANN manifest. The existing raw query returns a document posting carrier $P=Q_{G,k}(C,q)$ with complete tensor cosine scores. The requested document count $k$ remains the model target's `candidate_k`; graph expansion counts and tensor ordinals never substitute for it. `DiskANNQueryMetadata` returns $G$ and an optional canonical fingerprint from the same selected owner. The fixed-model API retains one physical/canonical snapshot before checking the target and searching it, so validation cannot describe one generation while KNN uses another.

`index_version` is `uqa-diskann-index-v1:` followed by the lowercase hexadecimal SHA-256 digest of the domain `uqa-diskann-index-v1\0` and the complete canonical manifest encoding. The encoding includes database/table/index incarnations, graph/PQ generation and artifact digests, format/navigation/scoring/build revisions, dimensions and effective build/search parameters. Reader preparation already checks the manifest against the selected configuration. Cache contents, page completion order and requested query controls are excluded because they do not change the retrieval function.

`corpus_version` is `uqa-vector-corpus-v1:` followed by a storage-owned fingerprint. Persistent vector writes already touch one shared field-reference marker in the same evaluated mutation; structural transitions fence that marker. The marker protocol merges independent document writers and does not add a global write permit. A fingerprint reads the marker's committed metadata and its exact private batch identity separately, on the canonical source's fixed view. It includes the storage history incarnation and physical marker key. Unrelated catalog commits, including saving a fitted model, do not change this field identity. A private marker must not mask a newly visible committed marker: that would miss peer changes to unselected documents at READ COMMITTED.

The marker encoding is domain-separated and length-delimited. Missing, live and tombstone committed states have distinct tags; committed revisions and optional private revisions have fixed-width little-endian encodings. Private revisions include a randomly allocated process incarnation and the process ID, preventing counter reuse across restart or a forked process from authorizing a different private view. Private targets are therefore view-local, not a claim of durable committed provenance. History restoration can conservatively invalidate a previous corpus target even when the copied values are equal.

Writable memory DiskANN roots use the existing non-reused vector mutation identity; undo restores the retained earlier root, and rebuild preserves that root's corpus identity while changing $G$. An immutable exact memory corpus computes its raw-bit fingerprint once when its already materialized buffers are adopted, including dimensions, document IDs, ordinals and coordinate bits. Reading metadata or retaining its raw capability does not rescan those vectors.

Materialized HNSW and IVF sources use a storage-allocated immutable-view identity when their already captured owner first exposes canonical values. The [method-transition argument](diskann-private-query-sources.md#canonical-sources-after-changing-the-index-method) establishes that this identity binds the same complete raw field without another coordinate scan or copy. Nested captures share it; independently captured equal fields can conservatively invalidate a prior target. This is snapshot-local identity, not a claim of persistent revision or content equality across separate captures.

Sparse row selections fingerprint their selected base, ordered document IDs and each evaluated replacement source or deletion tag. Complete selections omit the unselected base. An empty ordinary overlay returns the base fingerprint unchanged. Cross-definition matching uses the selected raw source's fingerprint, not the newer physical generation's live corpus. Unsupported providers or sources return no fingerprint; fixed-model reuse is rejected instead of accepting a caller-provided version string. Standalone numeric model transforms retain their existing caller-target contract.

## Preservation argument

Assume the existing mutation/visibility contracts: every vector change updates its field marker atomically, private batch identities are never reused within their process incarnation, committed revisions and history identities are not reused for another visible history, and physical generations are immutable. Also assume no SHA-256 collision among the accepted metadata encodings and no collision among allocated process or immutable-view incarnations. These are explicit identity assumptions, not an assertion that finite digests are mathematically injective.

For a persistent base source, equal marker inputs imply the same selected committed field changes and the same private evaluated field changes under those contracts. Reading the two marker layers separately is necessary: equality of only the overlaid marker would not establish equality of the committed input. Memory root identities have the same implication by their non-reused mutation allocator. For an immutable exact corpus, equality follows under the stated digest assumption from the complete canonical raw-bit encoding. For a sparse selection, equality of the ordered base/replacement/deletion encoding implies the same source identity in each selected document position; the right-biased row-selection rule therefore gives the same $C$. These implications are sufficient and deliberately conservative: equal values can have different version fingerprints.

Equal accepted physical metadata identifies the same $G$, algorithm/configuration contract and graph/PQ artifacts. Equal complete targets additionally require the same table/field identity, index kind, dimensions, embedding contract and requested $k$. Thus an accepted model describes the actual function $Q_{G,k}$ over the actual $C$, subject to the original ANN approximation. An unknown or unequal runtime identity produces an error before KNN results are exposed. It never triggers refitting, an exact-search fallback, or a query-pool transform.

For a fixed Gaussian distance transform $T_\theta$, the result is $\{(d,T_\theta(1-s_d)):(d,s_d)\in P\}$, with the existing deterministic ranking. The domain is the canonical raw cosine score; PQ distances and navigation scores cannot enter this map. The implementation uses the existing Scoring transform with the persisted $\theta$ and one supplied prior. Equal raw score bits and fixed parameters yield the same probabilities. The transform neither changes document support nor reinterprets payload collision or fusion operations. Ordinary filters still act after the requested candidate pool; this validation does not authorize a filter pushdown or a top-$k$ rewrite. SQL query-pool estimation and its prior-free hybrid evidence path remain unchanged.

Metadata capture does not execute a logical vector query or register a vector predicate. The actual KNN call retains its original serializable observer and original read allowance. Storage, budget and cancellation failures propagate. The fingerprints require bounded metadata workspace plus the existing sparse selection directory, without a persistent corpus scan or per-document global writer permit. None of these identity or transform properties establishes empirical probability calibration or ANN recall; those remain separate acceptance gates.

## Verification boundaries

Storage tests cover corpus mutations, unchanged corpus under rebuild, retained generations and both original and invoking cancellation. Execution tests exercise actual runtime versions and target/name/type rejection. Engine adapter scenarios cover the four runtime owners, literal fixed-transform probabilities, forged labels, private writes and savepoint restoration, retained old readers after recreation, persisted models after reopen, unrelated commits, and a private writer whose READ COMMITTED view advances after a peer updates another document. Final source-scoped outcomes are recorded in the [implementation plan](../plans/0014-diskann-vector-index.md); this design does not by itself claim that unfinished verification has passed.
