# Prepared mutation text publication

Execution owns grouping of prepared SQL row mutations in `uqa-execution/src/mutation/publication.rs`. Engine binds the existing row transaction, tuple lock, document store, vector indexes and text index. The source text, analyzer bindings, occurrence representation, scoring operations and physical commit protocol are unchanged.

## State and observation boundaries

Let `D` be a relation's document mapping, `T` its decorated occurrence index, `V` its vector and value indexes, and `O` its transaction observations and document guards. A prepared replacement at identity `i` supplies a fully evaluated document `d_i`. Its text operation `t_i` is the existing complete occurrence replacement, including analyzer revision validation, offsets, positions, reverse terms, field statistics, cache invalidation and serializable write observations. Equality of term support alone is insufficient to replace this operation.

An eligible publication interval contains prepared insertions, replacements and deletions at distinct identities, with no identity change, partition movement, cascading action, or index expression or predicate that can invoke runtime expression callbacks. Relation binding, source expression evaluation, row preparation and BEFORE triggers have already completed. Foreign-key deferrals record pending checks rather than executing a query. AFTER triggers, transition-table consumers and the statement result run only after `finish_mutation_publication`. The transaction and command snapshot rules retain the same original tuple-lock strength and prevent other sessions from observing private intermediate writes.

## Equivalence argument

For an eligible interval with distinct identities, each document/vector operation changes `D` and `V` at its prepared identity without reading `T`. The corresponding `t_i` reads its retained analyzer binding and text-index source, and consumes the already captured text fields rather than reading the newly stored document. Moving each `t_i` to the end of this interval therefore does not change an input to any intervening document/vector operation. Text operations retain their input order within each relation. The existing `add_documents` implementation coalesces complete posting replacements and applies each old-to-new contribution to field counts and lengths, so its final decorated index equals the sequential replacements, including complete occurrence metadata. Table-local text indexes have disjoint key namespaces; grouping separate relations does not merge their carriers or scores.

For an eligible deletion, the document, vector and value-index removals execute immediately under the original prepared tuple lock, including row-write observations and row-change journal publication. Its text input is an empty complete replacement. The built-in text providers and the observed deletion contract implement this as removal of the original reverse entries, complete occurrences and field statistics, without reconstructing deleted source text or rerunning its analyzer. Grouping these empty replacements preserves the same logical posting, document and field-statistics observations. An absent text document still produces no text change; a relation without text fields is not assumed to have an empty index and still passes through the provider's format and integrity validation.

The batch records every identity in an ordered set. Before an identity repeats, it publishes the entire pending batch. Thus an interval never coalesces two logical replacements of the same document into only its final input: intermediate term write observations and document guards remain present. Partition movement, identity changes and cascading actions also drain the batch before their existing immediate path. Expression or predicate indexes select immediate publication because runtime callbacks can observe text. This decision reads the retained physical index registry, whose identity already follows catalog replacement and rollback.

Induct on drained intervals. The initial state is identical. Given identical `D`, `T`, `V` and logical transaction evidence at an interval boundary, the commuting argument establishes identical state at the next boundary; the ordinary immediate operations between boundaries are unchanged. Every SQL observer occurs after such a boundary, so support, payloads, occurrence graphs, scores, RETURNING images and trigger-visible query results are preserved. No numeric approximation or changed scoring order is introduced. A failure aborts the same statement-owned mutation scope, which restores document, text and vector state together; no pending batch is independently committed or retried.

## Bounds and verification

At most 4,096 document text inputs are pending, matching the established INSERT batch bound. Identity tracking adds at most one `DocId` set entry per pending document and one map entry per participating relation. A flush clears both the inputs and identity sets. Large individual text inputs continue through the existing analyzer and storage budget controls. Physical durability settings are unchanged.

Execution unit tests cover repeated identities, independent relation namespaces, empty replacements, descending identity order, the document bound, and physical index registry replacement. SQL integration tests exercise memory and native persistence, replacement and deletion visibility in AFTER row triggers, NULL replacement, savepoint rollback, primary-key movement, cascading deletion, failure rollback and reopen. Timing observations are kept in ignored benchmark output and do not establish a performance acceptance threshold.
