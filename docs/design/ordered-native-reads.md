# Native storage reads, index maintenance and Cypher execution

These changes preserve the existing SQL, vector, full-text and Cypher operators. The borrowed document cursor contract belongs to `uqa-storage`; its native provider belongs to `uqa-storage-sqlite`; physical scalar evaluation and aggregate input adaptation belong to `uqa-execution`; Cypher binding expansion belongs to `uqa-graph`. Engine retains its existing state, session and transaction adapters. No dependency or feature boundary changes.

## Load-only session restoration

An independently initialized session restores its table and dependent registries inside one owned read transaction unless its supplied storage session already has a pinned transaction. Engine owns this session and transaction adapter. Each catalog lookup therefore observes the same storage boundary, and dependent validators resolve tables from the handles already restored at that boundary instead of invoking a recursive external-commit refresh. The unpublished Engine's existing drop path releases an owned transaction on failure or unwind; successful restoration explicitly releases it without publishing writes. The independent change monitor is sampled before admission and after release. If it changed, the restored cache remains associated with the earlier observation and the next ordinary synchronization must observe the later commit. Supplied retained transactions remain owned by their original session. Maintenance scheduling, statistics thresholds and DiskANN work are unchanged; only redundant construction-time restoration is removed.

## Borrowed graph vertices

For a fixed graph view and caller sequence of vertex identities `I`, the borrowed provider emits exactly the sequence `(i, vertex(i))` that repeated point reads produce, retaining duplicates and missing vertices. Native reads generate each key only after the preceding callback continues; they reuse the existing record decoder and the same committed/private MVCC selection. Only one decoded vertex is live at a time. A false callback result prevents admission of the next identity, and successful completion checks the original cancellation control. The catalog adapter parses the same property JSON and preserves a parsing failure before subsequent cleanup. No graph replica or query-result cache is retained.

Cypher enables this cursor only when every inline property expression is a literal, parameter, bound variable or bound-value property access. Each such evaluation depends solely on the immutable vertex, seed and query parameters and cannot call graph storage. The callback runs the existing label/property predicate and agtype conversion in the existing candidate order. It stops on the first evaluation error, which takes precedence over provider cleanup, so induction over `I` preserves each match, duplicate binding, path element and diagnostic. Other expressions retain point reads because functions and nested patterns can reenter graph storage. Serializable entity observers also retain point admission outside physical read windows, preserving their namespace attribution and read-before-result order. Batch matching keeps its established seed-major output restoration and OPTIONAL MATCH padding.

## Unchanged occurrence clusters

An occurrence cluster is an ordered finite map from document identity to the complete tuple `(document length, ordered token occurrences)`. Each occurrence retains position, position length and source offsets; equality of term support or frequency alone is insufficient. Document replacement constructs a finite partial map whose `Some` entries replace those complete tuples and whose `None` entries delete them. The existing merge is the identity exactly when each specified replacement equals the old map's value at that identity, treating absence and deletion as equal. Binary search in the already decoded and validated cluster tests this condition without constructing or encoding a replacement cluster. Occurrence comparisons poll cancellation in bounded chunks. A differing entry continues through the original merge and encoder.

Only identical score/position record replacements are omitted. Analysis, analyzer-revision checks, document guards, logical change visitors, reverse terms, field-end metadata, field statistics, source markers and accelerator invalidation retain their original ordering and atomic batch. Consequently unchanged postings still conflict with another replacement of the same document or a structural reset, while disjoint writers retain their existing merge behavior. Field-end metadata can change even when every posting is equal, so it is always published through the original path. A corrupt cluster is fully decoded and rejected before equality can suppress a write. For every retained view, the cluster's map and its score/graph projections are unchanged; newly committed disjoint deltas compose with the identity delta under the existing guarded merge. No stored format or algebraic operator changes.

## Point version selection

For a requested key `k` and retained boundary `b`, let `V(k,b)` contain the physical versions of `k` with sequence at most `b`. Point metadata selects the member with maximum sequence, or the null-extended head when that set is empty. The primary key `(key, sequence)` makes that member unique. A descending left-joined version range with limit one therefore returns the same head, selected version and encoded length as the predecessor-subquery formulation, while performing one version-tree search. The predicate belongs to the join condition, so a head whose versions are all newer than `b` remains visible to the existing validation code. Missing heads still consult compacted runs; compacted heads, tombstones, zero revisions and mismatching head/version diagnostics retain their existing rules. In particular, selection is bounded by `b`, not by the head sequence: a newer orphan version cannot be hidden by finding an older matching head. This changes neither record visibility nor payload admission and introduces no new algebraic operator. The physical metadata representation is specified below.

## Payload-free version metadata

SQLite record format 55 adds a guarded, payload-free table M with primary key `(key, sequence)` and a nullable integer `payload_length`. For a physical version value v, define f(v) as NULL for a tombstone, the exact byte length for a BLOB, and -1 for any other storage class. The representation invariant is M = {(k, s, f(v)) | (k, s, v) is in the version table V}. The original version table, heads, compacted runs, source identities and commit sequences are unchanged. M contains one narrow row per retained version; its disk and write costs are additional physical index costs, not user payload reservations or a result cache.

Fresh creation establishes the invariant on empty V and M. Conversion from record formats 1 through 54 fills M directly from V in the same admitted SQLite transaction that changes the format marker. INSERT maintenance adds the unique corresponding row. UPDATE maintenance deletes the old key/revision row and inserts the new one, including identity changes. DELETE maintenance removes exactly that key/revision. These three cases preserve the invariant by induction on physical version mutations, including native baseline import, logical publication, historical collection and compacted-head extraction. SQLite statement failure and transaction/savepoint rollback undo both sides together. Exact table, write-guard and maintenance-trigger definitions are validated on open and restoration; an incomplete current format is rejected rather than reconstructed. Format 55 excludes older binaries that do not understand the representation.

For any k and boundary b, projecting M onto `(key, sequence)` gives exactly the same candidate set V(k,b) as V. The unique maximal sequence and f(v) are therefore identical to the former predecessor query. Point and ordered metadata reads now traverse M without opening V's payload pages, preserving NULL/empty-BLOB distinction and invalid payload diagnostics. Head equality is still checked against the selected predecessor, so an orphan version does not become hidden. Payload reads continue to use V in the same physical read transaction and retain key, type and byte-length checks after admission. Historical visibility, compacted-head behavior, private-overlay precedence, limit counting, cancellation and error ordering remain as specified for the original cursors. The change performs no score arithmetic and cannot alter SQL bags, graph bindings or vector rankings.

## Ordered version payloads

Let `b` be the retained commit boundary and `P(k, b)` the newest point version for key `k` whose sequence is at most `b`. The existing ordered metadata cursor determines visibility, validates the head and selected version, admits key bytes before materialization, and merges compacted runs with point-head precedence. Its ascending key sequence, tombstones, exclusive continuation boundary, count and early-stop decisions remain authoritative.

The metadata cursor selects `P(k, b)` in one correlated predecessor lookup. When the head is visible, the subquery verifies the selected revision's storage class and width, then compares it with the head before returning only an integer size or a fixed negative diagnostic/tombstone code. Equality proves that the head supplies the selected revision; it does not select that revision or bypass the predecessor lookup, so newer orphan versions still fail. This keeps ordinary key-existence reads within their original small allowance. When the head is newer than `b`, a bounded scalar carries sixteen hexadecimal revision digits, a separator and either a NULL marker or decimal byte length; its maximum width is 36 bytes. The key-size cursor identifies this case on the same physical view and reserves that maximum with the key before the metadata cursor steps. Invalid sequence storage classes and widths produce fixed integer diagnostics before hexadecimal conversion, so malformed sequences cannot cause unbounded metadata materialization. Head decoding and visible compacted-head handling precede selected-version validation, as in point reads. Both representations preserve the selected revision, tombstone and encoded length and retain mismatch-before-payload-error ordering.

The payload cursor uses the same heads, prefix and continuation predicates and the same definition of `P(k, b)`. For a visible non-compacted head, prior metadata validation proves `P(k, b)` has exactly the head sequence, so a left join on the unique `(key, sequence)` supplies the same payload without a correlated predecessor subquery. A head newer than `b` retains the historical predecessor lookup. Both cursors advance once for every point head, including heads with no visible version and visible tombstones. A visible compacted head explicitly produces NULL without materializing a discarded historical payload. Heads remain the outer traversal, so neither cursor sorts or collects later payloads, and the joined unique key cannot multiply rows. One physical read transaction fixes both cursors to the same database state. Induction over the head sequence therefore gives the same key and predecessor at each payload step, and the implementation checks the key, storage class and encoded length before invoking the visitor. Invisible heads only synchronize the cursors; they neither invoke a public visitor nor consume the requested limit. Run entries do not advance the point payload cursor.

The visitor receives the same borrowed value and revision as the former point lookup. Every metadata entry still consumes one unit of the requested limit, including tombstones; a false visitor result still stops before the next selected key. Prefix restriction, exclusive continuation, ordered concatenation of pages, snapshot visibility and private-overlay precedence consequently remain unchanged. No numeric computation or approximation is introduced, so canonical vector scores, ranked tie rules and full-text payloads are unchanged.

The encoded value and duplicate payload-cursor key are admitted before stepping the payload cursor. The previous cursor row remains charged until the next step releases it; the final row remains charged until statement finalization, including error cleanup. Decoded values retain their existing allowances independently. Cancellation is checked before and after visitors. Thus early stopping does not materialize a later large value, and resource rejection cannot invoke a visitor for an unadmitted row.

The metadata cursor derives `P(k, b)` from the version history, independently of the stored head. A matching head version does not establish that no newer orphan version lies within `b`; replacing metadata selection with a direct head lookup would suppress the point reader's mismatch diagnostic. The selected historical predecessor therefore passes through the same head and version checks as a point read before payload admission or delivery. A later orphan cannot invalidate an older retained boundary that excludes it. Compacted heads retain their existing tombstone and run behavior.


## Catalog prefix selection and physical statement reuse

For a native metadata key string `s`, the existing single-TEXT identity encoding consists of its family and database owner, a TEXT tag, escaped UTF-8 bytes and a component terminator. Escaping replaces each zero byte with its established two-byte escape and preserves all other bytes. Encoding a requested prefix `p` without the terminator is therefore a byte prefix of the complete identity exactly when `s.starts_with(p)`: induction over input bytes preserves each ordinary byte and the complete zero escape, while the terminator cannot match a further input byte. The existing ordered record range can select exactly those identities before payload decoding. This preserves literal NUL, percent, underscore and Unicode behavior, ordered results, empty prefixes, the captured MVCC boundary and private-overlay precedence. No unrelated metadata payload is visited and no format or public SQL operator changes.

Physical native row reads, replacements, deletions and publication-verification statements reuse the connection's bounded prepared-statement cache. Each execution binds all parameters anew; returning a statement to the cache clears its bindings, so retained user bytes do not escape their original admission scope. Cache entries retain bytecode, not query results, evaluated rows, validation outcomes or write permission. SQLite still evaluates current functions, triggers, constraints and the active transaction for every execution and reparses invalidated statements when the schema or installed functions change. Size probes and their payload reads retain the same physical transaction, and every original publication check still runs. Consequently statement reuse preserves the sequence of validated native state transitions and rollback behavior.

## Exact vector input

Native exact KNN and threshold scoring consume the canonical vector sequence on the same retained boundary, ordered by document identity and tensor ordinal. They decode and validate one vector at a time, reserve its temporary payload before allocation, and run the unchanged cosine function on the same binary32 coordinates and query. Contiguous vectors of the same document fold into one maximum in an ordered score buffer, retaining the same comparison and insertion order as the former score map; final top-K selection, score decorations and identity tie rules are unchanged. Tensor ordinal identities, producer score buffers and output buffers are budgeted, and the original ordinal validator runs after all payload validation, preserving its original validation order without retaining corpus coordinates. Therefore induction over vectors gives the same per-document score map, and applying the unchanged threshold or top-K operations yields identical decorated postings. No numeric reassociation, score quantization or approximation is introduced. IVF and HNSW loading retain their original canonical materialization interface. A fixed axis-vector fixture verifies scores and tensor maxima while a 64 KiB read allowance excludes full-corpus coordinate retention. A public integration case also verifies bounded exact scoring, refusal when the remaining allowance is exhausted, reservation cleanup and writer recovery.

## Borrowed aggregate input

The new storage cursor exposes the same bounded ascending sequence of `(document identity, projected values)` as the ordinary identity-plus-projection path, with missing fields represented by SQL NULL. Its additional precondition prohibits storage reentry, nested SQL and host callbacks while a row is borrowed. Execution selects it only when the existing aggregate capability proves all grouping keys and aggregate inputs are direct positional operations without subqueries or routine hooks. The compiled positional predicate likewise has no callback or storage operation. Unsupported aggregates retain ordinary materialization.

For an unchanged query row view, the retained layout projection is a pure positional map with no field-presence probes or generated evaluation. Applying that map to every provider row gives the same projected row as ordinary materialization, including duplicate requested columns, SQL NULL, constants and catalog renaming. Views with private changes, generated expressions or missing-value presence requirements retain the existing merge and evaluation paths. The adapter validates increasing identities, projection arity and reported visit count before accepting a provider result. A rejected provider capability does not advance input.

For inline native fields, one ordered record cursor decodes one body and its tuple metadata, retains that decoded allowance, and lends its projection to the aggregate. No complete document collection is retained. A selected external BLOB instead stops the physical cursor before invoking the aggregate, retains that one decoded body, hydrates it through the same immutable record boundary after releasing the physical cursor, then resumes strictly after its identity if the consumer continues. Unselected BLOB markers do not hydrate. Induction over these inline and external steps establishes identical row order, fields and multiplicity, without reading a later body after early termination. Cancellation and quota failures unwind all producer and decoder allowances. The original reentrant public projection methods remain unchanged.

Since the aggregate consumes the same ordered row sequence through its existing accumulator operations, grouping, scalar types, NULL and overflow behavior, DISTINCT, spill transitions and final output semantics remain those of the original aggregate. No arithmetic expression is reassociated and no numeric approximation is introduced.

## Borrowed point projections

Let V(k) be the value, tombstone or absence of record key k at the captured committed boundary and private command root, and let I be the caller's finite ordered sequence of requested keys, with repetitions permitted. The point cursor computes the same sequence of V(I[j]) as separate point reads. With an empty private root, one physical read transaction encloses the original point lookup algorithm at the unchanged committed boundary; concurrent commits cannot change V because the retained lease protects its history. With a private root, the original per-key merged lookup remains authoritative, so a replacement or tombstone never exposes the underlying committed payload. Keys are generated one at a time, after the previous visitor has continued; early termination never generates or validates a later input identity. The current key is released before admitting the next one.

The native document projection decodes each live record and tuple metadata with the same selected-field decoder as an ordinary point projection. An absent or deleted row emits the same false presence flag and NULL fields. Duplicate and unordered requests keep their original multiplicity and order. Inline fields borrow that one decoded row while the physical read window remains open. A selected external BLOB stops the window, retains exactly one decoded body, hydrates its fields through the original fixed view, emits the pending request and then resumes the remaining key iterator. This partition of I into inline subsequences and individual external rows preserves every requested position by induction. Payloads, encoded keys and projection references retain their original allowances; cancellation checks bracket callbacks and failed windows release all temporary reservations.

The additional storage interface explicitly prohibits storage reentry, nested SQL and host callbacks from visitors. Execution enables it only for owned row construction with a compiled positional predicate or an aggregate advertising the existing strict storage-borrow capability. Unrestricted aggregate callbacks retain ordinary projections. Retained row adapters admit only unchanged views whose layout is a pure positional projection with no presence probes or generated evaluation, and verify requested IDs, arity, early termination and callback counts. Pinned tuple rechecks and generated/xmin reads keep their existing materializers. Consumer errors take precedence over subsequent provider cleanup errors. Therefore the same ordered decorated rows enter relational, full-text and vector operators, without changing scores, SQL types, NULL rules, row-lock origins, or aggregate arithmetic.

## Native commit work queues

The transaction-local work queue is ordered by `(family, physical key)`. With continuation `(f, k)`, its remaining order is the concatenation of records with family `f` and key greater than `k`, followed by records with family greater than `f`. Choosing the first eligible record from the first set, or from the second when the first is empty, is therefore equal to the original lexicographic successor under the same queue condition. Explicit equality on `family` permits a direct composite-key seek even when the queue condition itself fixes a family, avoiding repeated scans of preceding keys. The implementation still probes length before allocating or copying each key, releases the SQL cursor before applying a physical mutation, and advances only after that mutation succeeds. Callback-induced queue changes consequently retain their original continuation semantics, validation order and transaction atomicity.

## Occurrence format admission

For one occurrence operation, the provider supplies a fixed committed/private KeyValueRead boundary, a table name and immutable analyzer bindings. Let R be the existing format predicate on that view: its result depends only on the occurrence-format marker and the existence of the legacy/current namespaces. Those records do not change during the read scope, including when a separate mutation batch accumulates pending writes. Therefore every successful evaluation of R in that scope returns the same boolean. Retaining the first successful result and reusing it in later field-revision checks preserves the predicate and its position before each field's stored-revision validation. No result crosses a read or mutation scope, and a failed evaluation is not retained. Cancellation remains checked before every call, including a retained result. This removes duplicate namespace probes without changing analyzer selection, occurrence positions, posting replacement, field statistics, serializable write observations or atomic publication.

## Native coordination slot reuse

The native lock coordinator keeps an explicit pool of released holder slots and rechecks that pool before continuing its ordinary advancing probe cursor. A slot index is only the physical location of a published `(process, session, byte, lock mode)` tuple; lock compatibility and acquisition reference counts depend on that tuple and the original OS byte locks. Allocation still validates local occupation and foreign process liveness under the existing metadata lock before writing the same encoded tuple. Reusing a released slot therefore preserves the published holder set, duplicate-acquisition lifetime and wait-for edges. A reused slot does not move the advancing cursor back across live acquisitions, avoiding repeated scans of a growing transaction's existing holders. Each locally allocated slot belongs to either the occupied set or the released pool, and a pool entry is consumed before reuse, so their combined size is bounded by the slot count. Clearing retains its original ordering before the corresponding byte claim is released. With no foreign holders and a fixed transaction working set, repeated transactions reuse the allocated region instead of extending the file through every unused slot. Tests verify the file-size bound and reuse of disjoint holes without replacing live holders.

## Native record validation and borrowed document decoding

Native record keys concatenate the already validated family and owner header with ordered primary-key components. Integer components have tag 1 and the signed integer's big-endian bits with the high bit inverted. TEXT and BLOB components have tags 2 and 3 respectively; each zero byte becomes `(0, 255)` and each component ends with `(0, 0)`. Direct comparison consumes exactly these bytes for every identity column and succeeds only when no bytes remain. By induction over components and their byte positions, it is equivalent to comparing the encoded key with a newly allocated canonical encoding. Storage classes, row layouts, owner generations and corruption diagnostics are still validated. The comparison allocates no duplicate key and checks cancellation during long byte comparisons.

Native document body decoding may borrow the selected provider bytes because its internal callback only decodes JSON and tuple metadata. It never executes SQL, invokes a user callback, or probes another record. The encoded provider row remains charged throughout decoding. The decoded fields retain their independent allowance before the provider callback returns. Selected BLOB hydration and public projection callbacks still run after that read window closes, preserving reentrant writes, retained snapshots, duplicate projections, NULL fields and tuple metadata. Statement-cache reuse likewise reexecutes namespace validation on every read; it does not cache a validation result.

Physical scalar evaluation chooses the existing row schema when present and constructs the same empty schema only when absent. This changes allocation, not operand evaluation, integer-width inference, cast types, NULL propagation, overflow checks or diagnostic order.

Flat historical documents use one grammar traversal for primitive members. The shared JSON event reader validates every original key and primitive token before deduplication, including discarded strings and numeric grammar. Private serde envelopes and nested containers immediately select the existing normalization path. For an eligible object, normalization has no envelope or subtree transformation to perform; retaining the last occurrence of each decoded key and applying the existing legacy numeric conversion therefore gives the same field map. Numeric range conversion still occurs after deduplication, so an out-of-range number overwritten by a valid duplicate remains discarded while malformed JSON is still rejected. Decoded field names transfer with their original reservations instead of being allocated again. Canonical sorted-key conversion order, decoded payload accounting, cancellation and failure cleanup remain intact.

Direct aggregate integer bytecode now retains the canonical SQL integer width at every binary operation, including nested subexpressions. A successful checked i64 result is accepted only if it belongs to that operation's inferred int2, int4 or int8 range; out-of-range results and division failures use the canonical typed evaluator's diagnostic. This corrects an independently observed PostgreSQL 18 mismatch in which int4 multiplication overflow reached SUM as an i64 value. Explicit BIGINT casts of direct integer or NULL operands are identity maps on the bytecode's i64/NULL carrier, while their original syntax still determines the enclosing operation's widened type and result schema. Non-integer operands retain canonical scalar evaluation. Casts of arithmetic subtrees and narrower casts are not elided, preserving intermediate overflow and conversion boundaries.

Borrowed, owned and sorted aggregate scalar contexts now retain their declared input row schema. This fixes the same independently verified type-loss defect in general aggregate expressions: `(int4_column * int4_column)::bigint` must raise int4 overflow before its outer cast. The retained schema supplies the original widths and source types to the canonical evaluator without changing value lookup, evaluation order, callback boundaries or spill order. Tests exercise borrowed and owned input and DISTINCT aggregation; the independent native/PostgreSQL SQL checks include nested arithmetic and both int2 and int4 conversions.

Selective document decoding admits a direct projection only for primitive objects whose unescaped UTF-8 keys are already strictly increasing. These conditions exclude duplicate keys, nested serde envelopes and tagged values; other shapes use the complete historical normalization and conversion before projection. The shared JSON event reader validates the complete admitted object, including every unselected string and Unicode escape, before any numeric conversion. Conversion then follows the same key order as historical normalization and still checks every numeric value for range errors. Unselected validated primitive strings need no owned copy; selected values use the original numeric and string decoders. Consequently the selected field map equals restriction of the full decoded document to the requested names, preserving NULL versus missing fields, duplicate projection positions and diagnostics. Borrowed names and token spans remain inside the charged provider read window, and selected names, values and span buffers retain their own allowance. Native projection visitors and borrowed scan cursors use this restriction; complete-body reads and field-presence inspection retain their original full-field contract.

## Independent node-match expansion

The optimized carrier is an ordered bag of Cypher binding rows on one fixed graph view. For node pattern `N`, let `C(N)` be the existing ordered candidate identity sequence and `E_N(r)` the sequence of extensions of input row `r` whose vertices satisfy the existing label and property predicates. Ordinary MATCH computes ordered flat-map: concatenate `E_N(r)` in input-row order. Comma-separated patterns compose these flat-maps, retaining multiplicity.

The optimization applies only to standalone node patterns without path variables or WHERE predicates, with distinct variables absent from incoming bindings. Property expressions are restricted to literals, present parameters, known value bindings and infallible one-level property accesses, including properties of nodes introduced by earlier patterns. General expressions, missing parameters, bound or shared node variables, relationships and paths retain the ordinary matcher. This excludes volatile evaluation and expression-error reordering. A matched vertex still undergoes agtype graph-ID validation even when no path value is returned.

For each eligible pattern, the implementation traverses `C(N)` once and appends each matching extension to the result sequence belonging to its seed. Each seed sees the same candidate sequence and predicate as `E_N(r)`, hence its result sequence is equal, including duplicates. Flattening those sequences in seed order restores the ordinary ordered flat-map. Induction over comma-separated patterns proves equality of the final binding bag and its order. Group boundaries retain the original input rows; OPTIONAL MATCH pads exactly those groups whose final expansion is empty, preserving existing variables and setting newly declared variables to NULL. Subsequent projection, DISTINCT, aggregation, SKIP, LIMIT and mutation therefore consume identical bindings. The implementation retains outputs and one currently decoded candidate, rather than a graph payload cache.

These rewrites operate on a retained graph boundary, so sharing repeated identical reads preserves the union of observed identities and predicates without changing state. Read failures still abort the statement, and the existing transaction scheduler retains atomicity. The proof assumes a valid persistent graph and the documented fixed-snapshot storage contract; it does not promise which competing corruption error is diagnosed first in an invalid graph.

## Dense graph identity validation

For an ascending label-selected vertex page I, let E(i) mean that source vertex i is live and M(i, g) mean that its source membership in graph g is live on the retained committed/private view. The original selection checks E(i), reports a dangling label when it is false, and emits i exactly when M(i, g) holds. A compact page can obtain the same predicates by scanning the source entity and membership keys over the closed interval from the first to the last selected identity. Canonical key decoding identifies each source identity and graph; binary search places the two presence bits only on identities in I. Each source key has one effective revision on the fixed view, so after complete scans the bits equal E and M pointwise. Applying the original checks in I order therefore preserves selected identities, order, limit and dangling-source diagnostics. Scoped standalone families include their immutable scope prefix in both scans, preventing identities in another family from contributing.

The optimization requires at least eight selected identities and a numeric span bounded by twice the page length. Each source scan stops after at most twice that length plus two metadata records. If it cannot prove that the interval ended within this bound, selection discards the bits and uses the original point probes; high membership fanout and retained tombstones cannot turn the shortcut into an unbounded traversal. The bit array retains the original read allowance, every physical cursor uses the captured control, and source payloads are never decoded. User visitors run only after both physical cursors close. Private deletion, rollback and later committed mutation preserve the same view as the label selection. Requested small pages also bound the primary selector, so a later dangling identity cannot invalidate an already complete shorter result.

Presence-only document projections reuse the same source-identity primitive in pages of at most 256 requested IDs. The primitive admits strictly ascending pages with the same density bound; unordered, duplicate and sparse requests retain point reads in their original order. For each admitted ID i, its bit is one exactly when the selected document record is live at the captured boundary. Emitting `(i, bit(i), [])` in request order is therefore equal to the prior empty projection, including missing documents and private tombstones. All user visitors run after the physical scan ends and retain the same immutable page through reentrant writes. No document body or BLOB is decoded. Cancellation is checked after every callback, including an early stop, and dropping a failed or completed page releases its temporary encoded identities and presence flags. Invalid later input IDs keep the original point path, preserving early termination before their validation.

## Ordinary physical scans

For COUNT(*) the aggregate input is the constant integer one for every retained row, including rows whose fields are all SQL NULL. Its star therefore introduces no source-field dependency. Column pruning retains every dependency of the aggregate FILTER, aggregate ordering, other projections, grouping and residual predicates; a previously executed retrieval predicate contributes only its index dependencies. Projecting away any other fields preserves the ordered bag of row identities and all remaining expression inputs, so the aggregate receives the same sequence of ones and returns the same count, including zero for empty input. Whole-row COUNT(table.*), column counts, unknown function stars and invalid count arities retain their original conservative projection. This does not turn a count into an index cardinality estimate: missing documents are still checked on the captured storage view.

The borrowed ordered document cursor also supplies ordinary physical rows. The callback performs only the same positional predicate and field/metadata projection as the ordinary materializer; it copies each accepted row into an owned physical row before returning. It cannot execute host callbacks, generated expressions or nested SQL. Recheck pins, command overlays, virtual generated fields and tuple-xmin projections retain their original paths. A local join source appends the same table OID, structural metadata and lock origin after projection. Predicate rejection advances the storage cursor even when every row in a page is rejected; EOF is returned only after exhaustion. Induction on cursor pages proves that the ordered bag of accepted physical rows, including NULLs and metadata, is unchanged.

## Bounded top-K sorting

Let the comparison order be the canonical SQL sort-key order extended by the original input sequence number. On valid typed keys this is a total stable order. For a run prefix P and bound K greater than zero, the heap invariant is that H contains the smallest min(K, length(P)) records of P and its root is the greatest retained record. A new record enters while the heap contains fewer than K records. Once full, a record greater than or equal to the root cannot belong to the smallest K of the extended prefix; a smaller record replaces the root, and sifting restores the invariant. This induction establishes equality with stable full sorting followed by truncation. Every input row still evaluates all sort expressions in their original order; the optimization does not skip expression evaluation for a discarded row. Comparisons use the existing fallible typed comparator.

Heap construction is deferred until the first record beyond K arrives. A run with at most K records needs only its final ordinary sort, which avoids unnecessary heap comparisons for small already-bounded retrieval results. Bottom-up heap construction establishes the same greatest-at-root invariant before the first candidate can be discarded.

Exact encoded-byte accounting removes the replaced record before adding its candidate. If the last record carrying lock origins leaves a batch, its removal also removes the empty origin-count fields from origin-free records. When a replacement or append would exceed the byte allowance, the current heap becomes a sorted run and the new record starts the next run. For every partition of input into runs, topK(union(topK(run))) equals topK(input): any locally discarded record has at least K earlier records in its own run and therefore cannot enter the global smallest K. The existing merge uses the same stable comparison and global bound. One indivisible oversized row retains its existing immediate-spill behavior. Locking queries and WITH TIES do not activate the bound; ordinary LIMIT uses K equal to OFFSET plus LIMIT.

## HNSW visited identities

For a fixed HNSW layer search, a stored node identity n in a compact range beginning at a maps to word floor((n-a)/64) and bit (n-a) modulo 64. This mapping is injective, so testing and setting that bit returns true exactly on the identity's first insertion, as the existing visited set does. The bitmap is selected only when its size is bounded by four words per initially reserved visited identity; sparse or very large identity ranges retain the hash set. Missing links outside the stored range cannot produce a candidate. All existing node distances, neighbor iteration order, candidate ordering, search termination and canonical rescoring remain unchanged. By induction on neighbor visits, the candidate queues and returned scores are identical for both visited representations. The original search allowance reserves the complete bitmap before allocation and retains it through the search; initialization and traversal keep cancellation checks.

Owning-crate tests cover independent AGE 1.8.0 results on PostgreSQL 18.6 for matching multiplicity, OPTIONAL padding, dependent property access and anonymous nodes. Additional tests preserve seed order and agtype ID validation.
