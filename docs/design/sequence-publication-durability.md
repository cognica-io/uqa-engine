# Sequence publication and transaction durability

Issue #347 concerns the physical synchronization of autonomous sequence value records. PostgreSQL 18's [`nextval_internal`](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/commands/sequence.c) inserts a sequence WAL record and assigns a top-level transaction identifier so that transaction completion flushes the log. An independent FULL SQLite commit for every logged sequence block is therefore not required by PostgreSQL. Sequence increments must remain visible outside the caller's transaction and must not be undone by rollback, while committed uses of those increments must survive a database crash.

Common Storage owns the completion obligation and the conservative provider capability. Execution records the obligation for persistent `nextval` and `setval`, including cached values obtained from another session's shared position. Engine supplies the selected session adapter. SQLite alone decides whether a prepared publication contains only native sequence value replacements and whether its WAL supports deferred synchronization. Other records, direct storage callers, unsupported providers and rollback journals retain FULL publication. The existing sequence allocation arithmetic, cache sizes, generation checks and 32-value log lookahead do not change.

Let $s$ be the current record commit sequence and $d$ a durable-prefix certificate in the same guarded metadata row, with $0 \le d \le s$. An ordinary FULL publication commits both its records and $d=s$. An eligible autonomous sequence publication advances $s$ while retaining $d$. A successful completion that consumed persistent sequence values must establish a durable prefix covering every publication it observed, either through its ordinary FULL commit or a FULL metadata-only barrier. A barrier observes the latest $s$ under physical writer admission and commits $d=s$ without advancing record visibility. Savepoint undo preserves the completion obligation; failed completion retains it for retry. Successful rollback also discharges it, preserving UQA's existing stronger orderly-rollback persistence.

SQLite WAL commits form an ordered prefix. A FULL commit synchronizes all earlier WAL frames, including sequence publications. Therefore every successfully completed transaction's sequence observations are included in the durable prefix. If power loss removes an unsynchronized suffix, no successfully completed dependent transaction can be in that suffix. Process failure does not discard committed WAL frames. Values published independently are never rolled back with the caller's ordinary writes. The shared position's existing record-identity check rejects positions whose covering record disappeared after recovery. Current values, cached values, generation replacement and sequence exhaustion retain their existing evaluation order.

The capability is explicit and defaults to synchronous publication. Provider wrappers that enable deferred sequence publication must also forward completion obligations; a provider without both halves cannot opt in. SQL-only value publications retain their original transaction receipts and exact retry identities. No general asynchronous-write setting is introduced.
