# DiskANN global adjacency merge

Storage's `DiskANNBuildInput::merge_partitions` consumes [partition edge candidates](diskann-build-partitions.md) and returns encrypted global adjacency. The input and candidates must agree on canonical coverage, dense node count, memory allowance, cancellation signal and shared temporary-byte allowance. A different allowance cannot enlarge one build's resources. The captured vectors remain immutable; consuming candidates does not publish or stage a database generation.

## Bounded external ordering

The caller supplies a positive `sort_buffer_records` capacity. The builder computes full squared navigation distances for candidate pairs, sorts admitted chunks by `(source ID, distance, neighbor ID)` and writes fixed-width 24-byte records to one encrypted file. It reuses the current source's normalized coordinates within consecutive source rows. It does not retain the corpus, a global identity directory or a complete high-degree neighborhood. Initial chunk admission uses the smaller of the configured capacity and actual candidate count; the effective setting remains unchanged.

Two-way merge passes use known record counts and chunk widths, without a resident directory of runs. Two independently positioned readers share the current file owner and retain their charged decrypted blocks across successive ranges. An unaligned range start seeks to its containing 4,096-byte boundary, and a start already in the buffer reuses it. This prevents one-record ranges from repeatedly decrypting a complete block. The next complete file replaces the preceding pass; failed output is discarded. Sorting retains repeated records so fixed-width range boundaries remain derivable without extra metadata.

Ranges reject nonfinite or negative distances, invalid identities, self-edges, descending order and incomplete records. All coordinates, candidate chunks, readers, writers, selected neighbors and normalization buffers use the original build control. The two capture files and at most two current candidate/output files coexist; reopened cursors share their owners' descriptors. Their encrypted physical lengths use the capture's shared temporary-byte reservations, including simultaneous input and output. Opaque owner/allocator/filesystem bookkeeping retains the [capture accounting boundary](diskann-build-input.md#temporary-ownership-and-limits).

## Final pruning and connectivity

The final sorted stream visits every dense source ID, including sources with no partition candidates. Identical global pairs are adjacent and contribute once. Identical vector values with distinct IDs remain distinct vertices; tensor ordinals are not projected to their document before query-time candidate reduction.

For $n>1$, the effective degree is $r=\min(R,n-1)$. The stable global successor $(v+1)\bmod n$ is excluded from ordinary candidates. Vamana's shared `Selection` owner keeps at most $r-1$ other neighbors, testing the existing condition $\alpha^2\delta(u,w)\leq\delta(v,w)$ against previously selected full navigation vectors. Source-distance/node order makes this streaming selection equivalent to removing dominated candidates after each ordinary RobustPrune selection. The owner retains only selected coordinates and their stable insertion positions; local Vamana and global merge use the same selection logic.

The successor is then added exactly once, and the final neighborhood is stored in increasing node-ID order. Degree never exceeds $r$. Following these successor edges visits every node and returns to the start, so the complete graph is strongly connected without a resident reachability bitmap. Empty and singleton generations have no edges. This establishes physical graph invariants, not approximate-query recall.

The output has one fixed-width row per dense source: a little-endian `u64` neighbor count followed by $r$ little-endian neighbor IDs, with unused slots zeroed. The source ID is implicit in its row address. `visit_neighbors` checks lengths, range, strict order, padding, successor membership and the final construction digest while retaining typed consumer errors and cancellation. The result can outlive the capture, but generating canonical node pages still requires the captured raw vectors and origins.

## Carrier and provenance boundaries

The navigation graph is physical vector-index state, not the paper's graph-query result carrier. Distance ordering and duplicate edge removal introduce no posting collision policy, decorated score, probability evidence or ranked top-k. The [typed carrier boundary](diskann-vector-index.md#typed-carrier-boundaries) remains unchanged: query integration must check snapshot visibility, reduce to distinct documents, score all canonical tensor elements and preserve existing posting/ranking semantics.

`DiskANNMergeSummary` retains partition/source provenance, the effective sorting capacity, work-order revision 1, pass/edge counts and an adjacency digest. The digest binds source coverage, dense count, effective degree and complete fixed-width rows. Changing the sort capacity can change pass count but must preserve final neighborhoods and the adjacency digest for the same candidates. The summary is not a persistent manifest or artifact seal. Streamed node pages, PQ codes, numeric-side records, versioned persistent build provenance and complete physical generation sealing remain the next construction boundary; SQL/MVCC publication follows separately.

The [independent fixture](../../crates/uqa-storage/tests/fixtures/diskann/README.md#global-adjacency-merge) was derived with exact rational arithmetic before the Rust merge. It includes repeated/unsorted edges, a source without candidates, two ordinals from one document and equal-valued distinct vertices. Owner tests compare four sort capacities, enforce degree/successor invariants with a raw corpus larger than the workspace, verify exact cipher work across 350 one-record range pairs, and exercise shared ownership rejection, resource denial, malformed/corrupted inputs, typed consumer errors, cancellation and cleanup. These are correctness/resource checks, not timing or SSD performance acceptance.
