# Immutable memory-vector snapshots

Storage owns the memory vector index, its canonical values and exact reads. Memory snapshots and rollback captures previously cloned every vector even when the statement only read a finite candidate pool. `MemoryVectorIndex` now retains an immutable shared root; read and writable snapshots share that root, and the first mutation of a shared root creates a private copy. Engine retains the handles and transaction boundaries without implementing vector storage or selection.

## Values and ownership

Let a root $R$ map each document identity to its ordered vector tensor. A snapshot captures the same $R$, so document membership, ordinal order, dimensions, coordinate bits and scores are unchanged. An accepted mutation first validates the complete replacement tensor. If the root is shared, cloning its owned nodes and coordinate values produces a private $R'$ before applying the mutation; otherwise the sole owner may modify its private root. Thus other readers and rollback owners continue observing exactly $R$. Induction over mutations gives independent writable branches with the same values as eager deep copies, including delete, clear, replacement and failed validation. Public `Clone` retains its deep-copy behavior.

The root uses Core's existing owned ordered map, whose allocated node bytes are explicit. Every replacement updates the sum of outer tensor capacities, coordinate-buffer capacities and vector counts; removing a tensor subtracts its complete previous contribution. A private clone recalculates capacities because cloning a buffer can reduce spare capacity. Controlled capture reserves the root payload, exact node bytes and complete tensor-buffer capacities under the original allowance before publishing a shared reader. Sharing eliminates duplicate allocation but does not waive retention admission. The existing Core policy excludes allocator and reference-count bookkeeping from payload allowances; this change does not turn those allowances into an RSS bound. Failed admission leaves the source intact, and the complete retained lease survives until the last reader or canonical facet is dropped.

The public `vectors()` method retains its concrete `&BTreeMap<DocId, Vec<Vec<f32>>>` return type. An explicit call materializes and retains one complete export until mutation; internal reads and snapshots never call it. This preserves source and value compatibility but changes that full-map accessor's allocation cost. Callers that need bounded traversal should use the canonical read interface instead of requesting the complete exported map.

## Canonical identity and selection

The first controlled capture hashes dimensions and the ordered sequence of document IDs, ordinals, lengths and coordinate bits with the existing retained-vector content encoding. An immutable root caches that digest; mutation invalidates it. Equal tensors therefore produce the same identity as the previous retained reader, while a captured reader's identity cannot change after a later write. Signed-zero bits remain part of identity. Initial fingerprint work still visits the complete corpus; this change makes no constant-time snapshot or measured-latency claim. The fixed canonical reader advances through the owned map and copies only the requested vector under the invoking read allowance.

Memory and retained exact KNN use the [common bounded selection owner](bounded-exact-vector-selection.md). The same canonical tensor cosine scores enter the same total order and document-ID tie rule, so finite K changes retention rather than candidate membership or score bits. Threshold searches retain their complete-result contract. The ordinary unrestricted API keeps its caller-owned result boundary; controlled selection and result construction use the original quota. There are no persistence-format, dependency, feature or calibration changes.

## Verification

Owning tests capture 8,192 vectors of 128 dimensions plus a writable snapshot below an unchanged 64KiB additional-allocation ceiling while still charging the complete coordinate population. They preserve old values and identities through source/writable mutations and verify lease release. Separate tests cover spare tensor capacity, full-map export compatibility, invalid replacements, signed-zero identity and the existing retained reader's digest. A 32,768-document fixture checks K 0, 1 and 8 with 32KiB additional selection space and requires a typed memory failure for an unbounded result. All tests pass in the 345-case local composition and the overlapping final owner/provider checks, with strict six-crate Clippy. Automatic platform qualification remains required; no timing acceptance is claimed.
