# DiskANN overlapping partition construction

Storage's `DiskANNBuildInput::build_partitions` builds admitted Vamana graphs one at a time and returns encrypted global edge candidates. It extends the [canonical input owner](diskann-build-input.md) without reopening a provider snapshot or collecting the full corpus. The output is an unpruned union of overlapping local graphs; global ordering/pruning, successor connectivity, page/code construction and generation sealing remain separate work.

## Deterministic partitioning

The caller supplies validated index parameters and explicit `DiskANNPartitionOptions`: a leaf capacity of at least two points, depth from zero through 32, and existing PQ training settings with at least three centroids and enough sample slots for those centroids. The settings are retained exactly; memory pressure does not silently reduce the requested capacity or sample count. Empty input produces no leaf, and a singleton produces one leaf with no edges. Numeric-side vectors remain in the captured source and its coverage; they do not enter partition graphs.

A source at or below the leaf capacity goes directly to construction. Otherwise, before the depth limit, the builder reuses `PQTrainer` with one full-dimensional chunk to obtain Euclidean coarse centroids from its bounded seeded reservoir. Every point chooses the nearest two distinct labels by full squared navigation distance, with lower labels winning exact ties. It writes one ordered membership record containing the global node ID and both labels. PQ model labels here select partitions; they are neither public scores nor calibrated evidence.

Work-order revision 1 starts with `coarse_training.seed` and processes children in ascending label order. Each child seed is the first eight SHA-256 bytes interpreted as a little-endian integer, over `UQA DiskANN partition child`, bytes `00 01`, the parent's little-endian `u64` seed and the one-byte child label. Each local Vamana graph uses the unchanged index parameters and their configured graph seed. Source order remains ascending global ID, which preserves the original logical-key order within every leaf.

A split is accepted only when each child's count satisfies $4n_i \leq 3n$, compared without integer overflow. If skew or coincident centers prevents that reduction, the membership run is discarded and the source uses capacity windows. The same rule applies at the depth limit. Windows contain at most $C$ consecutive source IDs with stride $C-1$, retaining one boundary representative. An overlap-only trailing singleton is omitted; an original singleton is retained. This provides deterministic progress for identical vectors without loading their full population.

## Resource ownership

Children filter one shared labeled membership file instead of retaining a separate file for every child. The model is dropped before descending. At most `max_depth` membership file owners coexist with the two captured input files and one edge output file, hence at most 35 such owners. Reopened readers share their file owner's descriptor. Child counts, samples, centroids, membership/edge block buffers, ID windows, loaded vectors, borrowed point descriptors and graph workspaces use the capture's original memory allowance and cancellation signal.

Membership and edge writers buffer 4,096 logical bytes under that allowance and flush complete blocks plus one final tail. Readers similarly buffer one decrypted block, preserving records that cross block boundaries. Tiny records therefore do not rewrite or decrypt a complete block for every ID. Their files reuse the capture's shared physical temporary-byte allowance, including all simultaneously retained sources and output; no separate allowance can enlarge this build's limit.

Before loading a leaf, Storage computes a conservative bound for its requested buffers. The Vamana owner includes graph keys/edges/lengths, permutation, expanded flags, complete visited candidates, frontier, pruning pools, retained neighbors and entry work. Growing vectors include old and replacement capacities. The build owner additionally includes loaded vector descriptors/coordinates, borrowed point descriptors and raw decode/normalization scratch. Existing live buffers count toward the same admission. Actual controlled allocation remains authoritative if another owner grows or an allocator reports more capacity. Fixed cipher stack scratch, bounded opaque file owners, allocator bookkeeping and filesystem metadata retain the [input contract's accounting boundary](diskann-build-input.md#temporary-ownership-and-limits).

Invalid settings, source corruption, failed admission, cancellation or I/O failure discard all newly owned membership/edge runs. The captured source remains immutable. There is no partial successful output or staged generation. A returned edge run retains its own encrypted owner and original controls, including after the captured source closes; completing a physical index still requires the source's canonical vectors.

## Output and provenance

This owner stays at the [physical vector-identity boundary](diskann-vector-index.md#typed-carrier-boundaries). Overlapping memberships and repeated edges are construction candidates, not decorated postings or duplicate score contributions. No document projection, payload collision merge, probability conversion or ranked truncation occurs here; those query boundaries retain their distinct contracts.

`DiskANNPartitionRuns::visit_edges` streams `(global_source, global_neighbor)` pairs in deterministic leaf/source/neighborhood order. Each local graph retains its degree, range, uniqueness and connectivity contracts. Overlap can repeat global edges or exceed the final degree bound; the later merge must sort, deduplicate, prune with full navigation vectors and reserve the global successor cycle. Local cycles do not establish that final contract.

`DiskANNPartitionSummary` retains source coverage, all effective index/partition settings, work-order revision, leaf/membership/edge counts, maximum leaf size/depth and an ordered assignment digest. The digest binds settings and coverage, split decisions and membership streams, and the ordered leaf identity lists. The final generation stores compact effective settings and ordered digests as build provenance; canonical node pages supply durable global-to-logical identities. Complete temporary membership maps are not resident manifest data. The current summary is typed construction metadata; the later sealing owner must encode and validate it in the physical generation format.

The [independent partition fixture](../../crates/uqa-storage/tests/fixtures/diskann/README.md#partition-assignment-and-overlap) fixes rational nearest-two choices, duplicate-center ties, capacity windows and tagged child seeds. Owner checks cover exact two-point global edge translation, recursive/skew/identical populations, same-input determinism, empty/side/singleton cases, a raw corpus larger than the controlled build allowance, graph admission bounds, shared temporary limits, cancellation, typed consumer errors, corrupt output, final-owner release and block-level cipher work counts. Full merged-graph recall and persistent generation acceptance remain separate obligations.
