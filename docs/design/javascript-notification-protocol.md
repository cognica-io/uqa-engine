# JavaScript notification protocol preservation

The Node HTTP-only package implements bounded notification request encoding and incremental SSE decoding independently of the native addon. These primitives implement the wire portion of [SQL notifications and SSE](sql-notifications-and-sse.md) and preserve the same [Rust protocol contract](notification-protocol-decoding.md). The separate [HTTP ownership proof](javascript-http-notifications.md) establishes their actual client transport integration. Authenticated server authority, embedded delivery and browser runtime evidence remain required owners in the [implementation ledger](../plans/0015-sql-notifications-and-sse.md).

## Representation and ordered observations

Let $E$ be the admitted Core event carrier, including notification and explicit gap/reconnection variants. JavaScript notifications retain the same Unicode scalar sequences, signed 32-bit process identifier, canonical epoch, optional bounded request identity and unsigned 64-bit sequence. Sequences are parsed from canonical positive decimal strings directly to `bigint`; sender integers are admitted only from integer JSON tokens in the exact signed range. Fractional/exponent tokens and negative-zero tokens cannot become an integer sender through coercion. The existing integer-preserving SQL JSON parser supplies opt-in duplicate rejection, scalar-Unicode validation and a two-container nesting bound; callers without these options retain its previous behavior.

Define $J:E\to E_{JS}$ by this fieldwise conversion, with distinct variant tags and `null` for inapplicable fields. Inverse conversion on the image recovers the original integer domains and UTF-8 strings exactly, so $J^{-1}(J(e))=e$. In particular JavaScript binary64 rounding never touches a sequence or an out-of-range sender. Therefore the pointwise map preserves the empty history, concatenation, variant distinctions and every original field observation. Frozen event values preserve those observations after publication; private fields and a content-free inspection method keep payloads out of ordinary diagnostic formatting without removing explicit field access.

For one response, readiness validates every required field, exact channel count, protocol version and delivery/resume policy before publishing identity. A notification is admitted only if its identity matches, its channel belongs to the original selection and its sequence equals the previous sequence plus one. Exact `bigint` arithmetic and an independent unsigned-64-bit bound prevent wraparound or precision loss. Induction from the initial sequence zero proves contiguous ordered issuance; failure latches before any later event can be returned. Error and draining frames terminate that response; unknown remote codes cannot acquire automatic retry authority.

## Framing and finite retained input

The framer retains one 65,536-byte allocation, offsets, a possible initial UTF-8 BOM prefix and the state of an optional LF after CR. Every input byte has one transition independent of chunk boundaries. Event/data/comment field interpretation uses the first colon, at most one removed space, the last event field and joined data lines. Only a complete block is decoded, so multi-byte UTF-8 split between transport chunks retains its exact byte sequence. Invalid UTF-8, duplicate JSON fields, unknown fields, unsupported event shapes and excessive nesting terminate without retaining offending input in the error.

At the exact frame limit, a terminating CR is deferred until the framer sees the next byte or EOF. An immediately following LF would exceed the complete-frame bound and is rejected before readiness or data is exposed. A non-LF byte finalizes that frame without consuming the byte, and the caller resubmits it for the next frame. This gives the same transition sequence for any partition of the same byte stream, including a split at CR/LF, while preserving the complete-frame bound. Terminal frames admit only their outstanding optional LF; further bytes are rejected.

The decoder returns at most one observation with the consumed-prefix length and never stores the caller's chunk or an event queue. Parsed text, fields and JSON are bounded by the current frame; the same fixed storage is reused across arbitrarily long cumulative streams. JavaScript object/allocator overhead and transport buffers remain separate components of complete process-resource qualification. The incoming owner must bound its one retained transport chunk, event count, queued bytes and actual socket lifecycle.

## Portable byte representation

The request, framing, validation and encoded-queue primitives use `Uint8Array`, `DataView`, `TextEncoder` and `TextDecoder`, without Node globals or builtin imports. Let $U$ be the admitted Unicode scalar strings and let $\ell(s)$ be their UTF-8 byte length. The counting routine consumes each ASCII scalar once with weight one, each remaining scalar below $2^{11}$ with weight two, each remaining BMP scalar with weight three and each valid UTF-16 surrogate pair once with weight four. These disjoint cases are precisely the UTF-8 widths, so induction over the consumed scalars gives the same $\ell(s)$ as encoding. Isolated surrogates have the encoder's three-byte replacement length; public request and protocol validation reject those inputs before admission. Byte comparison examines unsigned octets in order and then prefix length, preserving canonical UTF-8 channel ordering.

Queue admission calculates $\ell(s)$ before creating a destination record. `encodeInto` writes directly into that already admitted record, without another encoded payload allocation. The fatal decoder preserves an initial U+FEFF with `ignoreBOM: true`; a BOM inside a channel or payload is data, independent of the framer's initial-stream BOM rule. Consequently decoding the encoding of every $s\in U$ returns $s$, including leading BOMs, supplementary scalars and embedded NUL payloads. Request snapshots retain the same independent bounded UTF-8 copy as before.

For an admitted unsigned $w$-bit integer, the big-endian byte sequence is the unique expansion $n=\sum_{i=0}^{w/8-1} b_i2^{8(w/8-1-i)}$. `DataView` writes and reads this same expansion for the 64-bit sequence and 16-bit text lengths; signed 32-bit process identifiers use the corresponding unique two's-complement representation. Epoch and variant bytes, offsets and record lengths are unchanged. Therefore the queue codec is the same injective map on admitted events and retains its inverse, FIFO observations and exact byte-admission boundary. The framer replaces only its byte carrier with an equally sized array, leaving every byte transition unchanged. These arguments preserve the existing history projection and queue invariants without adding a UQA operator. A realm with no `Buffer` or Node builtin access verifies the shared primitives, but is not evidence of an actual browser package, fetch transport or embedded WASM lifecycle.

Request construction checks count and individual scalar-valid UTF-8 channel lengths before retaining copies. Retained channel strings are decoded from those bounded UTF-8 copies so that a short caller-supplied slice cannot retain an arbitrarily large parent string. Each escaped channel contributes to the complete 65,536-byte body bound before the final concatenation. A bytewise UTF-8 sort produces the same canonical channel order as Rust without changing channel-set semantics. JavaScript timers admit only their supported positive millisecond range and check the wire relation $I>3H+M$ using exact integer arithmetic before reporting readiness; no universal timeout or capacity default is inferred.

## Evidence and limits

Eleven notification protocol cases run through the files copied from the actual npm package manifest without a native addon. They consume the independently specified shared fixture under every split and single-byte UTF-8 delivery, and exercise bounded escaped requests, depth-two/depth-three JSON, duplicate and unknown fields, exact integers, sender and timing bounds, deferred CRLF overflow, malformed/incomplete EOF, terminal order, cumulative streams, payload bounds and private diagnostics. The existing HTTP-only tests, including a local packed-package installation, run in the same harness. Runtime evidence currently uses Node 22.12.0; the existing automatic matrix includes Node 16, but no unobserved CI result or actual HTTP notification delivery is claimed here.

These adapters introduce no SQL evaluation, publication, query operator, ranking operation or optimizer rewrite. They preserve original event values and ordered projection under the stated native/transport preconditions. Actual connection, cancellation, authorization and resource-profile evidence is still required before the whole Node subscription unit is complete.
