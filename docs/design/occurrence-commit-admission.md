# Occurrence commit read admission and ordered spill

Issue [#1075](https://github.com/cognica-io/uqa-engine/issues/1075) concerns occurrence preparation and native SQLite publication while new statement snapshots wait for the existing change-publication gate. The investigation starts from `e38848f8a664c8d53a9d77e61f4a5d7b0ef5ae19`. Native SQLite stores score and positions together; SQLite Key/Value and redb use separate related records. Both representations had repeated unchanged-boundary read admission and unnecessarily merged unchanged output. This correction shares read admission and preserves input order for own-key effects. It introduces no storage format, SQL behavior, conflict exception or public API.

## Preserved observations

Let C_s(k) be the complete committed record at key k and sequence s, including absence, tombstones, revision and the complete decorated occurrence graph. Let E be the immutable evaluated batch, including each original revision condition and record kind. The unchanged-boundary branch applies only when the base and current committed sequence are equal. It validates the base and evaluated graphs and retains the evaluated bytes and original condition. It does not infer equivalence from document support or score equality. When the sequences differ, the existing three-way per-document merge, statistics arithmetic, structural fences and conflict handling remain required.

At the same sequence, one ordered point-value visitor returns precisely the C_s(k) values that separate point visitors return. Its committed snapshot lease retains s throughout the visitor. The resolver validates each source marker and complete stored/evaluated graph in the original order. A combined cluster needs one requested value. A split cluster copies only its compact stored score before borrowing positions, preserving the previous score-then-position validation and complete occurrence graph. Only immutable prepared lookups and private output writes run inside the visitor; canonical command validation, canonical peers and other derived effects close it before their ordinary committed reads begin. Invalid write kinds, missing peers and corrupt graphs remain errors.

Each unchanged cluster record is emitted at its own input key. For combined records this directly preserves key order, bytes, expected revision and mode-dependent kind. For a split pair, let k_s and k_p be its distinct score and position keys. The previous resolver emitted both evaluated records when processing k_s and skipped the later or earlier k_p input; the corrected resolver validates the complete pair at k_s and emits each record at its own input position. The valid layouts classify score, position, format, statistics and cache addresses into disjoint record families, and the immutable input contains each key once. Other pairs have distinct keys; intervening format invalidation writes cache keys and statistics writes its own key. Moving the unchanged k_p write across those distinct-key operations therefore commutes as map replacement: M[k_p := P][q := Q] = M[q := Q][k_p := P] for q != k_p. The final complete map, including original preconditions and kinds, is identical. No intermediate output is visible before resolution succeeds; failed validation discards the entire private result. A canonical peer follows the existing precondition-validation path instead of this permutation.

The own-key argument also applies to a computed combined cluster, a field-statistics replacement and a format marker whose related marker key equals its input key. Computed replacements obtain the same current revision and execute the same arithmetic and validation. Advanced-boundary split merges can compute a different key, so they retain the existing merged overlay. Other related-key effects also adopt that overlay before their first replacement, preserving their overwrite precedence. For an own-key prefix k_1 through k_n with records T_1 through T_n, appending each unique input key represents M_i = M_(i-1)[k_i := T_i]; a spilled input is already key-ordered. At a related-key effect the builder-to-overlay conversion retains that exact prefix and subsequent replacements use the original operation in the original order. This proves complete-record equality, not merely equal live document support.

Each visitor owns one copied request key, one selected prepared record or pair, and at most one compact stored-score buffer under the original `StorageReadControl`. Authenticated spill readers/writers keep their original allowance, bounded buffers and cleanup rules. Cancellation, admission failures, invalid input and producer/visitor errors propagate before publication and release unfinished output. SQLite and redb open the physical read lazily, preserve missing values, tombstones, duplicates and historical visibility, and stop before requesting another key when the visitor stops or fails. redb validates the same database metadata at admission and borrows payloads within that read transaction; an absent first key does not force opening the versions table. Physical publication still checks the same record preconditions and resolved sequence; retry resolves against a new committed snapshot.

Engine retains its existing exclusive publication gate across backend commit and row-change metadata publication, so storage snapshots and row-change metadata describe the same committed boundary. The default `Engine::new()` has a separate `MemoryInvertedIndex`, no persistent record provider and no independent persistent sessions. Its SQL commit/rollback values are verified separately; no occurrence spill or independent-session latency result is claimed for that Engine. SQLite in-memory mode and custom `MemoryVersionStore` consumers still use their selected MVCC record representation and the corresponding common correction.

## Reproduction and verification

The starting native fixture required 72 physical read admissions for 64 terms. A 512-combined-cluster input of 710,158 payload bytes wrote 2,023,647 bytes, including 1,313,489 recopied bytes. The split-record fixture under 256 KiB wrote 3,197,510 bytes for 708,110 input bytes, including 2,489,400 recopied bytes. The earlier regression limited split-record source reads but did not bound these incremental output rewrites.

The corrected native SQLite, SQLite Key/Value and redb fixtures each need 9 physical read admissions at 64, 256 and 1,024 terms. Unchanged-boundary split resolution now shares one base window and writes exactly one input payload pass, with zero recopy. Combined own-key resolution does so at both unchanged and advanced boundaries. The existing authenticated-input bound remains eight source-block passes. These operation counts are not elapsed-time speedups.
