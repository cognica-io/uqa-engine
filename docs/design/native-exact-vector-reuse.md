# Native exact vector reuse

The SQLite provider owns this optimization in `vector_index/brute_force/cache.rs`. It introduces no SQL operator, index kind, dependency or persistent format. Common Storage continues to own cosine scoring, top-K selection and decorated posting types. Engine retains its existing table, session and transaction adapters.

## Selected input and cache identity

For one native index, fix its table, field and dimensions. A selected committed/private view defines the finite canonical sequence C of `(document identity, tensor ordinal, binary32 coordinates)` in ascending identity and ordinal order. Canonical decoding validates coordinate dimensions and finite values, and the existing final ordinal validator checks that each document has exactly its contiguous ordinal sequence. Only a fully successful traversal may publish retained coordinates. A failed traversal, including a final ordinal failure, discards all provisional coordinates and scores.

The cache identity consists of the selected table object's immutable owner identity and generation, the committed data revision selected at the retained boundary, and the maximum non-reusable private revision under this field's vector family prefix. Native publication advances the provider-owned committed data revision atomically with vector changes. Private record mutations receive increasing, non-reusable revisions, including replacement and deletion; savepoint rollback restores the old private view without reusing revisions for a new branch. These are the same identity rules used by native HNSW, now factored into the provider's shared native-vector identity module. HNSW still includes its original four record families; exact scoring includes only canonical vectors.

For two reads of the same index with equal cache identities, the owner generation selects the same relation incarnation, the committed revision selects the same canonical committed vectors, and the private revision selects the same private vector modifications. Hence they select the same C. A different identity cannot use an earlier cached C. Old retained views may replace the live index's cache with their own generation, but a subsequent reader must compare identities again. Concurrent replacements affect reuse only: each active reader retains its selected immutable coordinates. The proof assumes the provider's guarded publication protocol; direct out-of-protocol corruption of a live physical database is not a supported mutation mechanism.

## Score and posting preservation

The cache copies each coordinate's binary32 bits in canonical traversal order and retains document identities. Ordinals can be omitted from the retained representation after full validation because their only subsequent role is the already-established within-document order. Let s(q, v) be the existing cosine function, including its existing floating-point evaluation order. For threshold t, the scoring fold visits every retained vector in the same order, includes it exactly when the existing `s >= t` comparison holds, and updates a document's retained score exactly when the existing `s > best` comparison holds. KNN uses the same fold without threshold filtering.

By induction on the prefix of C, the streaming and retained folds have identical document identities and identical binary32 score bits after every step: both evaluate the same function on the same bits, take the same comparison branch, and append or replace the same entry. This also covers zero vectors, overflow from finite coordinates, ties and tensors because no normalization, reassociation, quantization or alternative maximum operation is introduced. Applying the unchanged top-K selector and identity ordering therefore yields the same decorated posting sequence, not merely the same support. Conversion from binary32 scores to binary64 payload scores also remains unchanged. Threshold output retains its identity ordering. Any existing SQL retrieval composition consequently receives the same postings and scores.

## Resource and cancellation boundaries

Retention is optional and uses a child of the source read allowance, capped at the smaller of one sixteenth of that allowance and 16 MiB. Entry capacities, coordinate capacities and immutable sharing headers are charged before publication; replacement allocations retain both old and new charges while they coexist. Clones retain the original reservation through the final reader. Each query checks its own selected cancellation signal while reading cached coordinates; the cache does not retain an earlier query's cancellation signal as authority for a later reader.

An oversized corpus discards provisional retention and completes the original canonical streaming fold. Memory pressure during optional identity selection falls back to that fold. Pressure during source preparation or posting reservation releases the replaceable cache and retries only that failed read or reservation once. Pressure while a partial cache competes with streaming workspace discards both partial products and rescans the same already-selected immutable view once without retention. Pressure during cached scoring releases that reader's cache copy and the replaceable entry before one streaming attempt. No SQL statement, analyzer callback, mutation or transaction is replayed. A still-insufficient allowance reports the original typed memory failure; active concurrent readers retain their independent leases. Corruption, cancellation and other provider failures are not converted into successful cache fallbacks. Posting construction retains the established caller-owned output boundary.

## Verification

Owning-crate tests exercise committed and private mutations, savepoint branch divergence, old retained views, writes through another session, deletion, tensor replacement, clearing, current-reader cancellation and final lease release. Tests compare cold and retained threshold score bits with an independent canonical traversal under an allowance that excludes caching, and verify that a full-corpus cache is unnecessary for bounded exact search. Separate pressure tests cover source preparation and final posting construction. An invalid private tensor ordinal is rejected repeatedly without publishing a cache, remains rejected after commit, and does not invalidate a prior retained view. The existing native HNSW tests exercise the shared identity extraction. Independent PostgreSQL/pgvector workloads remain the result and quality oracle for SQL-level verification; generated observations and source provenance belong in ignored benchmark output, not in verifier expectations.
