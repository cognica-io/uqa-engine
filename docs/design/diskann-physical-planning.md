# DiskANN physical planning

DiskANN planning uses retained physical metadata instead of the generic dimension-times-log-population vector estimate. This document defines the implemented statistics and work estimate. Static EXPLAIN rendering, invocation counters, and exact selected-view current/change statistics remain required by the [implementation plan](../plans/0014-diskann-vector-index.md#sql-lifecycle-and-planning).

## Ownership and selected inputs

Storage projects a selected `DiskANNQueryMetadata` into data-only [Core statistics](../../crates/uqa-core/src/types/index_stats/vector.rs). It owns manifest layout, stored generation identity, training provenance, reader limits and the numeric route. Query classification calls the same `metric::norms` and `exact_reason` functions as execution: a zero or nonfinite binary32 norm selects exact search even when every input coordinate is finite. No normalized query, graph page, codebook, code batch, complete origin reader or corpus enumeration is required by this projection. The [bounded metadata contract](diskann-calibration-identity.md#metadata-reads-before-preparing-search) defines the preceding provider selection reads; this is not a claim that the complete Engine planning path performs only one read.

Planner's retained catalog interface receives these facts without depending on Storage at runtime. Engine supplies the selected table/registry guard and original retention/cancellation control; it does not interpret page layouts, compute norms or estimate work. Core `IndexStats` associates each fact set with its field and the exact binary32 query bits. Two fields cannot borrow each other's dimensions or configuration, and two queries on one field cannot overwrite different numeric routes. Signed zeros remain distinct keys. The legacy dimensions statistic remains available to other physical methods.

Stored facts include the physical database/table/index/generation identity, dimensions, degree/search/beam/PQ settings, graph and side-vector populations, optional base document count, page layout, optional edge count, and declared reader limits. When build provenance is present, the actual centroid count is the minimum of graph nodes, admitted training samples and admitted centroids; codebook coordinates are binary64. Missing provenance remains unknown. Current canonical vector count and outstanding changed-vector count are independently optional: neither a journal length, allocation watermark nor manifest fingerprint establishes those counts on the selected view. The current metadata projection leaves both unknown.

The existing selected table population supplies a planning estimate when a current vector count is unknown. It is not substituted into the stored facts. Implementing authoritative selected-view current/change statistics remains open; preparing the complete origin reader or scanning the corpus merely to obtain static costs is not an acceptable replacement.

## Work units and assumptions

The [Planner estimator](../../crates/uqa-planner/src/cost_model/vector.rs) reports uncalibrated work units. It does not predict elapsed time, claim a recall bound, or treat logical pages as measured SSD operations. Let $d$ be dimensions, $n$ graph nodes, $m$ PQ bytes per node, $L$ the stored search-list size and $B$ the logical beam width. Stored tensor density is $\rho=\max(1,V_b/D_b)$ when a positive base document count $D_b$ exists, otherwise one. The estimated current vector population is $\widehat V=V$ when known, otherwise $D_{table}\rho$. These density estimates are not upper bounds: a changed tensor can have arbitrarily different cardinality within the admitted public limits.

For requested document candidate count $k$, nominal approximate expansion is $a=\min(n,L)$ and estimated completion expansion is $c=\min(n-a,\max(0,k\rho-a))$. This does not redefine traversal capacity or claim that actual approximate expansions are bounded by $L$; the moving frontier can expand more nodes. Completion work estimates the separate traversal used to satisfy the document quota. It does not modify that quota or the executed search parameters.

| Quantity | Estimate and interpretation |
| --- | --- |
| PQ lookup coordinates | $dC$, where $C$ is the known centroid count, or $\min(n,256)$ when provenance is absent |
| PQ distances | Zero for an empty graph; otherwise $1+a\bar R$, with mean degree $\bar R=E/n$ from stored edge count, or $\min(R,n-1)$ when unknown; duplicate discoveries can reduce actual work |
| Resident PQ payload | $8dC+nm$ bytes; excludes allocation headers, directories and other retained owners |
| Logical page requests | $(a+c)F$, where $F$ is the number of page fragments for one node slot; assumes cold requests without packing/deduplication/cache-hit savings |
| Logical page bytes | Logical page requests multiplied by the physical page size |
| Side work | Stored side-vector count multiplied by estimated complete-tensor density; repeated side entries for one document can overlap |
| Changed work | Known changed-vector count, otherwise the entire estimated current vector population; unknown is never relabeled as a measured zero |
| Candidate reranking | $\min((a+c)\rho,\widehat V)$ complete-tensor coordinate groups; possible overlap with side/change work is retained in this estimate |

For a beam requiring $p$ page fragments, let $b$ be the smaller of maximum batch pages and the in-flight byte allowance divided by page size, and let $r$ be the smaller of provider read concurrency and $b$. Dispatch-round work is $\lfloor p/b\rfloor\lceil b/r\rceil+\lceil(p-b\lfloor p/b\rfloor)/r\rceil$. Apply that expression to each full logical beam and its final partial beam. For example, eight pages split into batches of three with concurrency two require $2+2+1$ rounds. Provider limits split dispatches without changing the configured logical beam or approximate frontier. An allowance below one page is explicitly marked insufficient; serial required work is still reported, but the estimate does not authorize a read or suppress an execution error.

The CPU term adds PQ lookup coordinates, PQ distance evaluations times $m$, and $d$ times the side/change/rerank vector estimates. The I/O term uses the fixed relative weight eight for each logical page request and each dispatch round. These weights have no machine calibration. A zero candidate count has no query work. Exact threshold retrieval and numeric exact KNN routes use $d\widehat V$ with zero ANN/PQ/page-navigation work. The existing calibrated-vector overhead is applied after estimating its unchanged raw KNN work; it does not change probability conversion.

## Preservation argument

Fix one retained catalog/canonical view $S$ and a valid field/query pair $(f,q)$. Let $P$ denote an existing retrieval tree, whose leaves return decorated postings with raw scores and whose compositions retain their existing operators. Statistics collection produces $\sigma(S,f,\operatorname{bits}(q))$ and the estimator produces an annotation $C(\sigma,k)\in\mathbb R_{\ge0}$. Erasing this annotation returns exactly $P$: no query coordinate, candidate count, threshold, field, calibration parameter, retained owner or logical operation is replaced. All terms above are finite nonnegative products, minima and sums of bounded integer inputs converted to binary64; divisions use positive dimensions of the dispatch/density model. Consequently annotation is closed in the nonnegative finite cost domain and introduces no new posting or score operation.

The projection derives numeric routing through the execution owner's same norm computation, so its exact/approximate classification agrees for every admitted query, including underflow and overflow of the binary32 norm. Its costs never dispatch search and never authorize a different route. KNN's approximate candidate membership, canonical complete-tensor maximum, exact threshold predicate and document tie order therefore retain their existing definitions. No graph observation or canonical value read is introduced by the metadata projection, and it performs no publication or mutation. Original control failures remain errors through the existing typed Storage-to-SQL mapping.

Within `QueryOptimizer`, the changed `CostModel` leaf estimates could otherwise affect intersection order. The [ordered decorated-intersection rule](architecture.md#ordered-decorated-intersections) prevents that: any intersection containing these scored vector leaves retains its declared fold and grouping, while membership-only operands have no changed vector leaf cost. Thus neither floating-point reassociation nor payload collision precedence is licensed by the new numbers. Fusion signal ordering uses the existing cardinality estimator, whose inputs and algorithm are unchanged; filter index selection uses the existing unary scan estimator. The addition does not introduce or broaden any rewrite. Relational access costing may select among the existing admissible relation plans, without changing their bound predicates, candidate K or residual filtering contract; each selected plan remains subject to those original plan-equivalence preconditions.

It follows by structural induction on unchanged retrieval compositions that replacing a cost annotation preserves each executed leaf result and each parent operation on those results. This argument concerns full decorated values, not merely support: it invokes neither a semiring law for `Payload` nor commutativity of rounded score addition. Unknown population counts affect only estimated work. They cannot weaken validation, alter membership, refill a post-KNN filter, or change hybrid evidence/prior combination.

## Verification obligations

Owning Planner tests assert independently calculated PQ, page-fragment, dispatch-round and complete-tensor terms, exact and zero-k routes, two differently configured fields, and different query bits on one field. Storage's metadata-only source rejects graph/PQ/origin/corpus reads and checks numeric edge routes and original cancellation with no projection allocation. Engine tests retain actual metadata across index replacement on memory, native SQLite, SQLite Key/Value and redb, verify unchanged literal KNN scores, and preserve cancellation SQLSTATE `57014`. Existing decorated-intersection, calibration and retrieval-planning regressions protect the integration boundaries. The implementation plan records executed source-scoped results; these obligations do not claim completed static EXPLAIN or invocation diagnostics.
