# DiskANN paged navigation

`uqa-storage::diskann_index::search::DiskANNTraversal` owns physical navigation over one retained [generation reader](diskann-page-readers.md). It emits checked `DiskANNNode` values with generation-local node IDs, original document/ordinal identities, versions and raw coordinates. The [implementation plan](../plans/0014-diskann-vector-index.md) keeps canonical retained-query integration separate: this primitive does not implement `VectorIndex`, decide snapshot visibility, score a document, create posting payloads or enable SQL DiskANN.

## Navigation order

The constructor requires `NavigationVector` and checks dimensions even for an empty graph. Numeric-side queries use their declared canonical path; they cannot manufacture an entry into this navigation primitive. Nonempty readers supply one codebook, resident codes and the manifest entry. The query lookup returns typed `PQDistance` estimates only.

The pending frontier keeps at most `search_list_size` unexpanded candidates ordered by ascending `(PQDistance, node ID)`. A separately charged maximum heap retains at most that many expanded identities and their squared Euclidean distances from the normalized query to the original physical vectors. This refined set supplies the admission cutoff once it is full. Before that, the cutoff is unbounded. Expanded identities never consume pending slots. Their separate membership set prevents duplicate expansion even after an identity leaves the refined set.

This corrects the use of an expanded node's lossy centroid distance as if it were its available original distance. PQ reconstruction can substantially underestimate that distance and cut off a better reachable node. The pending capacity, beam width, PQ bytes, graph construction and encoded artifacts are unchanged. Query workspace additionally retains one normalized query and up to `search_list_size` refined `(distance, node)` pairs under the original allowance. Additional expansions and coordinate arithmetic are real costs, exposed by the existing execution counters; neither list size nor the refined cutoff is a bound on the total number of expansions. No general recall floor, timing improvement or exact-search guarantee follows.

Each `next_beam` freezes up to `beam_width` unexpanded candidates in priority order before reading. `read_nodes` sorts and deduplicates their page addresses, reads each required page once within the call, then decodes nodes in the frozen order. Packed nodes share leases; fragmented nodes assemble complete validated slots. Provider calls obey the in-flight page limit, while all retained page leases and returned node buffers must also fit the original query allowance. This batches real reads even when the cache is disabled. The single-node reader retains its separate one-fragment-at-a-time path.

After the complete beam is decoded, all its identities enter the expanded set and update the refined heap. Pending entries above the new cutoff and all expanded entries leave the frontier. Every frozen node then expands its sorted unique neighbors in priority order, including cache hits. A neighbor's `(PQDistance, node ID)` must not exceed the refined cutoff; the best pending candidates compete for the unchanged frontier capacity. An evicted pending candidate may be admitted if another edge rediscovers it, because freeing pending slots can relax that separate capacity cutoff. Neither cache residency nor provider completion order changes the sequence. The [pinned reference](https://github.com/microsoft/DiskANN/blob/78256bbab4685e1774e78d331e081a153be26823/src/pq_flash_index.cpp) supplies the original PQ/beam mechanics; using available original coordinates for the cutoff is an explicit UQA refinement rather than a claim of identical reference traversal.

The persisted algorithm revision continues to describe the unchanged Vamana construction, codebook, work order and metric formats. Previously sealed generations are read without migration or rebuilding; their approximate candidate sets may improve under the corrected query strategy. Public canonical scoring and probability conversion remain separate and unchanged.

## Bounded refinement and preservation proof

Let $V$ be the finite physical node set, $q$ the normalized query, $x_v$ the normalized original vector of node $v$, $p(v)$ its PQ estimate, and $d(v)=\lVert q-x_v\rVert_2^2$. Both priority keys include node identity as a final tie breaker. Let $L$ be the configured list size, $E$ the expanded identities, $F$ the pending frontier and $H=\operatorname{top}_L(E,d)$ the nearest expanded identities. The cutoff is $\tau=\max H$ when $|H|=L$, and $+\infty$ otherwise. This is a navigation construction; neither distance is a public posting score.

Initially $E=H=\varnothing$ and $F$ contains only the manifest entry. A transition freezes at most the configured beam width from the beginning of $F$, reads that exact beam and inserts each identity into $E$ once. Offering every decoded node to the bounded maximum heap establishes $H'=\operatorname{top}_L(E',d)$: before the heap is full every element is retained; afterward replacing its maximum exactly when a smaller key arrives preserves the least $L$ keys by induction. Therefore the finite cutoff never increases once established. Rejection by the refined cutoff remains valid for this heuristic on every later transition because $p(v)$ is fixed and $\tau$ only decreases. PQ is not a lower bound on $d$, so this does not prove that rejected nodes cannot be true neighbors.

Removing the frozen identities and candidates beyond $\tau$ from $F$, then admitting unique unexpanded neighbors in PQ order while dropping the largest pending key when necessary, preserves $|F|\leq L$, $F\cap E=\varnothing$ and $|H|\leq L$. Capacity eviction is distinct from cutoff rejection: a later edge may offer an evicted identity again. No unbounded deferred-candidate queue or global-vector enumeration is introduced. Each nonempty beam strictly increases $|E|$, so approximate traversal terminates after at most $|V|$ expansions, including in cyclic graphs. Equal keys have deterministic identity order. The separate ascending-ID completion visits precisely the complement of $E$ and retains its existing document-quota purpose.

All distances in a frozen beam are incorporated before neighbor admission, so successful read completion order and cache residency cannot alter either heap, the next frontier or emitted order. Every new query, heap, frontier and membership allocation is charged to the original invocation; decoding and page ownership retain their existing controls. A failed step has already removed workspace from the resumable traversal, so its partially updated sets cannot escape as a successful beam or be resumed. Cancellation and allocation failure therefore preserve the existing error and release boundary.

For unit navigation vectors, $d(v)=2(1-\langle q,x_v\rangle)$ in real arithmetic. The implementation evaluates normalized coordinates in scalar `f64` and computes no posting payload from this value. Its only observable search change is the approximate physical candidate support. The canonical query owner still validates origins and ordinals, deduplicates documents, scores every visible tensor ordinal with the original sequential `f32` cosine, adds unchanged numeric-side and uncovered-change contributions, and completes an undersized document quota. Consequently the existing ranked carrier, score domain, tie rules, tensor maxima, visibility and downstream fusion conversion are preserved on the selected support. No equality of approximate supports or optimizer rewrite is asserted. Exact threshold and exact numeric query paths do not invoke this traversal and remain unchanged.

## Explicit completion and failure ownership

An empty approximate beam signals exhaustion of the bounded frontier. It is not evidence of exact support or a complete visible document quota. After that signal, `complete_next_beam` scans remaining dense generation IDs in ascending order, skipping every approximate expansion. A cursor guarantees that completion does not replay nodes, without growing the membership set for the scanned suffix. It releases the PQ lookup, pending frontier, normalized query and refined heap when completion starts, and releases all remaining workspace when the cursor reaches the generation end.

The canonical query owner may request completion beams until it has enough distinct visible documents, including its separate changed/numeric-side contributions. It must still validate versions before document projection and score every visible ordinal of each selected document. Physical tensor ordinals remain distinct here, even when they name the same document. The completion order is a UQA rule with an independent fixture; it does not promise the exact nearest documents or replace recall acceptance. It is never entered to recover from a storage error.

Starting completion before approximate exhaustion is an error. Approximate work cannot resume after completion starts. Failed admission, cancellation, invalid pages, missing completions and original provider errors release the traversal's owned workspace and make it non-resumable. A step returns its node batch only after every read, decode and expansion succeeds; the caller must discard candidates from earlier successful steps if any later step fails. Retained reader/cache bytes keep their original owner; separate queries do not inherit this query's cancellation.

`DiskANNTraversalStats` counts successful approximate expansions, completion expansions, PQ estimates and nonempty beams. These logical counts are invariant across cache and provider completion order. They do not claim physical SSD reads, latency, canonical rerank work or public EXPLAIN integration.

## Typed observations and validation

The [typed carrier manuscript](../papers/A%20Typed%20Carrier%20Algebra%20for%20Unified%20Query%20Execution.md) requires separate observations at each conversion. PQ order is a navigation observation. Generation-local node equality is not document equality; document support projection is not payload collision merging. Canonical score equality, final ranked order, approximate support recall and calibrated probability remain separate obligations. No top-k rewrite or evidence conversion follows from this physical traversal.

The independent [beam fixture](../../crates/uqa-storage/tests/fixtures/diskann/README.md#paged-beam-order) fixes rational distances and every pending-frontier/beam transition without reading Rust output. A separate three-node regression uses nearest-centroid labels and literal axis/3–4–5 vectors to demonstrate premature cutoff by a lossy centroid, successful refined navigation and a remaining unexpanded node reserved for explicit completion. Owner tests also exercise packed and fragmented pages, priority-order decoding, zero/tiny/warm caches, reversed provider completions, cycles, equal distances, multiple tensor ordinals, empty/singleton graphs, original controls and non-resumable failures. The [implementation ledger](../plans/0014-diskann-vector-index.md) records source-scoped provider, canonical, binding and integrated quality evidence.
