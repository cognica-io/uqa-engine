# Backup image and repository encoding

The common Storage [backup module](../../crates/uqa-storage/src/backup.rs) owns versioned image identities, ordered inventory encoding, fixed backup roots and protected frames for the [online backup design](online-and-incremental-backup.md). These codecs do not capture a database, publish a durable repository root, import provider state or advertise Engine backup support. Those deliveries remain tracked in [#1322](https://github.com/cognica-io/uqa-engine/issues/1322) and the [implementation plan](../plans/0031-online-and-incremental-backup.md).

## Ownership and compatibility

Common Storage interprets archive structure and treats provider image bytes as opaque. The existing runtime dependency directions remain unchanged: Storage depends on Core and Analysis; no Engine, SQL, Execution or concrete provider dependency is introduced. The implementation uses the existing SHA-256, XChaCha20-Poly1305, random-source and Core memory interfaces without modifying external dependencies. No Cargo feature advertises a provider image implementation.

An image format is a provider tag and nonzero provider-owned version. Tags 1 through 4 identify memory, native SQLite, SQLite KV and redb respectively. Envelope decoding recognizes those mappings without asserting that an exporter or importer exists. Default provider capabilities are unsupported. Format migration and owner resource compatibility must be validated by the eventual importer; accepting an envelope is insufficient.

`BackupCut` carries the source incarnation, provider image format, optional committed record sequence and an opaque snapshot identity covering the jointly retained committed data and autonomous metadata. The snapshot owner must establish that joint cut; allocating a random descriptor does not create consistency. A root rejects a zero source incarnation. Repository, backup, snapshot, namespace, object and protection IDs are distinct nonzero 16-byte types. They are never interpreted as filesystem paths.

## Joint record and autonomous metadata snapshots

Common Storage's `CommittedBackupSnapshot` combines a retained record view with an independently typed `MetadataEpoch`, source identity and bounded identifier-watermark visitation. Unsupported persistence adapters return `None`. redb implements the joint boundary through the existing shared `Arc<Database>`. SQLite implements it through managed native and Key/Value record owners, including plain, encrypted, compressed and compressed-encrypted files. Neither retains a physical transaction between visits. Complete provider image encoding/import and the actual memory Engine remain separate deliveries.

redb record format 64 stores an unsigned current metadata epoch `C`, a creation/head-birth pair for each allocator namespace, and historical `(namespace, birth) -> watermark` entries. The format upgrade initializes existing namespaces at epoch zero in the same physical transaction as the format change. Existing record sequences, values, database identity, receipts and watermarks are preserved. Every supported identifier writer then publishes its watermark and metadata history together. Ordinary allocation leaves the record sequence and `C` unchanged.

SQLite record format 68 stores the same epoch, namespace births and watermark history in guarded `_uqa_mvcc_backup_metadata`, `_uqa_mvcc_identifier_epochs` and `_uqa_mvcc_identifier_history` tables. Its atomic upgrade streams existing allocations into epoch zero without collecting them in Rust. Native and Key/Value admission validate the shared record-table inventory; these internal tables do not enter catalog cache generations or native image families. A capture uses the ordinary FULL-synchronized physical writer and advances the existing sequence-durability certificate to the captured record sequence. That commit also covers earlier relaxed WAL observations and autonomous sequence publications without adding a record revision.

Capture takes record admission followed by metadata admission, then one physical writer. That transaction validates the source, reads the committed record sequence and metadata epoch `E = C`, and durably advances `C` to `E + 1`. It retains both logical leases before releasing admission; a failed capture returns no usable cut and retires all partially acquired leases. An unexposed sealed epoch after failed memory admission changes no record or allocation observation. Epoch exhaustion rejects capture without wrapping. A namespace updated in a later epoch archives its old head once and replaces its birth with `C`; repeated updates before the next capture coalesce in that head. No allocation collection is copied during capture.

For a captured epoch `E`, visitation yields the current watermark if its head birth is at most `E`, otherwise the latest historical watermark with birth at most `E`. A creation epoch greater than `E` yields no allocation. Missing required heads/anchors, invalid epoch ordering, an unsealed cut, changed source identity and malformed encodings fail. Each call visits at most its requested number of physical identifier positions in byte order; internal coordination positions and namespaces created after the cut still advance the cursor. The storage-internal callback borrows provider bytes within that read, so it must only encode or copy admitted data and must not write the repository, reenter the provider or invoke application callbacks. Cancellation, a false callback result or an error closes the physical read window.

Collection takes the same admission order and preserves the predecessor at the oldest metadata lease plus all newer revisions; with no metadata lease it discards superseded history. Record cleanup continues to use its independent committed horizon. Every adapter over the same live redb owner shares both registries. SQLite adapters over an in-memory pool share typed local registries; native file owners use distinct record and metadata lease transports. The `.uqa-backup-snapshots` sidecar uses `UQAMET01`, the database incarnation and OS byte locks. A live slot can hold metadata epoch zero; liveness comes from its lock, and process death releases it. Every joint snapshot also owns its original record lease, preserving existing restore exclusion. The common admission order excludes cross-process collection until both leases are installed. Lease destruction releases only its own allowance and does not wait for either admission gate or physical storage. Native database page-cache allocations remain provider-owned; retained snapshot owners use the caller's `StorageReadControl` allowance.

For preservation, let `R_s` be the existing committed record observation at sequence `s`, and let `A_E` be the finite partial map from allocator namespaces to watermarks at capture `E`. Assume the existing provider physical transaction, durable-commit and record-retention guarantees. The joint writer orders capture with every record and identifier publication, hence its returned pair `(R_s, A_E)` belongs to one physical state. Initially each namespace has exactly its current value at birth zero. Inductively, an update in the same unsealed epoch is invisible to all older cuts and changes no archived value; the first update in a later epoch saves the preceding value before atomically replacing it. A namespace created after a cut is excluded by its creation epoch. Therefore the greatest birth not exceeding `E` has exactly the value observed at capture. Missing data is an error, never a substituted current value.

Let `H` be the minimum retained metadata epoch. For any retained `E >= H`, its selected predecessor is either the predecessor selected at `H` or a newer birth. Collection removes only older entries, so it preserves every `A_E`. The record registry separately preserves every `R_s`. Admission excludes capture from collection until both leases exist, and direct source publication cannot violate retention because it preserves replaced heads in the same atomic transaction. Short read windows may observe later physical states, but this predecessor argument gives the same `A_E` and `R_s` on every visit. Concatenating increasing bounded windows therefore enumerates exactly the captured allocation map, even when later namespaces appear between windows. Identifier namespaces are monotone within an incarnation; internal reclamation markers are excluded from the image.

These operations neither evaluate SQL nor change any record carrier, score, graph value, sequence cache or catalog expression. Every existing deterministic observation over the selected record view and allocator map consequently has the same inputs and result; allocator reservations retain their original monotonicity and exhaustion behavior. Failure returns no completed snapshot, and uncertain native synchronization resolves through the existing storage recovery boundary rather than a caller-side state repair. This proves the joint input contract only; complete provider image coverage, import and fresh-history restoration still require their owning implementation and evidence.

## Chunked committed record reads

`CommittedRecordSnapshot::read_value_chunk` copies a caller-selected range and returns the selected revision, complete value length and copied length. Absent records, tombstones and live empty values remain distinct. A destination buffer may be empty; offsets beyond the selected value are rejected before copying. Callers own and account for destination storage, and discard its contents on error. Snapshot wrappers forward the provider method so a bounded implementation cannot accidentally fall back to full-value materialization.

SQLite selects the committed version's physical identity under its existing short read transaction, verifies its payload type and length, and uses the dependency's public [incremental BLOB reader](https://www.sqlite.org/c3ref/blob_read.html). The BLOB handle closes before the method returns. Compacted runs expand their existing at-most-128-byte template. redb borrows the retained version inside one read transaction and copies only the selected range; the reference memory version store retains its existing immutable value. Copying checks cancellation in at-most-16-KiB pieces. Source page caches remain provider-owned; SQLite binding workspace is proportional to the selected key, and no whole-value payload allocation is required. Repository writes occur only after return, when the physical read has closed. This is an image-input primitive; it does not by itself qualify complete provider images or the actual memory Engine.

For preservation, fix a committed key and its retained observation `(v, b)`, where `v` is the selected revision and `b` is either a tombstone or a finite byte string. For live length `L`, offset `o <= L` and destination capacity `c`, the result is exactly `(v, L, b[o..o+n])` with `n = min(c, L-o)`. The subtraction admits the range before any addition, so its end cannot exceed `L` or overflow. An offset beyond `L` is rejected; a tombstone permits only offset zero and keeps an absent length. Empty chunks are the concatenation identity, and concatenation is associative: any adjacent partition from zero through `L` reconstructs exactly `b`, independently of chunk sizes. No decoding, expression evaluation or normalization occurs.

Record retention preserves `(v, b)` across intervening publications and collection. SQLite resolves the version and reads its BLOB inside one physical view, while its run decoder expands the same existing bytes; redb's guard and the memory owner's immutable value provide the corresponding borrowed observation. The physical view ends between calls, but every call resolves the same retained logical version, so concatenation preserves both source bytes and all deterministic observations of them. Reading neither changes publication order nor adds source state. Failure returns no successful range, and cannot produce a complete image. These arguments establish byte preservation and finite per-call work; full-image inventory coverage and restore remain separate obligations.

## Bounded record-image input cursor

Common Storage's `RecordImageCursor` consumes a joint snapshot and emits its allocator watermarks followed by its live MVCC records, preserving byte order within each family. Watermarks use eight big-endian bytes; records retain their existing encoded bytes and exact committed revision. A provider image adapter must still assign qualified namespaces, account for its other state planes, define the image version and implement import. This raw stream alone does not assert complete Engine coverage or a restorable backup.

The retained source supplies physical record and allocator ceilings and bounded position visitors. A ceiling is the greatest current physical key, including possible post-capture keys. Every captured live key remains represented at or below it because the retained cut excludes its reclamation. SQLite merges ordinary heads with compacted-run keys; redb reads its existing head table. Each `advance(n)` visits at most `n` positions, including positions created after capture and tombstones, stopping at the first selected live unit or the ceiling. Empty byte keys are valid positions. Retained boundaries and continuation keys consume the invoking allowance. Later appends beyond the ceiling cannot extend the traversal; the position limit and cancellation bound each call even if writers continue inserting keys below that ceiling. No completion-time bound under indefinitely growing concurrent input is claimed.

After selecting a unit, the cursor requires its complete consumption before advancing. `read_current` copies at most the caller's remaining output capacity and validates the retained revision, total length and exact copied length. Every source read closes before either operation returns; repository writes therefore need no source transaction or callback. Scan progress includes excluded positions, and output-byte progress counts only successful copies. Neither counter is a page-I/O measurement. A failed read, failed advance or cancellation terminates the cursor and immediately releases its source and scan buffers. Typed cancellation and memory failures keep their resource error kinds across provider read wrappers. Completion releases the same resources and remains complete even if cancellation arrives later. No operation can reopen a failed or completed cursor.

For preservation, fix the jointly captured maps `(R_s, A_E)` above and their finite live domains. Retention preserves each captured key's representation, and each ceiling is at least its family's greatest retained live key. A strictly increasing exclusive continuation never repeats a key. Post-capture positions and captured tombstones produce no image unit, so filtering cannot add another state to the output. Every still-unvisited captured key lies after the continuation and at or below the ceiling; whenever traversal reaches its physical position, the retained snapshot yields exactly its captured value. Thus an exhausted traversal emits exactly `A_E` followed by the live part of `R_s`, with no omission or duplication. Finite additional source positions give finite completion; continuously inserted positions do not weaken each call's work bound or the identity of any emitted value.

For each selected value, the chunk identity established above shows that concatenating successive admitted ranges reconstructs its exact bytes. The cursor advances only after the declared length has been consumed, including length zero, so unit boundaries cannot merge or truncate values. Watermark encoding is injective over the existing unsigned allocation domain. The resulting stream therefore preserves the captured record and allocator observations without evaluating or changing an algebraic operation. Its dynamic workspace consists of a fixed number of bounded keys and the caller-owned output buffer, independent of record count and payload size; provider page caches remain outside that workspace. An error cannot certify a partial stream as complete. These conclusions establish the input adapter, not provider-image completeness, repository publication or restore activation.

## Wire formats

All integer fields are little-endian. Encoders write explicit fields, never Rust memory layouts. Unknown protocol versions, provider tags, unit kinds or required framing fail; reserved fields must be zero. The checked-in [fixtures](../../crates/uqa-storage/src/backup/tests/fixtures) were independently assembled from these layouts with Python `struct.pack` and `hashlib.sha256`, rather than emitted by the Rust codecs.

| Encoding | Fields in order |
| --- | --- |
| Object span, 80 bytes | Object ID (16), complete object SHA-256 (32), complete encoded object length (8), starting byte offset (8), encoded span length (8), frame count (8) |
| Inventory header, 16 bytes | `UQAINV01` (8), envelope version 1 (2), provider tag (1), reserved zero (1), provider image version (4) |
| Inventory unit | Tag 1 (1), namespace (16), generation (8), owner family (2), key length (4), key bytes, unit kind (1), decoded unit length (8), unit SHA-256 (32), object span (80) |
| Inventory footer, 49 bytes | Tag 0 (1), unit count (8), total decoded unit bytes (8), logical image digest (32) |
| Root, 240 bytes | `UQAROOT1` (8), envelope version 1 (2), reserved zero (6), repository ID (16), backup ID (16), parent ID or all-zero absence (16), source incarnation (16), snapshot ID (16), provider tag (1), provider image version (4), sequence-present tag (1), reserved zero (2), sequence or zero when absent (8), inventory object span (80), inventory summary without tag (48) |
| Frame header, 96 bytes | `UQAFRM01` (8), version 1 (2), protection mode (1), frame kind (1), repository ID (16), protection domain or zero for plaintext (16), object ID (16), byte offset within object (8), decoded payload length (4), nonce or zero for plaintext (24) |

Owner family zero is invalid. Unit kinds 1 through 5 denote metadata, records, tombstones, artifacts and resources. Inventory order is the lexicographic order of `(namespace, generation, family, key)` using unsigned integer order for generation/family and byte order for namespace/key. Duplicate or descending identities fail. Keys can contain arbitrary bytes, including empty keys; they are not names to create on disk. A unit spans one or more contiguous frames in one object, so its metadata has fixed size even for large payloads. An object may pack many small units.

Each span has a nonzero encoded length and frame count, a checked nonoverflowing end within its declared object length, and enough bytes for at least the minimum frame framing. A unit's declared decoded length must fit the remaining span bytes and the stated frame count under the decoded-frame limit. The eventual object-graph verifier must also compare the actual object's digest and length, walk exactly the stated frames, reject overlapping references and validate the provider's decoded structure. The span parser does not claim those checks without accessing objects.

The logical image digest is SHA-256 over the domain bytes `UQA backup logical image`, a zero byte and byte 1, followed by the provider tag/version and each ordered unit's namespace, generation, family, key length/key, kind, decoded length and content digest. The unit content digest is SHA-256 over its exact encoded image bytes. Object locations, protection nonces, backup IDs and provenance are absent from the logical image digest, permitting verified repacking and re-encryption without changing image identity. They remain covered by the enclosing object/frame integrity.

A root's parent ID records comparison provenance. Incremental parent validation requires the same repository, source incarnation and provider image format and the exact recorded parent ID. Snapshot IDs and record sequences may differ. A root cannot name itself as parent. Complete inventory lookup never needs the parent descriptor; retaining and verifying the referenced objects is a separate repository obligation.

## Protection and bounded I/O

Plaintext frames append SHA-256 over the complete header and payload. This detects accidental corruption and is not authentication against an attacker who can rewrite the archive. Encrypted frames append a 16-byte XChaCha20-Poly1305 tag and use a fresh random 24-byte nonce. The complete header is associated data, binding the protocol, protection domain, repository, object, position, kind and length. Frames have no compression in this version, so encoded payload length equals decoded payload length. A future compressed encoding requires a distinct understood protocol.

Readers receive the expected repository, object, byte offset, frame kind and protection domain from their owning object reader. They compare that context before allocating a payload. The key is a separate caller-owned 32-byte repository credential; it is neither derived from a source SQLCipher credential nor serialized in the archive. Clones share a non-serializable owner, the final owner zeroizes the key bytes, and debug output redacts keys and unit key contents. Inventory and root frames use the same protection as unit frames.

Key and decoded frame limits are explicit and independent of the shared `StorageReadControl` heap allowance. Variable buffers reserve before allocation and retain the allowance until their owner drops. Inventory traversal keeps only its previous address and the current entry; it does not retain a directory of all units. Frame readers and protected writers keep at most one bounded payload buffer per invocation. Fixed stack scratch, including the 16 KiB I/O window, cryptographic state, allocator bookkeeping, caller-owned inputs/outputs and caller-owned keys are separate from the dynamic buffer allowance. A caller that retains many returned entries or frames continues to consume the shared allowance.

I/O and hashing are divided into windows of at most 16 KiB with cancellation checks. AEAD computation is bounded by the configured frame limit. Cancellation is checked again after an interrupted I/O result, so a stream returning repeated interruptions cannot prevent cancellation indefinitely. This is not an operating-system blocking-I/O deadline guarantee. No source lock or provider snapshot is owned by these codecs.

## Codec state transitions

An inventory writer admits entries in strict order and applies its own key and frame limits, including to entries constructed under a larger producer allowance. The reader uses the same admission boundary. Any append error, including invalid order, cancellation, memory exhaustion or partial I/O, makes that writer permanently failed; further appends and finalization return a lifecycle error. Finalization consumes an open writer and emits the counts and logical digest. Its returned stream still requires protected object finalization, synchronization and durable repository publication. Dropping an unfinished writer cannot produce a completed backup.

An inventory reader is open, complete or failed. It returns a completed summary only after the terminal tag, counts, digest and end of its bounded input are validated. A decoding error makes further reads fail; an early prefix never obtains a summary. Completing a reader verifies inventory structure, not payload integrity or restore compatibility. Frame operations consume one frame; partial output must be abandoned by the eventual object writer rather than appended to or published. No caller-side repair or state reset is exposed.

## Preservation argument

Let an owner image be a finite partial map from qualified unit addresses to `(kind, length, image bytes)`. Its domain is ordered by the address order above. An inventory `I` is the unique ordered sequence of descriptors containing each address, kind, length, image digest and immutable object reference; the referenced image bytes are not part of the descriptor encoding. The common codec operates on `I`. It neither evaluates SQL nor changes a carrier, score, posting annotation, graph entity, vector topology, sequence value or stored expression. Source snapshot completeness, object-content verification and provider decoding remain explicit premises for later integration proofs.

For fixed-width fields, little-endian encoding is injective on the specified unsigned range. For variable keys, the preceding exact length determines a unique boundary. Distinct tags and reserved/version checks separate every supported alternative. Induction over the ordered unit stream therefore gives `decode(encode(I)) = I` for every admissible inventory `I`: the header selects one format, each step consumes exactly one encoded unit and rejects duplicates or reversals, and the footer fixes the cardinality, total length and end of input. Root and span codecs have the same property by their fixed offsets and checked bounds. Truncated or appended inputs are not encodings of that completed inventory.

Assume SHA-256 collision resistance and the standard integrity/confidentiality guarantees of XChaCha20-Poly1305 with independent random nonces under each key. Unit digests certify byte equality subject to that assumption. The format-qualified logical digest commits to every ordered address, kind, length and unit digest, so substituting any semantic image component changes its committed input. Repacking changes only excluded repository references; it preserves the logical digest by equality of the included sequence, while the enclosing authenticated frame and object digest still commit to the new references. Expected-context comparison and associated data prevent an authenticated frame from being substituted across repository, domain, object, offset or kind. Plaintext checksums have only their stated accidental-corruption boundary.

Allocation ownership composes with the codec: each new variable buffer reserves while any old buffer remains charged, and failed admission publishes no replacement. Returned buffers retain their original allowance. Induction over inventory steps bounds live address workspace independently of inventory cardinality; the large-state test exercises 10,000 entries with a 64-byte dynamic allowance. A failed writer has no transition back to open or complete, and a failed reader has no transition to complete. Thus failure cannot convert a prefix or a mixed retry into a successful encoded inventory. These are codec properties, not a proof of filesystem durability, source consistency, object reachability, provider restoration or Engine carrier preservation; those owners must discharge their remaining obligations before public backup delivery.

## Verification

Owner tests compare independent wire fixtures, round-trip all four provider tags, validate parent incompatibilities, reject every truncated frame prefix and every one-byte frame corruption, exercise wrong keys and contexts, verify nonce separation, reject oversized advertised lengths before payload access, inject short/failed writes and interrupted reads, and verify terminal failure states. The automatic Linux/macOS regression inventory includes the 10,000-unit work/memory/output test and frame admission before payload allocation. No timing improvement is claimed.


## Evaluated memory text documents

Common Storage owns the versioned `UQATXT01` document image for actual `MemoryInvertedIndex` state. The enclosing unit address supplies document identity. An image contains a nonzero little-endian u64 field count followed by strictly ordered UTF-8 field names, each prefixed with its u64 byte length. Every field has the existing 84-byte `IndexedFieldMetadata` encoding and a u64 term count. Each strictly ordered canonical `TokenTermKey` has a u64 byte length, its original tagged bytes, a nonzero u64 occurrence count and its ordered occurrences. An occurrence stores little-endian u32 position and position length, a zero/one offset flag, and, when present, four little-endian u64 original UTF-8/UTF-16 offsets. Equal occurrences remain separate. Empty analyzed fields remain present even with no terms; a document absent from the text corpus produces no unit.

`InvertedIndex::write_image_document` is an explicit provider capability. The memory implementation borrows reverse keys and posting buffers from the selected immutable generation; it does not collect a second field map, vocabulary or occurrence list. Read-only wrappers retain the original cancellation alongside the caller's output allowance. I/O attempts contain at most 4 KiB and check cancellation between partial or interrupted calls. The return count describes emitted bytes, including fixed metadata; it is not a timing or page-I/O estimate.

`RetainedInvertedIndexBuilder::add_image_document` decodes under its original allowance and requires exact standalone input consumption before publication. It rejects invalid versions, encodings, ordering, duplicated fields/terms, empty posting lists, invalid graph edges, decreasing positions, invalid source offsets and inconsistent normalization lengths. Emitted-token length equals the number of occurrences; overlap-discounted length equals the number of distinct start positions across all terms of that field. The distinct-position workspace has admitted ordered nodes. Buffer capacities, reverse names/keys and all corpus nodes are reserved before allocation/publication; failed input or admission releases temporary ownership without changing earlier documents. Existing counter/footprint publication reconstructs the immutable corpus without invoking any analyzer, SQL expression or resource callback.

Analyzer bindings, descriptors and external-resource closure are separate required image components. A field can reference a historical revision independently of the currently selected search configuration. This codec preserves that fingerprint and metadata; it does not establish that the referenced resource exists. The enclosing validated database image must supply those immutable owners before Engine activation. This document-level primitive, including retained reconstruction, does not expose complete memory Engine backup or fresh writable Engine activation.

### Preservation argument for evaluated text documents

Let a valid text document be the finite ordered mapping D from field names f to (m_f, T_f), where m_f is the complete existing field metadata and T_f maps each canonical term key to its nonempty sequence of occurrences in emission order among equal positions. The document identity belongs to its enclosing address. Validity requires the existing occurrence/revision formats, ordered unique fields and terms, valid graph edges and offsets, and the normalization equation above. Descriptor/resource closure is an independent premise supplied by the enclosing database image. Let E be the specified encoder and R its decoder on fully admitted, valid images.

Every scalar in E has a fixed width or an explicit length followed by exactly that many bytes. The fixed tag, strict zero/one flags, existing metadata validator and canonical term-key validator distinguish all encoded alternatives. Therefore decoding the fixed prefix determines exactly the number and boundaries of fields. Induction over fields determines each original UTF-8 name and exact metadata and term count; induction over those terms determines its original tagged key and occurrence count; induction over occurrences recovers every integer and optional offset without deduplication or reordering. Exact input exhaustion excludes an unobserved suffix. Consequently R(E(D)) = D for every admitted valid D. Conversely, every accepted image defines precisely one such D; validation and admission failure produce no new published document.

For a finite corpus C of uniquely addressed documents, reconstruction uses the existing replacement owner only after validating a complete previously absent document. Its field counters add each m_f.length and one field-document membership; the document counter adds one per nonempty field mapping. Induction over imported document identities yields exactly C's postings, reverse memberships, integer field lengths and counts. Corpus totals do not depend on import order, since checked nonnegative integer addition is associative wherever the complete valid total fits; overflowing inputs are rejected before that document is published. The existing legacy position projection, exact occurrence frequency, graph/phrase observations and BM25 inputs are therefore unchanged. Query compositions consume the same carriers and statistics, preserving their existing laws without adding a new algebraic operator or numeric approximation.

Under the lazy capture owner's committed-cut and source-adapter premises, the frozen source supplied to E is the original source at that cut. Substitution into R(E(D)) = D preserves that cut after subsequent source writes and source closure. This establishes the document codec and retained reconstruction only; it does not prove joint Engine capture or completeness of unimplemented resource images. Independent byte fixtures exercise raw UTF-16 keys, equal graph edges and historical metadata; actual memory captures exercise synonym overlaps, original Unicode offsets, empty fields and corpus statistics. Malformed/truncated units, deferred invalid analyzers, exact retained capacities, cancellation and small allowances exercise the publication and resource premises. A 32,768-occurrence export requires no heap scratch and bounds each output call to 4 KiB.

## Lazy memory source capture

Common Storage's `MemoryCaptureRegistry` registers a process-local cut without enumerating its sources. `MemoryCaptureCell<T>` owns a source's read/write admission and uses `MemoryCaptureSource::freeze` to retain an independent immutable value. The first read through a cut freezes an unchanged source; the first later write freezes it before returning any mutable guard. Later reads reuse that same retained value. Document and text adapters call their existing controlled snapshot interfaces, preserving evaluated tuples, postings, occurrence metadata, analyzer bindings and original resource ownership without rerunning analysis. Other owners require their own adapters. This primitive does not establish the actual Engine's committed catalog/data/resource boundary or complete its image codecs.

The registry separates capture admission from its live registration index. A write guard retains shared admission through its last mutation; capture registration takes exclusive admission and checks cancellation while waiting. Mapped guards retain the same admission. Nested cell guards use recursive shared admission so a waiting capture cannot deadlock an already admitted operation. An enclosing transaction owner must register cuts at committed boundaries and exclude registration during its multi-cell publication or rollback. Separate nonoverlapping cell guards alone do not make a transaction atomic. Cells created after a cut are outside that cut, and a cell rejects a capture from another registry even if their local numeric identities match.

Define the eligible cells of a cut q as those created before q, and let v(x, q) be cell x's value at q's registration. Let F_x be its source-owned freeze operation and A_q the cut's initially empty map of frozen values. Assume all logical source mutations pass through the cell's write admission, F_x returns an independent immutable owner preserving the source's existing observations, and registration occurs at the required committed boundary. For an eligible x, the first event after q that could change or observe it is either a captured read or an admitted mutation. If it is a read, no preceding mutation has changed v(x, q), so the read installs F_x(v(x, q)). If it is a mutation, write admission installs the same frozen value before exposing mutable state. These are the only insertion paths. Both preserve an existing entry, hence induction over later reads and writes gives A_q[x] = F_x(v(x, q)) for every admitted captured observation.

Registration's exclusive admission orders q after every already live write guard and before every subsequently admitted guard. If a reader observes no archived value immediately before a writer preserves it, the reader checks the archive again after a failed live-source lock attempt. It can therefore select the newly archived value while that writer still owns its mutable guard; it never has to substitute the new live value or wait for a writer that needs the retained read to finish. The archive mutex serializes competing first reads and writer preservation, so one cut installs at most one frozen value for each cell identity. Capture identity and cell-birth admission prevent a later cell from being mistaken for a value that existed at q.

For every existing observation O supported by the frozen owner, the source contract gives O(F_x(v)) = O(v). Substitution in the invariant above yields O(A_q[x]) = O(v(x, q)). Compositions over several selected cells receive their original inputs at q when the enclosing committed-boundary assumption holds. Thus source capture adds no new query operator or numeric approximation and preserves the laws and observations already proved by its document, text and subsequent owner adapters. Neither this result nor the scalar and actual-storage fixtures proves that all Engine state is registered; that remains a distinct integration obligation.

A cut transitions only from active to failed or to destruction. Cancellation or a failed archive/node/source reservation makes it failed, releases its archived owners and removes its live registration before source write admission continues. Every later capture check/read reports the first failure, including after cancellation-token reset; no path repopulates a failed archive. Failure changes no source value and consumes no ordinary mutation, so the source retains its existing success, error and rollback semantics. An archive job must observe this terminal cut state through its source adapter before it can certify completion. Independently retained frozen values remain immutable and keep their original leases; their existence cannot reactivate a failed cut.

Registration admits its fixed capture object and one exact-layout `OwnedMap` node under the invoking allowance before either escapes. A first source observation admits its archive node and complete frozen wrapper before calling the source's controlled freeze. Source payload and generation retention belong to that freeze's original allowance, while allocator bookkeeping and diagnostics retain their existing contracts. Last-handle destruction unregisters the cut and releases its archive; an escaped frozen value retains its own wrapper and payload charges until its final owner drops. The registration index holds weak handles, avoiding a retention cycle. Source writes select one live registration at a time without building an uncharged list of active captures, and release the index lock before invoking or destroying a capture owner.

For c live cuts and m values already retained in a selected cut, registration performs one O(log c) index insertion and no source visits. Archive lookup is O(log m). A write considers the active eligible cuts, but invokes each source freeze at most once per cut; its cost includes the source owner's declared capture/detachment cost. This is not a claim of constant-time writes or complete bounded Engine capture. Tests compare one-source and 8,192-source registration allocation/work, exercise independent cuts, mapped and nested guard admission, exact memory exhaustion, cancellation during admission, last-handle destruction during writer preservation, and deterministic read/write interleavings. Actual document and text fixtures retain the original values and term frequencies after replacement and source closure, including original cancellation and final lease retirement.


## Evaluated memory graph images

Graph owns `MemoryGraphStore::write_image` and `read_image` in its [image module](../../crates/uqa-graph/src/memory_store/image.rs). They encode a borrowed immutable memory graph and construct a fresh unpublished graph, respectively. They do not invoke SQL, Cypher, analyzer or host callbacks. Committed Engine capture, surrounding catalog identity and source-retention admission remain the enclosing backup owner's obligations. A completed graph codec call does not activate an Engine or publish a repository root.

The `UQAGRA01` image begins with little-endian u64 next-vertex and next-edge counters. Four counted sections follow, each prefixed with its u64 entry count: global vertices, global edges, named graph memberships and label registries. Vertices contain their u64 identity, a UTF-8 label prefixed with its u64 byte length and one complete Core `UQAVAL01` Map image of evaluated properties. Edges contain u64 identity, source and target, then the same label and properties encodings. A graph contains its sized UTF-8 name and two counted, strictly increasing u64 sets for vertex and edge membership. Both global maps and both name maps are strictly ordered; every membership must reference a global entity of its own kind. Global allocation counters must exceed existing identities, preserving unused reservations and exhaustion. Empty graphs and unattached global entities remain present.

Each label registry contains its original 16-byte allocation identity, little-endian u32 next-label counter and four counted ordered maps/sets: sized UTF-8 label name to u32 identity, sized name to one-byte kind (0 vertex, 1 edge), u32 identity to u64 sequence watermark, and u32 dropped-label identities. Registry names need not name an existing graph: the existing import owner permits metadata before graph creation. Registry values are preserved without migration, including missing historical kinds, aliases created by registry merges, overlapping merged tombstones and unused reservations. Decoding rejects unknown kind tags and duplicate or decreasing keys; it does not reinterpret these retained fields by replaying entity insertion or registry observation.

Endpoint identities are evaluated edge payloads. Existing graph difference and label removal can retain edges whose endpoints are outside that partition or absent globally. The image preserves those existing carriers and their query diagnostics; it does not add an endpoint foreign key. Source validation instead checks exact entity identity, primary membership, reverse membership, label indexing and both adjacency directions. Missing primary entities and inconsistent nonempty derived entries fail before output. Empty derived index buckets are omitted on reconstruction, because all public label, membership and adjacency observations treat an absent bucket as empty.

Common Storage's [image I/O](../../crates/uqa-storage/src/image_io.rs) supplies bounded length/scalar I/O to both graph and text codecs, reusing Core's exact value codec for properties. Metadata I/O uses at most 4 KiB per call; property payloads use Core's at-most-16-KiB windows. Every partial or interrupted attempt checks the original cancellation before another attempt. Encoding borrows graph state without collecting a second entity, membership or property map. Core's numeric-format workspace remains controlled separately. Blocking operating-system I/O retains its existing cancellation boundary.

Import admits the store header, map/set entry payloads and every decoded or copied name/property buffer before construction. Reconstructed adjacency and reverse membership have their own entry/name charges; a shared graph does not imply that these distinct buffers are free. This follows the existing Core payload accounting model for standard B-tree maps: live entries and exposed buffer capacities are charged, while opaque B-tree slack and allocator bookkeeping retain their native-owner boundary. The returned `Budgeted<MemoryGraphStore>` keeps that reservation until the value and lease are transferred together to an activation owner. Admission does not prepay later ordinary mutations. Decode, reconstruction, exact standalone EOF and source-invariant validation all finish before a candidate escapes; any error drops partial state and returns its complete allowance.

### Preservation argument for evaluated graphs

Let the primary carrier be S = (V, E, P, L, n_v, n_e), where V and E are finite identity-to-entity maps with exact evaluated properties, P maps graph names to separate finite vertex/edge identity sets, L is the complete ordered registry mapping and n_v/n_e are the original global allocation counters. Membership identities reference their respective global maps; edge endpoints are payloads rather than additional membership constraints. Let D(S) be the derived reverse membership, vertex/edge label indexes and incoming/outgoing adjacency obtained by inserting each primary membership once with its entity's unchanged label/endpoints. Source validity means its nonempty derived entries equal D(S). Empty buckets are identified with absent buckets for public observations.

Every integer has its fixed-width inverse, every UTF-8 name has a length-delimited byte inverse, and every properties Map has Core's carrier-preserving image inverse. Distinct kind tags encode the existing enum. Induction over each strictly ordered map and set therefore reconstructs exactly V, E, P and L; equality includes floating-point bits, opaque tuple bytes, historical registry fields and unused watermarks. The two fixed counters are recovered unchanged. Exact EOF rules out a valid prefix with an ignored suffix. Thus read(write(S)) = S for every source-valid, representable S under sufficient allowance. This is byte/carrier identity, not merely graph connectivity or equality under a weaker numeric comparator.

For each (graph, vertex) in P, reconstruction inserts that membership once in the corresponding reverse set and that vertex's label set. For each (graph, edge), it inserts the reverse membership, edge label, outgoing source and incoming target entries once. Strict input membership ordering excludes duplicate insertion. These are exactly the defining comprehensions of D(S), so reconstructed nonempty derived state equals source-valid derived state. Consequently graph enumeration, label/degree observations, traversal inputs, evaluated properties and graph-algebra inputs are identical, including loops, parallel edges, shared entities and defined dangling-edge behavior. Union, intersection and difference retain their existing set laws because their two membership carriers are equal before and after reconstruction; this codec introduces no new graph operator, optimizer rewrite or numeric approximation.

Future deterministic allocation and mutation consume the same counters, label registries and primary/derived observations. They therefore produce the same success, identifier, exhaustion or existing diagnostic and the same successor primary state. Induction extends this correspondence to finite compositions of defined existing operations under the same external catalog/runtime conditions. Destruction of the source cannot affect the reconstructed graph, which owns its decoded properties and names. All failures precede candidate return, so a malformed or underfunded prefix never becomes a published graph. Repository integrity, joint committed Engine capture and complete surrounding resource validation remain separate prerequisites for database backup correctness.

Owner tests compare independently assembled bytes and literal graph observations, preserve exact property bits and lazy datums, exercise graph algebra, dropped-label edges, registry merges and later allocation, reject every truncated fixture prefix and corrupted primary/derived state, sweep all insufficient import allowances, and check cancellation and partial-I/O failure. A two-MiB property export uses no admitted dynamic scratch and calls output in at most 16-KiB windows. These finite checks exercise the boundaries above; they do not replace the preservation argument or claim complete Engine backup qualification.


## Evaluated memory vector images

Common Storage owns `VectorIndex::write_image` and `vector_index::image::read_vector_image` for exact memory, IVF, HNSW and memory DiskANN indexes. The writer exports the selected physical owner without constructing a full canonical export map. The reader returns a private `Budgeted<Box<dyn VectorIndex>>` only after complete decoding, owner validation and standalone EOF. Unsupported owners reject this capability before output. The [DiskANN extension](#evaluated-memory-diskann-images) retains sealed physical generations and canonical origins. Catalog bindings, committed source capture and fresh Engine activation require their own integration; these codecs alone do not expose database backup.

The `UQAVEC01` envelope contains a one-byte method (0 exact, 1 IVF, 2 HNSW, 3 memory DiskANN) and little-endian u32 dimensions. Counts and identities are little-endian u64 unless stated otherwise. A vector is its counted sequence of little-endian f32 bit patterns, with finite components and an exact dimension match. Zero dimensions retain the existing exact/IVF/HNSW Rust owners' carrier; DiskANN retains its own dimension validation. All metadata and coordinate I/O uses at most 4 KiB per call, checking cancellation between partial or interrupted attempts. Unknown methods, invalid tags, unordered identities, truncated input and trailing bytes fail. Declared counts are checked for host-size conversion and admitted allocation before construction.

Exact images contain document and total-vector counts, followed by strictly increasing document IDs and nonempty counted tensors. Tensor order and coordinate bits, including signed zero, are retained. The decoder installs validated tensors directly into its private `MemoryVectorState`, using that owner's existing count and footprint maintenance. It does not call normalization, index training or a query. The resulting immutable root has no legacy full-map export cache.

IVF images contain nlist, nprobe, training threshold, a one-byte Untrained/Trained/Stale state, trained-size and deletion counters, counted centroids and counted vectors ordered by (u64 document, u32 ordinal). Each vector retains both raw and normalized coordinates, the exact original f32 norm and a strict optional centroid assignment. The source owner keeps centroid lists in sorted key order; reconstruction derives those identical lists from the canonical assignments. Import does not normalize, reassign or train vectors, including Stale indexes. Future queries retain the existing owner's training transition. Norms may be positive infinity after finite-input arithmetic overflow; they cannot be NaN or negative. Untrained state has no centroid or assignment and zero training/deletion counters; trained and stale states retain their original nonempty centroids and valid assignments.

IVF export acquires its vectors publication lock before the dependent configuration and state locks, checking cancellation while waiting. It validates one coherent state and retains those guards through output. A complete online backup must therefore provide a detached selected IVF owner before repository output, and must keep that owner separate from query paths that can retrain through shared references. `VectorIndex::capture_image_with_control` returns a `VectorImageSnapshot` with only an output method and no access to its private query-capable source. This prevents captured queries from retraining the exported owner; it does not route live shared-reference training or configuration changes through Engine's committed source admission. The generic read-only query adapter alone does not establish that invariant. Engine source registration and transaction admission remain separate obligations; neither the codec nor the lazy capture registry substitutes for them.

HNSW images retain m, construction/search ef, rebuild threshold, seed, optional entry ID, maximum level, next-node ID, deleted count, full-rewrite flag and every node in identity order. A node contains its ID, document, u32 ordinal, level, deletion flag, original raw norm and coordinates, original normalized norm and coordinates, and each layer's counted adjacency in its existing order. The final ordered dirty-node map retains both identities and values. The decoder reconstructs active (document, ordinal) membership from nondeleted nodes and preserves dirty/full-rewrite state for later persistence deltas. It never reruns normalization or graph construction. Structural validation checks identity counters, dimensions, finite coordinates, contiguous active ordinals, layer bounds, unique reciprocal edges, entry/max-level consistency and layer-zero reachability. Normalized-vector norms retain the owner's exact 1.0 representation; original raw norms preserve defined overflow.

HNSW's existing spillable map owner supplies private ordered builders, payload admission and temporary-file lifetime. Export reads spilled records and performs topology-validation workspace under the invoking backup allowance, independently of retained source admission. Ordinary invariant validation without an explicit control retains its original allowance. Import can spill evaluated nodes and vectors when their corpus exceeds memory; it does not substitute another storage backend or claim a bound on temporary-file bytes. Decoded transfer buffers and the builder's own copies coexist under the same allowance until ownership transfers, after which temporary reservations release.

Exact/IVF imports admit concrete headers, exact owned-map nodes or standard B-tree entry payloads, outer tensor/list buffers and all coordinate capacities. Standard B-tree slack and allocator bookkeeping retain their existing native-owner accounting boundary. HNSW maps retain their own controlled resident/spilled representation and the returned wrapper admits its concrete index header. Every failed candidate drops its buffers, map owners and reservations. A successful value and its reservation must transfer together to an activation owner; the initial image reservation does not prepay later ordinary mutations or IVF query-triggered training. Retained-reader output observes both its original cancellation and the invoking workspace control, including original cancellation between output attempts; cancellation does not interrupt a blocking operating-system call.

### Preservation argument for evaluated vectors

The exact carrier is a finite ordered map from document IDs to nonempty ordered tensors of finite f32 coordinates, together with its fixed dimensions. IVF extends the canonical (document, ordinal) map with evaluated raw/normalized coordinates, norms, assignments, ordered centroids, configuration and training counters/state. HNSW extends canonical values with evaluated node identities, normalized values, ordered layered adjacency, tombstones, entry/max-level/allocation metadata and pending persistence state. All claims assume source-valid states, representable counts, successful I/O, sufficient admitted workspace and the same surrounding runtime/catalog semantics. They do not assume that a logical canonical vector map uniquely determines an approximate index.

Fixed-width integer and f32-bit encodings are injective. Length-delimited vectors retain both arity and order; distinct method/state/option tags retain their alternatives. Induction over each strictly ordered identity sequence therefore recovers every explicitly encoded field exactly. For exact indexes, the existing replacement owner derives count and footprint from those tensors, so its restored logical state equals the source. For IVF, define list j as the increasing sequence of keys whose original assignment is j. Existing training and insertion maintain exactly that sequence; ordered reconstruction therefore restores the same list and iteration order without computing a new assignment. For HNSW, active membership is exactly the injective (document, ordinal) projection of nondeleted nodes, so reconstructing that map preserves the existing identity relation. Both remaining derived structures are thus uniquely determined by their retained primary state.

Consequently decode(encode(S)) equals S in every operation-observable field, modulo allocation layout, empty caches and resident versus spill representation. Exact and threshold scans consume the same tensors in the same order. IVF candidate selection consumes the same centroids, assignments, normalized values and probe parameter; its existing stale-training transition starts from identical inputs. HNSW traversal consumes the same entry, adjacency order, normalized values and search parameters. Final scoring uses the same raw values and norms in the same numeric order. On the same floating-point execution model this preserves result support, score bits, tie decisions and diagnostics, including the owner's defined overflow behavior; it adds no approximation and does not assert associative floating-point arithmetic or a cross-platform bitwise floating-point guarantee.

For subsequent deterministic operations, identical input state and configuration give the same successor state: exact replacement changes the same ordered tensor; IVF insertion/deletion/training consumes the same counters, lists and numerical input; HNSW allocation and graph changes consume the same next ID, seed, topology and tombstones. Dirty maps and full-rewrite flags give identical persistence deltas. Induction extends the correspondence to finite compositions of defined operations under equivalent runtime and resource conditions. Existing query operators and their algebraic laws are unchanged because every supplied carrier and observation is unchanged; no optimizer rewrite or new ranking law is introduced.

Candidate privacy separates parsing from publication. A prefix, invalid reference, failed I/O or failed allowance cannot escape as an index, because return follows complete validation and EOF. Source export mutates no selected physical state. These facts preserve failure isolation but do not prove a joint Engine cut, repository authenticity or completeness of surrounding catalog/resources. Those remain prerequisites for complete backup correctness. Independent wire fixtures, exact-score comparisons, stale-state transitions, future deltas, corruption/truncation tests, source destruction and spill/allowance tests exercise these obligations separately from this argument.

After the envelope, the image contains the physical generation's 16-byte database identity and u64 table, index and generation IDs, followed by a counted existing `DiskANNManifest` encoding. Memory table/index IDs are both 1. The manifest retains its existing parameters, complete build provenance, origin summary and artifact digests. Five u64 values retain resident, cache, in-flight page, query-record and construction-record byte ceilings in that order. Neither path performs a build or creates build files during import.

The physical section contains a u64 record count and strictly ordered records. Input admits record lengths against the construction ceiling before allocating, checks page count/order against the manifest, and passes every physical artifact through the existing complete memory-source sealer. Canonical decoding uses the controlled persistent ordered-map owner directly without invoking mutation or allocating replacement revisions.

Validation recomputes populations, checks the revision against current origins and requires every change to name its current canonical version. A merge walk over the sealed physical origin stream and current canonical documents requires every base document to remain represented. A changed origin must appear in the change map, an unchanged origin must not, and each document absent from the base must appear as an uncovered change. Thus a self-consistent reduced population cannot hide a deleted change entry. Complete physical verification and prepared-query validation precede standalone EOF and return of the private candidate. This validates owner structure and coverage; enclosing repository authentication is still responsible for detecting an externally rewritten, otherwise valid payload.

The physical generation, old canonical origins and selected revision retain their exact identities. The mutable revision allocator is intentionally fresh: restored writers use a new nonzero incarnation and checked monotone counter, so divergent source and restored mutations cannot reuse one origin identity under the existing unique-incarnation assumption. A later explicit rebuild likewise uses the new lineage while retained older readers keep their original generation. These internal identities are separate from SQL sequence watermarks, which remain part of complete Engine capture and restore. Allocator exhaustion retains its normal error; fresh restoration does not reproduce the source writer's remaining counter capacity.

Original source, capture and invoking cancellation remain independently effective. Source records retain their original allowance; capture owns its fixed wrapper; output buffers and decoded candidate state use the invoking allowance. Metadata, vector and page I/O checks cancellation between at-most-4-KiB attempts. The source and restored owners keep their existing native allocator/reference-count bookkeeping boundaries. Physical sealing, canonical validation and prepared query opening may fail for invalid input or insufficient memory; all temporary and candidate reservations then drop without publishing an index. Cache contents and runtime cache statistics are not archive state. Engine still needs joint catalog/data/resource selection, live mutation admission and atomic activation before these owner images constitute a database backup.
