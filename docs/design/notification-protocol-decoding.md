# Bounded notification protocol decoding

The [notification/SSE design](sql-notifications-and-sse.md) defines the wire contract. This document derives preservation and bounded incremental decoding for the implementation in [uqa-client](../../crates/uqa-client/src/notifications.rs). Core retains notification values and its existing borrowed JSON grammar; Client owns request encoding, SSE framing and response admission. No Engine, provider, runtime task or HTTP connection is constructed by this codec.

## Request and response admission

`SubscriptionRequest` owns an exact nonempty channel set. Names are nonempty UTF-8, at most 63 bytes and contain no NUL. The caller supplies a positive channel-count limit. Construction counts escaped JSON bytes before copying names; parsing checks the raw 65,536-byte body limit, UTF-8 and depth-two JSON grammar before constructing fields. Both paths reject duplicates without truncation, case folding or normalization. Sorting names preserves set membership and bounds subsequent membership lookup. A nonempty resume header fails even if it contains only whitespace.

The decoder receives an immutable shared request, the already validated response-header request ID, and explicit runtime/local timer limits. It admits exactly one ready envelope before notification or terminal envelopes. Every envelope has a closed field schema; duplicate keys are rejected after JSON key unescaping. A flat event cannot substitute a nested value for a scalar, and structural depth three fails before recursive materialization. Request IDs equal the original header, UUIDv4 epochs are canonical and remain equal after readiness, and channel membership uses the original exact set.

Notification sequences are positive canonical decimal strings parsed directly as unsigned 64-bit integers. The first is one; each subsequent value must equal the prior value plus one under checked arithmetic. The signed 32-bit process identifier and opaque payload are preserved exactly. The payload limit applies to its decoded UTF-8 bytes. Terminal error codes have the specified bounded ASCII syntax; an unknown code or a remote retryable Boolean does not by itself authorize a retry. The transport owns retry policy and SDK gap/reconnection observations.

The positive duration strings are also parsed without floating-point conversion. Readiness requires supported timer ranges, a compatible optional local idle ceiling, and checked $I>3H+M$. Caller-supplied timer limits describe a receiving runtime's policy; the codec neither measures the margin nor qualifies server/proxy clocks and deadlines.

## Incremental framing

Framing follows the [WHATWG event-stream grammar](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream): one optional initial UTF-8 BOM, CRLF/CR/LF line endings, the first colon, at most one following space, the last event field, and data lines joined by LF. UQA version one accepts only event/data fields and comments, requires valid UTF-8 everywhere, and rejects unsupported fields such as id and retry. Empty/comment-only blocks produce internal heartbeat observations without consuming a notification sequence.

Each decode call consumes a prefix of the caller's slice and returns at most one observation. The caller retains the unconsumed suffix. An unfinished line or block is retained in a single bounded buffer; the implementation never copies an entire HTTP chunk or constructs a queue proportional to its event count. A complete event counts all its raw field bytes and line delimiters before JSON unescaping. The optional initial BOM has separate fixed three-byte prefix state.

A CR normally completes its line immediately. Its optional following LF belongs to the same line, including when it arrives in the next chunk. If a final blank-line CR leaves the block below the byte limit, the block can be admitted immediately: adding its possible LF is still legal. If that CR occupies exactly byte 65,536, admission waits for the next byte or EOF. An LF then fails before the event becomes visible; another byte or EOF confirms a legal bare CR. A non-LF lookahead remains unconsumed for the next block. This boundary prevents both premature over-limit admission and unnecessary delays for ordinary CR-delimited heartbeats.

EOF never dispatches an unterminated event. It may confirm the exact-limit bare-CR block, which the caller receives before asking for the final EOF result. A stream without a complete terminal envelope reports unexpected end. Definite invalid UTF-8 at EOF reports corruption; a missing multibyte suffix reports incomplete transport input. The first failure latches, clears the logical frame buffer and prevents recovery by feeding later valid frames to the same epoch.

## Preservation proof

Let $C$ be the requested finite exact channel set and let $H=(n_1,\ldots,n_k)$, with $k\leq 2^{64}-1$, be the committed notification history selected by a correctly established server registration boundary. Each $n_i$ is the original triple $(p_i,c_i,v_i)$ of process identifier, channel and opaque payload, satisfying the declared integer, membership and payload bounds. This codec assumes that the server has selected that history; it does not establish registration, authorization or commit ordering. Let $E$ be one fixed response epoch and request identity, and let $W_{E,C}(H)$ be any valid version-one wire encoding of ready, those notifications in order, and a terminal envelope, with optional comment blocks and valid line endings.

Define $D$ as repeated prefix decoding followed by EOF, and define $\pi$ to erase ready, heartbeat and terminal observations and remove only epoch/sequence metadata from notification observations. JSON string decoding preserves the represented Unicode string, integer fields are checked in their exact integer domains, and no payload interpretation occurs. Therefore admission of notification $i$ returns precisely $(E,i,n_i)$ if and only if its identities, channel and next sequence satisfy the declared preconditions. By induction on $i$, the first accepted notification is $(E,1,n_1)$ and the only possible successor of $(E,i,n_i)$ is $(E,i+1,n_{i+1})$. No state update occurs before full validation. Thus

$$
\pi(D(W_{E,C}(H)))=H.
$$

For a malformed or interrupted stream, the notification projection is only an admitted prefix before the first visible error; the decoder never silently skips a frame, relabels a channel, wraps a sequence, or manufactures a replacement epoch. A value of $2^{64}-1$ is exactly representable as the last notification sequence; checked successor failure prevents another notification in that epoch. A terminal envelope remains admissible. Sorting the request preserves $C$ because bytewise equality is exactly the duplicate/membership relation; request order adds no history-order semantics.

For chunking, model framing as a deterministic state transition $\delta$ over one input byte, with state consisting of the bounded raw block, line start, possible LF, initial BOM prefix, deferred exact-limit CR, and envelope state. Every byte transition depends only on that state and the next byte, never the length or end of a non-EOF chunk. A completed block yields an observation and leaves the remainder unconsumed. The deferred-CR transition can yield an observation without consuming its non-LF lookahead, after which the next call processes that same byte. For any finite partition $b=b_1\cdots b_m$, induction over consumed bytes and these progress-producing emissions gives the same observations, final state and failure as feeding $b$ whole. EOF is a separate final symbol and is applied once all chunks are consumed. Hence partitioning preserves history and errors, including UTF-8, CRLF, JSON escapes and exact-limit CR boundaries.

The notification histories form the free monoid of finite ordered triples under concatenation, with the empty history as identity. On legal continuations within one epoch, decoding extends the existing prefix in precisely that order; grouping byte chunks changes neither concatenation nor its identity or associativity. This is an observation-preservation statement, not a claim that different epochs concatenate as continuous delivery. It introduces no document-support, payload-merge, score, ranked-result or value-relation operator and no optimizer rewrite. Existing UQA operations and their applicable laws remain unchanged because the codec neither invokes them nor changes any projected value or database state. No numeric approximation is introduced.

## Resource bound and qualification boundary

Let $F=65{,}536$ and let $c$ be the admitted channel count. Raw frame length never exceeds $F$: the only byte append checks that length first, including an LF following a nonterminal CR. At a terminal CR below the limit the possible skipped LF can increase only the already admitted prior length by one, still at most $F$; an exact-limit terminal CR defers and rejects that LF. Clearing the block releases its logical contents between observations. The framer requests a fixed $F$-byte buffer once. There is no cumulative-stream counter that rejects a sequence of individually legal frames.

Joining multiple data fields removes field prefixes and line delimiters while adding at most one LF per boundary, so joined data length is no greater than the original block length. The optional joining buffer requests at most $F$ bytes. Core's iterative grammar checks depth before adding a container. Its stack has depth at most two. Subsequent closed-schema decoding has a fixed number of scalar fields, total scalar content bounded by the admitted input and no recursively materialized arbitrary JSON tree. The request's vector requests bounded growth up to the caller's count ceiling and the intrinsic $F/4$ channel ceiling; channel strings have the stated individual limit. Encoded requests use a bounded writer that checks each append, and count-only validation retains no encoded body.

These bounds account for requested parser storage, bounded scalar materialization and $O(c)$ immutable channel metadata. They do not equal process RSS: serde scratch allocation, allocator rounding, caller-owned HTTP chunks and returned events, runtime/TLS buffers, connection output, Engine/provider state and all active subscriptions belong in the complete resource profile. The decoder owns no unbounded event queue; callers must preserve that property. This proof does not supply deployment capacity defaults or a measured scheduling margin.

## Verification obligations

The [hand-authored shared fixture](../../crates/uqa-client/tests/fixtures/notifications-v1.md) supplies exact wire values independently of any encoder. Owner tests check every byte split and one-byte input for LF/CRLF/CR with and without BOM, multiline data, closed schemas and duplicate escaped keys, UTF-8 failures, request/frame/unfinished/comment limits, exact-limit CR lookahead, long cumulative streams, full-width integer boundaries, timer arithmetic, opacity and diagnostic redaction. These exercise the proof boundaries; finite runs do not replace the argument. Actual HTTP connections, server registration, cancellation, clocks, authorization and Python/Node/browser artifacts remain distinct required units in the [fixed ledger](../plans/0015-sql-notifications-and-sse.md).
