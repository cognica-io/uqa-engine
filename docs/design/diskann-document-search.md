# DiskANN retained document search

Storage's `DiskANNQuery` combines a selected physical generation with its fixed canonical tensors and current change journal. Both native SQLite and Key/Value retained sources expose `query`, which performs the actual catalog/head selection before preparing the common owner. The Key/Value path also serves redb. Public `VectorIndex` registration, SQL routing, logical SSI observations and final runtime acceptance remain in the [implementation plan](../plans/0014-diskann-vector-index.md).

## Retained input and preparation

`DiskANNQueryRead` extends the canonical read contract with the existing ordered current-change cursor. It has no default empty implementation: a source without a journal cannot silently claim that every visible vector belongs to the base. The lifecycle owner must establish complete initial coverage and maintain atomic canonical/origin/change writes before exposing this query path. Unstamped legacy input still requires lifecycle adoption; the search algorithm does not infer coverage from absent journal records.

The provider adapter first selects the physical source through the [retained generation contract](diskann-query-generations.md). Preparation validates dimensions and all effective parameters, opens resident PQ data and verifies the complete ordered origin artifact on that same immutable source. The reader and origin manifest must agree. Origin verification streams all origin batches once at preparation, with one bounded batch at a time; it is not a constant-time open. The prepared owner reuses that verification and resident PQ data across searches. Graph pages stay lazy, and each search keeps the same canonical visibility. No new persistent format, crate dependency or Cargo feature is introduced.

Original canonical, preparation and invoking controls remain binding. Scoring borrows the prepared owner's canonical adapter so cancellation is checked inside long vector reductions as well as between documents. Preparation failure, missing publication resources, invalid records or query quota exhaustion propagate as errors; none chooses a replacement exact index.

## Candidate support and scores

Normal finite navigable queries exhaust the existing deterministic PQ beam traversal. Each physical document is looked up in the generation's complete origins and compared with the canonical version. Every encountered physical version and ordinal must belong to that original tensor, including stale routing nodes. A changed or absent canonical version contributes no old score. A matching version is scored from all of its current tensor ordinals through the [canonical scorer](diskann-canonical-scoring.md), and its cardinality must still match its immutable origin.

The numeric side stream is read completely in document/ordinal order. It includes zero, underflowed and nonfinite-derived norms under the existing arithmetic contract. A document containing both ordinary and numeric-side vectors receives its complete tensor score and one heap entry. Zero scores can therefore outrank negative graph scores. Side records, ordering and the complete side digest retain the existing reader checks.

The current change cursor is streamed in document order. Its version must match the current canonical origin. A change whose exact version already belongs to the selected generation is skipped even if physical pruning has not removed its journal record. Other current replacements contribute their complete tensor score; an explicit empty replacement contributes none and masks all old ordinals. Journal pruning cannot change the selected candidate pool merely by removing covered records.

Let $G$ be the live document support of visited graph nodes, $S$ the live numeric-side document support and $C$ the vector-bearing current changes outside the selected generation. The query applies the existing raw-score order to $G \cup S \cup C$. Each admitted document has one fixed canonical score $s_q(d)$, independent of which source or ordinal discovered it. A bounded heap and its current identity map retain at most $k$ distinct documents. Reencountering a selected document cannot consume another result slot; reencountering a previously rejected or evicted document cannot displace a better retained score because the canonical source and total ordering are fixed.

After approximate exhaustion and the exact side/change scans, a short document pool continues through the traversal's unexpanded physical IDs. Completion retains earlier work and stops only when the distinct-document quota is met or the entire base is exhausted. Under complete base/change coverage, every live vector-bearing document is either a current base document or an uncovered change; consequently full exhaustion returns fewer than $k$ only when the visible corpus has fewer than $k$ eligible documents. This argument establishes result cardinality and score correctness, not exact nearest-neighbor membership or a recall guarantee.

Numeric-edge queries explicitly select the complete canonical top-k path and report `ExactVectorReason`. Threshold queries always stream the complete canonical corpus with the existing finite-threshold validation and ordinary comparison, independently of ANN candidate membership. Zero-k requests validate query shape, values and retained controls without traversing pages or enumerating canonical documents. Execution must still arrange its own zero-k and logical-read boundaries before preparing runtime index adapters.

## Memory and result ownership

The graph document cache holds one checked origin and optional complete tensor score per encountered physical document, under the invoking allowance. It prevents a many-ordinal tensor from being rescored once per graph node. Its growth is tied to physical traversal, whose separate expanded-node set remains charged. A large graph cannot silently exceed that allowance.

The side stream retains only the current document's additional score, reusing graph entries when present. The change stream retains no corpus directory. The selected heap and its identity map are bounded by actual selected documents, at most $k$, and grow incrementally rather than reserving an arbitrarily large requested k. Graph cache entries are released before final posting construction. Output uses the existing controlled posting helper and its caller-owned result boundary.

Postings remain sorted by document ID, and raw `f32` cosine widens to the existing `f64` payload without a probability transform. `DiskANNQueryResult` reports the declared exact reason and logical traversal counts; it does not relabel PQ estimates as scores or logical expansions as measured SSD I/O. Existing Operators/Scoring calibration, relational filtering and hybrid fusion remain their owners' responsibilities.

## Verification boundary

Hand-checkable axis and `(3,4)` fixtures cover stale tensor replacement, empty deletion, new document changes, complete tensor maxima, score ties, zero scores above negative scores, repeated graph/side identities and deterministic completion after tensor collapse. Covered-journal removal preserves the result pool. An empty base with 4,096 changed documents exercises top-three selection under a 4,096-byte invoking allowance without canonical corpus enumeration. These are resource and output checks, not timing or process-RSS measurements.

Numeric-edge and threshold cases compare the established exact index, while ordinary ANN tests verify no full canonical scan occurs. Faults reject missing page completions, provider quota errors, cancellation and an inconsistent tensor shape with the same version, releasing partial query workspace. Existing real native SQLite, SQLite Key/Value and redb selection schedules now execute document search on retained committed/private views, after refresh/undo, after session closure and after cold reopen. Final source-scoped results and automatic review evidence are recorded in the plan and PR.
