## Capture and membership

Storage's `DiskANNBuildCapture<S>` owns both the retained `DiskANNCanonicalRead` source and the encrypted `DiskANNBuildInput` produced from it. The concrete source keeps the original committed/private snapshot, canonical scope, leases and read controls. Construction walks the existing ordered canonical document cursor once. The same tensor callbacks supply graph/side input and an encrypted fixed-width origin run; explicit empty tensors append an origin without emitting a vector. Returned origins must match every emitted ordinal, and suppressed callback failures poison the capture. The operation does not open a fresh source or collect a corpus-sized origin directory. All three temporary streams share the original encrypted-file allowance.

After construction, `finish` checks the manifest's complete capture fingerprint and separate navigation/side counts against that input. A mismatch fails and releases the capture. When an origin artifact is present, its document count and digest must also match the original capture, distinguishing equal zero-vector fingerprints. Successful completion releases encrypted temporary input and returns `DiskANNCanonicalCoverage<S>`, keeping the selected source and original build control. Physical artifact sealing is a separate prerequisite: matching metadata alone does not certify stored graph pages or publish a generation.

For a document $d$ and original vector version $v$, membership is $C_S(d,v) = [\operatorname{origin}_S(d)=v]$ on the retained source $S$. The source validates the complete canonical tensor before returning its origin. An explicit empty replacement has an origin and can be covered; absence cannot. An earlier writer allocation, a later live read or a missing journal entry never establishes membership. The token has no public constructor from a manifest or digest.

This distinction matters even without hash collisions: a source with only empty tensors and an absent source emit the same zero-vector capture fingerprint, while selecting different origins. The fingerprint binds emitted build input; the retained source answers membership. A writer allocated before capture but committed afterward remains outside the earlier source. A privately captured replacement remains the same selected version after savepoint rollback. Source, build and invoking cancellation remain active during membership checks, including absent documents.

## Durable origin artifacts

`DiskANNBuildCapture::write_generation` writes graph/side output and the complete captured origin stream to the same unpublished sink. Manifest envelope 3 appends the document count and ordered origin digest to revision-2 construction provenance; envelopes 1 and 2 retain their previous bytes and do not acquire origin coverage implicitly. An origin entry records the document ID, original writer history/allocation, mutation revision, dimensions and complete tensor cardinality. Fixed batches contain up to 64 documents and use dense document positions, preserving sparse IDs and explicit empty replacements. The [generation format](diskann-generation-format.md#complete-document-origins) specifies their bytes.

Physical sealing validates contiguous complete batches, global document order, complete tensor cardinality against graph plus numeric-side counts, every envelope checksum and the final origin digest. Unexpected, missing, extra, damaged and mismatched streams fail without producing a seal. `DiskANNCanonicalCoverage::origins` retains the independently captured expected descriptor alongside its actual source, so publication can compare the sealed artifact to that source even when no vectors were emitted. A persisted descriptor or physical seal alone grants no catalog or publication authority.

`DiskANNOriginReader::open` verifies the complete immutable origin stream using one charged batch at a time before returning a lookup handle. It needs neither resident PQ codes nor the original canonical snapshot. Point lookup binary-searches fixed-capacity batches without a resident document directory; `Some` with count zero means an explicit empty tensor, while `None` means a document absent from the verified stream. Missing records, corrupt envelopes and incomplete stream digests remain errors. Opening has linear verification work; each point lookup reads logarithmically many batches and keeps one bounded encoded batch plus fixed metadata. Original build controls govern capture/publication evidence, while reopened physical reads use their own invoking controls and retained provider leases.

## Provider and publication ownership

The generic capture preserves its concrete source type. A subsequent provider publication/retirement operation must validate that source's actual table/field and stable owner against the destination index, require a physically sealed matching generation, and validate the expected current definition/generation. `source()` exists for those owner checks; caller-provided generation numbers or equal vector contents do not establish provider binding. SQLite and Key/Value adapters retain their existing source layouts and dependency direction; Engine does not compute coverage.

Key/Value canonical sources can now use `retain_for_index` to capture the actual table and index records on the same view as vectors, origins and changes. The catalog owner checks the canonical table name, nonzero object/storage identities, field dimensions, single indexed field, access method and complete persisted DiskANN parameters. SQL expression definitions remain opaque to Storage. The source retains each exact catalog record's database/history identity, committed revision and private undo-branch identity, rather than comparing names or JSON contents. Identical drop/recreate operations therefore invalidate a capture, and unrelated commits leave it valid. `record_revision` is an explicit read capability; readers without exact record provenance fail instead of substituting a whole-view cache revision.

`require_current_index` rechecks those captured identities on the publication command's reader and adds the committed record requirements to that same command's batch. The caller must supply the reader and batch from one evaluated mutation callback. A concurrent definition change between evaluation and commit then rejects the whole batch; ordinary canonical writes remain independent. Private definitions are accepted only on the same selected undo branch, and an unbound source cannot acquire authority from a later live catalog read. Original source/query controls and charged catalog decoding remain active. This gate does not select a generation, validate a manifest's physical table/index handles, publish a head, retire changes, or guard later private catalog commands in the same transaction; the complete publication/lifecycle owner must coordinate those remaining operations. Native SQLite uses the same guard contract through the borrowed `RecordRead` adapter over its existing native snapshot; it does not open a second session or end the caller's transaction.

Native `SQLiteDiskANNCanonical::retain_for_index` captures three physical records: the table-name owner, the object/generation-owned table definition and the database-owned index definition. Their fixed native view also selects canonical vectors, origins and changes. The provider checks the real row identities and backing relation, while the common Storage catalog validator checks the field, dimensions and persisted parameters. The table-name record remains part of the guard even when an older object-owned definition survives a name change. Record provenance uses the actual transaction-history database identity; the native data namespace stays separate because backup restoration preserves physical addressing while changing history. Bounded row visits reject oversized catalog values before decoding, and retained keys and decoded fields use the invoking allowance.

A bound source can expose `index_scope` by passing its captured SQL definition to the owning `DiskANNIndexResolver`. Execution supplies the existing SQL decoder and immutable catalog-identity validator. Storage neither interprets the expression declaration nor accepts a later live definition. The resulting scope retains complete table/storage/index incarnations and the original controls; the [physical repository](diskann-key-value-generations.md#ownership-and-identities) validates its actual history before allocating durable 64-bit handles. The scope does not replace `require_current_index`, physically sealed manifest validation, expected-head selection or source coverage at publication.

The authorized publication transaction must atomically install the generation and its complete logical coverage. Physical deletion of covered immutable change keys may then proceed in bounded, resumable batches using that durable authority; publication must not retain the original canonical snapshot indefinitely or delete an unbounded journal in one mutation. Every current change outside the selected source, including a late commit or later private revision, must remain available on its selected view. The pruning contract separately establishes when a committed version is obsolete and preserves older snapshots and original receipt recovery. Atomic head selection, logical retirement and bounded deletion are not implemented by the artifact reader or membership token.

The token is process-owned evidence. Losing its retained source before publication invalidates the unfinished authority; a manifest hash cannot reconstruct it. Existing staged-generation recovery must preserve the previously published index and discard or otherwise resolve the unpublished candidate under its ownership rules. Normal open must eventually validate the published generation and outstanding journal together; it must not rebuild an index as a substitute for missing publication evidence.

## Verification

The [generation publication adapter](diskann-generation-publication.md) compares the exact completed manifest and full origin summary against an actually sealed generation, guards the original catalog records, and selects a head using the captured source's expected head. It rejects changed private input and carries independently sealed metadata into the caller's transaction without refreshing the SQL data snapshot. Bounded journal pruning uses the actual published artifact and current committed canonical view. Final private-DDL scheduling and retained query routing remain unfinished.

Storage tests distinguish equal zero-vector fingerprints with different empty-origin membership, reject foreign capture metadata and changed navigation/side classification, and exercise source/build/query cancellation and temporary-file release. Actual SQLite Key/Value and redb conformance constructs and physically seals generations from real canonical origins, then checks late commits, replacements, private undo and empty tensors. Native SQLite tests keep both committed and undone sources after closing their original plain/encrypted/compressed connections. Verification uses bounded owned workspace, with no timing or RSS acceptance claim.

Catalog-binding acceptance uses actual native SQLite and SQLite Key/Value files in plain, encrypted, compressed and compressed/encrypted modes plus redb. Independent databases carry equal fixture catalog bytes and IDs but cannot share a binding. Same-content index recreation, table recreation, storage-generation replacement, private undo, wrong fields/methods/dimensions, incomplete parameters, cancellation and quota failures reject the source. Evaluated guard batches exercise real commit conflicts, absence of partial writes after failure and a successful concurrent canonical write. Native bindings survive connection closure and distinguish data/history identities after an actual format upgrade. Oversized native catalog rows fail before full materialization. These checks establish catalog binding, not complete generation publication.

Durable-artifact tests independently pack exact origin bytes, reject rechecksummed shape/version errors and missing/repeated/corrupt completions, and distinguish empty tensors from an absent corpus. An origin artifact larger than capture/query workspace is built and opened without increasing those bounds. Actual retained SQLite Key/Value and redb sources feed complete sealed origin artifacts; native SQLite covers private undo, subsequent live changes and cold reopen in all four file modes. Shared persistent build/reopen acceptance also checks multi-batch sparse origin lookup through plain native SQLite, plain SQLite Key/Value and redb. These checks do not claim journal retirement or public SQL support.
