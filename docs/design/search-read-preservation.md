# Preservation of bounded search reads and vector writes

These changes alter physical reads, vector mutation retention and private-write restaging without introducing a new query operator. Storage owns vector representation, provider equality seeks and transaction-private roots; Execution owns candidate restriction and posting composition; Engine binds these capabilities to the selected table, catalog and serializable participant.

## HNSW representation

Let an original node with identity `i` contain topology `T(i)`, canonical vector and norm `R(i)`, and normalized vector `N(i)`. The separated representation stores the same three values in maps with the same identity domain. Ingestion validates vector dimensions and finite coordinates before publication. Topology validation requires equal map cardinalities, each topology key equal to its node identity, membership in both vector maps, and the original edge, level, active-identity and ordinal invariants. Thus every accepted topology node has exactly one canonical and one normalized vector; extra vector identities cannot exist because cardinalities agree.

Map encoding preserves each coordinate's floating-point bits. A distance step receives the same `N(i)` and query as before; final scoring receives the same `R(i)`. By induction on traversal steps, the same entry points, neighbor order, distances and identity tie breaks produce the same candidate queues and visited identities. The unchanged tensor fold and ranking therefore produce identical decorated postings. An adjacency mutation changes only `T(i)`; canonical persistence still emits the original node snapshot shape with `R(i)`. Prepared mutations publish the complete candidate or leave the prior immutable roots intact. The component allowances partition the former node allowance, and all three maps retain the existing encrypted spill and lease lifecycle. Validation and edge restoration need no vector-page decoding or rewriting.

## Residual filter reads

Let `P1, ..., Pm` be the posting branches of an intersection other than source-less filters, and let `C` be the intersection of their identity supports. Let `D` be the selected relation's live document domain and `Fj = {i ∈ D | predicate_j(value_i)}`. Any surviving document must belong to `C`; hence intersecting all original branches has support `C ∩ F1 ∩ ... ∩ Fn`, unchanged when each filter evaluates only `C ∩ D`. Graph branches may contribute identities outside `D`; those identities have no relational filter posting and must be omitted, including for `IS NULL`. A present row with a null field remains in `D` and retains ordinary SQL null behavior. The relation view remains fixed. This restriction does not move a filter across the operation producing a `Pi`: a KNN branch still selects its original K before intersection.

Support equality alone is insufficient for decorated postings. For every surviving document, the restricted filter emits the same default payload, every non-filter branch emits its original payload, and the implementation folds these outputs in exactly the original branch order. Induction over that fold preserves the complete payload, even when collision merges are not commutative or idempotent. Column validation still occurs for empty candidates; executed branch errors are collected in original branch order. A missing posting anchor, failed anchor or mixed carrier retains ordinary filter execution. Unindexed filters retain their original logical relation-scan observation, so bounding physical reads does not narrow serializable conflicts.

An explicit filter source, ordinary relation enumeration or relational retrieval branch promises document identities and retains the snapshot-consistency error for a missing promised row. This promise follows support algebra: an intersection is contained in every operand, so one promising operand suffices; a union requires all operands to promise relational identities. Support-preserving decorations retain the promise, and sequential composition uses its last output. Graph, synthetic and opaque carriers supply no promise. Consequently an independent filter restricted by intersection support permits absence only when no executed operand promises that those candidates belong to the selected relation. Provider errors and cancellation propagate in both modes; neither is represented as an absent row. Owning Execution tests cover absent versus null rows, exact requested identities, preserved errors, set-operation provenance and strict source consistency. Existing Engine integration tests cover graph edge support extending beyond the driver's relation and a stale same-relation index identity rejected before SQL mutation.

## Durable equality seeks

The supported key domain consists of NULL, booleans, integers, non-NaN floats, strings, bytes and recursively supported rows. Define `E(v)` by the versioned canonical encoding. Integers and booleans use exact integer bytes. A float uses the same bytes only when Core's exact represented-value comparison makes it equal to that integer; otherwise its IEEE bits identify its equality class. This also canonicalizes signed zero. Type tags, component lengths and row arities make the remaining encodings unambiguous. Structural induction on rows then gives `E(a) = E(b)` if and only if `a` and `b` compare equal in the supported Core domain. Unsupported stored values map to SQL NULL, which an indexed existence check detects before any result is returned. SQL null predicates retain their ordinary typed path, since a row's null predicate inspects its fields rather than testing key equality.

Complete support is a separate obligation from key equality. Native bootstrap derives document and per-index population certificates from the physical rows, and marks predecessor dangling postings for the existing sparse repair path. Native document-membership guards establish that each unmarked posting support is a subset of the document support; the posting primary key makes it a set. Equal populations therefore prove equality of those two supports. Guarded native UPSERT/DELETE publication maintains both counters in the same physical transaction, including key movement. They are derived physical state, not new versioned user records; only a selected latest-commit reader may use them. Historical snapshots and unmanaged legacy writers retain the original hydration path. For private changes, metadata-only checks compare document and posting presence for every changed identity on either side; unchanged identities inherit the committed certificate. An incomplete base or private index declines instead of returning false negatives.

For a certified current committed snapshot, let `B(v)` be the physical equality result and `D` the set of privately replaced or deleted identities. The visible result is `(B(v) − D) ∪ {i in D | the selected private row is live and its key equals v}`. The ordered private cursor implements exactly this expression: it masks each private identity before considering its replacement, including tombstones. Unsupported private values decline the capability. The physical read is admitted only for the selected latest commit and unchanged owner mapping; historical snapshots retain their versioned reader. Savepoints and captured command views select the same immutable private cursor as ordinary reads. Engine accepts the capability only for its selected live table and catalog search key, and records the original predicate before exposing even an empty posting list. Cold projections read the selected documents instead of constructing an unrelated full-field accelerator.

The equality projection, population certificates, guards and format marker change in one physical transaction. Commit installs all of them; rollback installs none. The upgrade reads existing physical populations once without rewriting MVCC history or embeddings, and reopen validates the existing projections. Keys, selected IDs and private cursor workspaces retain the original allowance and cancellation. Physical SQLite decoding and caller-owned final posting buffers retain their existing ownership boundaries.

## Spilled vector mutation and reconciliation

Let a visible IVF generation be its canonical vectors, training state, centroids and assignments. Mutation preparation applies the existing ordered vector operation to immutable roots. Key/Value retention uses `IndexView::evaluate_candidate`, and native SQLite uses the same provider-certified staged snapshot and uncontended-commit certificate as native HNSW. A candidate is reused only when its selected physical identity equals the reader's identity, including canonical vectors and all IVF metadata families. Certification is unavailable on unsupported or intervening publication boundaries, so those reads restore the persisted generation. Induction on certified mutations therefore gives exactly the same generation as restoration after each successful write. Failure before staging leaves the old generation; undo and peer changes select a different identity. Independent retained readers continue owning their original immutable roots and allowance.

Ranked IVF posting lists are a pure projection of a validated immutable generation: ordered canonical addresses grouped by their retained centroid assignment. They are constructed only when a ranked read needs them, in the identical address order used by eager construction. Write-only generations and exact/untrained reads do not need that projection. Construction checks the active reader's cancellation and uses its allowance; only a reader sharing the generation's original allowance may retain the result. Failure leaves the optional projection absent. Repeated reads may share the complete projection, and later writes own another generation.

Native private vector identity is the maximum private revision over each selected family, owner and field. Its provider summary records that same maximum on every atomic write and follows the record root through savepoints, failed staging and refresh. The field prefix includes the complete escaped text terminator, so one field cannot invalidate or conceal another. A point lookup therefore replaces a full private-key scan without changing identity equality. Catalog projection still folds these field scopes into the same maximum per table. Unclassified providers retain exact key metadata scanning with one cursor per prefix, rather than restarting spill readers for every page; no payload is needed.

Native IVF previously rewrote every centroid and assignment even when only one document changed. If centroids are unchanged, the assignment function and tie order for all unchanged vectors are identical. Replacing the changed document's assignment range, including deleting obsolete tensor ordinals, and writing the new scalar header therefore produces the same full metadata relation. Training that changes centroids, initial publication and explicit reconstruction retain complete rewriting. Deletion counters and eager retraining still come from Storage's unchanged preparation rules. Controlled IVF clones share immutable roots only within the same allowance; foreign allowances receive their own controlled copy. No canonical values, persistence formats or score calculations change.

For population reconciliation, consider the prepared sequence of unique key replacements `(key, expected revision, kind, optional value)`. Reconciliation validates the same preconditions in the same input order, filters the same discarded previews and applies the same kind transformation. A spilled input is already strictly ordered, so writing the surviving sequence directly to one encrypted run yields the same finite partial map as inserting it into a private tree and repeatedly merging spills. Tombstones remain entries, and every expected revision and value is preserved. Generated population changes then use the same private overlay precedence and precondition checks as before. Final preparation and retained effects are unchanged, so command reads, commit fingerprints, conflict checks and publication observe the same replacements. New roots receive a fresh private revision and own their spill files; failed construction drops only the unpublished root. This removes repeated copying during ordered restaging without changing ordinary spill compaction, encryption, cancellation, savepoint ownership or the original memory ceiling.

Transaction refresh and graph preview construction use the same direct ordered restaging. A new spilled root receives a fresh revision shared by its writes; provider summaries derive from those exact entries, while refresh separately inherits the same retained sources as before. Resident prepared input keeps its original incremental staging and admission path. Every refreshed precondition is still checked before root replacement. The former root remains visible if construction or source inheritance fails.

An immutable spill-map insertion previously appended each ancestor header separately, re-encrypting the partially populated tail block for each header. The new append computes the same leaf and ancestor offsets from the original file length and constructs the identical byte sequence before one vectored write. The parent workspace is charged by its actual bounded path length. Only after the complete append succeeds does the map publish the new root and update its header cache. Failure truncates the unpublished suffix and clears cached appended addresses, preserving retained roots and the authenticated active-slot protocol. This changes block publication work without changing lookup paths, values, physical encoding, compaction or encrypted-file ownership.

An authenticated temporary block header is the fixed concatenation of its nonce, populated length and authentication tag. Reading and writing that concatenation in one physical request preserves the exact byte offsets and authenticated inputs. Ciphertext still reaches the inactive slot before the separate one-byte active selector; failed writes still roll back the logical extent without changing the prior selector. Header batching uses fixed-size stack workspace, leaves encryption, authentication, populated-length checks and key lifetime unchanged, and introduces no retained plaintext or uncharged heap memory. Existing partial-write tests fail at boundaries within every header field, the ciphertext and selector; they continue to require the same prior bytes through independent readers. The deterministic I/O regression bounds each block publication to three physical write requests instead of five.

Authenticated immutable prefixes of each encrypted spill-map block are retained in a small charged read cache. A cache entry records both its block offset and the number of authenticated bytes available at admission; it becomes visible only after that entire prefix has been read successfully. An append at logical length L cannot change any byte below L, so a request covered by a previously admitted prefix returns the same bytes even when the tail has grown. A request reaching beyond that prefix refreshes the entry from the current authenticated extent; bytes outside that extent are never served. Truncation after a failed append clears the cache before addresses can be reused. Thus cached bytes equal the original file read for every retained root, including partially populated tails. Cache allocation remains bounded by the original allowance, and unavailable admission keeps ordinary reads. Membership checks do not decode a value whose presence is already established by its leaf header.

HNSW adjacency changes now publish only the final pruned neighbor list. Pruning depends on the supplied candidate identities and fixed vectors, not on the tentative adjacency entry, so computing the selected list before writing the node yields the same selection and reciprocal removals in the same order. When all distinct non-self neighbors of a validated graph fit the degree bound, diversity selection followed by rejected-candidate filling retains the entire list; sorting identities directly is equivalent and reads no dense vectors. A topology candidate equal to the original node does not write a replacement or mark it dirty. Previously dirty nodes stay dirty; every actually changed node is still emitted. Streamed graph comparisons cover each node, canonical vector, metadata and final search postings against the former two-stage connection order.

Bulk spill-map construction buffers at most one charged logical block while the candidate file is unpublished. Headers and values keep the identical byte sequence and offsets; splitting writes at block boundaries makes each complete block reach authenticated storage once. The last partial block is flushed before the root becomes visible, and any write or final-flush error drops the unpublished candidate while the original map remains retained. Pending HNSW persistence identities form a set: inserting an identity already present cannot change the emitted delta because values are read from the final graph. Avoiding that repeated set write therefore preserves every final node and retained root.

HNSW restoration now uses unpublished builders for its canonical and normalized vector maps. An increasing identity stream first uses the same resident component allowance; at its first failed resident admission, existing entries and each subsequent value are appended to one bulk builder. Strict order gives the same finite identity map, with each surviving value encoded once and each Patricia branch constructed once. If an input identity is not increasing, the builder first completes its private root and resumes ordinary replacement semantics, preserving the public restoration API's unordered-input behavior. Topology and active-identity checks still reject duplicate nodes and live ordinals before vector admission. The graph publishes only after both vector roots, pending edges, counts and all original invariants validate. Cancellation or any failed insertion poisons the unpublished builder, so a caller cannot publish its incomplete prefix after an error.

Vector effect resolution also copies surviving ordered prepared writes directly into a spill run before applying generated changes. It preserves the same position-specific canonical and preview revision checks, kind transformation, discarded rebase previews, generated overlay precedence and retained effects. Therefore it is the same partial-map construction established for population reconciliation above, including expected revisions, tombstones, immutable source roots and command/publication distinctions.

During one HNSW diversity selection, the normalized vector of an already selected identity is immutable. Reusing an exact decoded copy therefore leaves every pairwise distance, strict comparison, short-circuit, rejected-candidate fill and final identity order unchanged. The optional cache is a child of the original allowance, bounded by one sixty-fourth of its ceiling and one quarter of initially available space. Its buffers and values are charged; values that cannot be admitted keep ordinary reads. Resident vectors remain borrowed, no cache survives the selection, and cancellation is checked before the same candidate comparisons. This removes repeated decoding without changing the graph algorithm or enlarging its memory budget.

Neighbor scoring carries that same bounded vector cache into diversity selection. The candidate identities and vectors cannot change between these two read-only stages; sorting and duplicate removal still operate on the same scored candidates. Reusing the already decoded value therefore preserves each diversity comparison while avoiding a second spill read. Partially admitted candidate sets and resident values retain their ordinary reads without exceeding the original cache ceiling.

One hierarchy query also retains a bounded set of exact `(node identity, distance)` pairs, charged to at most one one-hundred-twenty-eighth of the original allowance and one quarter of initially available space. A read-only query holds a fixed graph; during a single insertion the query and all existing normalized vectors are fixed while only adjacency changes. For every repeated identity the distance function's two input sequences are therefore identical. Reusing its original floating-point result preserves its bits, candidate ordering, tie breaks and traversal decisions by induction on visits. No cache crosses a query or insertion boundary, a missing identity is not cached, and failed optional admission computes ordinary distances. Existing cancellation checks remain before every visited candidate.

Generated vector records now receive their resolution mode's write kind when constructed. Previously command refresh prepared a separate canonical generation and then copied every generated record to change that kind. For each generated key the layout, encoded value and expected committed revision are unchanged, and the same final kind is assigned. The common replacement rule retains the original condition when a later generated record shadows an earlier deletion. Therefore the final ordered prepared writes and publication conflicts are identical without an intermediate complete generation.

A transaction mutation's expected revision, liveness and prior write kind now come from one private metadata lookup. The private overlay still wins over the same committed snapshot, including tombstones; a missing private entry still uses committed metadata. Canonical and typed-write precedence and skipped absent deletions are unchanged. An evaluated batch retains cache-reader leases for its initial immutable spill runs, allowing adjacent point checks to share their authenticated entry blocks. The leases retain no record view and cannot change lookup precedence, so new resident writes, spilled replacements and undo continue selecting the latest applicable root. Cached bytes and reader handles remain charged to the original allowance; the last active reader drops decoded blocks even when a savepoint retains the run. Cancellation and every error path release the operation leases through ordinary ownership.

## Table data visibility after maintenance

A native table data generation carries the database identity and sequence of its last committed modification. This is read from the same retained committed record snapshot as the generation, before projecting private changes. Let `S` be the committed boundary already reflected by Engine's data caches and `D(t)` the certified last committed modification of table `t`. If the visible token is private and `D(t) <= S` in the same database, no committed table change is new to those caches; the transaction's own writes already maintained them. An unrelated statistics or other-table commit can therefore retain the caches even if read-free adoption of an earlier own commit left the generation-token baseline behind. A peer row write has `D(t) > S` and takes the ordinary refresh. Missing certificates, another database, unversioned identities and non-private tokens remain conservative. Undo keeps its explicit invalidation boundary. No receipt read, full catalog capture or data scan is added to own-commit adoption.

## Regression evidence

An immutable spill run optionally indexes every nonempty literal key prefix in a charged Bloom filter. After an ordered key is inserted, all its prefixes are represented: prefixes up to the longest common prefix with the previous key were already inserted, and rolling hash states insert every longer prefix using the same hash as lookup. By induction every prefix of every run key, including tombstones, is represented. A negative filter answer therefore proves the run cannot contribute to that prefix; a collision, saturated filter or omitted allocation takes the ordinary bounded merge. Empty prefixes bypass the filter. Newer resident writes and retained run roots keep their existing precedence, so excluding a proven absent run preserves complete keys, payloads, revision metadata and tombstone shadowing. Hash construction is linear in input key bytes, and the filter is limited to one quarter of the remaining shared workspace; no allocation is required for correctness. Binary and long-key regressions check every prefix and shared-budget release. A synthetic missing-prefix regression inside a block's endpoint interval observes three block reads and 387 entry decodes before filtering and zero afterward, with unchanged matching results, savepoint undo, retained snapshots and cancellation. This is a deterministic fixture bound, not a promise that a Bloom filter rejects every absent prefix.

An exact visible-record revision now selects the private entry's original committed revision, liveness and private identity in one point lookup. Previously it selected the same metadata and then opened a one-key prefix scan to recover the private identity. For a fixed immutable private root both operations select the same newest entry; using that entry's identity directly preserves private precedence, tombstones and undo-branch distinctions. A private miss still reads the retained committed snapshot, while a private tombstone still suppresses the committed value. No value is materialized, and cancellation and storage errors continue to propagate. Point misses outside spill-key ranges no longer open unrelated run heads; point hits decode the selected entry only once.

Synthetic Storage revision regressions vary the unrelated private corpus size, force spill, and assert zero entry/block/value reads for committed keys preceding the private range. Private revision checks compare work against a single metadata lookup, retain old views across deletion and replacement, verify savepoint undo and distinct replacement identities, and enforce cancellation and allowance release. Both regressions fail against the former metadata-plus-range implementation without changing the production path for tests.

A forward spill cursor also uses the immutable run's last key to reject disjoint starting bounds before opening its last block. For maximum key `m`, an included lower bound `k > m` or excluded lower bound `k >= m` has empty intersection with the run. Returning the block-count end position therefore preserves ordered support, including tombstones, while an included `k = m` still visits the last entry. The same boundary selection handles forward seeks from an active cursor; exhaustion releases cached readers and still checks cancellation. A synthetic run test varies 128/1024 records and asserts zero block, entry and value reads for disjoint ranges and seeks, exact last-key inclusion, cancellation and complete allowance release.

A literal prefix describes one lexicographic interval. For a run with first key `a` and last key `z`, that interval is disjoint if `z < prefix`, or if `a > prefix` and `a` does not start with the prefix. Omitting such a run from the merge cannot remove a matching identity, payload, tombstone or shadowing write because the run contains no key in the requested interval. All potentially intersecting runs retain their original newest-first precedence and ordinary per-key prefix checks. Entry, value and metadata scans pass this bound before opening any spill readers; empty-prefix merges and ordered selections remain unbounded. The regression observes six unrelated block reads before the correction and zero afterward, with unchanged matching results, cancellation and memory release.

Each immutable entry block now retains its last key as well as its first. For an inclusive start `s`, blocks with `last < s` contain no requested entry; for an exclusive start, the condition is `last <= s`. Binary search over these monotone endpoints selects the first possibly contributing block, including a gap between blocks. Point lookups reject gaps before opening an entry reader. Prefix pruning applies the same interval proof to the first block whose last key reaches the prefix. Paged readers pass their existing exclusive continuation bound directly, so the previous page's last entry is not decoded again. Endpoint keys share charged immutable allocations, the block-index cardinality remains bounded, and unchanged readers still validate every selected entry and preserve newest-write precedence. The boundary regression reads two blocks and 390 entries on the former path; its contract is exactly one block and the first selected entry, plus unchanged cancellation and complete allowance release.

The committed record scan contract explicitly makes a short page an exhaustion certificate at the fixed snapshot. Private scans return the same complete ordered prefix segment, including tombstones. Merging two such pages cannot return fewer than the limit while leaving another visible identity: either input with a full page already supplies that many unique identities to their union. Population reconciliation therefore stops after processing a short merged page, instead of opening another complete set of spill readers to prove exhaustion again. It keeps owned pages so callbacks may safely perform other storage reads, and checks cancellation after the final callback. Full pages still request a continuation. The owning regression covers both sides of the 64-record page boundaries, exact live values amid tombstones, unrelated suffix keys, cancellation and complete memory release; the former path performs an extra block read on every short terminal page.

An encrypted temporary-file read returns at most the remainder of its current physical block. For a requested interval `[a, b)` and physical block width `B`, exactly `ceil(b/B) - floor(a/B)` blocks intersect a nonempty interval. Spill entry and value loops now consume each short physical read before requesting more bytes. Every nonterminal iteration therefore ends on a physical boundary, so no intersecting block is decrypted twice within the range. The former `read_exact` loop filled a logical chunk across that boundary, then reread the partially consumed trailing block on its next iteration. Concatenating short reads returns the identical interval in order; value-copy callbacks still receive only bounded consecutive chunks. Memory reservations and ciphertext authentication are unchanged, cancellation is checked before every read, interruptions retry and premature EOF remains an error. Owning regressions observe three physical reads where an entry interval needs two and five where a value needs three before the correction; they assert the exact interval bound, complete value bytes and release of every reservation afterward.
