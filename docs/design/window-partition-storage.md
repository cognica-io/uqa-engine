# Bounded positional window partitions

Execution owns window evaluation and its temporary row representation. `spill/indexed/buffered.rs` implements a positional store whose small partitions remain in memory and whose larger partitions use the existing encrypted `IndexedSpill`. SQL and built-in physical windows each pass their existing one-third `work_mem` phase allowance. Engine, query planning, sorting and scalar evaluation remain unchanged; no dependency, SQL syntax or durable format changes.

## Representation invariant

Fix one physical schema S and the finite ordered sequence R of rows already accepted by a partition. Let E_S(r) and D_S(b) be the existing typed physical-row encoder and decoder used by indexed spill. Their existing round-trip contract preserves every physical slot, value tag, floating-point bit pattern and lock origin, while S retains logical names, hidden slots and aliases. The memory representation is exactly `[E_S(r) for r in R]`. The disk representation is the existing offset-indexed concatenation of those same encoded row records. Both therefore implement `len = |R|` and `get(i) = D_S(E_S(R[i]))` for valid i, and reject an out-of-range position.

The empty memory store establishes the invariant. An admitted memory append validates the row against S, reserves its encoded buffer and row-header capacity, encodes it with E_S and publishes it at the next position. Failed validation or allocation publishes no new row. When retention would exceed the allowance, a private disk store receives the already-validated encoded prefix through the original indexed-spill framing and write path, followed by the incoming row through its original encoder. The representation changes only after every append succeeds. Failure drops the unpublished temporary files and leaves the old memory prefix intact. Success releases the original buffers and their reservations, then subsequent operations use the existing disk store. Induction on appends proves the invariant in either representation and across the single transition.

## Window observations

Window sorting and partition-key evaluation produce the same R in the same order. Each existing window evaluator issues the same positional reads, evaluates the same scalar expressions with the same context, and uses the same peer and frame boundaries. Replacing each positional read with the observationally equal result established above preserves each subsequent evaluator state by induction. Thus row number, rank, dense rank, lag, lead, ntile and aggregate frames retain their values, types, NULL behavior, numeric evaluation order and diagnostics. Output construction and subsequent relational composition receive identical physical rows. No aggregation rewrite, arithmetic reassociation or new algebraic operator is introduced.

The memory representation uses the codec even when no file is needed. It therefore retains the same value validation, physical-width checks, nesting limits and owned decoding boundary as the disk representation. It does not retain a shallow source-row clone or skip serialization errors. Temporary-file creation errors can arise only when disk storage is actually required; accepted in-memory rows perform no file operations.

## Frame boundary corrections

Independent PostgreSQL 18 checks exposed two frame-selection errors in the owner shared by both representations. ROWS bounds now retain signed positions outside the partition until the complete interval is intersected with `[0, n-1]`. Clamping each bound separately can turn an empty preceding or following interval into one boundary row; intersecting the complete interval yields the required empty frame, with COUNT equal to zero and SUM equal to NULL. Positions use i128, so a u64 row identity plus or minus an admitted i64 offset remains representable.

GROUPS offsets now move across equivalence classes of adjacent equal ORDER BY keys in the already sorted partition, then choose the first or last row of the target peer group. Induction on the requested offset shows that each outer step crosses exactly one group boundary; the final within-group scan selects the requested endpoint. Moving beyond the first or last group returns an out-of-partition sentinel, preserving empty-frame behavior through the same interval intersection. Descending ordering and NULL peers use the selected partition order and existing key equality. The traversal exits at a partition boundary even for very large offsets, so it does not loop once for every absent group. These are correctness fixes to frame selection; both storage representations use the corrected evaluator.

## Resource and file ownership

Core's `BudgetedVec` charges complete row-header capacities, including simultaneous old and replacement allocations. Each encoded payload is reserved before encoding and its actual capacity is reconciled before publication. Those payload reservations remain live until their buffers are destroyed. The partition's retained representation stays within its explicit phase allowance; zero allowance and oversized rows select disk storage. The existing single-row codec and disk workspace, input/output operator buffers, schema sharing and allocator bookkeeping keep their existing separate boundaries. A transition holds the memory prefix until the disk copy is complete, and releases its retained charge only afterward.

The existing indexed-spill owner continues to frame records, authenticate and encrypt both temporary files, validate offsets and lengths, roll back failed appends, and unlink its files on drop. Appending already-validated encoded bytes reuses that same owner rather than implementing a second file format or write path. No persistent database synchronization or durability setting changes.

## Verification

Owner tests compare positional values and floating-point bits between buffered and disk stores, exercise zero and bounded allowances, verify oversized-row transition with every preceding row preserved, check reservation release and encrypted-file cleanup, and reject malformed rows without changing either representation's accepted prefix. Existing window, indexed-spill and execution tests cover frame semantics and row layouts. Independent PostgreSQL SQL checks exercise aggregate, peer, frame, ordering, NULL and small-`work_mem` behavior. Performance observations use fixed source and binary manifests and remain separate from correctness acceptance.
